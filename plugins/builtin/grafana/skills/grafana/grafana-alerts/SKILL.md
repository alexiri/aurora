---
name: grafana-alerts
description: Use when an agent should create, change, list or delete Grafana alert rules, for example to be woken when a problem comes back
---

Manage Grafana alert rules only through `scripts/grafana-alert` (see `--help`): `create`, `list`, `update`, `delete`, `expire`. Every rule carries the guard labels `managed_by` and `expires` (at most 30 days; an extension needs `--renew --reason`; the expiry is read from the `expires` label, and a rule whose label and annotation copy disagree is refused — it was changed outside the script), and change and delete refuse a rule without the agent's label or outside the given folder — never touch a rule the agent did not make. Change refuses a rule that left the shape the script builds: a recording rule, a second query, or a label, annotation or receiver setting the script does not set. Caps: 10 managed rules per folder and 5 per `--service`; one Prometheus query, `--for` at least 2m, a range of at least 5m, and a receiver a person made. To change the query or threshold, delete and create again. Every write is held for a person's approval, and the approval shows the script's shape field by field; the card cannot print a map's keys, so a body built by hand could carry fields no card shows — never send one. The script is help, and now also enforcement: the gateway refuses a rule body the script cannot build (a recording rule, a second query, or a label, annotation or receiver setting the script does not set) before the approval, and the remaining hard limits are the approval and the service account's folder permission. A rule costs a query every interval: few and short-lived.
