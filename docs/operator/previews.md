# Port previews and the relay (phase 4)

Port previews let people open a web app that runs inside an agent's sandbox at
`https://<label>.<preview domain>/`. They are **off by default** at three levels: the instance
(`relay.enabled`), the organization (an owner or admin switches **Port previews** on) and each share
(a person with `can_use` on the workspace shares a port). The design is
[docs/15 §Port previews](../15-deployment-operations.md#port-previews-phase-4-p4-prv-1-p4-prv-2-d-144d-147-sec-80sec-82-sec-85)
(deployment), `docs/16 §W18` (stream protocol and limits) and `docs/04 §Preview access` (authority). This page
is the operator's path through it. Chart keys are listed in
[docs/23 §Port previews (relay)](../23-helm-values.md#port-previews-relay).

## What you need

1. **A preview domain** you control and that is **not** the dashboard's host or a parent of it, for example
   `aurora-previews.example.org` next to `aurora.example.org`. Startup refuses a domain that contains, is or sits
   under `server.external_url`, an `auth.trusted_origins` entry or the gateway's advertised proxy host, a single
   label, or a bare public suffix. Set it as `config.previews.domain` **and** `relay.domain` (they must be equal).
2. **Wildcard DNS**: `*.<preview domain>` → your edge. Aurora creates no DNS records.
3. **A wildcard TLS certificate** for `*.<preview domain>` on the edge (DNS-01 through cert-manager; HTTP-01 cannot
   issue wildcards). The chart renders no TLS block for the wildcard host and has no `previews.tls.*` values: configure
   it on your ingress controller or Gateway listener. Previews are https only.

## Enable

```yaml
relay:
  enabled: true                     # the single switch; also renders config.previews.enabled
  domain: aurora-previews.example.org
  # replicas: 1
  # request_body_max_bytes: 33554432   # chart default 32 MiB; the ceiling is 100 MiB
  # max_streams: 2048
  # max_streams_per_user: 64
config:
  previews:
    domain: aurora-previews.example.org
```

Do not set `config.previews.enabled` alone: the chart refuses a render where it disagrees with `relay.enabled`. The
image `aurora-relay` must be available (see [install-helm.md](install-helm.md#images-publish-pull-or-build-and-load)).
The relay anchor token is generated by the `secrets` hook as `AURORA_RELAY_TOKEN` (with `secrets.existingSecret`,
create that key: `aul_` + 48 hex characters). Then:

1. Wait for the relay pods to be Ready and for **Admin → Overview → Previews** to show the relay replicas the API has
   seen. Prometheus' own `up{job="aurora-relay"}` is the liveness series (there is no `aurora_relay_up`).
2. An org owner or admin switches **Port previews** on in the organization settings.
3. A person with `can_use` shares a port from the agent's page; the sandbox's supervisor then allows only that loopback
   port.

**Turn it off**: `relay.enabled: false`. Shares are kept but inert; the supervisor allow-list empties at its next sync.
Switching the org setting off has the same effect for that organization.

### The edge

`relay.enabled` adds one wildcard host rule `*.<preview domain>` → `aurora-relay:4112` to the Ingress and HTTPRoute
templates; the dashboard host rules, `/internal` and `/metrics` are unchanged. The edge in front of the cluster must
**not buffer responses**, must pass **WebSocket upgrades** (nginx: map `Upgrade`/`Connection`, see the recipe in
[terminal.md](terminal.md#the-edge-and-websockets)), use read/send timeouts of at least 600 s and accept request bodies
up to `relay.request_body_max_bytes`. The relay trusts the edge's overwritten `X-Forwarded-Proto`/`-For` as the API does
(`server.trusted_proxies`).

## NetworkPolicy flows

Rendered only with `relay.enabled` and `networkPolicy.enabled` (default deny stays):

| From | To | Port | Purpose |
|------|----|------|---------|
| edge namespace | relay | 4112 | browser traffic |
| relay | api | 4101 | registration, resolve, stream grants, heartbeat |
| relay | runner pods of this release | 4108 | leg-1 WebSocket streams |
| relay, api | runner | 4108 | the runner's stream listener accepts only these (and the API for the terminal) |
| relay | DNS | 53 | `-allow-dns` |

The relay has **no** other egress (no Postgres, gateway, hook host, sandboxes or internet) and the sandboxes namespace
never reaches 4108. The chart opens **no** ops/metrics port to other namespaces: a Prometheus outside the release
namespace needs a NetworkPolicy of your own that admits it to the relay's 4193. A runner **outside** the cluster must be
reachable from the relay on its stream listener (`runner.stream_bind`, default port 4108) over your own overlay or
private link; without it previews of that runner's sandboxes answer 502 `preview_unreachable`.

## Limits

Enforced as specified in [docs/16 §W18](../16-wire-protocols.md) and `docs/02 §Limits` (FIX-072, C-636/C-637). The
stream caps and the grant rate are per relay replica; the daily quota is one counter shared by all replicas:

| What | Value |
|------|-------|
| Shares per agent / per org | 10 / 200 |
| Concurrent streams per share / per sandbox / per user | 32 / 64 / 64 (`relay.max_streams_per_user`). Over a share or user cap a plain request answers 429 `preview_streams_limit` (`Retry-After: 1`) and a WebSocket upgrade is accepted and closed 4409 |
| Relay streams in total (per replica) | `relay.max_streams` (2048) |
| Request body | `relay.request_body_max_bytes` (chart 32 MiB, ceiling 100 MiB) |
| Bytes per share per day | `previews.bytes_per_share_day` (5 GiB), one shared counter per share and UTC day; over it 429 `preview_quota` with `Retry-After` to the next UTC midnight (a stream already started may finish; the bound can be exceeded by what the relays move between two 15 s heartbeats). With the `management` counter class `closed` and the store down, usage reporting answers 503 `counter_unavailable` and the relay re-sends the bytes with its next heartbeat |
| Grant redemption | `PREVIEW_GRANT_RATE`: 30/min per client address and 10/min per share (per replica, every attempt counts), over it 429 `grant_rate_limited` with `Retry-After` |
| Idle / WebSocket idle / stream lifetime | 120 s / 600 s / 4 h |
| Browser session / idle | 8 h / 1 h |
| Revocation reaches open streams | within `PREVIEW_AUTH_CACHE`, 15 s |

## Troubleshooting

| Symptom | Likely cause |
|---------|--------------|
| Relay refuses to start / API refuses the config | preview domain equals or contains a host the dashboard uses; `relay.domain` differs from `config.previews.domain` |
| Every preview is a 404 | the share was deleted, the org setting is off, the agent is frozen/paused, or the label is wrong (all denials are deliberately the same 404) |
| 502 `preview_unreachable` | nothing listening on the shared port, the runner's 4108 is not reachable from the relay, or the sandbox is gone |
| Login redirect loops | the browser blocks the `__Host-` cookies (the wildcard host is not served over https), or the edge rewrites `X-Forwarded-Proto` |
| WebSocket apps fail, page loads | the edge strips `Upgrade`/`Connection` (see the nginx recipe) |
| Previews refused under load or after heavy use | `aurora_relay_refused_total{reason}` says which limit: `share_streams`/`user_streams` (429 `preview_streams_limit`, or WebSocket close 4409), `quota` (429 `preview_quota`, daily bytes per share), `grant_rate_address`/`grant_rate_share` (429 `grant_rate_limited`: too many logins from one address or for one share) |
| Uploads fail at about 32 MiB | raise `relay.request_body_max_bytes` (at most 100 MiB) and the edge's body limit |
| Dashboard shows no relay replicas | the relay cannot reach api:4101 (policy), or the anchor token key is missing |

## Metrics

Scrape the relay's ops port 4193 `/metrics`. Series emitted (all of them are in the code):

| Series | Labels |
|--------|--------|
| `aurora_relay_requests_total` | `outcome` |
| `aurora_relay_streams_open` (gauge) | — |
| `aurora_relay_stream_bytes_total` | `direction` |
| `aurora_relay_stream_closed_total` | `reason` |
| `aurora_relay_stream_dial_seconds` (histogram), `aurora_relay_stream_dial_errors_total` | `kind` |
| `aurora_relay_grants_total` | `result` (`redeemed`, `invalid`, `no_state`) |
| `aurora_relay_resolve_cache` | `hit` |
| `aurora_relay_refused_total` (FIX-072, C-636) | `reason` (`share_streams`, `user_streams`, `quota`, `grant_rate_address`, `grant_rate_share`) |
| `aurora_preview_shares` (API gauge) | `org` |
| `aurora_preview_stream_bytes_total` (API) | `direction` |

Alert on `up{job="aurora-relay"} == 0`, on a rising `aurora_relay_grants_total{result="no_state"}` or `"invalid"`
(login CSRF, replayed or tampered links) and on a rising `aurora_relay_stream_dial_errors_total`. Logs carry label, share
id, outcome and byte counts, never paths with query strings, headers, cookies or bodies.

## Upgrade and rollback

The relay and the preview columns are additive: an older API ignores them and an older runner reports no `previews`
capability. Upgrade the API and the runners first, then the relay (see
[docs/15 §Upgrades](../15-deployment-operations.md#upgrades)). Rolling back removes the relay Deployment; shares stay
in the database, inert.
