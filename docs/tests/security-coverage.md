# Security invariant coverage (TEST-018)

One row per invariant of `docs/17-security.md` (SEC-01..SEC-88; the phase-4 and phase-5 rows SEC-62..SEC-88 carry the status of their own task, `pending` until implemented). Test ids are
`path::test_name` relative to the repo root, with these prefixes:
`api` = `services/aurora-api/tests`, `gw` = `services/aurora-gateway/tests`,
`sup` = `services/aurora-supervisor/tests`, `run` = `services/aurora-runner`,
`reg` = `crates/aurora-registry/tests`, `e2e-h` = `tests/e2e-hosted/tests`,
`e2e-g` = `tests/e2e-gateway/tests`, `crypto` = `crates/aurora-crypto/tests`, `config` = `crates/aurora-config/tests`,
`channels` = `crates/aurora-channels/tests`, `hookhost` = `services/aurora-hookhost/tests`. Integration tests of a crate are one binary (`tests/it/main.rs`, OPS-016); `file.rs::name` is run as `cargo test -p <crate> --test it -- file::name`. Level: unit / service (real Postgres, in-process
`e2e-g` = `tests/e2e-gateway/tests`, `cfg` = `crates/aurora-config/tests`, `cli` = `services/aurora-cli`. Level: unit / service (real Postgres, in-process
services) / e2e (full stack) / guard (script).

**Where each kind of evidence runs (FIX-101; docs/18 §Skip policy).** A row's "proven" rests on a suite that actually
executes where this column says; an env-gated suite fails in CI rather than skipping.
