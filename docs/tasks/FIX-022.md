# FIX-022: Agent Access tab — connection grant editor (spec gap found 2026-11-09)

## Problem
`docs/14-web-dashboard.md` › agent page › **Access** has specified connection grants since phase 0 (full, or custom with allow/ask/block per tool, read/write groups, wildcard umbrellas only where valid, inert-tool flags; and from phase 4 the P4-GRANTS `custom_only` / `block_untooled` behaviour). The dashboard never built it: `web/src/components/agents/access-tab.tsx` has secret checkboxes, Model readiness (FIX-021) and the effective view, and no web code edits a connection grant per agent. FIX-021 added the credential-side "Give agents access" step (full, or every tool when a `custom_only` 422 comes back). This task adds the **per-agent editor**.

## Spec (read; do not re-decide)
- `14` › agent page › **Access** (the whole bullet, incl. the P4-GRANTS sentences) and §Visual design.
- `05 §Grants and effective views`: `GET /v1/agents/{agent}/grants`, `PUT/DELETE /v1/agents/{agent}/grants/connections/{conn}` (`{ mode, allow_tools, ask_tools, ask_timeout_secs? }`), `GET /v1/agents/{agent}/effective`.
- `09 §3`: tools, read/write classes, groups, wildcard umbrellas and where they are valid, inert tools (tools whose mechanism the current snapshot cannot enforce), the grant validation errors (`empty_custom`, `tool_in_both`, `unknown_tool`, `ask_timeout`).
- `07 §Approval deadlines` for `ask_timeout_secs` bounds.
- The app detail the dashboard already reads (`GET /v1/apps/{app}` via `web/src/lib/api/apps.ts`, as FIX-021 does) for the tool catalogue; the generated types in `web/src/lib/api/schema.d.ts`.

## Scope
1. **Connections section** on the Access tab (owners edit; others read-only): every connection in the agent's scope (workspace and org connections the caller can see) with its grant state: none / full / custom (n allowed, m ask), and **Edit** / **Remove**.
2. **Grant editor** (dialog or side panel, shared primitives):
   - Mode: **Full access** or **Custom**. Full is hidden for `custom_only` apps (from `app_restrictions` when the API sends it, else learned from a 422 `full_grant_forbidden`, as FIX-021 does), with the `14` copy; custom then starts with every tool on *block*.
   - Custom: a per-tool table with **Allow / Ask / Block** per row, grouped **Read** and **Write**, with a group-level setter; wildcard umbrellas offered only where `09 §3` says they are valid; inert tools marked (and explained) rather than hidden; `ask_timeout_secs` input with its bounds when any tool is on Ask.
   - Validation errors from the API map to rows/fields (`empty_custom`, `tool_in_both`, `unknown_tool`, `ask_timeout`); Save uses the agent-side `PUT`; Remove uses `DELETE`.
   - `block_untooled` apps show the "Requests that are not in the tool list are always blocked" note.
3. After save/remove, the effective view and Model readiness refresh (React Query invalidation, reusing FIX-021's hooks in `web/src/lib/api/credential-grants.ts` where they fit).
4. Mock data uses real built-in packages (e.g. GitHub, Jira Cloud, Indico) and their tool names from `plugins/builtin/*/plugin.yaml`.

## Constraints
- **Owns:** `web/src/components/agents/access-tab.tsx` and new components under `web/src/components/agents/` (e.g. `connection-grants.tsx`, `grant-editor.tsx`), `web/src/lib/api/*` hooks it needs, web tests and Playwright specs. Shared UI primitives only if one is missing (say which).
- Does **not** own Rust code or contracts: if the API lacks data the editor needs (e.g. read/write class or umbrella validity per tool), ask through Orca `ask` before inventing a client-side rule.
- `docs/14 §Visual design`: tokens only, shared primitives and page patterns, both themes, no horizontal page scroll at 390 px (the tool table must work at 390 px).
- Change files only with the Edit/Write tools; never python, sed, awk, perl, `cat >>` or heredocs. No `scripts/e2e/*` or `scripts/perf/*`.
