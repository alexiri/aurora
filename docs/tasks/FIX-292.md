# FIX-292: large and binary skill files reach the agent's home (2026-11-28; FIX-291's measurements)

## Why

FIX-291 measured `anthropics/skills` at e4bb5d9 (19 skills) and raised the limits, so 14 of them can be added (D-513). It
found two things numbers can't fix:

1. **Binary skill files are accepted, but never projected.** Aurora accepts and counts a skill's binary files, such as
   theme-factory's PDF and web-artifacts-builder's `tar.gz`. But the supervisor's home sync (`home.rs`) never writes
   them into the agent's home. A skill added "successfully" is missing files the agent's instructions refer to. This is
   a bug.
2. **Five skills need a design change:**
   - One home-sync entry carries at most 202,752 JSON bytes (`HOME_SYNC_PART_MAX` 200 KiB minus 2 KiB). A bigger
     entry is logged and silently skipped.
   - `claude-api` has a 346,255-byte file and 95 files. `docx`, `pptx` and `xlsx` have 242,277-byte files, 52–60 files,
     and folder depth 6. `canvas-design` has 82 files, 7.4 MB in total, more than any tier's budget.
   - The limits they meet: 50 files per skill, path depth 4, and the per-tier budgets.

## Change

1. **Binary files (the bug, always):**
   - project a skill's binary files into the agent's home, base64 in the sync entry and decoded by the supervisor,
     with their mode;
   - count them against the same limits as today;
   - a binary file that can't be carried is refused at add time with a plain reason, never accepted and then missing;
   - a test: a skill with a PDF is added, and the file is in the agent's home with the same bytes.
2. **Large files (owner's choice, see below):** split a file bigger than one part across several home-sync entries and
   reassemble it in the supervisor (protocol and supervisor), so a file is bounded by the skill limits, not by the part
   size. Then raise the file count (to about 120) and the path depth (to 6), and decide the budgets for skills of
   several MB. Update `docs/16` (the wire protocol), `docs/12` and `docs/02` §Limits.

## Placement

Part 1 is a bug fix: one Sonnet lane, size S–M (`aurora-supervisor` `home.rs`, `aurora-api` home sync). It can start now.
Part 2 waits for the owner. If he wants all 19 skills to fit, it's a lane of size L, with a security review of the
protocol change. Tests only through `scripts/dev/test.sh`, plus crate clippy.
