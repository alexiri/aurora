# P4-011B-2: Deciding parked approvals — grants, resume follow-ups, revocation, reminders, settings — **large, phase 5**

## Goal
Make a decision on a parked approval reach the agent: approving turns it into a `ready` single-use
grant and, in the same transaction, writes one platform-composed **system follow-up** in the origin
conversation (a steer into the running origin turn, else a new system turn); denying writes a
"denied" follow-up; expiry, an unused window and every access-removal event end it honestly with a
notice and no turn. Also the reminder e-mail, the DTO fields, cards, the agent preamble paragraph,
the `approvals.park.*` settings and the approval-limits route.

## Scope

2. **Decisions** (C-823): in the deciding transaction for parked rows — approve sets `ready` and

   transaction, `PARK_FOLLOWUP_LINES_MAX`, door `{ kind: "system", ref: "approval:<id>" }`, the

4. **Transcript and cards** (C-825): event payload additions, notices `approval_window_ended`,

5. **Revocation hooks** (C-826): extend `abandon_pending_depending_on` and the freeze path so the

6. **Jobs** (C-828): resume-window expiry (`expired`, event, notice, card edit, no turn); the

## Acceptance criteria (each new test seen failing first)
1. `api/it/approval_park.rs`: approve/deny/expire under the unchanged decider matrix (RFE-012,
   RFE-009, groups); approve → `ready` with the window, follow-up steered into a running origin
   turn (fake harness with `steer`) or queued as a system turn without a speaker (harness without
   `steer`); deny follow-up; expiry → event + notice, no turn; frozen agent → no follow-up,
   `revoked`; canary strings in the request path/title appear only through the sanitized summary.
2. Batch decision over three parked approvals of one conversation → exactly one follow-up with
   three lines and door `{kind:"system", ref:"approval:…"}`; a forced failure after the decision
   statement rolls back decision, follow-up and audit together.
3. `api/it/approval_park_revoke.rs`: each FIX-084 event (grant delete, grant narrowing, connection
   disable, secret delete, blocking snapshot), freeze, agent delete, conversation delete, harness
   switch and `reset_session` redaction → pending parked `abandoned`, ready `revoked`, notice
   where a transcript remains, no turn; unfreeze revives nothing.
4. Resume-window expiry and the reminder: reminder e-mail once per user across two job runners
   (claims), none with a live watcher, none after a decision; `approval_notifications` initial
   claims unchanged.
5. Settings: the two cross-key refusals; loosening flags in the preview; `GET
   /v1/policy/approval-limits` reflects a live change; rule timeout bound follows the switch;
   simulate shows `approval_parks`/`approval_timeout_clamped`.
6. Stall exemption still applies to held approvals and not to parked ones (existing
   `approval_stall.rs` extended).
7. Sandbox lifecycle (fake runner): a parked approval does not keep the sandbox awake; the resume
   turn starts a new boot with the session restored.
8. OpenAPI and `web/src/lib/api/schema.d.ts` regenerated; fmt, clippy, targeted tests, guards exit
   0, `extract-schema.py --check`.
