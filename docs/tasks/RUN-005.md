# RUN-005: Inbound attachment delivery (`file.in`) and `send_file` tool

## Goal
Implement decision S-11: the runner downloads inbound attachments and streams them to the supervisor as `file.in` frames before `turn.deliver`. The supervisor writes them into the inbox, and `send_file` becomes a listed supervisor-local tool.

## Linked requirements
- Decision **S-11** in `docs/90-decisions.md` (authoritative frame shape and ordering)
- `docs/10-agents-conversations.md` §Attachments; `docs/16-wire-protocols.md` §W5 (`GET /runner/attachments/{id}`), §W6 (frame kinds, sequencing, `WS_FRAME_MAX`)
- `docs/12-supervisor-harness.md` §Platform tools (phase 0 catalogue: `send_file {path, caption?}`), §Outbound files
- SEC: filenames are untrusted. There must be no path traversal outside `/workspace/.aurora/inbox/<turn_id>/`.

## Context
- Protocol: `crates/aurora-protocol/src/supervisor.rs`:
  - `FilePart` / `MAX_FILE_PART_DECODED` (S-06) is the pattern to mirror
  - add `FileIn` to the runner→supervisor enum with a `Validate` impl
  - regenerate `schemas/` (`UPDATE_SCHEMAS=1 cargo test -p aurora-protocol`)
  - add a wire test to `tests/wire.rs`
- Runner: `services/aurora-runner/src/channel/plane.rs` (outbound file handling), `api.rs` (API client; add `download_attachment(id)` with a size cap = `max_attachment_bytes`). Find where `turn.deliver` work items are forwarded to the channel (executor / hub) and insert the download + `file.in` frames before it. On a download failure, forward `turn.deliver` anyway; the supervisor reports the missing file to the model.
- Supervisor: `services/aurora-supervisor/src/supervisor.rs` (`attachment_paths` built around line ~425 from `d.attachments`); `outbound.rs` (`send_file`); `tools.rs` (`ToolHub::catalogue`, local tool dispatch); `process.rs` (`local_descriptors`, `is_local_tool`, the pattern for local tools).
- Spawn rule: any child process must go through `crate::spawn` (SEC-FIX-01). Writing files doesn't need child processes.

## Scope
### In scope
- `FileIn` wire type, schema and validation (decoded chunk ≤ 144 KiB, filename chars, index/last consistency).
- Runner:
  - for each attachment in `turn.deliver`, fetch it, chunk it into `file.in` frames, then send `turn.deliver`
  - a size cap and timeouts on the download
  - metrics/log lines without file contents
- Supervisor:
  - assemble `file.in` frames per (turn, attachment) in a temp file under `/workspace/.aurora/inbox/<turn_id>/`
  - verify size and sha256 on `last`, then atomically rename to the sanitized filename (`[A-Za-z0-9._-]`, ≤ 128, de-duplicate collisions with `-1`, `-2`)
  - discard on mismatch
  - when the turn starts, pass only the files that exist to `attachment_paths`, and add a line to the turn input for each missing one
  - cap total in-flight inbound bytes per turn at `ATTACH_IN_COUNT × ATTACH_IN_FILE_MAX`
- `send_file` as a supervisor-local tool:
  - add a descriptor to `local_descriptors` (or a sibling list) with schema `{path: string, caption?: string ≤ ATTACH_CAPTION_MAX}`
  - route it in `ToolHub` to `outbound::send_file` with the current conversation/turn of the calling session
  - return `{ attachment_id }` after `file.result`, or a tool error with a clear message (bad path, too large, rejected by the API)
- Tests:
  - protocol wire round-trip
  - runner: a fake API serves an attachment, and the channel receives `file.in` frames in order, then `turn.deliver`
  - supervisor:
    - frames are assembled into the right path
    - traversal filenames (`../x`, `/etc/passwd`, `a/b`) are sanitized
    - a sha mismatch is discarded and noted
    - `tools/list` includes `send_file`
    - `send_file` happy path through the fake channel

### Out of scope
- API routes (BE-064, in parallel). Use the W5 contract as written in 16 + S-11, and mock the API in tests.
- E2E (TEST-014 will exercise it through podman).
