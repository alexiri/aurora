# FIX-226: the platform tools index shows the tools' real names

**Owner 2026-11-22.** An agent reported that the *Platform tools* section of its instructions is
misleading: "the actual tool names are different from what is stated". It proposed, for every family:

```diff
-- memory (save, get, list, search, delete): notes you keep across conversations
+- memory (`memory_save`, `memory_get`, `memory_list`, `memory_search`, `memory_delete`): notes you keep across conversations
```

The owner agreed ("go for it").

- Size S, Rust (supervisor only) plus two spec lines.
- One lane, Sonnet. Orchestrator code review; no security review (no new input, no new authority).
- **No numbers.** D-297(c) already says the fragment lists each family's "purpose and tool names"; the
  short verbs came in with C-654's wording and the P5-GUIDE-7 build. This fix brings both back to
  D-297. C-654 and `24 §10b` are amended in place in this commit.

## Problem

`platform_tools_fragment` (`services/aurora-supervisor/src/instructions.rs:131`) prints one line per
family as `- <family> (<verbs>): <purpose>`. It makes the verbs by stripping the family name, minus a
trailing `s`, plus `_` from each tool name:

1. **The verbs are not names the command accepts.** The paragraph above the list says
   `aurora-agent describe aurora <name>` and `aurora-agent call aurora <name> …`. The platform target
   looks a tool up by its exact name (`services/aurora-supervisor/src/agent_cli/platform.rs:161`), so
   `aurora-agent call aurora save` fails with `unknown platform tool "save"`. The agent only finds the
   real name after a failed call and an `aurora-agent list aurora`.
2. **The stripping is inconsistent, so one list mixes verbs and names.** `memory_save` → `save`,
   `schedule_create` → `create`, `skill_get` → `get`, but `processes` tries the prefix `processe`
   and prints `process_start, process_status, …` in full, and `messaging` (`send_message`,
   `find_recipient`, …) has no common prefix and prints full names. The current snapshot shows both
   forms side by side (`aurora_supervisor__instructions__tests__platform_tools_on_demand.snap`,
   lines 58–60). The agent can't tell which entries are names and which are shorthand.
3. **The 200-character cap can cut a name in half.** The joined list goes through
   `inline(…, 200)`, which truncates silently. With full names a long family line gets closer
   to that cap. A half name would be a new misleading name.

## Do

### 1. `platform_tools_fragment` (`services/aurora-supervisor/src/instructions.rs`)

- Print each family's tools by their **full names, each in backticks**, in the order received,
  joined by `, `:

  ```
  - memory (`memory_save`, `memory_get`, `memory_list`, `memory_search`, `memory_delete`): notes you keep across conversations
  - processes (`process_start`, `process_status`, `process_stop`, `process_watch`): long-running commands that outlive a turn
  ```

- Remove the prefix stripping (`verbs`) entirely.
- A name is printed only if it is 1–64 characters of `[a-z0-9_]`. Skip any other name, because a
  backtick or a space would break the line. The render inputs come over the home sync and the
  supervisor treats them as data; every registry and local name matches today. A family left with
  no printable name is omitted, as an empty family is today.
- Do not cap the joined list. Each name is already bounded, and the list is bounded by the
  registry. `inline(&f.name, NAME_MAX)` and `inline(&f.purpose, 200)` stay.
- Update the doc comment above the function (it says "its verbs (the tool names without the family
  prefix)"): it now prints the tool names as the `aurora-agent` `<name>`.
- The fixed paragraph does not change.

Nothing changes in the API: `platform_tools_input` (`services/aurora-api/src/domains/hosted/home.rs`)
already sends full names in `families[].tools`.

### 2. Spec (already done in this brief's commit; check that the code matches)

- `docs/24-apps-for-agents.md` §10b, *Index in the instruction file*: the example lines use full
  names in backticks, and the token estimate is updated.
- `docs/API_CONTRACTS.md` C-654: per family `` - <name> (`<tool>`, …): <purpose> ``, with full tool
  names (the `aurora-agent` `<name>`).
