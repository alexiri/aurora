# FIX-248: the one-time secret dialog — a Copy button that copies visibly, and a webhook secret that says what it is (owner 2026-11-26)

## Why

Owner request 2026-11-26: creating an agent from the NightManager template ends with the dialog
"Webhook Grafana alert" showing a long code with a "Copied" button and an "I have saved it" button.
Two defects: the "Copied" button "doesn't actually do anything", and the dialog says nothing about
what the code is or why it must be copied.

The shared component is at fault for (1): `useSecretCopy` sets `used` on the first successful copy
and `SecretBox` labels the button "Copied" with a check **for ever** once `used`; the two-second
`state` is only used for the screen-reader text. So after the first click the button is a permanent
"✓ Copied": every later click still copies, but nothing visibly happens. The bare dialog (2) is the
new-agent page's `SecretOnce` with no description and no children.

## Fix

1. **A Copy button that gives feedback on every click** (`web/src/components/ui/secret-once.tsx`, the
   shared component behind every one-time secret): the button says **Copy**; after a click it says
   **Copied** with the check for about two seconds (the existing `state`), then goes back to
   **Copy again**; every click copies and gives that feedback. A failed copy keeps the existing red
   sentence ("Your browser blocked copying; select the text instead.") and the button stays **Copy**.
   The screen-reader status line announces every copy (a repeated identical text is not announced, so
   the wording changes: "Copied", then "Copied again.", then "Copied n times."). `used` keeps exactly
   its old job: gating the "You haven't copied it. Close anyway?" confirm. A copy that the browser
   refuses (or cannot even attempt: focus trap, iframe, non-secure context) falls back to selecting
   the box's text and `document.execCommand("copy")`; no new dependency.
2. **The explanation** (`web/src/components/templates/new-agent/page-view.tsx`): the dialog for each
   new webhook's secret (`res.webhooks[].secret`, shown once, C-1111) says, in the product's words
   (`14 §Vocabulary`): what it is (the secret the sender of this webhook must present with every
   alert so Aurora knows the alert is genuine and wakes the agent), why copy it now (shown only this
   once; if lost, make a new one by editing the webhook), what to do with it (paste it into the
   sender — as the Bearer token of the sender's contact point, or as the signing secret the sender
   signs the signature header with, said from `webhook.verification`), that the webhook starts Paused
   and where to turn it on (the agent's Automations page), the agent's and webhook's names in the
   heading ("Secret for the webhook “Grafana alert” of NightManager"), and "Webhook 1 of 2" when
   there are several. One-sentence lead, short list of steps, no manual.

## Audit

Every other caller of `SecretOnce`/`SigningSecretOnce` is listed in the report with whether it
explains the value and why to copy it; the ones that show a bare code get one sentence in the same
style (only the cheap ones are fixed).

- vitest for the new-agent page: the dialog explains a Bearer-token webhook and a signed webhook, says
  Paused and where to turn it on, and shows "1 of 2".
