# FIX-148: AUDIT-004 run-half findings — SCIM status errors never recorded, Previews line missing from Admin › Overview, uninstall leaves the CA key undocumented, SCIM settings PUT returns a stale body — **small–medium, phase 4 (exit follow-up)**

## Problem
`docs/audit/phase4-exit.md` §Open findings (run lane), on the audited commit `1f77f68f`:
- **F-3 (medium, fix before the phase-4 sign-off):** `GET /v1/orgs/{org}/scim/status` has an `errors` list ("the last rejected requests per org", C-472, `docs/operator/scim-provisioning.md` §Operation, `docs/15`) that is **always empty**: it reads audit rows `action = 'scim.error'`, and `record_scim_error` (`services/aurora-api/src/domains/scim/management.rs` ~563) has **no caller**. On the audit cluster, 4 rejected authenticated requests (409, 3 × 400) left `errors: []`.
- **F-4 (low):** `docs/15 §Port previews` and `docs/operator/previews.md` tell the operator to wait for "Admin → Overview → Previews" to show the relay replicas the API has seen. `GET /v1/admin/relays` exists, nothing in `web/src` calls it, and `GET /v1/admin/overview` has no relay field.
- **F-5 (low):** after `helm uninstall` the namespace also keeps the Secrets `aurora-secrets` (generated DB passwords, relay token…), `aurora-gateway-ca` (the gateway CA **private key**) and the ConfigMap `aurora-config` (hook resources); `docs/operator/install-helm.md` ("what remains", §Database) and the chart's `NOTES.txt` name only the Postgres objects.
- **F-6 (low):** `PUT /v1/orgs/{org}/scim` answers 200 with a body that does not reflect what was stored (`enabled:false`, `email_domains:[]`); a `GET` right after is correct.

## Plan
1. **F-3:** call `record_scim_error` from the SCIM plane's error path for **authenticated** requests (the org is known) that end in 4xx/5xx, sanitized as the function's doc comment requires (no request body, no token, SCIM `detail` truncated per its bound); unauthenticated 401s have no org and are not recorded (say so in the doc). Make sure the write cannot fail the SCIM response (best effort, logged) and is bounded (the status reads the last N — check the existing limit, `02`). Failing-first IT in `services/aurora-api/tests/it/scim_*.rs`: a rejected request (e.g. 409 duplicate userName, 400 bad filter) appears in `/scim/status` `errors` with its status and a sanitized message; a 401 does not.
2. **F-4:** add the Previews line to Admin › Overview as the docs promise: the overview DTO gains the relay replicas seen (count, last seen; from what `GET /v1/admin/relays` reads) when previews are enabled, and the Overview page shows it (tokens/primitives only, both themes, 390 px). OpenAPI regenerated (`UPDATE_OPENAPI=1 … openapi_matches_checked_in`, `pnpm -C web gen:api`). If the overview route's contract (C-number) needs a new field, add it in the existing block's style. Unit test for the page state; IT for the field.
3. **F-5:** extend `install-helm.md` (uninstall step and §Database) and `deploy/helm/aurora/templates/NOTES.txt` with the three objects, what each holds, and which to keep for a reinstall in the same namespace (the generated secrets and CA make the old PVC and existing sandboxes' trust usable) versus delete for a clean removal (the CA private key).
4. **F-6:** the PUT returns the stored settings (re-read after the write, in the same transaction or by the same function the GET uses); assert it in the SCIM management IT (fails first).
