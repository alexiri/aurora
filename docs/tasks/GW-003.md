# GW-003: Gateway resolution + decision + secret/LLM injection + guidance + request log

## Goal
Make the MITM lane functional for **secrets and LLM keys** (app connections arrive with M3): connect-time resolution (cached, invalidated), credential selection, policy decision, injection, guidance codes, request-log batching. Also the open-lane policy check.

## Linked requirements
- M2/06 `§MITM lane: connect-time resolution` steps 1, 3, 4, 5 (policy view; secret and LLM candidates; injection selection; app candidates/availability = later), `§Per-request pipeline` steps **4, 6 (secrets/LLM part), 7, 11 (secret recipes + LLM injection; plaintext lazily via SecretVault, 60 s zeroizing cache), 14 (guidance for upstream 401/403 without injection: `access_restricted`, `credential_not_found` subset), 15**, `§Guidance responses` (codes used here), `§Lanes` (open lane: host-level policy; refuse needs-approval with 403; never inject), `§Caches and invalidation` (ResolvedHost + plaintext caches, registered with GW-002's `Hub`), `§Rate limiting` (in-memory per replica, D-05); `07 §Evaluation`, `§Injection selection`; `08 §5 Injection recipes` (escaping rules), `§6` LLM injection (strip agent-supplied auth headers); SEC-03 (policy before decryption), SEC-04, SEC-05 (overwrite, never merge), SEC-08, SEC-12; `18 §Policy and gateway` (pipeline tests per guidance code; cache invalidation changes the next outcome).

## Scope
### In scope
- `crates/aurora-secrets/src/recipe.rs`: `InjectionRecipe` serde enum exactly per `08 §5` (`bearer`, `header{name, format}`, `query{name, format}`, `basic{username}`, `path_template{prefix}`, `path_regex{pattern, replacement}`) + `validate()` (header name token, forbidden `Host`/`Content-Length`/hop-by-hop, `{value}` only substitution, regex anchored ≤256 chars compiles). Used later by the API for create-time validation.
- `crates/aurora-db/src/repo/gateway.rs` (extend): load published policy generation + rules for org and workspace scopes, derived rules for the workspace (+ org), active secrets of org/ws (metadata only: id, scope, kind, llm fields, host/path patterns, injection, value_ref, value_version, origin), batched `request_log` insert (COPY or multi-row insert), `touch_secret_last_used`.
- Gateway modules: `resolve.rs` (ResolvedHost per (org, ws, credential, host) with TTL 60 s; implements `Invalidatable`), `decide.rs` (implements `RequestHandler`: body prefix buffering per step 4 when any candidate rule has conditions or approval may occur (holds are GW-004: for now `needs_approval` → respond 403 `manual_approval_denied`? **No** — respond 503 `approval_store_unavailable` with a `TODO(GW-004)` so it fails closed), selection precedence (path-limited secret over whole-host; workspace over org), ambiguity 409 `multiple_providers` with choices + `x-aurora-connection-id` choosing, decision mapping to guidance codes with `manage_url`s built from `server.external_url` (`/o/<org-slug>/w/<ws-slug>/policy` etc. — load slugs with the identity), rate limit 429 + `retry-after`), `inject.rs` (apply recipe or LLM injection, overwriting agent values; strip agent-supplied auth headers for LLM; header values reject CR/LF/NUL → 502 `credential_unavailable`), `plaintext.rs` (zeroizing 60 s cache keyed by `(SecretRef, version)`; store unavailable → 503 `secret_store_unavailable`), `reqlog.rs` (in-memory batch flushed every 5 s or 500 rows, path redacted per `02 §Coding rules`; shutdown flush), open-lane `open_lane_check` using the same policy view (no injection; needs-approval → 403; rate-limited → 429).
- LLM governance step 6a and holds are **out of scope** (GW-004/GW-005) — leave clearly marked seams.

### Out of scope
- App connections/snapshot/mechanisms (M3), approval holds (GW-004), governance (GW-005), request-log partitions (API job).

## Acceptance criteria
Pipeline tests (DB rows inserted via SQL; mock upstream via `aurora-testkit::MockUpstream` or GW-001 TLS helpers):
- [ ] Granted generic secret (workspace allow rule with `secret{id}` target + identity agent) is injected as bearer/header/query/basic/path_template; agent-supplied `Authorization` is overwritten (upstream asserts single header).
- [ ] Ungranted secret not injected; upstream 401 → guidance `access_restricted` (status preserved); unknown host 401 → `credential_not_found`.
- [ ] Block rule → 403 `blocked_by_policy` with `rule_name`; default `block` with injection → `blocked_by_default_policy`; workspace `uncredentialed_default=block` + not allow-listed → `blocked_by_egress_policy`; rate limit 2/minute → third request 429 with `retry-after`.
- [ ] Policy before decryption: a blocked request never calls the secret store (memory store counter or a store that panics on `get`).
- [ ] Two candidates → 409 `multiple_providers` listing ≤20 choices; `x-aurora-connection-id` picks one; unknown id → 404 `connection_not_found`.
- [ ] LLM key for a LiteLLM endpoint injected as Bearer and agent `x-api-key` stripped.
- [ ] Invalidation: after `NOTIFY aurora_gateway_invalidate {"scope":"workspace",…}` a newly published block rule applies on the next request (no 60 s wait).
- [ ] Request-log rows written with decision, rule name, status, injected count; open-lane tunnel row with byte counts.
- [ ] `cargo test -p aurora-gateway -p aurora-db -p aurora-secrets`, clippy, fmt, `scripts/guards/dep-graph.sh`.
