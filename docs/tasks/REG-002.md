# REG-002: `aurora-registry` package format, digest, signatures, archive/asset rules, zones, reserved hosts, cross-package checks

## Goal
Complete the validator (`09 §6`) with everything that needs the archive, keys, the public-suffix list or other packages; plus the group wildcard superset check deferred from REG-001.

## Linked requirements
- M3/09 `§2 Package format` (tar.gz, allowed paths, no symlinks/absolute/`..`/duplicates, `PACKAGE_MAX`, icon PNG ≤256 KiB square ≥64 px, setup.md CommonMark without raw HTML ≤64 KiB, canonical digest, `SIGNATURE` format, trust: compiled-in project key for publisher `aurora` or non-revoked trusted key with matching publisher; unsigned only with `allow_unsigned`), `§6` remaining rules (signature/publisher; archive/sizes/icon/guide; zone broader than `*.<registrable domain>` via PSL; egress hosts reserved or private; claims on reserved hosts: LLM endpoint hosts, instance external host, internal service hosts, `*.aurora.internal`; duplicate app ids across all active packages; group wildcard true superset of its group); SEC-15, SEC-16, SEC-17.

## Context
- Read `docs/09-app-plugins.md` §2 and §6 (and §3.4 `tools` for wildcards). REG-001 code: `Manifest::parse`, `validate::manifest`, `Violation`, `template`.
- `aurora-crypto` ed25519 (`verify`, `parse_public_key_b64`, `parse_signature_b64`, `generate_signing_key`). `aurora_policy::{HostPattern, PathPattern}`. `aurora_core::limits::{PACKAGE_MAX…}`.
- Workspace deps now available: `flate2`, `tar`, `psl`, `pulldown-cmark` (default-features off), `sha2` (or use aws-lc-rs digest via aurora-core/crypto). Do not edit root Cargo.toml further.
- WIT/`hooks.wasm` checks are **out of scope** (need the wasm toolchain, decision I-02) — validate only that `hooks.wasm` presence matches `permissions.hooks` being non-empty.

## Scope
### In scope (`crates/aurora-registry/src/{package,digest,signature,validate/*}.rs`, tests + fixtures)
- `Package::read(bytes, limits) -> Result<Package, Vec<Violation>>`: gunzip+untar in memory with size accounting (reject > `PACKAGE_MAX` compressed and a decompressed cap, e.g. 4× — document), entry type checks, path rules, required files.
- `digest(&Package) -> [u8;32]` per the canonical text; `Signature::parse`; `verify(pkg, trust: &TrustStore, allow_unsigned) -> Result<Signer, Violation>` where `TrustStore { project_key: Option<VerifyingKey>, keys: Vec<TrustedKey{publisher, key, revoked}> }`; `key_id` `builtin` ⇒ project key and publisher must be `aurora`.
- Asset checks: PNG signature + IHDR dimensions (square, ≥64 px), ≤256 KiB; guide UTF-8, ≤64 KiB, no raw HTML (pulldown-cmark events `Html`/`InlineHtml` ⇒ violation).
- Zones: `*.example.com` OK; zone whose registrable domain (PSL) is not the zone suffix (e.g. `*.co.uk`, `*.com`, `*`) ⇒ `zone_too_broad`.
- `ValidationContext { running_version, reserved_hosts: Vec<HostPattern> (LLM endpoint hosts + external host + internal names + `*.aurora.internal`), active_app_ids: HashMap<app_id, package_id> }` and `validate::package(&Package, &ValidationContext, &TrustStore, allow_unsigned) -> Vec<Violation>` running REG-001 rules + these. Egress hosts in `permissions.egress` must not be reserved, private IP literals, or `localhost`.
- Wildcard superset: a group wildcard is valid only if every item in its group would be matched by the wildcard's implied coverage — define the wildcard as covering the union of the group's items (hosts/paths/methods) and verify the group has no item outside the declared app hosts; document precisely what "true superset" means in code comments (spec gives no algorithm) and report it as an ambiguity.
- Test helper (feature `test-util` or dev module): `PackageBuilder` to build signed/unsigned tar.gz packages from a manifest + assets for tests (also used later by `aurora plugin build/sign`).

### Out of scope
- Snapshot compiler, lifecycle/ingestion, WIT inspection, CLI.

## Acceptance criteria
- [ ] Tests (one per rule, expected violation code): unsigned refused / allowed with dev flag; wrong publisher; revoked key; tampered file ⇒ digest mismatch; symlink, `..`, absolute path, duplicate entry, unknown path; oversize; icon not PNG / not square / too small; guide with raw HTML; `*.co.uk` zone; reserved host claim (LLM endpoint host, `x.aurora.internal`); egress to `127.0.0.1`; duplicate app id with an active package; a valid signed package passes with zero violations and returns the signer.
- [ ] `cargo test -p aurora-registry`, clippy `--all-targets -D warnings`, fmt.
