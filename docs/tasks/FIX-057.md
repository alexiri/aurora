# FIX-057: A SIGKILLed e2e gateway run leaks the e2e lock — podman `conmon` inherits fd 9 (TEST-021 lane, 2026-11-13)

## Problem

`scripts/e2e/gateway.sh` takes a host-wide flock on `/tmp/aurora-e2e-gateway.lock`,
held on **fd 9** (`exec 9>lock`, `flock -n 9`). When a run is SIGKILLed
(untrappable), its `aurora-testkit-*` Postgres containers keep running — they
are `--rm`, but that only takes effect when the container *stops* — and each
container's podman `conmon` supervisor **inherited fd 9** (bash's `exec 9>file`
does not set close-on-exec). The flock therefore stayed held for as long as any
leaked container lived, and every later e2e run — including the CI-parity local
loop and the tier-2 `FRONTDOOR=1` suite — blocked on lock acquisition for up to
an hour until someone ran `podman rm -f` on the leaked containers by hand.

Reproduced 2026-11-13: after a killed run, `lsof /tmp/aurora-e2e-gateway.lock`
showed four `conmon` processes (one per leaked `aurora-testkit-*` container)
holding fd 9 while no `gateway.sh` was alive.

## Fix

`scripts/e2e/gateway.sh`:

1. **Close the lock fd on every spawned child** (the real fix, since SIGKILL
   cannot be trapped and teardown cannot run): the whole run body — build,
   port checks, container starts, `cargo test` — executes in a subshell opened
   `9>&-`, and every detached `podman run` call closes fd 9 explicitly
   (`… >/dev/null 9>&-`). The test target's own children (aurora-testkit's
   `podman run` inside the `cargo test` process tree) inherit only a closed
   descriptor, so no `conmon` can ever pin the flock again.
2. **Stale-lock self-heal**: if `flock -n 9` is refused, the script asks
   `lsof` who holds the lock. A live holder → wait (up to 1 h, as before), with
   an actionable hint naming any leftover `aurora-testkit-*` containers and the
   exact cleanup command (`podman ps --filter name=aurora-testkit`,
   `podman rm -f -t 1 …`, or `just clean-testkit`). No live holder → the
   flock is already dead (it dies with its last open descriptor), so the lock
   file is re-opened and the non-blocking acquire retried instead of waiting
   behind a ghost.
3. The EXIT-trap container teardown was already present (TEST-021) and is kept
   verbatim; it handles every trappable exit, and (1) covers the one exit it
   cannot.
4. The failure mode is documented in the script header (FIX-057 block).

## Verification

- `bash -n` and `bash scripts/guards/run-all.sh` green; fmt/clippy untouched
  (no Rust changes).
- SIGKILL-then-rerun: a run killed mid-build leaves no fd-9 holder, and a fresh
  run acquires the lock immediately; a pre-seeded leaked container is reported
  with the cleanup command.
- `FRONTDOOR=1 FRONTDOOR_HAPROXY=1 bash scripts/e2e/gateway.sh` fully green
  (nginx + haproxy doors up, 24 passed / 0 failed).
