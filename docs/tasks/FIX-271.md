# FIX-271: the template review page shows every change, says when the diff is not loaded, and never calls a new skill "Unchanged" (AUDIT-2026-11-27)

## Why

The audit's web area (`docs/audit/AUDIT-2026-11-27.md`) read the review page for a template version (P6-TPL-4,
FIX-247, FIX-250: `web/src/components/templates/review-version.tsx`, `web/src/lib/template-diff.ts`,
`web/src/lib/line-diff.ts`). An administrator approves on this page, so what it leaves out matters.

1. **Removed skills, skill files and helper files appear nowhere (medium).**
   - `diffTemplateContent` emits `skill:<name>`, `skill:<name>:file:<path>` and `helper:<path>` changes of kind
     `removed` with `attention: false` (`template-diff.ts` ~:298-332).
   - `WhatChanged` drops every part that has a section (`review-version.tsx` ~:165:
     `others = diff.changes.filter((c) => !sectionOf(c.part) && !c.attention)`).
   - The sections iterate only the **new** version's `c.skills`, `s.files` and `c.helpers` (~:307-356).
   - So the summary says "1 skill", but the page shows no removed skill. Removed apps, inputs, automations,
     references and memories are shown, through `DetailChanges`.
2. **A new skill's body is labelled "Unchanged" (medium).** For an added skill the diff emits only `skill:<name>`
   (`template-diff.ts` ~:298), with the body in `new`. `SkillCard` (~:218) looks for `skill:<name>:body`, finds
   nothing, and `PartText(change=null)` renders a closed **Unchanged** fold around the brand-new body. An
   administrator reviewing a new skill reads "Unchanged".
3. **Approve is enabled while the diff is loading, or after it failed (low).**
   - `const diff = offered.data?.content && d?.content ? diffTemplateContent(…) : null` (~:499).
   - While `useAdminTemplates()` or the offered version's query is pending, `diff` is null, and `firstVersion` is
     false (it needs `list.data`). The page shows no notice and renders every section as plain text, and Approve is
     enabled once `d.content_sha256` exists.
   - If the offered version's query fails (`retry: false`), there is no error and no diff, and Approve stays enabled.
   - The full text is still shown, so nothing is hidden, but FIX-247's "what changed first" is silently lost.
4. **A lock-only memory change shows an empty diff (low).** A change that only locks or unlocks a memory yields a
   `memory:<key>` change with no text and the detail "Now locked…" / "No longer locked." (`template-diff.ts`
   ~:246-262). The section renders `PartText` with an empty `DiffView` and never the detail (~:373). Unlocking widens
   what the agent may change: the reviewer should read it.
5. **The minimum-version attention rule misjudges a lowered version (low).** `template-diff.ts` ~:345
   `n.some((p, i) => p > (b[i] ?? 0))` is not an ordered comparison: 6.2.0 → 5.9.9 reads as "raised" (9 > 2) and goes
   to **Look at these first**.
6. **A large file silently diffs as "all removed, all added" (low).** `line-diff.ts` ~:69-71: past 4,000,000 cells
   (after trimming the common head and tail) the middle becomes all del + all add, with no note.
   - Two 20k-line files that differ in two distant places hit it: the reviewer sees the whole file replaced, and gets
     about 40k unfolded rows.
7. **Small UI points (cleanup):**
   - `templates-table.tsx` ~:59 links only `waitingReview[0]` though the label says "review them" for several.
   - `key={l.url}` (~:39) collides when two needed libraries share a URL with a different ref or path.
   - The `DiffView` scroll box (`ui/diff-view.tsx` ~:89, `tabIndex={0}`) has no accessible name of its own.
   - The word highlight (~:48-53) pairs only the last deleted line with the first added one of a block.

## Change

1. Render removed skills (the whole skill, a `DiffView` with status "removed" of its body), removed skill files and
   removed helper files inside their sections, after the current ones, marked **Removed** in words.
2. `SkillCard` treats an added `skill:<name>` as the body's change (status "added"). Or the diff emits
   `skill:<name>:body` for an added skill too; pick one and use it for files as well. `use_it_when` of an added skill
   is shown as added.
3. While a comparison is expected (`current && current !== version`) and `diff` is not ready, show `Loading` in the
   What-changed slot and disable Approve. On `offered.isError` / `list.isError`, show an `ErrorState` with Retry and
   keep Approve disabled. A first version (`current == null` once the list loaded) stays as today.
4. The memory section shows the lock/unlock detail in words beside the memory (and in **Look at these first** for
   "No longer locked", which widens the agent).
5. Compare `min_core` by the first differing component (or reuse the semver comparison the page already has).
6. Past the cap, show a `Notice`: "This file is too large to compare line by line; the whole old and new text are
   below." Keep the folds closed by default. Alternatively replace the LCS by a Myers O(ND) diff with an edit budget,
   like the server's merge, and keep the notice for the budget.
7. Link the oldest waiting version and say "N waiting: <versions>", each a link. Key the libraries by url + ref + path.
   Give the scroll box `role="region"` and an `aria-label`. Pair a block's deleted and added lines in order for the
   word highlight.

All with the existing primitives (`Notice`, `Loading`, `ErrorState`, `DiffView`, `Badge`) and tokens: no new
one-off styling (docs/14 §Visual design).
