# FIX-044: A paused share answers 409 `preview_paused`, docs/11 says 403 — the documented status code is unreachable (C-540..C-549 named in docs/05 §Port previews)

## Problem

`start()` refuses a paused share with
`ApiError::conflict("preview_paused", …)`
(`services/aurora-api/src/domains/previews/service.rs:71-73`), i.e. HTTP 409
(`crates/aurora-core/src/error.rs:169-171`), on both the pre-lock check
(`:499-501`) and the post-lock re-check (`:507-509`). docs/11's state bullet
is normative and says 403: "the hostname is kept, access is refused with
**403 `preview_paused`**, no wake, no start command"
(`docs/11-runner-sandboxes.md:394-396`). The same table row also gives 403
for the paused state ("403 `preview_paused`; streams closed within 15 s",
`docs/11-runner-sandboxes.md:473`).

The test suite locks in the 409
(`services/aurora-api/tests/it/previews.rs:632`,
`assert_eq!((s, code(&v)), (409, "preview_paused"), …)`), so the code and the
docs disagree and one of them is wrong. Related reads are consistent with the
docs' intent: `frozen_error` is 423 (`freeze/service.rs:44-51`) and the
wake-limit is a custom 429, so "paused" was never part of a 409 family in
this domain; 409 elsewhere in previews means *state conflicts that a retry
can resolve* (`preview_exists`, `preview_limit`,
`previews_not_enabled_for_org`, `preview_no_start_command`), while a paused
share is a plain authorization-style refusal like 403/423.

Also unfixable from the API alone: `web/openapi.json` and
`web/src/lib/api/schema.d.ts` were generated from the routes' utoipa
annotations (`routes.rs`), which do not enumerate per-route error statuses
for this code — no change needed there unless the route annotations gain
status docs.

## Goal (priority: **low**, size: **S**)

One decision, applied everywhere: either the code moves to 403 (docs/11 and
the sibling 423 `frozen` pattern win), or docs/11's two lines change to 409.
The repo's convention is that docs/11 is normative for share lifecycle, so
the brief recommends the code change to 403.

## Scope

1. `services/aurora-api/src/domains/previews/service.rs` — `paused()`
   (`:71-73`) returns
   `ApiError::new(axum::http::StatusCode::FORBIDDEN, "preview_paused", …)`
   (the file already uses the explicit-status form for 429, `wake_limited`
   at `:63-68`).
2. `services/aurora-api/tests/it/previews.rs:632` — expect 403.
3. No docs change (docs/11 already says 403).

## Acceptance

- The updated test passes; `cargo test -p aurora-api --test it previews`
  stays green; the openapi.json diff (if any) is regenerated by the usual
  `cargo run -p aurora-api -- openapi` flow, not by hand.

## Constraints

- Do not touch the other 409s of this domain (`preview_exists`,
  `preview_limit`, `previews_not_enabled_for_org`,
  `preview_no_start_command`) — they are state conflicts and docs/05 lists
  them as 409 (`docs/05-control-plane-api.md:676-679`).
- No change to the `preview_paused` code string (callers match on code).
- Change files only with the Edit/Write tools; never python, sed, awk, perl,
  `cat >>` or heredocs.
