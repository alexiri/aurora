# FIX-010: Hosted sandboxes reach the gateway at an in-cluster address, separate from the external proxy URL (phase 2 exit)

## Problem
P2-E2E-1 found that hosted sandboxes on Kubernetes were told the gateway proxy is at `localhost:4102`, derived from `server.external_url` (`crates/aurora-config/src/validate.rs::advertised_proxy_url`: `gateway.advertised_proxy_url`, else `https://<external host>:4102`). One value serves two audiences:
- **BYO agents** run outside the cluster and need the **external** address (`ContainerConfig.proxy_url`, C-54/C-134);
- **hosted sandboxes** run inside the cluster: the Kubernetes runner already gives them a host alias `aurora-gateway` → the gateway Service (`services/aurora-runner/src/backends/kubernetes/objects.rs`), and that name is on the proxy listener's certificate; but their boot document (`AURORA_BOOT.gateway.proxy` and `server_name`, `11 §The boot document`, C-55) is filled from the same external value.

In a real Helm install the external host's port 4102 is usually not reachable from inside the cluster, so hosted agents fail (the fake harness never uses the proxy, which is why nothing caught it). P2-E2E-1 worked around it in the dev profile only (`deploy/kind/values-dev.yaml` sets `advertised_proxy_url: https://aurora-gateway:4102`), which in turn gives BYO agents in dev an address they cannot resolve.

## Decision (coordinator, D-87)
Separate the two addresses. The **sandbox proxy address** is what the boot document carries; the **advertised proxy URL** stays what BYO agents and container config get.
- New config key `gateway.sandbox_proxy_url` (optional). When unset, the default depends on the runner backend: **kubernetes** → `https://aurora-gateway:4102` (the host alias the runner already writes); **podman** → whatever the podman backend uses today to reach the gateway from a container (find it; keep current behaviour); **fake** → unused.
- The boot document's `gateway.proxy` and `server_name` come from the sandbox proxy address; the TLS verification in the supervisor stays unchanged (the name must be on the proxy certificate; check the chart's certificate SANs include `aurora-gateway`, and add it where they don't).
- `gateway.advertised_proxy_url` keeps its meaning and default (external host) for BYO agents and `ContainerConfig`.
- Remove the dev-profile workaround from `deploy/kind/values-dev.yaml` (and its guard `scripts/guards/dev-gateway-address.sh`, or change the guard to check the new key), so BYO agents in dev get the external address again.

## Scope
1. Config: the key, validation (https URL, host and port only), defaults per backend, a config test; `docs/15 §Configuration` and `docs/11 §The boot document` updated; contract note in `docs/API_CONTRACTS.md` (C-300..C-309).
2. API/runner: the boot document uses the sandbox address; tests for kubernetes and podman defaults and for an explicit override.
3. Helm chart: certificate SANs include `aurora-gateway`; no `advertised_proxy_url` override needed for in-cluster sandboxes; `docs/operator/install-helm.md` explains both addresses (when an operator must set either).
4. Proof: `scripts/e2e/first-run.sh` (P2-E2E-1) stays green on a fresh kind stack **without** the dev workaround; `scripts/e2e/kind.sh` k8s scenarios stay green; a BYO container-config test shows the external URL.

## Constraints
- Don't weaken TLS verification between sandbox and gateway; the sandbox must still verify the gateway certificate.
- Migrations: none expected.
- Owns: `crates/aurora-config` (the key), the boot-document builder in `services/aurora-api/src/domains/runner_plane/boot.rs`, the runner backends only if they hold address logic, `deploy/helm/aurora/**` (certificate SANs, values docs), `deploy/kind/values-dev.yaml`, the guard, the docs named above.

## Acceptance criteria
- [ ] Hosted sandboxes on kind get `https://aurora-gateway:4102` by default, with no override in the dev values; BYO container config gets the external URL.
- [ ] `scripts/e2e/first-run.sh` green twice on a fresh stack; `kind.sh` green; config, api and runner tests green; fmt, clippy `-D warnings`, guards, `helm lint`.
