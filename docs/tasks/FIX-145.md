# FIX-145: Self-hosted apps served under a path (`https://its.cern.ch/jira`) — **medium–large, phase 5**

## Goal
The owner (2026-11-14) cannot register CERN's Jira. It is served at `https://its.cern.ch/jira`, and a
self-hosted app instance is a bare host (D-74; D-92(e) and P2-CAT-7 G7 left servers under a path
out). Lots of real deployments live under a path like this: Jira/Confluence Data Center under
`/jira` and `/confluence`, GitLab under a relative URL root, Indico under a prefix. **D-231**
(decided 2026-11-14) adds an optional **base path** to a registration. Manifests stay unchanged:
everything a manifest writes as `https://{instance}/…` means `https://<host><base_path>/…` for that
registration.

## Design (D-231, summary; C-731 has the wire detail)
1. **Stored**: `app_instances.base_path text NULL`, normalized, with a CHECK constraint matching the
   validator. Migration `20261201000140_app_instance_base_path.sql` (block 000140–149).
2. **Validation** (`instance_base_path_invalid`, `/base_path`): it starts with `/`, has 1–8 segments,
   and each segment is 1–64 characters from `[A-Za-z0-9._~-]` and is not `.` or `..`. Total length
   ≤ 128. A trailing `/` is dropped; `""` or `/` = `null`. Case is kept (paths are case-sensitive).
   It cannot be changed after registration, like the host.
3. **Conflicts**: two registrations visible to each other on the same host conflict when their base
   paths **overlap**: either is `null`, they are equal, or one is a segment prefix of the other
   (`/jira` overlaps `/jira/x`, not `/jira2`). Disjoint paths on one host may be registered, for the
   same app or different apps (Jira at `/jira`, Confluence at `/confluence`). Static claims, LLM
   hosts and Aurora's own addresses stay host-level: a path never gets around them. The promote
   check (`instance_host_shared`) uses the same overlap rule. The per-host lock stays.
4. **Resolution**: one helper in `aurora-registry`, e.g. `InstanceBase { host, base_path }` with
   `resolve(raw_template) -> Option<Url>`, used everywhere `{instance}` resolves today: registration
   probe (`app_instances/service.rs run_probe`), connect probes (`connect/probe.rs instance_url`),
   OAuth authorize/token URLs (`connect/service.rs oauth_url`, gateway `refresh.rs token_url`),
   token mint (`gateway/mint.rs`), git skill library fetch (`gateway/library_fetch.rs`),
   `gateway/decide.rs` (≈ l. 1032), and the hook host request (C-249: add `instance_base_path`).
   Hook egress `{instance}` stays a host (egress is checked per host). Remove the other places that
   do their own string substitution.
5. **Gateway matching**: a request matches a registered instance when its host equals the instance
   host **and** the path is the base path itself or starts with base path + `/` (no base path matches
   every path). Among several matches, the longest base path wins. Everything the manifest decides
   uses the **app path**, i.e. the path with the base path removed: `identify_instance_app`
   (`path_prefix`), tool `serves`/`PathPattern`, `{path.N}` templates, params conditions, approval
   summaries. The upstream request, audit `path` and approval display keep the **full** path. A
   request to the host outside every registered base path matches no instance, so nothing is
   injected (fail closed, as for an unknown host). The base-path test runs on the same normalized
   path that tool matching uses. Check how the gateway treats `..`, `//` and percent-encoded
   segments today, and make sure none of them can reach a different registration's credentials or
   escape the base path (an encoded `/%6Aira` does not match `/jira`, so nothing is injected).
6. **Default-host connections** have no base path: `default_host` stays a bare host.
7. **Agent**: the FIX-144 account `address` becomes `https://<host><base_path>`. Snippets already say
   `<address>`, so they need no change.
8. **Offline fixtures** (`aurora plugin test`): `connection.instance_base_path` next to
   `connection.instance_host`. Requests in the case use the full URL, and the expected tool is
   matched on the app path.
9. **Manifests and linter**: unchanged (`{instance}` stays a whole host).

## Scope

### Step 0 (coordinator or the Rust lane, before code): spec text
Update the docs listed above to D-231/C-731. Mark D-92(e) and P2-CAT-7 G7 "superseded by D-231
for registered instances". Update SEC-59 to "only on the instance's host and under its base path".

### Part A — Rust
Migration and repo (`crates/aurora-db/src/repo/app_instances.rs`, `repo/gateway.rs`
`InstanceHostRow`/`visible_instances` gain `base_path`), validation and conflict rules
(`app_instances/service.rs`), DTOs (`AppInstance.base_path`, `AppInstance.base_url`,
`CreateAppInstanceRequest.base_path`, conflict details), the resolution helper and every call site
in 4, gateway matching in `resolve.rs` (instance selection ≈ l. 669–690) and `apps.rs`
(`identify_instance_app`, `serves`, `needs_body`), connection DTO `instance` gains `base_path` and
`base_url` (C-731), hook host request, offline fixture runner, OpenAPI. Regenerate
`web/src/lib/api/schema.d.ts` the usual way.

### Part B — Next.js
- Registration form (`web/src/components/apps/instances-view.tsx`): an optional **Path** field after
  Host, with the hint "Only if the app is served under a path, for example /jira for
  https://its.cern.ch/jira". Pasting or typing a full URL into Host splits it on the client into
  host and path (scheme dropped, query/fragment dropped). If it also has a port or userinfo, leave
  it as typed so the server's `instance_host_invalid` explains. The server stays authoritative.
- Lists (org and admin Self-hosted apps), the connect picker and the connection's instance line show
  `base_url` instead of the host. Delete/disable/promote confirmations name `base_url`.
- `probeFailedMessage` (FIX-144): the 404 and same-host-redirect texts end with "If {App} is
  served under a path, such as https://{host}/jira, enter it in Path." `instance_base_path_invalid`
  gets a static message in `errors.ts`. The conflict message names the holder's `base_url` when
  present.
- Follow `14 §Visual design` (tokens, shared primitives, both themes, 390 px).

### Out of scope
- Different base paths per connection (the base path belongs to the registration).
- Path-scoped static claims in manifests, a base path for `default_host`, and following redirects
  during the check.

## Acceptance criteria
- [ ] Registering jira-dc with host `its.cern.ch`, base path `/jira` against a fake upstream that
      serves only `/jira/rest/api/2/serverInfo` succeeds. Without the base path it fails with
      FIX-144's 404 message.
- [ ] Validation: each rule in Design 2 has a refusal test. `/jira/` stores `/jira`. `/` stores null.
- [ ] Conflicts: `/jira` vs `null`, `/jira` vs `/jira`, `/jira` vs `/jira/x` refused; `/jira` vs
      `/jira2` and `/jira` vs `/confluence` accepted; promote follows the same rule; a static claim
      on the host refuses any base path.
- [ ] Gateway (security tests, both injection and tool match): a connection on `its.cern.ch` +
      `/jira` gets its credential on `/jira/rest/api/2/myself` and is matched to the manifest tool
      for `/rest/api/2/myself`. Nothing is injected on `/rest/api/2/myself`, `/jira2/rest/…`,
      `/JIRA/rest/…`, `/%6Aira/rest/…`, or on dot-segment or double-slash variants that would leave
      the base path. Two registrations on one host (`/jira` jira-dc, `/confluence` confluence-dc)
      each get only their own credentials. `{path.N}` in an approval summary counts from the app
      path. Audit records the full path.
- [ ] Every `{instance}` resolution goes through the one helper (grep: no other
      `replacen(INSTANCE_HOST`). Connect probe, OAuth URLs, refresh, mint, hook request and library
      fetch each have a test with a base path.
- [ ] Agent instructions show `— at https://its.cern.ch/jira`.
- [ ] Offline fixture with `instance_base_path` passes for a jira-dc case.
- [ ] Web: path field, URL paste split, `base_url` in lists/picker/confirmations, messages; unit
      tests and mocked Playwright for the registration flow; no horizontal scroll at 390 px, both
      themes.
- [ ] `cargo fmt --check`, workspace clippy, targeted tests (api `app_instances`, connect, gateway
      resolve/apps/refresh/mint/library, registry, aurora-db), web typecheck/lint/unit/build,
      `scripts/guards`.
- [ ] Owner journey: register `its.cern.ch` + `/jira` on a real deployment, connect with a PAT, the
      agent reads an issue.
