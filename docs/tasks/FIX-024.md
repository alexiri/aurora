# FIX-024: Upgrade test from a phase-1+ base, Playwright port, base-image override smoke test (AUDIT-003 F-1, F-8, F-9)

## Problems (from `docs/audit/phase3-exit.md`)
- **F-1** `scripts/e2e/upgrade.sh` can only upgrade from a phase-0 base: `write_cfg` writes a phase-0 config (no OIDC provider, plaintext advertised proxy URL), the baseline session uses `POST /v1/auth/signup` (removed in phase 1, C-150), and its assertions are the phase-0 → phase-1 TLS story. The phase-3 exit criterion "`upgrade.sh` from the phase-2 exit commit" (`UPGRADE_BASE=cc6ccbb…`) therefore cannot pass. Evidence: `/tmp/audit-003-logs/7-upgrade-cc6ccbb.log`.
- **F-8** `web/playwright.config.ts` hard-codes port 4100 with `reuseExistingServer: true`, so another checkout's dev server on 4100 is silently tested.
- **F-9** `docs/18 §Deployment-neutral defaults` asks for an image-build smoke test: with and without a `SANDBOX_BASE_IMAGE` override the image has the same package list and `org.aurora.capabilities` label; none exists.

## Scope
1. `upgrade.sh`: a baseline-phase mode (`UPGRADE_BASE_PHASE=0|2`, auto-detected from the base commit when unset, e.g. by the presence of the dev IdP or of `auth.oidc_providers` validation). For a phase-1+ base: write an OIDC (dev IdP) + TLS-proxy config the baseline accepts, sign in through the dev IdP instead of `signup`, keep a data-bearing check across the upgrade (a conversation with messages, a memory, a secret, an agent, a running or parked sandbox where the phase allows), and phase-appropriate assertions; the phase-0 path stays exactly as it is (`UPGRADE_BASE=baabe11f` must still pass 36/0). Then run `UPGRADE_STRICT=1 UPGRADE_BASE=cc6ccbb345cf03ad2b881d9585e8a19329ceac9a bash scripts/e2e/upgrade.sh` green.
2. `web/playwright.config.ts`: port from `AURORA_E2E_WEB_PORT` (default 4100), and fail fast when `reuseExistingServer` would reuse a server not started from this checkout (e.g. compare a marker the dev server serves, or disable reuse unless `AURORA_E2E_REUSE=1`). Document it in the config comment.
3. A smoke script `scripts/images/sandbox-base-smoke.sh` (or a step in an existing image script): build the `sandbox-min` target twice, default base and with `SANDBOX_BASE_IMAGE` set to the same image by another reference (e.g. the tag instead of the digest), and compare the package list and the `org.aurora.capabilities` label; wire it into the place `18` names (nightly or a script the audit runs) and mention it in `18`.
