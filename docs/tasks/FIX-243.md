# FIX-243: documentation: send Grafana alerts to an agent's webhook, step by step (owner 2026-11-25)

## Why

Owner, 2026-11-25: "write a fix to improve the documentation to walk a user through how to create an alert contact point in
Grafana to point to said webhook." FIX-241 lets an agent create alert rules; FIX-242 gives NightManager the webhook those
rules reach. The piece in the middle is **a Grafana contact point that calls the webhook**, which only a person can create.
Nothing in Aurora's docs says how.

## What the documentation must get right (verified in Grafana's docs, 2026-11-25; check the target version)

- Grafana's **webhook contact point** has a URL, a method, optional HTTP basic authentication **or** an Authorization header
  (scheme defaults to Bearer, credentials), optional custom headers (older versions: none), optional **HMAC** signing (a
  header and a timestamp header, with a hex signature), a **Max alerts** limit and **Disable resolved message**.
- Aurora's webhook verification is `Authorization: Bearer <secret>` for a password webhook, or `X-Signature: sha256=<hex>` for a
  signed one. Grafana cannot produce Aurora's signed format, so the walkthrough uses the **password** (bearer) kind. The
  secret is shown **once** when the webhook is created or its secret rotated.
- Aurora answers 202 within the request, refuses over 60 deliveries a minute per webhook (429), records a repeated identical
  delivery as `duplicate` without running a turn, and creates a webhook paused (templates) until a person enables it.
- A delivery's body is fenced untrusted data for the agent; the contact point should therefore send the **default JSON
  payload** (do not customise the message into free text).

## Work

### 1. `plugins/builtin/grafana/docs/setup.md`: a new section "Send alerts to an agent"
Written as a numbered walk-through a first-time Grafana user can follow, with where each value comes from:
1. **In Aurora:** open the agent, Webhooks, the webhook ("Grafana alert" for NightManager). If it is paused, turn it on.
   Copy its **address**, and its **secret** (shown once: if you no longer have it, "Rotate secret" and copy the new one; the
   old one stops working at once).
2. **In Grafana:** Alerting, Contact points, **Add contact point**.
   - Name: the name the agent's notes expect (for NightManager: the one in its `service-<name>` memory, `aurora-nightmanager`
     in the example).
   - Integration: **Webhook**. URL: the Aurora address. HTTP method: **POST**.
   - **Authorization header** (not basic authentication): scheme `Bearer`, credentials: the secret.
   - Optional settings: switch **Disable resolved message** on (a resolved notice would start a turn for nothing); set
     **Max alerts** (for example 10) so one notification does not carry a hundred alerts; leave the message template at
     the default.
   - **Test**, then **Save**. Back in Aurora, the webhook's Deliveries shows the test as answered (or refused, with the
     reason in words: wrong secret, paused, too large).
3. **Route notifications to it.** Either (a) rules name the contact point themselves (`notification_settings.receiver`;
   Grafana 11 and later), which is what the agent's rules do, or (b) on older Grafana, a **notification policy** whose
   matcher is the label the agent's rules carry (`managed_by = nightmanager`) and whose contact point is the one you made.
   Say which versions each applies to after checking, and how to tell which you have.
4. **Repeat and grouping settings that protect you:** group wait and interval, and a **repeat interval of at least 4
   hours**, so a rule that stays firing does not wake the agent every few minutes. (Aurora also ignores an identical
   repeated payload as a `duplicate`, but a payload that changes every time is a new delivery.)
5. **Folder and token** for the agent's rules (FIX-241's section): a folder named for the agent, the service account with
   Edit on that folder only, its token in the agent's Grafana connection.
6. **Check the whole path:** a harmless test rule (for example, "up == 1 for 1m" on a throwaway label), what a delivery looks
   like in Aurora, how to delete the rule. And what to look at when nothing arrives: the contact point's last delivery in
   Grafana, the rule's state, the webhook's Deliveries and its paused/frozen state.
7. **Turning it off:** pause the webhook in Aurora, or delete the contact point in Grafana; neither deletes the agent's rules,
   which expire by themselves (FIX-242); how to see and delete them.

Screenshots only if the docs of other apps have them (they use text); no images.
