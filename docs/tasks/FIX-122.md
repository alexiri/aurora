# FIX-122: Deleting an agent or org discards its webhook and connector secrets; `email_tokens` are pruned; one name for an abandoned approval (REVIEW-5 data-lane follow-ups) — **medium**

## Problem
Recorded by the REVIEW-5 data lane (FIX-097/111/109, 2026-11-13) as outside its briefs:
1. **Secrets outlive their owner.** Deleting an agent or an org (FIX-097's deletion completeness) leaves the agent's/org's **webhook** signing secrets and **managed/connector** secrets in the secret store (the `SecretRef`s are dropped from the rows, the stored material is not discarded). A deleted scope must not leave usable secret material behind (`08` lifecycle: discard on delete; SEC-01's spirit).
2. **`email_tokens` are never pruned** (expired/used rows accumulate; the FIX-111 retention pass doesn't cover them).
3. **Two names for one event:** FIX-084 abandons dependent pending approvals with an event/status `expired`, FIX-109's freeze path uses `abandoned`. Pick one per `07` (the approval state machine) and use it on both paths; dashboards/channels that render it follow.

## Scope / constraints
- Find the deletion paths (agent delete, org delete — FIX-097's code) and discard every secret reference they drop through the secret store's discard API (Vault and Postgres stores), in the same transaction or via the existing outbox/discard queue if the store call can't be transactional (say which; never leave a dangling ref that still resolves).
- Add `email_tokens` to the retention pass (expired + used older than N days — take N from `02 §Limits` if it names one, else propose and document it).
- Approval event naming: align with `07`; amend the doc if it names neither.
- Owns: api deletion/retention code (`domains/{tenancy,agents,retention}` or wherever FIX-097/111 put it), `crates/aurora-db/src/repo/{approvals,email_tokens}.rs`, secret discard helpers, related ITs, `docs/07`/`08`.
- Gates per LANE_RULES (targeted per task; this is a small task — run the full api it-suite once at the end).

## Acceptance criteria
- [ ] IT: delete an agent with a webhook and a connector secret → both secret refs no longer resolve (Postgres store; Vault store when `AURORA_TEST_VAULT=1`).
- [ ] IT: retention prunes expired/used `email_tokens` past the bound and keeps live ones.
- [ ] IT: both the revocation path (FIX-084) and the freeze path (FIX-109) produce the same approval state/event name.
- [ ] Each new test fails before the fix.
