# FIX-122: Deleting an agent or org discards its webhook and connector secrets; `email_tokens` are pruned; one name for an abandoned approval (REVIEW-5 data-lane follow-ups) — **medium**

## Problem
Recorded by the REVIEW-5 data lane (FIX-097/111/109, 2026-11-13) as outside its briefs:
1. **Secrets outlive their owner.** Deleting an agent or an org (FIX-097's deletion completeness) leaves the agent's/org's **webhook** signing secrets and **managed/connector** secrets in the secret store (the `SecretRef`s are dropped from the rows, the stored material is not discarded). A deleted scope must not leave usable secret material behind (`08` lifecycle: discard on delete; SEC-01's spirit).
2. **`email_tokens` are never pruned** (expired/used rows accumulate; the FIX-111 retention pass doesn't cover them).
3. **Two names for one event:** FIX-084 abandons dependent pending approvals with an event/status `expired`, FIX-109's freeze path uses `abandoned`. Pick one per `07` (the approval state machine) and use it on both paths; dashboards/channels that render it follow.

## Analysis (lane misc, 2026-11-14)
- **Item 2 does not reproduce: there is no `email_tokens` table to prune.** Migration `crates/aurora-db/migrations/20261117000001_drop_password_hash_email_tokens.sql` (CONTRACT-001, D-78) dropped it; `rg email_tokens services crates --glob '*.rs'` finds no reader or writer, and `docs/05` §Background jobs already says "`email_tokens` are no longer written (OIDC-only sign-in)". Nothing was added to the retention pass.
- **Item 3 was real but narrower than written.** The *status* was already `abandoned` on every path (freeze, dependency revocation, unseen gateway); the *bus event* was `expired` on the FIX-084 revocation path (`abandon_pending_depending_on`) and on `abandon_unseen`, and `abandoned` only on the freeze path. The gateway woke a held request only on `decided`/`expired`, so a freeze-abandoned hold relied on its poll. Fixed: events follow the status everywhere (`expired` only for deadline expiry), the gateway wakes on `abandoned` too; `docs/07` already named `abandoned`, `docs/05` §`aurora_approval` now says so for every path.
- **Item 1 scope.** "Connector secrets" are the channel-integration credentials (`channel_integrations.credentials_ref`, org-level) and dedicated-presence credentials (`channel_presences.credentials_ref`, agent-level); platform connectors (`connectors.secret_refs`) are not owned by an agent or org. Webhook signing secrets sit in `webhooks.verification->>'secret_ref'`. Agent delete had no discard step at all; workspace/org delete (FIX-097) covered secrets, connections and OAuth clients only. Refs are collected in the deleting transaction and discarded after the commit (the store call cannot join the transaction; a failed discard is logged, the rows and every reference are already gone). No change under `domains/connectors/**` was needed (its seal-context helpers are only called). Vault-store variant: the discard path is the shared `vault.discard`; the IT uses the memory store (`AURORA_TEST_VAULT=1` not run).

## Scope / constraints
- Find the deletion paths (agent delete, org delete — FIX-097's code) and discard every secret reference they drop through the secret store's discard API (Vault and Postgres stores), in the same transaction or via the existing outbox/discard queue if the store call can't be transactional (say which; never leave a dangling ref that still resolves).
- Add `email_tokens` to the retention pass (expired + used older than N days — take N from `02 §Limits` if it names one, else propose and document it).
- Approval event naming: align with `07`; amend the doc if it names neither.
- Owns: api deletion/retention code (`domains/{tenancy,agents,retention}` or wherever FIX-097/111 put it), `crates/aurora-db/src/repo/{approvals,email_tokens}.rs`, secret discard helpers, related ITs, `docs/07`/`08`.
- Gates per LANE_RULES (targeted per task; this is a small task — run the full api it-suite once at the end).
