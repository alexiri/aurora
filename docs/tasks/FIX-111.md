# FIX-111: Retention that exists — the daily pruning pass, webhook deliveries, request-log age, reach-grant expiry; cursors on run and delivery history (REVIEW-5 CHAN-2/3, SPEC-1/4/9, DB-5/6/11, TOOL-6) — **medium**

## Problem
1. **The documented daily retention pass does not exist.** `docs/05` §Background jobs: "Retention pruning (inbox/ops/cards > `CHANNEL_LEDGER_RETENTION`, used action tokens, expired email/CLI tokens, sessions, expired context credentials) | daily"; `docs/03`: "Rows of revoked or expired sessions are removed by the daily session pruning". `services/aurora-api/src/jobs.rs` prunes used action tokens, counters and request-log partitions only. `channel_inbox` (every inbound chat message payload; no org column, so it survives org deletion), `channel_ops`, `channel_cards`, `link_requests`, `sessions` and expired context `gateway_credentials` grow forever. `CHANNEL_LEDGER_RETENTION` (`crates/aurora-core/src/limits.rs` ~190) has no reader.
2. **`webhook_deliveries` is never pruned**, and every rejected request (bad signature, oversize, paused) writes a row — up to 60 per minute per webhook (`webhooks/receive.rs` ~150–190). No retention is specified.
3. **The request log keeps rows 30 to 61 days.** `drop_expired` drops whole monthly partitions only (`crates/aurora-db/src/repo/request_log.rs` ~151–180); `docs/02` ~205 and the operator pages say 30 days. The default-partition purge is one unbounded `DELETE` (~177).
4. **Reach grants never expire.** `docs/05` lists "Peer-task and reach expiry — every 60 s"; nothing sets `reach_grants.expires_at` and no sweep reads it (`repo/reach_grants.rs` ~127; the expired branch in `channels/inbox/message.rs` ~718 is dead).
5. **Run and delivery history cannot be paged.** `GET /v1/schedules/{id}/runs` and `GET /v1/webhooks/{id}/deliveries` take `limit` only and always answer `next_cursor: null` (`schedules/routes.rs` ~237; `webhooks/routes.rs` ~242) against the list convention in `docs/05` ~111.
6. `REQUEST_LOG_RETENTION` and `WATCH_PATTERN_MAX` are constants no code reads (the job uses the config key; the validator and the supervisor use literals).

## Linked requirements
- `docs/05` §Background jobs, list convention; `docs/03` (sessions, channel tables, `webhook_deliveries`); `docs/02` §Limits; `docs/13` ~270; `docs/operator/retention-and-quota.md`; SEC-47/48 (retention).

## Spec change (apply with the fix)
- `docs/02` §Limits: `WEBHOOK_DELIVERY_RETENTION` (30 days, and at most 10,000 rows per webhook); `SESSION_PRUNE_GRACE` (7 days after expiry or revocation).
- `docs/02` ~205 and the operator page: "request-log rows are deleted when older than the retention period, checked daily" (after the code change).
- Reach grants: an optional `expires_in` on the decision (`docs/05`, `docs/13`); without it a grant does not expire. The 60 s sweep expires grants past `expires_at`.

## Scope
- One daily singleton job, batched with `SKIP LOCKED`: terminal `channel_inbox`/`channel_ops` rows (a pending deprovision op survives), settled `channel_cards`, expired `link_requests`, sessions past the grace, expired context credentials, webhook deliveries.
- Request log: bounded per-pass `DELETE` of rows older than the cutoff in the oldest kept partition, then drop empty partitions; default partition purged in batches.
- Reach expiry: DTO field, repo write, sweep; the dead branch becomes live.
- Keyset cursors (`created_at`, `id`) on the two history routes; OpenAPI and `schema.d.ts` regenerated; the dashboard's history lists gain "Load more".
- Constants: the job, validator and supervisor read them (or the constants are deleted with their `docs/02` rows).

## Constraints / file ownership
