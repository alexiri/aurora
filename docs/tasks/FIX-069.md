## Problem (code review of `09e955c9..bc7857ad`, deploy/ + docs/)
1. **docs/23 drift (P4-DOCS).** `docs/23-helm-values.md` (~271) documents `relay.networkPolicy.runnerEgressTo`, `previews.tls.certManager.issuerRef`, `previews.tls.secretName` — none exist in `deploy/helm/aurora/values.yaml`/templates — and has no rows for real keys: `relay.domain` (**required** when `relay.enabled`; render fails without it), `relay.replicas`, `relay.max_streams`, `relay.max_streams_per_user`, `relay.request_body_max_bytes`, `relay.nodeSelector`, `relay.tolerations`, `relay.extraEnv`. The owner asked for docs/23 to be the comprehensive reference (P4-DOCS), so drift is a defect.
2. **Dead relay token key.** `deploy/helm/aurora/templates/hooks.yaml` ~181–182 generates two different random values `AURORA_RELAY_TOKEN` and `AURORA_BOOTSTRAP_RELAY_TOKEN`; `templates/workloads.yaml` ~16 feeds the api's `AURORA_BOOTSTRAP_RELAY_TOKEN` env from the secret key `AURORA_RELAY_TOKEN`; the second key is dead, and `docs/15-deployment-operations.md` ~913 describes it as used (operators with `secrets.existingSecret` may create the wrong key).
3. **Broad egress.** The `-hooks` NetworkPolicy allows `0.0.0.0/0` on 443/6443 when `networkPolicy.kubeApiCidrs` is empty (the secrets hook can reach any host on those ports); the relay NetworkPolicy (`templates/networkpolicy.yaml` ~225–245) includes the `aurora.external` egress although the relay only talks to the api and runners — an unneeded exfiltration path from an edge-exposed pod.
