# FIX-110: What an agent can do through its tools — active turn required, link consent by approvers, bounded skills and peer queues, schedule and webhook integrity (REVIEW-5 TOOL-1..TOOL-8, TOOL-10, SUP-1, CONV-7) — **high, security**

## Problem
The agent is untrusted: a prompt-injected agent will use every tool to its limit.

1. **Tool calls are accepted with no active turn.** The tools socket is world-writable inside the sandbox and accepts any `session` string (`services/aurora-supervisor/src/tools.rs` ~394); when no turn is running the supervisor sends the call with `turn_id: None` (~434–444), and the API checks the turn only when present (`services/aurora-api/src/domains/tools/service.rs` ~56; `tools/messaging.rs` ~47). A background process started in an earlier turn can post messages to channels or peers hours later, unattributed. SEC-24: "tool calls are fenced on the agent's active turns" (marked proven); the API test at `tests/it/tools.rs` ~294 asserts the opposite ("Turn id is optional"); `docs/16` W7 has the weaker wording.
2. **Tool calls ignore the agent's own freeze** (`tools/service.rs` `identity`; `peer_tasks/service.rs` ~124 checks only the target). SEC-45.
3. **A member can consent to cross-workspace messaging without an approver.** `PUT /v1/agent-links/{id}/policy` lets any workspace member set their agent's side to `allow` (`agent_links/service.rs` ~57–68). `docs/07` §Agent links and `docs/04` (~531, RFE-012) give that consent to `can_approve`; C-29 says `can_use` — the contract row is the outlier.
4. **No cap on skills or skill files per agent** (`skills/service.rs` `create` ~409, `put_file` ~489; `tools/skills.rs` ~267): `skill_create` in a loop writes unbounded rows that every home sync then projects. Memories and schedules have per-agent caps.
5. **Peer tasks queue without bound** (`peer_tasks/service.rs` `open_task` ~256–282): each `message_agent` while one task is open adds a queued task, a conversation and a notice of up to 12,000 characters; each later runs a turn on the peer.
6. **The cron minimum interval checks four gaps** (`schedules/cron.rs` ~43–56): `0,5,10,15,20,21 * * * *` passes when created in the right minute and then fires at one-minute spacing.
7. **Stale full-row writes.** Schedule PATCH and the agent's `webhook_update` read without a lock and write every column (`schedules/service.rs` ~135–180 with `repo/schedules.rs` ~121; `tools/webhooks.rs` ~159 with `repo/webhooks.rs` ~192): a PATCH racing a fire restores the old `next_fire_at` and clears the lease (double fire); a stale `verification.secret_ref` undoes a rotation.
8. Smaller: the webhook `Content-Type` header is interpolated into the trusted preamble of the turn text (`webhooks/receive.rs` ~409–420; SEC-31); skill path validation checks only the last segment for `skill.md` (`skills/service.rs` ~104–128); peer names, channel labels and schedule names enter the agent's instructions unsanitised and unlabelled (`hosted/home.rs` ~115, ~200, ~219; SEC-18/31).

Owner question outside scope: signed webhooks without a delivery id are deduplicated for 60 s only, so a captured request replays later (Q-R5-20: require a signed timestamp, or state that replay protection is the sender's).

## Spec change (apply with the fix)
- `docs/16` W7 and `docs/12`: "`turn_id` is required and must be an active turn of the calling agent; a call without one is refused `no_active_turn`". SEC-24 evidence row updated.
- C-29 and `docs/05`: setting a side to `allow` needs `can_approve` on that agent's workspace; `ask` and `blocked` need `can_use`.
- `docs/02` §Limits and `docs/10`: `SKILL_PER_AGENT_MAX` (50), `SKILL_FILES_MAX` (50 per skill), `PEER_TASK_QUEUE_MAX` (10 queued per ordered pair); the existing schedule (50) and webhook (20) per-agent caps listed.

## Scope
- API `identity`: active turn required, frozen agent refused; supervisor refuses before sending when no turn is recorded. Messaging tools take the turn from the call.
- Link policy authorization as specified.
- Caps enforced under the agent row lock (the pattern `schedules::service::create` uses); queue cap under the link lock.
- Cron: minimum gap checked over a full cycle (minute field cyclically, or a week of occurrences).
- Schedule and webhook updates: `SELECT … FOR UPDATE`, write only the edited columns; fire-time columns never written by user-facing updates.
- Header moved inside the fence (or dropped); `skill.md` refused in any segment; home render sanitises and labels the three name fields.
