# FIX-174: `sandbox-min` on the AlmaLinux 10 minimal image

**Owner, 2026-11-18.** The owner asked whether AlmaLinux 10 **bootc** images would make the service and
sandbox bases more secure. They would not. A bootc image is a whole bootable operating system (kernel,
firmware, systemd, bootloader pieces) that is installed on a host and updated as one unit. Its
protections (read-only `/usr`, signed images, atomic update and rollback) exist only on a booted host.
Used as a container base it is several times larger, puts many more packages in front of the CVE scanner
and expects systemd as PID 1, which conflicts with the supervisor being PID 1 (`11 §Backend podman`).
The services already use `gcr.io/distroless/cc-debian12:nonroot`. The owner then asked for the smaller
AlmaLinux base for `sandbox-min`.

Decision **D-377**. No contract, no migration, no SEC number.

## Today
- `images/sandbox/Containerfile`: one `os` stage `FROM ${SANDBOX_BASE_IMAGE}`
  (`docker.io/library/almalinux:10@sha256:5a4b41a4…`, digest-pinned) installs with `dnf` the shared
  package set (`shadow-utils glibc-common postgresql rpm bash bash-completion zsh which ncurses
  openssh-server openssh-clients`), creates the `agent` user, removes any `sshd` unit link and copies the
  shell defaults and harness wrappers. `base` → `sandbox` and `sandbox-min` both build `FROM os`.
- `sandbox-min` (OS + supervisor + `preview-echo`, fake harness) is the image of the e2e scripts, CI's
  hosted job, `deploy/dev/kind-dev.sh` and the RUN-003 podman integration tests. Production runs `sandbox`.
- Sizes on Docker Hub, amd64, compressed, 2026-11-18: `almalinux:10` 69 MB, `almalinux:10-minimal`
  31 MB (digest of the index `sha256:61a5d87b6ef31f1db8ac1a6f24fe99bc90e93ecc1234c56a61fc5caf980d8a3b`;
  re-read it when you pin). The minimal image has `microdnf`, not `dnf`, and keeps `rpm`.
- `scripts/images/sandbox-base-smoke.sh` (FIX-024, nightly `sandbox-base-smoke`) builds `sandbox-min`
  with the default base and with an override reference of the same digest and compares `rpm -qa` and the
  capability label. `scripts/guards/no-deployment-defaults.sh` checks that `SANDBOX_BASE_IMAGE` defaults to
  a digest-pinned `docker.io/library/almalinux` image.

## Fix (D-377)

### 1. Containerfile
- New build argument `SANDBOX_MIN_BASE_IMAGE`, default `docker.io/library/almalinux:10-minimal@sha256:<digest>`
  (the multi-arch index digest, the same form as `SANDBOX_BASE_IMAGE`).
- **One package list, one setup script.** Move the body of today's `os` `RUN` into
  `images/sandbox/os-setup.sh` (bash, `set -euo pipefail`). It uses `dnf` when present, else `microdnf`,
  with weak dependencies off, installs the same package list, creates the user and directories, removes and
  asserts the absent `sshd` unit links exactly as now, and cleans the package cache. Both stages run it, so
  the package set cannot drift between them.
- Stages: `os` (`FROM ${SANDBOX_BASE_IMAGE}`, unchanged result) and `os-min`
  (`FROM ${SANDBOX_MIN_BASE_IMAGE}`). Each is one
  `RUN --mount=type=bind,source=images/sandbox,target=/mnt/sandbox bash /mnt/sandbox/os-setup.sh`
  plus the same `ENV PATH` and `WORKDIR`. The script also installs `/etc/profile.d/aurora.sh`,
  `/etc/zshenv`, `/etc/zshrc` and the `/opt/aurora/bin` wrappers (`install -m`, same modes as today's
  `COPY`), so nothing is listed twice.
- `sandbox-min` builds `FROM os-min`. `base` and `sandbox` stay on `os`.
- A deployment that overrides `SANDBOX_MIN_BASE_IMAGE` with a full AlmaLinux 10 image (for example a
  mirror that has no minimal variant) still builds: the script picks `dnf`.

### 2. Scripts, CI, guards
- `scripts/images/build-sandbox-min.sh`, `scripts/e2e/hosted.sh`, `deploy/dev/kind-dev.sh`: pass
  `SANDBOX_MIN_BASE_IMAGE` from the environment the way they pass `SANDBOX_BASE_IMAGE` today.
- `.github/workflows/ci.yml`: the `sandbox-min` build takes `vars.SANDBOX_MIN_BASE_IMAGE` (unset = the
  Containerfile default), like `SANDBOX_BASE_IMAGE` for `sandbox`. Update the comment near line 635:
  the two targets now share the supervisor compile only, not the OS layer.
- `scripts/guards/no-deployment-defaults.sh`: the same rule for `SANDBOX_MIN_BASE_IMAGE`
  (`docker.io/library/almalinux:<tag>@sha256:<64 hex>`).
- `scripts/images/sandbox-base-smoke.sh`: the default mode now checks **both** arguments: `sandbox-min`
  with `SANDBOX_MIN_BASE_IMAGE` (default vs. the same digest by another reference), and the `os` target
  with `SANDBOX_BASE_IMAGE` (cheap: no Chromium). `SMOKE_FULL=1` keeps the full `sandbox` comparison.
  The `rpm` extraction keeps working (both `os` stages keep `/usr/bin/rpm`).

### 3. Docs
- `11 §Sandbox image`: the `sandbox-min` target is built from `SANDBOX_MIN_BASE_IMAGE` (AlmaLinux 10
  minimal), same package list through `os-setup.sh`; production `sandbox` unchanged.
- `15` (line 37 and the base-image override paragraph near line 444), `docs/operator/install-helm.md`

## Acceptance criteria
1. Measured and recorded in the completion report and `docs/ops/build-performance.md`: `sandbox-min`
   size before and after, uncompressed (`podman image inspect --format '{{.Size}}'`) and compressed
   (`podman save` piped through `gzip -c | wc -c`), and the `rpm -qa | wc -l` count before and after.
   **If the new image is not smaller, stop and report** instead of merging.
2. `rpm -qa` of `sandbox-min` contains every package of the shared list (the smoke's comparison).
   Inside the image: `bash`, `zsh`, `which`, `psql`, `scp`, `/usr/libexec/openssh/sftp-server` run;
   uid 1000 `agent` owns `/workspace`; no `sshd` unit is enabled.
3. `sandbox` (production) is byte-for-byte the same package set as before: `rpm -qa` of the `os` stage
   before and after are equal.
4. `bash scripts/images/sandbox-base-smoke.sh` passes in default mode; `SMOKE_FULL=1` is not required
   locally (nightly runs it), but say whether it ran.
5. `bash scripts/guards/run-all.sh` passes, and the new guard rule fails on a planted unpinned default
   (check once by hand, then remove the plant).
6. With the new `sandbox-min`: the RUN-003 podman integration tests (`AURORA_TEST_PODMAN=1`) and
   `scripts/e2e/hosted.sh` pass. Name any scenario that is skipped and why.
7. Building `sandbox-min` with `--build-arg SANDBOX_MIN_BASE_IMAGE=docker.io/library/almalinux:10@sha256:<digest>`
   (a full base) also succeeds (`dnf` path).

## Out of scope
- The production `sandbox` image's base. If the measurement shows a large saving, the completion report
  says so and the owner decides on a follow-up (the `base` stage installs EPEL and Chromium and removes
  `dnf`; it would remove `microdnf` instead).
- AlmaLinux `10-micro` (no package manager; quay.io only, not in the Docker official library).
- Service images (already distroless).
