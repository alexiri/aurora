# FIX-268: template sources with a folder work; only folders with a template.yaml are templates; the check retries what it failed to store (AUDIT-2026-11-27)

## Why

The audit's template-pipeline area (`docs/audit/AUDIT-2026-11-27.md`) read the source check (P6-TPL-2, C-1103,
C-1108) as on master.

1. **A source with a folder (`path`) can never accept a version (high, the feature is broken).**
   - `agent_templates/git.rs` ~:98-127 strips the source folder from every entry (`rel(prefix, …)`), so a template's
     `dir` is stored **relative to the folder**.
   - The package = source comparison then reads the tree at that relative name from the repository root:
     `check.rs` ~:902 `read_dir_at(state, source, token, &v.version.commit_sha, &v.dir)`, which builds
     `Reader::with_profile(&g, &dir, …)` (~:178).
   - **Scenario:** a source with `path: "templates"` and a template at `templates/service-monitor/`. The read of
     `service-monitor/` at the root is empty, `read_tree` fails "template.yaml is required", and the version is
     `invalid` on its first check.
   - Prefixing the folder alone is not enough: `read_tree(&v.dir, …)` would then refuse `templates/…` paths as "not
     under the template's own directory".
   - No integration test adds a source with a `path`.
2. **Every top-level folder becomes a "template" (medium).** `git.rs` ~:124-166 collects every depth-1 tree entry
   and pushes the ones without `template.yaml` with the problem "template.yaml is missing". The preview (`mod.rs`
   ~:385-420) lists `.github` and `docs` as templates in state `new`, and the check (`check.rs` ~:460-480) reports
   them as problems.
   - They also count toward `TEMPLATES_PER_SOURCE_MAX` before the truncation (~:141), and `.github` sorts first. A
     repository with 100 real templates and a `.github` folder silently loses its last template.
   - C-1103 / `docs/25` ~:76-84: only folders holding `template.yaml` are templates, everything else is ignored, and
     `.github` is never an error.
3. **A version that failed to store is not retried on the same commit (low).** The code's own comment (`check.rs`
   ~:645) says "since nothing was stored, the next check offers it again". But the final transaction always writes
   `set_head_sha(head)` (~:768), and the next check's step-1 shortcut (~:418-426: same head, nothing waiting, no
   `needs_newer`) answers `up_to_date` without reading. The version waits for the next push.
4. **The final check transaction does not re-assert its lease (low).** `check.rs` ~:768-786: `finish_check`
   (`WHERE lease_owner = $2`) ignores `rows_affected`, and `set_head_sha` has no owner guard. If the lease was lost
   during the last `process_awaiting`, the old owner still commits `last_head_sha`, its stay reasons and audit rows.
   The `Left` rows are guarded by their status, so no double approval or notice.
5. **A relative redirect breaks the package download (low).** `fetch.rs` ~:99 `url::Url::parse(loc)` refuses a
   relative `Location` (legal HTTP). The version waits as `download_failed` and then expires as `invalid`.
6. **Docs drift (cleanup):**
   - The stored `content_sha256` is computed **after** the avatar re-encode (`check.rs` ~:940). For a template with
     an avatar, the hash the admin approves differs from the `content:` line that `aurora template pack` prints and
     CI logs. `docs/25` step 4 reads as if there were one hash.
   - `docs/25` says a package is retried "up to 24 hours", while `is_transient_stay` gives transient failures 48 h.

## Change

1. Read the comparison tree at `{source.path}/{dir}` (or `dir` when `path` is empty), and strip the
   `{source.path}/` prefix from every entry before `is_content` and `read_tree`. Use **one** helper for "the template
   folder's path in the repository", shared by the head read, the package comparison and anything else that joins
   the two. Grep `v.dir` / `.dir` in `agent_templates/`.
2. `git.rs`: keep only the folders present in `metas` (those holding `template.yaml`), **then** sort and truncate.
   The preview and the check list nothing else. Nested `.github` handling is unchanged.
3. Don't advance `last_head_sha` when the run had a `template_not_stored` (or `set_head_state` failed) problem, so the
   next check reads again. Add the condition to the step-1 shortcut too.
4. At the start of step 7, inside the transaction:
   `UPDATE agent_template_sources SET updated_at = now() WHERE id = $1 AND lease_owner = $2`. On 0 rows, roll back
   and stop (log "lease lost", no writes). Assert `rows_affected` in `finish_check`.
5. `fetch.rs`: `logical = logical.join(loc)`, keeping the same-origin token rule and the redirect cap (the joined
   URL goes through the same checks as an absolute one).
6. `docs/25`: say which hash the review shows for a template with an avatar (and, if the dashboard shows only one,
   that `pack`'s `content:` line differs for avatars, or store and show both). Correct the retry window to what the
   code does.

**What changed**

1. Folder sources: `git::in_folder` / `git::below_folder` are the one way between a template's stored `dir` and its
   path in the repository (head read and package comparison; nothing else in `agent_templates/` joins them). The
   comparison reads `{path}/{dir}` and strips `{path}/` before `is_content` and `read_tree`. The check's head read
   now opens its reader at the source's folder, as the preview already did (it used the root).
2. Only folders with a `template.yaml` are listed; the cap applies to those. The git reader already skipped
   `.github`, so the folders that took places under the cap were ordinary ones such as `docs`.
3. A run with a `template_not_stored` problem (this covers the `set_head_state` and `removed_upstream` writes) does
   not record the head. It **clears** `last_head_sha` when an earlier check had recorded that head: without that,
   the step-1 shortcut would still match. This is the brief's "condition on the shortcut" without a new column.
4. Step 7 starts by asserting the lease in its transaction (the existing `extend_lease`: the same owner-guarded
   update and row lock as the brief's SQL). `finish_check` returns whether it wrote; step 7 and the shortcut stop
   with 409 `template_check_in_progress` when it did not; `fail()` ignores it (a lost lease writes nothing there).
5. `fetch.rs` resolves `Location` with `Url::join`. The joined URL goes through the same `prepare`, token-origin
   rule and redirect cap.
6. `docs/25` (the two hashes with an avatar; 24 h, or 48 h after a transient failure; folder; relative redirects;
   the retry of a failed store) and `docs/03` (`last_head_sha`).
