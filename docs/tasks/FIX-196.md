# FIX-196: A computer's start-failure history is for instance admins only, like the engine (SEC-141)

## Goal
Owner, 2026-11-20 (D-424). P5-REFINE-4 (SEC-141, D-412) made the image, the runner, the start detail and the pod
events of `GET /v1/agents/{agent}/sandbox` visible to instance admins only. But `GET …/start-failures` (C-613) still
gives workspace owners the runner's wording and the pod events (`can_see_failure_detail` in
`services/aurora-api/src/domains/hosted/routes.rs`). That text can carry the same deployment detail: the registry,
image tags and cluster addresses such as `10.x:4105 svc.ns`. The owner chose to close it the same way.

## Change
1. `GET …/start-failures` gives the runner's wording and the events only to instance admins (`can_see_engine`).
   Workspace owners and members get what members get today: each failure's class and the member hint. Remove
   `can_see_failure_detail` if nothing else uses it.
2. The dashboard: any place that shows an owner the failure detail now shows the member view to non-admins.
   Find the components that read `start-failures` and adjust them. Tests move with the UI.
3. Docs: `05`, `API_CONTRACTS` C-613 (amended by D-424), `11` if it describes who sees failure detail,
   `docs/tests/security-coverage.md` (the SEC-141 row covers this route too).

## Tests
- API IT: a workspace owner gets class and hint only, with no runner wording, events or addresses; an instance
  admin gets everything; a member is unchanged.
- Update the ITs that expected owner detail (`fix_029.rs` and others; search for `start-failures`).
- Vitest for any dashboard component touched.
- Targeted only (CI is the gate). Also run `cargo fmt --check` and clippy on aurora-api.

## Ownership
`services/aurora-api/src/domains/hosted/routes.rs` (the start-failures route) and its ITs, plus the web component
