# P5-UX-15: Names and labels that tell things apart (owner app-setup walkthrough, 2026-11-15)

## Goal

Small things in the walkthrough made the setup screens hard to read:
- **Two Daneels.** The team lead's give-access picker listed two agents, both "Daneel @daneel", one
  per workspace, told apart only by a small heading.
- **Four GitHub clients.** The OAuth client form's app picker offered four GitHub entries, distinguished
  only by internal keys (`github`, `github-app`, `github-app-ghes`, `github-ghes`).
- **GitLab methods.** GitLab's connect methods had no labels or descriptions ("Access token or keys",
  "Sign in").
- **Other people's workspaces.** Org › Apps › Connect… offered every workspace of the org to an org
  owner, other people's personal workspaces included, in creation order.

## Linked requirements

- D-336; contracts **C-946, C-947, C-948, C-949**.
- Normative: `14 §App setup` §13, `10 §Default agent` (`agents.default_name`), `05` (workspaces row).

## Context

- **Pickers.** Agent pickers: `web/src/components/credentials/give-access.tsx` `AgentPicker` (~145–171)
  groups by owned workspace. The starter-grant picker is in the placement view.
- **Default agent.** `tenancy/service.rs` ~213–220 `create_workspace_in_tx` →
  `agents::insert_default` with `agent_handle(cfg.agents.default_name)`. Handles are unique per
  workspace.
- **OAuth client form.** `web/src/components/apps/oauth-clients-panel.tsx` ~174:
  `${app_name} (${client_key})`. `AppOauthClient` (`apps/dto.rs` ~179–184) has no label. Methods
  reference clients by `client:` (github `plugin.yaml` ~121–158, ~382–416).
- **GitLab.** `plugins/builtin/gitlab/plugin.yaml` methods `token` (~44) and `oauth` (~60) have no
  `label`, `description` or `recommended`.
- **Workspace items.** The `Workspace` DTO has no personal marker (`tenancy/dto.rs`). `/v1/me` marks only
  the caller's own personal workspace.

## Scope

1. **`used_by_methods` (C-946).** In `AppDetail.oauth_clients[]`, add `used_by_methods: { id, label }[]`
   from the connect methods whose `client` equals the client's key (label falls back to the kind label).
   The OAuth client form's app picker shows "<app display name> — for <label>[, <label>]". `client_key`
   moves to a tooltip.
2. **`personal_of` (C-947).**
   - In `GET /v1/orgs/{org}/workspaces` items, add `personal_of?: { id, name }`: the owner of a personal
     workspace, from placement's record of personal workspaces, or however the API marks them for `/v1/me`.
   - Org › Apps › Connect… orders:
     1. **For the whole organization** (when P5-UX-11 has merged);
     2. the caller's own and shared workspaces;
     3. others' personal workspaces under a collapsed group.

   If P5-UX-11 implemented C-947 first, only use it.
3. **Agent naming (C-948).**
   - `POST /v1/orgs/{org}/workspaces` accepts optional `agent_name`, validated by the same function as an
     agent's name. The handle is slugified; the default stays `agents.default_name`.
   - The New workspace dialog gets **Agent name** (placeholder "Daneel").
   - Every multi-workspace agent picker shows rows as "<workspace> · <agent>": give-access pickers, the
     starter-grant picker, and the P5-UX-11 org Done picker.
4. **GitLab labels (C-949).** `token`: "Personal access token", with a description (scopes, expiry,
   project or group tokens). `oauth`: "Sign in with GitLab", with a description (needs an OAuth client; a
   self-managed server must be registered). Patch-bump the package; run `check-builtin.sh`.
5. **Tests.**
   - API ITs: `used_by_methods` for github (four clients, the right methods); `personal_of` present only
     for personal workspaces; `agent_name` creates the agent with that name and handle, and an invalid
     one → 422.
   - Vitest: the picker labels; the chooser order; the multi-workspace row format.
   - Playwright: create a workspace with agent name "Atlas"; the give-access picker shows
     "Platform team · Atlas" and "dev-dana · Daneel".

- Not beside P5-UX-9 (OAuth client panel), P5-UX-11 (chooser), or P5-UX-12/13 (builtin `plugin.yaml`):

## Acceptance criteria

1. No picker shows two indistinguishable agents; new workspaces can name their agent.
2. The OAuth client form never shows a bare `client_key` as the label.
3. GitLab's methods have labels and descriptions.
4. Org › Apps › Connect… folds other people's personal workspaces away.
5. Rust and web gates; builtin check; axe and narrow-route suites, both themes.

## Dependencies

None hard. Coordinate the overlaps listed above.

Sonnet, or Haiku for parts 1 and 4 alone: small, separate API additions and label changes across several
