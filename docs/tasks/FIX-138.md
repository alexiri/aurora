# FIX-138: Terminal — a real shell (tab completion), a pane that scrolls, and its own window — **medium, phase 5**

## Goal
The owner (2026-11-13), on the agent Terminal tab (P4-TERM, D-161):
1. "Tab completion in the terminal must work."
2. "As I type commands into the terminal, it starts to get longer but it never scrolls. It should scroll!"
3. "I'd also like to open the terminal in its own window so I can make it as big as I'd like."

## What the code suggests (confirm before fixing)
1. **Shell**: the supervisor runs `$SHELL` if set, else **`/bin/sh`** (`services/aurora-supervisor/src/pty.rs:37-43`,
   `12 §Terminal`). The sandbox image creates the agent user with `--shell /bin/bash`
   (`images/sandbox/Containerfile:46`) but the supervisor's environment likely has no `SHELL`, so the PTY
   gets Debian's `dash`: no completion, no history, no line editing. A key-handling cause is also
   possible: check that the browser does not take Tab (focus move) before `@wterm/react` sees it
   (`web/src/components/agents/terminal-tab.tsx`, the agent page's `Tabs` keyboard handler, FIX-129's
   overflow menu).
2. **Scrolling**: `<Terminal autoResize …>` sits in a `.wterm.term-pane` with no height bound
   (`web/src/app/globals.css:223`), so the pane appears to grow with its content instead of keeping a fixed
   number of rows and scrolling its scrollback; with a growing pane the newest line can end up below the
   fold. Confirm in a browser.

## Plan
1. **Login shell**: the PTY starts the agent user's login shell from the passwd entry (fall back to
   `$SHELL`, then `/bin/bash` if executable, then `/bin/sh`), as an interactive login shell (`-l`), with
   `TERM=xterm-256color` and the user's home; the sandbox image ships `bash-completion` (and `less`,
   so pagers work) — image change with its size delta. Amend `12 §Terminal` and `11` (image contents).
   Verify that Tab, Ctrl-R, arrow history and Ctrl-C/Ctrl-D reach the shell; if the page swallows Tab,
   the terminal must capture it while focused, with a documented way out of the terminal for keyboard
   users (e.g. Escape then Tab, announced to screen readers) — WCAG 2.1.2 (no keyboard trap).
2. **Fixed-size pane that scrolls**: the pane takes a bounded height (fills the available viewport below
   the agent header, min ~16 rows; on phones a fixed share of the viewport), `autoResize` derives
   cols/rows from that box, output scrolls inside it, the view follows the cursor unless the person has
   scrolled up (then a "Jump to latest" control), scrollback size stated (`scrollbackLines`).
   Window/pane resizes send `pty.resize` (existing path).
3. **Own window**: an **Open in new window** button opens a standalone route
   (`/o/<org>/w/<ws>/agents/<agent>/terminal`, no app chrome, full viewport, title "<agent> — Terminal")
   via `window.open` (no opener: `noopener`). Same session cookie, same `GET /v1/agents/{agent}/terminal`
   WebSocket and single-use grant (no new auth path). Decide and specify the session model with the
   leg cap (FIX-092): either the pop-out is a second independent shell (two legs; counts against the cap,
   refused with a clear message when full) or it **takes over** the shell (the tab then shows "Open in
   another window — Bring back here"). Recommended: independent shells (simplest, matches a desktop
   terminal), with the cap message. Reconnect/close-code behaviour as in the tab (FIX-098).
4. Docs: `14 §Terminal tab` (pane size, scrolling, new window, keyboard escape), `12`, `11`, operator
   `terminal.md`.
