# FIX-138: Terminal — bash by default with zsh as an option, `PATH` with the harnesses, a pane that scrolls, and its own window — **medium–large, phase 5**

## Goal
The owner (2026-11-13), on the agent Terminal tab (P4-TERM, D-161):
1. "Tab completion in the terminal must work."
2. "As I type commands into the terminal, it starts to get longer but it never scrolls. It should scroll!"
3. "I'd also like to open the terminal in its own window so I can make it as big as I'd like."

## What the code suggests (confirm before fixing)
1. **Shell**: the supervisor runs `$SHELL` if set, else **`/bin/sh`** (`services/aurora-supervisor/src/pty.rs:37-43`,
   `12 §Terminal`). The sandbox image creates the agent user with `--shell /bin/bash`
   (`images/sandbox/Containerfile:46`) but the supervisor's environment likely has no `SHELL`, so the PTY
   gets Debian's `dash`: no completion, no history, no line editing. A key-handling cause is also
   possible: check that the browser does not take Tab (focus move) before `@wterm/react` sees it
   (`web/src/components/agents/terminal-tab.tsx`, the agent page's `Tabs` keyboard handler, FIX-129's
   overflow menu).
2. **Scrolling**: `<Terminal autoResize …>` sits in a `.wterm.term-pane` with no height bound
   (`web/src/app/globals.css:223`), so the pane appears to grow with its content instead of keeping a fixed
   number of rows and scrolling its scrollback; with a growing pane the newest line can end up below the
   fold. Confirm in a browser.

## Plan
1. **bash by default, zsh as an option** (owner, 2026-11-13: "the terminal is currently sh, change it for
   bash. add zsh as an option too"). The PTY runs **bash** as an interactive login shell (`-l`) unless the
   person chose **zsh**; `/bin/sh` only as a last-resort fallback when neither binary exists (with a
   one-line notice in the pane). `TERM=xterm-256color`, the user's home. The sandbox image ships `bash`,
   `bash-completion`, `zsh` (with its completion system enabled in a minimal default `/etc/zsh/zshrc`
   — `compinit`, history, no frameworks) and `less` — image change with its size delta.
   **Choosing**: a **Shell** selector (bash | zsh) in the terminal toolbar, remembered per person per agent
   (server-side preference so it follows them across browsers, or `localStorage` if no preference store
   fits — say which); the choice travels as an **enumerated** value on the terminal open
   (`GET /v1/agents/{agent}/terminal?shell=bash|zsh` → the single-use grant → the runner → the supervisor's
   PTY spawn), never a path: the API rejects anything else (422), the supervisor maps the enum to a fixed
   path and falls back to bash if the binary is missing. Changing the shell applies to the next session
   (the open one keeps running). Amend `12 §Terminal`, `16 §W18/W19` (PTY target gains `shell`), `05`
   (query parameter), `11` (image contents), `14 §Terminal tab` (selector).
   Verify that Tab, Ctrl-R, arrow history and Ctrl-C/Ctrl-D reach the shell; if the page swallows Tab,
   the terminal must capture it while focused, with a documented way out of the terminal for keyboard
   users (e.g. Escape then Tab, announced to screen readers) — WCAG 2.1.2 (no keyboard trap).
1b. **`PATH` and harnesses usable from the terminal** (owner, 2026-11-13: "make sure path is set
   correctly, I want to be able to run `claude` (or other harnesses) inside the web terminal"). Today the
   harnesses are installed off-`PATH` (`/opt/aurora/harness/claude-code/node_modules/.bin/claude`,
   `/opt/aurora/harness/codex/codex`, `images/sandbox/Containerfile:85-110`), the image `ENV PATH` is
   `/workspace/.local/bin:/usr/local/bin:/usr/bin:/bin`, the supervisor's spawn default is
   `/usr/local/bin:/usr/bin:/bin` (`supervisor/src/spawn.rs:15`), and a **login** shell re-reads
   `/etc/profile` (bash) or `/etc/zprofile`/`zshenv` (zsh), which may reset it. Specify and build:
   - **One `PATH` for both shells**, set where login shells read it (`/etc/profile.d/aurora.sh` for bash,
     `/etc/zsh/zshenv` for zsh) and in the PTY spawn: `/workspace/.local/bin` (npm `-g` installs, the
     user's own tools), `/opt/aurora/bin` (below), `/usr/local/bin`, `/usr/bin`, `/bin`. `echo $PATH` is the
     same in both shells and in agent turns (`spawn.rs` default updated to match).
   - **Harness wrappers on `PATH`**: `/opt/aurora/bin/claude` and `/opt/aurora/bin/codex` (only for
     harnesses present in the image **and** in `hosted.enabled_harnesses`; a disabled one prints "not
     enabled on this instance" and exits non-zero). Each wrapper sets up exactly what the supervisor's
     adapter sets up for a turn to reach the LLM **through the gateway** — base URL, the placeholder
     credential the gateway replaces (`spawn.rs` `PLACEHOLDER`, `adapters/{claude_code,codex}/config`),
     proxy and CA — and execs the pinned binary. It never receives a real key (SEC-01/SEC-34 unchanged:
     no platform credential in the terminal environment; the gateway injects the agent's governed LLM key
     as it does for turns, with the agent's model allow-lists and governance).
   - **Separate harness state**: the wrappers point the CLI at its own config/session directory
     (e.g. `CLAUDE_CONFIG_DIR=/workspace/.aurora/terminal/claude`, `CODEX_HOME=…/terminal/codex`) so an
     interactive session never reads or changes the agent harness's configuration, sessions or memory
     (FIX-095: harness configuration must not be alterable between turns); the agent's own adapter paths
     stay as they are. Say in `12` whether the terminal session may *read* the agent's instructions/skills
     (recommended: yes, read-only, via the same files the turn sees; no write-back).
   - **Attribution and limits**: LLM requests from a terminal harness are the agent's traffic through the
     gateway; record in `07`/`08` how they appear in the request log (the terminal's person as speaker if
     the terminal leg can carry it, else "terminal" as the source) and that they count against the same
     budgets/rate limits; spending is visible on the agent's activity.
   - Spec: `12 §Terminal` (environment, `PATH`, wrappers), `11` (image layout), `08` (no key in the
     terminal, gateway injection), `14 §Terminal tab` (a hint line "`claude` and `codex` are available").
2. **Fixed-size pane that scrolls**: the pane takes a bounded height (fills the available viewport below
   the agent header, min ~16 rows; on phones a fixed share of the viewport), `autoResize` derives
   cols/rows from that box, output scrolls inside it, the view follows the cursor unless the person has
   scrolled up (then a "Jump to latest" control), scrollback size stated (`scrollbackLines`).
   Window/pane resizes send `pty.resize` (existing path).
3. **Own window**: an **Open in new window** button opens a standalone route
   (`/o/<org>/w/<ws>/agents/<agent>/terminal`, no app chrome, full viewport, title "<agent> — Terminal")
   via `window.open` (no opener: `noopener`). Same session cookie, same `GET /v1/agents/{agent}/terminal`
   WebSocket and single-use grant (no new auth path). Decide and specify the session model with the
   leg cap (FIX-092): either the pop-out is a second independent shell (two legs; counts against the cap,
   refused with a clear message when full) or it **takes over** the shell (the tab then shows "Open in
   another window — Bring back here"). Recommended: independent shells (simplest, matches a desktop
   terminal), with the cap message. Reconnect/close-code behaviour as in the tab (FIX-098).
4. Docs: `14 §Terminal tab` (pane size, scrolling, new window, keyboard escape), `12`, `11`, operator
   `terminal.md`.
