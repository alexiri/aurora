# FIX-081: SCIM protocol and management defects — list totals, lost updates on PATCH, authentication before the body, e-mail filter paths, expiry notice, missing OpenAPI routes (REVIEW-5 SCIM-6/7/9/10/11/12, EVID-3/4/8/11) — **medium**

## Problem
1. **Lists stop at 10,000 rows.** `scim/resource_users.rs` ~526–528 and ~544–547 fetch `users_page(…, 10_000)` and report `totalResults = rows.len()` (~557–560); `repo/scim.rs` ~249–268. An org with more users reports a wrong total and an empty page past 10,000; an IdP that reconciles by listing may treat the rest as absent and deprovision them.
2. **Concurrent user PATCHes lose attributes.** `patch_user` reads the row outside the transaction (~647–651), merges (~654–673) and writes every attribute (~979–991); the row lock (~888) serialises writes, not the read. Two overlapping PATCHes revert each other, including `userName`, which D-167 decisions depend on. The group path reads under the lock (`resource_groups.rs` ~436).
3. **Body before authentication.** `scim/protocol.rs` ~374–390 reads and parses up to 1 MiB before `ScimToken::authenticate`; a bearer-less request is not charged (`rate_limit.rs` ~103–108); a dead token with a malformed body gets 400 instead of the identical 401 C-470 requires; a malformed `{id}` gets axum's plain-text 400 (~404–412).
4. **`emails[type eq "…"].value` ignores its filter** (`resource_users.rs` ~756–775): any `emails[` path rewrites the primary e-mail, and so the `userName`.
5. **Owner links.** SEC-72 says "an owner is never mutated by SCIM" and C-473 "any mutation of an owner membership → 403"; the code refuses owner PUT and deactivation but writes `userName`/`displayName` on the link (~893–904, ~930–946).
6. **Expiry notice is only an audit row.** `services/aurora-api/src/jobs.rs` ~95–140 writes `scim_token.expiry_notice` and notifies nobody; `docs/05` ~356 and C-471 promise "a notice to the org owners and an audit row 14 days and 1 day before a token expires".
7. **SCIM management routes are absent from `web/openapi.json`.** `scim/management.rs` ~478–484 registers plain axum routes merged after the OpenAPI router (`app.rs` ~340); C-471/C-472 routes are ordinary owner `/v1` routes.
8. **Wrong error code.** Invalid domain → `invalid_request`; C-472 names 422 `scim_domain_invalid` (`management.rs` ~95–131).
9. **Untested claims.** No SCIM case in `tests/it/audit_atomic.rs` (SEC-72 "audit failure = nothing applied" rests on a static scan); no test with the shared counter store down; `scim_scope.rs` ~306–345 stops at the first 429.

## Linked requirements
- RFC 7644 §3.4.2 (`totalResults`), §3.5.2 (PATCH paths); `docs/04` §SCIM; C-470..C-479; SEC-72, SEC-73; D-167.

## Spec change (apply with the fix)
- SEC-72 / C-473: state the owner rule precisely — "a SCIM request that would change anything about an owner (membership, link attributes, state) answers 403 and writes nothing; reads are unaffected".
- C-471 / `docs/05`: name the notice channel (the existing owner notification path used for approvals — in-app and e-mail where a mailer is configured), once per threshold.
- `docs/04` §Rate limits: no undocumented list bound; lists page in SQL.

## Scope
### In scope
- Count query plus SQL paging (OFFSET from `startIndex`, `count` ≤ `SCIM_PAGE_MAX`) for unfiltered and `displayName`-filtered lists; same check on the groups list total.
- Read-merge-write of PATCH (and PUT) under the link row lock.
- Authenticate (and charge) before reading the body; bearer-less requests charged to the per-address bucket; `{id}` taken as a string and answered with a SCIM error body.
- Filtered `emails[…]` paths: apply only to the matching entry; a non-primary/non-work target never changes `userName`; unsupported filter → 400 `invalidPath`.
- Owner rule as worded above.
- Owner notice delivery, deduplicated per token and threshold.
- Management routes on the OpenAPI router; regenerate `web/openapi.json` and `web/src/lib/api/schema.d.ts`; `web/src/lib/api/scim.ts` uses the generated types.
- `scim_domain_invalid`.
- Tests in item 9, including SCIM cases in the `audit_atomic.rs` table (POST user, PATCH group, token create, token revoke).

### Out of scope
- Admission gates and suspension ownership (FIX-080); adoption by asserted e-mail (FIX-082); the limiter's refund defect (FIX-087).
