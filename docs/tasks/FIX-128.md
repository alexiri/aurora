# FIX-128: Chat notices without raw space ids, and a "via" line only where it helps (Mattermost) — **small–medium**

## Goal
Two odd things the owner saw in Mattermost:
1. Writing to the bot in a DM while unlinked produced
   `In ~endjsdy15pdw5x8bbfzwa74n3o__w4gfbzdfiffr3fzkjbiw4uk1ay: To work with agents here, link your Aurora
   account: https://…/link/channel?token=… (the link works once, for 30 minutes).`
   The prefix names the DM's internal channel name — meaningless, and pointless when the notice arrives in
   that same DM.
2. Replies start with `Daneel · via R`: the "via" line appears in a 1:1 DM with the bot where only one agent
   can answer, and the bot's name renders as `R`.

## Linked requirements
- `13 §4.5` (private notices: ephemeral, else a DM naming the space), `13 §5.2` (shared bot starts its
  first post in a thread and every proactive post with "Agent · via Bot"), `13 §5.9` (user linking),
  `20` (Mattermost), FIX-112 (link prompts throttled; same `speaker.rs`).
- Owner feedback 2026-11-13.

## Context
- Prefix: `services/aurora-api/src/domains/channels/inbox/send.rs::private` — `PrivateNotice::DirectMessage`
  formats `In {space_mention(space_ref)}: …`; `aurora_channels::content::space_mention` renders
  `<#space:ID>`, which the Mattermost renderer turns into `~<channel name>` (for a DM: `user1__user2`).
  The connector reports `ephemeral: false` without a working admin token (`connectors/mattermost/src/
  connector.rs`, `validate`), so every private notice falls back to a DM.
- "via": `domains/channels/messaging.rs::compose` and `domains/channels/mirror.rs`; display name from
  `Ctx::shared_display_name()` = the integration's stored `shared_bot.display_name`, set in the connector's
  `validate` from `shared_bot_display_name` (default "Daneel") when the bot PUT succeeds, otherwise the bot
  user's `first_name`. Find out why it is `R` (likely the bot's `first_name`, or the label sanitiser cutting
  "R. Daneel …") and fix the source, not the symptom.

## Scope
### In scope
- **No prefix when it adds nothing**: when the notice's target DM *is* the space (space kind `dm` with that
  user), send it there without a prefix. Otherwise prefix with the space's **label** (channel display
  name, `In #Town Square:`), never an id; group DMs: "In your group message with A, B:" (or omit when the
  label is empty). Never expose a raw id; add a test over all space kinds.
- **"via" line**: omit it in a 1:1 DM with the shared bot and wherever the space has exactly one bound agent
  whose name the platform already shows; keep it in shared channels with several agents (its purpose,
  `13 §5.2`). Amend `13 §5.2` with the rule.
- **Bot display name**: use the bot's real display name as Mattermost shows it (bots have `display_name`
  via `/bots/{id}`), refreshed when the integration is re-validated; never fewer than 2 characters — fall
  back to the bot's username. Keep the default name "Daneel" only as the name Aurora *sets* when allowed.
- Link prompt copy stays as FIX-112 leaves it; only the prefix changes here.
### Out of scope
- Ephemeral posts without an admin token (Mattermost limitation); link-flow changes (FIX-112).
