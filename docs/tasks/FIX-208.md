# FIX-208: The SSH user name is the agent's handle (owner 2026-11-21)

## Why

The owner, on an agent's SSH page: "why is the username `…`? It's the bot's handle, right? Just fill it in." The plain-ssh
block reads `ssh -i ~/.ssh/aurora-daneel -o CertificateFile=~/.ssh/aurora-daneel-cert.pub …@188.185.130.101`: the user
name is hidden because it is **not** the handle. The terminator accepts only the agent's UUID as the SSH user name
(`services/aurora-terminator/src/cert.rs`: principals exactly `[username]`, the username a UUID, the key id's `a=` equal to
it; SEC-92, D-356), so `web/src/components/agents/ssh-page.tsx:130–134` shows `…` and keeps the UUID behind **Copy**
(C-1060: "mapping handles is not done here"). P5-REFINE-4 left "should the terminator map SSH handles?" open; the
owner's answer is this fix.

## Decision, contract, security

- **D-445** (owner, 2026-11-21): an agent's SSH user name is its **handle** (`ssh daneel@host`). The agent's UUID keeps
  working as a user name. The agent a session opens is always the one **in the certificate**, never one looked up from
  the typed name.
- **C-1121**: `POST /v1/agents/{agent}/ssh-certificate` issues certificates with **two** principals, `[<agent uuid>,
  <handle>]` (the uuid first), and answers `username: <handle>`. Key id, validity, extensions unchanged. Amends C-1060's
  SSH note and `16 §W20` Authentication ("principals exactly `[username]`" → the rule below).
- **SEC-147** (amends SEC-92's principal clause, D-356 unchanged otherwise): after the signature, the terminator applies
  the certificate law with this principal rule: the principals are `[uuid]` or `[uuid, handle]`, the first a UUID equal
  to the key id's `a=`; the typed user name must be one of the principals; the session is opened for the key id's agent
  (the UUID), and the typed name is never sent to the API as the agent. No lookup by handle anywhere in the terminator.
  A renamed agent: a certificate issued before the rename still connects with the old handle until it expires (≤ its
  validity, 15 min by default) and always lands on the same agent. **Security review before merge** (the Orchestrator's
  reviewer, against SEC-92/SEC-147 and D-356).

## Change

**Rust (`services/aurora-api`, `services/aurora-terminator`):**
1. `domains/ssh/service.rs` (~:255–320): add the handle as the second principal (`b.valid_principal(handle)`), answer
   `username: handle`. The handle is read in the same transaction as the agent (it is what the page shows). Handles are
   `[a-z][a-z0-9-]{0,39}` (`crates/aurora-core/src/ids.rs` `is_valid_handle`), all valid OpenSSH user names. A handle
   may look like a UUID; that is harmless because the session's agent always comes from the key id (unit test it).
2. `aurora-terminator/src/cert.rs` `check`: the principal rule above (`valid_principals()` length 1 or 2, `[0]` a UUID,
   `username ∈ principals`); `key_id_ok` compares the key id's agent with `principals[0]`, not with the typed name. Return
   the agent UUID from the check (e.g. `Result<Uuid, Refusal>`), so the caller cannot use the typed name by mistake.
3. `aurora-terminator/src/server.rs` (~:280–300): open the session with the agent UUID returned by `check`. Keep the typed
   name only for logs/metrics if they need it. Check every other use of `username` in the terminator and the API's
   session-open route for the same rule (the API must not resolve an agent from a typed handle).
4. `services/aurora-cli/src/ssh.rs` already uses the answer's `username`: confirm, update its test fixture (:474) and make
   `aurora ssh <handle>` pass the handle.

**Web:** `ssh-page.tsx`: the block shows the full command with the handle (`ssh … daneel@188.185.130.101`), no ellipsis,
and **Copy** copies exactly what is shown (from the certificate answer's `username`, falling back to the handle before
one is minted). Remove the comment about the id behind Copy. (Already on master from `alexiri/ssh-show-id`, owner
2026-11-21: the block shows the agent UUID in full, `CopyBlock` has no `display` prop any more, and the button is "Copy
the ssh command". This fix only puts the handle where the UUID is.)

**Docs:** `docs/16-wire-protocols.md` §W20 Authentication; `docs/17-security.md` SEC-92 (pointer) and new row SEC-147;
`docs/API_CONTRACTS.md` C-1121 (and C-1060's SSH note "superseded by C-1121"); `docs/11-runner-sandboxes.md` §SSH access
examples; `docs/tests/security-coverage.md` row for SEC-147.

### Done (lane B, 2026-11-21)

**Principal rule as implemented.** `aurora-terminator/src/cert.rs` `check(..) -> Result<Uuid, Refusal>`: type `user`; one
or two principals; the first a UUID in canonical form (`Uuid::to_string()` equal to the string, so upper case, braces or
the simple form are refused); the second, if any, `is_valid_handle`; the typed user name one of them (else
`Refusal::Principal`); key id shape with `a=` equal to the first principal (else `Refusal::KeyId`). An empty principal
list (OpenSSH's "any user") is refused. `server.rs` opens the session with the returned UUID as
`SessionOpenRequest.username`; the typed name is not used past `check` (no other use of it in the terminator). API
`ssh/sessions.rs` `verify_certificate`: principals `[id]` or `[id, handle-shaped]`, `username` must be the first and
equal the key id's agent, so a handle there is refused. Mint (`ssh/service.rs`): `principals_for(agent, handle)` →
`[id, handle]` (the handle from the agents row the mint reads; a stored handle outside the shape is left out so the id
still works), `username` = the handle, `principal` = the id. CLI: `cert_reusable` wants the id first (1–2 principals);
`ssh_user` takes the answer's `username` (or a reused certificate's last principal) only when it is a principal and the
id or a handle shape, else the id, so nothing ssh could read as an option becomes the destination; `aurora ssh daneel`
runs `ssh … daneel@host`. Web: `user = live?.username ?? handle`; a certificate kept in sessionStorage from before
shows the id (it names only the id). Handles never change (C-12): "rename" is answered in C-1121/SEC-147 and tested as
"a certificate keeps its own handle until it expires; another name is refused".
