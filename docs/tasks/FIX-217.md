# FIX-217: the API's guarded outbound clients ignore proxy environment variables (security, SEC-04)

**Found 2026-11-21** in the Orchestrator's security review of P5-SKLIB-1 (SEC-148); pre-existing, not
introduced by that brief. Size S, Rust. One lane.

## Problem

`services/aurora-api/src/domains/connect/env.rs` (~150-172) builds `http` and `http_instance` with
`redirect(Policy::none())` and a guarded DNS resolver (`Guarded`, `GuardedAllow`) that refuses private,
loopback, link-local and metadata addresses unless `gateway.allowed_private` opens them. Neither builder
calls `.no_proxy()`, and reqwest uses the system proxy (`HTTPS_PROXY`, `HTTP_PROXY`, `ALL_PROXY`) by
default. If an operator sets one on the API pod (the chart's `api.extraEnv`, a corporate proxy), every
request through these clients goes to the proxy, the proxy resolves the name, and the guarded resolver
is never consulted: the connect probe, the account Test, skill library reads (P5-SKLIB-1) and every
other caller could reach internal addresses the instance never allowed.

Nothing in the chart sets these variables by default, so default installs are not affected.

## Do

1. Add `.no_proxy()` to both builders in `connect/env.rs`, and to every other API `reqwest::Client`
   whose safety depends on a guarded resolver or an address check (grep `services/aurora-api/src` and
   shared crates for `reqwest::Client::builder()` and `dns_resolver(`; list each and say why it does or
   doesn't need it). The gateway's own egress path is out of scope (it has `gateway.egress_proxy` by
   design, `06` step 2).
2. Docs: where the API's outbound guard is described (`06`/`15`, `docs/operator/`), one sentence:
   proxy environment variables do not apply to the API's guarded clients; outbound proxying for apps is
   the gateway's `egress_proxy`.
3. Test: a unit or IT that builds the clients with `HTTPS_PROXY` pointing at a local listener and asserts
   a request to a private address is still refused by the guard and the listener receives nothing (set
   the env var only inside the test process, serialised; or use reqwest's builder in a way that proves
   the proxy is disabled without global env if that is cleaner).
4. SEC row: add a line under SEC-04 in `docs/tests/security-coverage.md` naming the test.
