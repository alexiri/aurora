# BE-008: Service binaries with health, metrics, config validation; `aurora-api migrate`

## Goal
Every service binary starts, validates its configuration (refusing to start on error, naming the key), logs JSON, serves health/readiness/metrics, and shuts down gracefully. `aurora-api migrate` applies migrations (+ gateway grants).

## Linked requirements
- M0/15§obs: `15 §Observability` (`/healthz` liveness, `/readyz` readiness: DB reachable where used; Prometheus `/metrics`), `15 §Configuration` (validate at startup), `02 §Coding rules` (Logging: JSON with `service`, `instance`), `01 §Components` (ports), `05 §Authentication surfaces` (`/metrics`, `/healthz`, `/readyz` unauthenticated; edge routes only `/v1/**`), `06 §Listeners` (gateway proxy 4102 vs internal 4103), `19 §M0` (service binaries; `aurora-api migrate` on an empty DB).

## Context
- Crates ready: `aurora-core` (errors, limits), `aurora-config` (`load`, per-service validated views), `aurora-db` (`connect`, `MIGRATOR`, `grants::apply_gateway_grants`).
- Ports (`01`): api 4101 (public) + 4111 (internal, `/internal/v1/**`, empty for now); gateway 4102 proxy + 4103 internal; hookhost 4104; runner 4105 (sandbox-facing WS); fake connector callbacks 4110 / test control 4190.
- Decision I-09 (add to `docs/90-decisions.md` is the orchestrator's job; just implement): shared service bootstrap lives in `aurora-core` behind feature `service` (tracing JSON init with `service` + `instance` fields, Prometheus recorder + `/metrics` handler, health router builder with pluggable readiness checks, SIGTERM/SIGINT graceful shutdown future). Health/metrics are served on: api 4101; gateway **4103 only** (never on the proxy port); hookhost 4104; runner a separate ops port 4106 (not the sandbox-facing 4105); fake connector 4190.
- CLI flags: `--config <path>` (else `AURORA_CONFIG`, else `/etc/aurora/aurora.toml`), `clap` derive.

## Scope
### In scope
- `crates/aurora-core` feature `service` (new module `service`), plus its Cargo deps (`tokio`, `axum`, `tracing`, `tracing-subscriber`, `metrics`, `metrics-exporter-prometheus` — all workspace deps).
- `services/aurora-api`: subcommands `serve` (binds 4101 + 4111; `/healthz`, `/readyz` = `SELECT 1` ok, `/metrics`; `/v1/*` → 404 envelope for now) and `migrate` (runs `MIGRATOR`; if `database.gateway_role` configured, `apply_gateway_grants`). Other subcommands from `02` (`bootstrap-admin`, `secrets`, `plugins`, `openapi`) are added by later tasks — do not stub them.
- `services/aurora-gateway`: `serve` (binds 4103 with health/ready/metrics; 4102 bound and answering every request with the error envelope 503 `gateway_not_ready` — placeholder until M2).
- `services/aurora-hookhost`: `serve` (4104 health/ready/metrics).
- `services/aurora-runner`: `serve` (config validated incl. `runner.backend`; ops port 4106; no work loop yet).
- `services/aurora-supervisor`: clap skeleton (`run`, `mcp-bridge`) that exits with code 2 and a clear "not implemented in this milestone" message.
- `services/aurora-cli` (bin `aurora`): clap skeleton with `--version` only.
- `connectors/fake`: `serve` with health on 4190.
- Each binary: config error → stderr lists every invalid key, exit code 78 (EX_CONFIG).

### Out of scope
- Any `/v1` route, auth, proxying, work loops (M1+). Containerfiles (OPS-003).

## Acceptance criteria
- [ ] `cargo run -p aurora-api -- migrate` on an empty dev DB (reset first with `~/.cargo/bin/sqlx database reset -y --source crates/aurora-db/migrations` or create a fresh db) succeeds; rerun is a no-op.
- [ ] `aurora-api serve` with a minimal config: `curl :4101/healthz` 200, `/readyz` 200 (DB up) and 503 when DB URL points nowhere, `/metrics` returns Prometheus text, `/v1/x` returns 404 JSON envelope. Gateway: 4103 health 200, 4102 returns 503 envelope. Missing `server.external_url` → exit 78 naming the key.
- [ ] Logs are JSON lines with `service` and `instance`.
- [ ] `cargo build --workspace`; `cargo clippy --workspace --all-targets --all-features -- -D warnings`; `cargo fmt --all --check` pass.
- [ ] A small `deploy/dev/aurora.dev.toml` example config used for the manual checks (document commands in the report).
