# BE-021: `aurora-secrets` — SecretRef, SecretStore seam, registry, inline + memory stores, SecretVault

## Goal
The pluggable secret-store seam of `08 §1–2` with the phase 0 stores, so every `*_ref` column is read/written through one service.

## Linked requirements
- M2/08 `§1 Where credential material lives`, `§2 The SecretStore seam` (SecretRef format, store modes, rules 1–4, registry validation), `§3 inline`; D-12, D-13; SEC-01 (no plaintext in errors/logs), SEC-08 (fail closed), SEC-11 (purpose/owner binding); `18 §Secrets` (memory test store, reference mode, store-unavailable fail-closed, AAD row-swap).

## Context
- Read `docs/08-secrets-credentials.md` lines 1–149 (§1–§3). Normative.
- `aurora-crypto` (done): `Keyring::{parse, seal, open, needs_rekey, active_key_id}`, `Aad { purpose, org_id, owner_id }` rendering `aurora:v1:<purpose>:<org>:<owner>`. The inline store = `Keyring` + AAD from `SealContext` (purpose string from the §1 table).
- `aurora-config`: `[secrets]` section (`default_store`, `stores[]` with `id`, `kind`, opaque extra keys). `aurora-core::secret::Secret`.
- Workspace deps: `async-trait`, `percent-encoding`, `thiserror`, `tokio`, `uuid`, `serde`. Do not edit root `Cargo.toml`.

## Scope
### In scope (`crates/aurora-secrets/**`)
- `SecretRef` parse/format for `inline:v1:<key_id>:<b64>` and `ext:<store_id>:<pct-encoded path>[#<field>]@<version>`; opaque `Display`/`Debug` that never prints ciphertext beyond a short prefix (refs are not secrets, but keep logs small).
- `Purpose` enum for the six §1 purposes with their AAD strings; `SealContext { purpose, owner_id, org_id, workspace_id }`.
- `SecretStore` trait exactly as `08 §2` (+ `StoreCapabilities`, `StoreHealth`), errors: `SecretRefMismatch`, `StoreUnavailable`, `StoreNotConfigured`, `ReferencesNotSupported`, `ReferenceNotPermitted`, `Malformed`, `NotFound` — none carrying plaintext.
- `InlineStore` (managed, no references; `put` seals a new value; `get` opens with AAD — wrong purpose/owner/org ⇒ `SecretRefMismatch`; `delete` no-op).
- `MemoryStore` (tests only; `managed` + `references = true`; versioned map; stores ctx alongside value and enforces purpose/owner binding; `resolve_reference` for preloaded paths with an allow-list of path globs per org id; can be toggled unavailable to test fail-closed). Gate it behind feature `memory-store`.
- `StoreRegistry::from_config(secrets_cfg, keyring)` — `inline` implicit; unknown `kind` → error naming the phase (`hashicorp-vault` → "available in phase 3"); `default_store` must exist and be `managed`.
- `SecretVault { registry, default_store }` with `seal`, `open` (dispatch by ref kind/store id; `ext` with unknown store ⇒ `StoreNotConfigured`), `discard` (no-op for inline and reference refs — reference vs managed is passed by the caller as `value_source`), `check_reference`.
- Helper for migration: `reseal(ctx, old_ref, target_store) -> new_ref` (read → put); the CAS swap and CLI live in the API later.

### Out of scope
- `aurora-api secrets migrate|rekey` commands, gateway caching, Vault store (phase 3).

## Acceptance criteria
- [ ] Tests: SecretRef round trips (incl. percent-encoded paths, field, version); inline seal/open; open with another owner/org/purpose ⇒ `SecretRefMismatch` (row-swap, SEC-11); key rotation (old ref opens after active key change; `reseal` produces a ref under the new key); memory store reference mode (permitted/not permitted path); unavailable store ⇒ `StoreUnavailable`; `ext` ref with unconfigured store ⇒ `StoreNotConfigured`; registry rejects unknown kind / unmanaged default; `Debug` of errors and of `Secret` contains no plaintext (assert).
- [ ] `cargo test -p aurora-secrets --all-features`, clippy `--all-targets --all-features -D warnings`, fmt.
