# FIX-020: Credential-side bulk grants (owner request, 2026-11-09)

## Goal
The owner wants to give agents access right after creating an LLM key, a secret or an app connection, instead of going agent by agent. This lane is the API half; FIX-021 builds the dashboard on it.

## Spec (read; do not re-decide)
- D-137 in `docs/90-decisions.md`.
- `docs/05-control-plane-api.md` §Grants and effective views: the three FIX-020 rows.
- `docs/API_CONTRACTS.md` **C-503, C-504, C-505** (shapes, errors, atomicity, audit).
- `docs/02-engineering-conventions.md` `GRANT_BULK_MAX` (50).
- `docs/17-security.md` **SEC-77**, and its row in `docs/tests/security-coverage.md` (set it to `proven` with the test path when done).
- `docs/18-testing.md` §Model readiness and credential-side grants: the "Bulk grants" bullet.

## Scope
1. `GET /v1/secrets/{id}/grants` and `POST /v1/secrets/{id}/grants` (C-503).
2. `POST /v1/connections/{id}/grants` (C-504). Extend `GET /v1/connections/{id}/grants` with `agent_name`, `workspace_id`, `workspace_name`, filtered to workspaces the caller can own.
3. **One authorization path.**
   - Refactor `services/aurora-api/src/domains/grants/service.rs` so the per-agent checks and the write run in one function that takes a transaction.
   - The agent-side `PUT` routes and the bulk routes both call it.
   - Checks: `can_own`; credential in scope for the agent; P4-GRANTS `custom_only` → 422 `full_grant_forbidden`; whatever freeze or other rules the agent-side route applies today.
   - Any failure rolls the whole bulk request back and returns that error with `details.agent_id`.
   - An existing grant is returned `existing` and never modified.
   - Before refactoring, read what the agent-side route checks today. If it lacks a check that SEC-77 names, stop and report rather than inventing one.
4. **Audit:** the agent-side action name (`grant.create`), one row per created grant, `details.via = "credential"`, atomic with the write.
5. **Invalidation:** whatever the agent-side route triggers after a grant (gateway invalidation NOTIFY, home sync, effective-view caches) fires for each created grant, after commit.
6. OpenAPI (utoipa), permission-matrix rows for the new routes, and `web/src/lib/api/schema.d.ts` regenerated.

## Constraints
- **Owns:** `services/aurora-api/src/domains/grants/**`, the matching `aurora-db` repo functions, `services/aurora-api/tests/it/grants_bulk.rs` (new) and the permission matrix, OpenAPI + `schema.d.ts`, `docs/tests/security-coverage.md` (SEC-77 row only).
- Does **not** own: `domains/hosted/**`, `domains/secrets/**` (FIX-019), web components (FIX-021).
- `schema.d.ts` and the OpenAPI file are generated, and FIX-019 also regenerates them. On merge, the coordinator regenerates rather than hand-merging.
- Change files only with the Edit/Write tools; never python, sed, awk, perl, `cat >>` or heredocs. Repo generators are fine.
- No e2e or perf scripts are needed. Check `df -h /home` before building.
