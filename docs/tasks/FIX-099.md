# FIX-099: Dashboard — agent page, chat and onboarding defects (REVIEW-5 WEBA-6/7/8/9/11/12/15/20, WEBX-4/5/6/7/9/14, WEBC-1/3/4/5/6) — **medium**

## Problem
Chat and streams
1. **Any refused stream is reported as "too many streams".** `web/src/lib/chat/use-transcript.ts` (~38–45) treats every `EventSource` `CLOSED` as `too_many_streams`; a 401 after session expiry or a 5xx shows the "too many open tabs" notice and the transcript never reconnects (`docs/14` ~36–38; C-53).
2. **Retry re-post is fire-and-forget.** `components/chat/message-group.tsx` (`TurnErrorWithRetry`, `onRetried`) calls `chatApi.send` with no `Idempotency-Key`, no `catch` and no feedback (RFE-018; C-615).
3. **Approvals stream swallows missed-event signals.** `services/aurora-api/src/domains/approvals/routes.rs` ~117 ignores `BusMsg::Resync` and `Lagged`; the client (`web/src/lib/api/approvals.ts` ~98) refetches only when the EventSource itself reconnects, so decided or expired approvals stay shown as pending. The conversations stream handles the same signal.
4. "Retry now" is shown on a frozen agent's chat error (`chat/status-rows.tsx` ~151; C-615 "hidden on frozen agents"; the Computer tab hides it).
5. `at_capacity` and `agent_start_failed` have no error copy (`lib/chat/transcript.ts` ~184–251) and C-581 does not list them; unknown codes put the server message into the main copy (`errorCopy`).
6. Person attachments render as "Attachment" with no name (`message-group.tsx` ~125); `?draft=` refills the composer on every remount (`chat/composer.tsx` ~48–52).

Agent page
7. Choosing **Default** effort is never saved: the PATCH omits `effort` when empty (`agents/instructions-tab.tsx` ~50); the API takes `null`.
8. The Access tab swallows an org-secret list error (`agents/access-tab.tsx` ~24).
9. Terminal and Previews tabs are shown without a `can_use` check (`agents/agent-page.tsx` ~71–80; `docs/14` ~677: "a non-`can_use` caller never sees the tab").

Onboarding, shell, credentials
10. A failed readiness query leaves the guide on "Checking what … can use…" forever (`lib/onboarding/use-guide.ts` ~81; `readinessError` is never read); a failed secrets query shows "Add an LLM key" although one exists (~77–80); the Overview shows `Loading` forever when the workspace query fails (`overview/overview-view.tsx` ~150).
11. The admin navigation renders for any signed-in user on an `/admin` path (`app-shell.tsx` ~437; the page guard is correct).
12. The connect popup navigates to the provider while keeping `window.opener` (`apps/connect-view.tsx` ~101); `useCreateSecret`, `useSetSecretValue` and `useAcceptSecret` keep the plaintext in the mutation cache for five minutes (`lib/api/secrets.ts`; every other one-time-secret mutation sets `gcTime: 0`); `safeNext` accepts control characters the server rejects (`lib/auth/use-unauthorized-redirect.ts` ~9); policy publish/rollback/draft save do not invalidate the agent `effective`/`grants` caches (`lib/api/policy.ts` ~74–106).

## Analysis
- **Item 9 (Terminal/Previews tabs without a `can_use` check) does not reproduce as a defect.** The agent page renders only from `GET /v1/workspaces/{ws}/agents`, which is `can_use`-gated (`web/src/lib/api/schema.d.ts` "List the agents of a workspace (`can_use`)"), and `docs/04` §The access law makes every workspace role (`owner`, `approver`, `member`) a `can_use` holder; there is no workspace role below it. A caller without `can_use` gets a 403/404 before the page has an agent to show tabs for, so a non-`can_use` caller never sees the tab. The tab list therefore needs no extra predicate; the API re-checks `can_use` on every terminal open and preview share (C-622). No code change.
- **Item 6 (attachment names):** the transcript names a person's attachments by id only (`turn.queued.payload.attachments`), and there is no attachment-metadata read route. The card now asks the content route with `HEAD` and reads the stored filename and size from `Content-Disposition`/`Content-Length` (C-30); no API change. A purged attachment, or a failed lookup, still reads "Attachment".
- **Item 1 (refused stream):** `EventSource` exposes no status, so the hook probes the stream URL once on `CLOSED` and classifies the answer (429 `too_many_streams`, 401, anything else); other refusals reconnect with backoff from a fresh history read. The same generic-`CLOSED` shortcut remains in `approvals.ts` (the approvals stream), outside this brief's scope.
