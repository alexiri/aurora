# FIX-113: Connectors — Mattermost event ordering, callback routing and tests, platform URL guard, lease, unsigned types (REVIEW-5 CONN-1/2/4..14) — **medium**

## Problem
1. **Mattermost events are handled in unordered tasks.** `connectors/mattermost/src/integ.rs` ~876 spawns a task per WebSocket event; `handle_post` awaits channel, user and file lookups before emitting (~436–487) while `handle_changed` emits after one lookup (~488–513). A post deleted or edited within the lookup latency reaches the core as "deleted" (unknown message) followed by "posted" with the original text: deleted content is delivered to the agent, or an edit is lost.
2. **Callback routing by team.** Slash-command and action callbacks find "the first integration in the team" and check the token against that one (`callbacks.rs` ~120–122, ~142); two integrations in one team overwrite each other's `/aurora` command (`connector.rs` ~357–380).
3. **No refusal tests.** `callbacks.rs` tests cover `ct_eq` only; the conformance suite's fourteen scenarios are all happy paths. Nothing proves a bad signature, an unknown integration or a wrong command token is refused.
4. **Clicker identity rests on Mattermost.** The action callback takes the clicker from the body's `user_id`; the connector's HMAC covers the action token only (`callbacks.rs` ~66–98; `render.rs` ~214–232). This is sound only because the Mattermost server makes the callback itself and does not send an action's integration context to clients. That trust is unstated and untested.
5. **The platform URL is tenant-supplied and unguarded in the connector** (`api.rs` ~81–98): destination control is left to the NetworkPolicy, and up to 200 characters of the target's JSON `message` are echoed into validation errors shown to the org admin.
6. `tls.extra_ca_bundle` is documented for connectors (`docs/15` ~184) but the WebSocket and REST clients use system roots only (`ws.rs` ~46–58).
7. The SDK never reads `lease_secs`: a replica cut off from the API keeps its platform sockets past its lease (`crates/aurora-connector-sdk/src/runtime.rs` ~149–170).
8. Smaller: reaction events skip the team-scope check (`integ.rs` ~606–640); a WebSocket reply without an error code is treated as a revoked token (`ws.rs`); catch-up reads `since` without paging; a bootstrap `aun_` token can attach to a managed connector id (`crates/aurora-db/src/repo/connectors.rs` ~178–196; C-454); a managed connector in `pending_approval` still receives decrypted settings in assignments (`connectors/host.rs` ~232; C-456).

Owner question outside scope (Q-R5-8): every connector host shares one `auh_` token, which authenticates as any managed connector and receives that connector's decrypted integration credentials for every org (`connectors/auth.rs` ~50–64; C-456 calls the type filter "not an authorization boundary"). Recommended: a token per host, bound to the connector types that host announced.

The action context (token and signature) is never delivered to Mattermost clients; the conformance suite checks this against the supported server versions."

- C-456: assignments are served for `active` and `awaiting_registration` connectors only. C-454: bootstrap tokens never attach to managed connectors.

## Analysis
- **Item 8, "a bootstrap `aun_` token can attach to a managed connector id" (`crates/aurora-db/src/repo/connectors.rs` `upsert_bootstrap`) does not reproduce.** A managed connector row is created by `insert_managed` without a `token_hash` (NULL), and `upsert_bootstrap`'s `ON CONFLICT … DO UPDATE … WHERE connectors.token_hash <> EXCLUDED.token_hash` is NULL (not true) for such a row, so the update never fires: `connectors_managed::bootstrap_token_never_attaches_to_a_managed_connector` passes on the unfixed code. The guard `AND NOT connectors.managed` is added anyway (the intent no longer rests on a NULL comparison) and the test stays as the regression fence; there is no defect to report.
- Item 2 as written ("action callbacks find the first integration in the team") is already not the case: `/mm/actions` resolves the integration from the HMAC-signed context (`iid`). Only the slash-command callback resolved a team to its first integration; that is what changed.
