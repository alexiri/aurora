# P5-UX-11: Connect an app for the whole organization, dashboard (owner app-setup walkthrough, 2026-11-15)

## Goal

Org owners and admins can make org-scope connections through the API. Starter grants (C-521) and skill
libraries (D-148, D-149) require them. Workspace owners may already grant them to their agents (`07`).
But **no dashboard path creates one**:
- every connect sends `scope: "workspace"` (`connect-dialog.tsx` ~302, ~649);
- Org › Apps › Connect… asks for a workspace;
- the org Connections tab's empty state sends people to Org › Apps.

In the walkthrough, the org owner had no way to set up "one GitHub connection for the whole
organization". This task adds that path and the org connection actions.

## Linked requirements

- D-332; contracts **C-936, C-937, C-947** (the chooser part); C-22 (connect with `scope: organization`),
  I-27 (org connection read access for workspace owners), C-504 (bulk grant), C-521/C-525 (starter
  grants), C-740 (`PATCH access`), C-842 (reconnect).
- Normative: `14 §App setup` §9, `07` (org connections granted to agents of any workspace of the org),
  `04` permission matrix (org connections: owner/admin).

## Placement in the new structure (D-342)

- Everything here lives in the org's **Apps & services** topic (`/o/<org>/apps`, P5-IA-1):
  - the Connect… chooser on its Apps tab;
  - org connections on its Connections tab;
  - **Connect for the organization** on the org setup page (P5-UX-9).
- Workspace owners meet org connections in the workspace's Apps & services and on the agent's Access tab,
  labelled "Shared by <org>".
- The Done step's agent picker rows read "<workspace> · <agent>" (C-948).

## Context

- **API.** `connect/service.rs` `authorize_scope` (~165–167, `require_admin` for org scope). The grant
  service accepts org connections for agents of any workspace of the org (`grants/service.rs` ~674–679).
- **Dashboard.**
  - Org Apps: `components/apps/org-apps-list.tsx` (~66–67, owned workspaces; for org admins, every
    workspace of the org, ordered by creation).
  - Org Credentials: `credentials-view.tsx` (~40, ~47) and `connections-tab.tsx` (~50–55; no Reconnect
    for org connections).
  - Starter grants: placement API (C-520/C-521), instance admin only.
- **Data.** `/v1/me` `workspaces[].personal` covers only the caller's own personal workspace. C-947 adds
  `personal_of` to org workspace items: that API part is owned by **P5-UX-15**. If P5-UX-15 has not
  merged, implement C-947's field here and P5-UX-15 uses it; say which in the report.

## Scope

1. **Journey org mode (C-936).** Add a mode to the P5-UX-3 journey (`connect-journey`):
   - `scope: "organization"`, `org_id`, no agent step, no Account step for workspace connections. An
     existing org connection of the app is offered as "Use <label>", which skips to Done.
   - The access step is unchanged.
   - **Done** offers:
     - **Give it to every new person's agent**: only when this org is placement's default org, the
       caller is an instance admin, and placement allows starter grants. It updates placement
       `starter_grants` the way the P5-UX-6 wizard does.
     - **Give agents access now**: the agent picker over every workspace the caller owns, implicit
       included, grouped "Platform team · Daneel", with own and shared workspaces first. Save calls
       C-504.
     - **Done**.
   - If P5-UX-3 has not merged, run this on the existing connect dialog with a scope prop and the Done
     step above, and leave the journey to adopt it.
2. **Entry points.**
   - The org's Apps & services › Apps **Connect…** lists **For the whole organization** first, then the caller's own and shared
     workspaces, then others' personal workspaces under a collapsed **Other people's personal
     workspaces** (C-947 ordering).
   - The org setup page (P5-UX-9) has **Connect for the organization**.
   - The org's Apps & services › Connections tab's empty state has **Connect an app for the
     organization**.
3. **Org connections tab (C-937)**, the org's Apps & services › Connections. For org owners and admins, rows get the actions:
   - **Reconnect** (C-842 reconnect with the org scope);
   - **Make read-only** / **Allow writes** (C-740);
   - **Disable**;
   - **Delete**, with the existing confirm.

   The org page is for org owners and admins only (C-961). Workspace owners see org connections (I-27) on
   their **workspace's** Apps & services › Connections tab, labelled "Shared by <org>", read-only, with
   the line "Managed by <org> admins".
4. **Workspace side.** In the journey's App and Account steps and on the Access tab, org connections read
   "Shared by <org>" with the org's icon. A workspace owner's journey offers "Use <label> (shared by
   <org>)" first when one exists.
5. **Tests.**
   - Vitest: org-mode step machine; Done options per role (instance admin of the default org, org admin
     of another org, org admin who is not an instance admin); chooser ordering with `personal_of`.
   - Playwright:
     - an org owner connects AWS (access keys) for the organization from the org's Apps & services, gives it to two
       agents in two workspaces, and both agents' Access tabs show the connection "Shared by Users";
     - a workspace owner sees it in the journey and grants it to a third agent;
     - the workspace owner sees no Reconnect or Delete.
   - Axe and narrow-route suites.

- After P5-IA-1; preferably after P5-UX-3 (soft, see Scope 1). Not beside P5-UX-9 (org setup page),
  P5-UX-15 (chooser data), or P5-UX-4 and P5-UX-14 (both also edit `connections-tab.tsx`).

## Acceptance criteria

1. An org owner can make an org-wide connection from the dashboard and give it to agents in several
   workspaces in one flow.
2. Org connections can be reconnected, made read-only, disabled and deleted from the org's Apps &
   services › Connections tab.
3. The Connect… chooser leads with "For the whole organization" and folds other people's personal
   workspaces away.
4. Workspace owners see and can grant org connections, but not change them.
5. Web gates; axe and narrow-route suites, both themes.
