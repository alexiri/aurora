# FIX-255: one safe way to run tests on the shared machine (owner 2026-11-27)

## Why

Owner, 2026-11-27: "we had issues with heavy jobs, especially with testing. they tried to launch all the tests at once,
with each one running its own postgresql container. it was insane, the computer became unusable! I think this needs to
be solved once and for all: write some scripts to run tests in such a way that no agent can ever make these mistakes
again because the script does the correct thing and doesn't run too many tests at once. reuse the heavy job script, of
course."

What went wrong (twice, 2026-11-25, load 70–80 on a 16-core, 31 GB box):
- `crates/aurora-testkit/src/lib.rs` `server_url()` resolves `AURORA_TEST_DATABASE_URL`, then `DATABASE_URL`, then the
  repo-root `.env`. **If none is set it starts a podman `postgres:16` container once per test process**
  (`container_url` / `start_container`). nextest runs one process per test, so a workspace-wide `cargo nextest run`
  without a URL started **193 containers**.
- `/home/alex/orca/workspaces/aurora/heavy.sh` caps machine-wide heavy jobs (two flock slots, nice 10). It cannot see
  what a job does inside: one "job" was the whole workspace with a container per test.
- Agents also started their own throwaway Postgres per lane, ran several crates in parallel, and some `.env` files point
  at `aurora-dev-pg` (`127.0.0.1:55432`), the owner's dev database, which must never be touched.
- Rules in prompts ("ONE container, `-j 2`, one crate at a time") did not hold: an agent that forgets one rule takes the
  machine down. The safe behaviour has to be the default, built into the tools.

## Decision

**D-491** (owner 2026-11-27; coordinator for the details): on the shared development machine, tests run only through one
script that does the right thing by itself, and the test kit itself can never start more than one database server.
- (a) **One shared test Postgres for the whole machine.** One container (`aurora-test-pg`, `postgres:16`, data on tmpfs,
  bound to `127.0.0.1` on a fixed port), started on first use and reused by every lane, every run and every crate.
  `sqlx::test` / the testkit already create a scratch database per test on that server, so lanes do not collide.
  Nothing on the machine starts a second test Postgres.
- (b) **The test kit fails closed.** When no URL is set, `aurora-testkit` uses the shared server: it starts it (once,
  machine-wide, under a lock) if it is not running, instead of a container per process. It refuses a URL that points at
  `127.0.0.1:55432` / `localhost:55432` (the owner's dev database), with a message that names the script.
- (c) **One entry point for test runs: `scripts/dev/test.sh`.** It takes a heavy slot through the heavy job script
  (reused, not rewritten), exports the shared server's URL on the command line, caps parallelism inside the slot, runs one
  crate at a time, refuses or waits instead of overloading, and prints what it ran and the exit code. CI does not use it
  (CI has its own Postgres service and runners); nothing in CI changes.
- (d) **Agents are told once, in the repo.** `CLAUDE.md` (Quality gates) and the developer docs say: run tests only with
  `scripts/dev/test.sh`; never `podman run` a database; never `cargo test`/`nextest` across the workspace by hand.

## Work

### 1. The heavy job script moves into the repo (reused, not rewritten)
- Copy `/home/alex/orca/workspaces/aurora/heavy.sh` (read it first; it is outside the repo) to `scripts/dev/heavy.sh`
  **unchanged in behaviour**: two machine-wide flock slots, the waiter files, `.heavy.status`/`.heavy.status1`,
  `nice -n 10`, the slot descriptors closed for the child. The lock directory stays the same shared directory: make it
  `${AURORA_HEAVY_DIR:-/home/alex/orca/workspaces/aurora}` so every worktree and the old path share the same slots.
- Replace the old `/home/alex/orca/workspaces/aurora/heavy.sh` with a two-line wrapper that `exec`s the repo copy from
  master's checkout (`/home/alex/agent-platform/aurora/scripts/dev/heavy.sh`), so lanes and prompts that use the old path
  keep working. **Write the wrapper atomically** (write `heavy.sh.new`, `chmod +x`, `mv` over the old one): bash reads a
  running script lazily, and other lanes may be inside it. Do this step only after your branch's `scripts/dev/heavy.sh`

### 2. `scripts/dev/test-pg.sh`: the one shared test server
- `up` (idempotent; under its own flock so two callers never start two), `status`, `url`, `down`.
- `postgres:16` from `docker.io/library/postgres`, name `aurora-test-pg`, `--tmpfs` for PGDATA (no volume of any kind,
  so nothing leaks: see the testkit's existing `podman run` arguments for the PGDATA path), `-p 127.0.0.1:<port>:5432`
  with a fixed port (pick one that is free today and not 55432; e.g. 55990, configurable by `AURORA_TEST_PG_PORT`),
  `max_connections` raised enough for `-j` parallel tests that each open a pool (measure: start with 300), user/password
  `aurora`/`aurora`, database `aurora`.
- Readiness check (`pg_isready` inside the container, bounded wait). If a container of that name exists but is stopped
  or unhealthy, recreate it. Never touch any other container.
- `url` prints `postgres://aurora:aurora@127.0.0.1:<port>/aurora`.

### 3. `scripts/dev/test.sh`: the entry point
- Usage (print it on `-h`):
  - `scripts/dev/test.sh <lane> rust -p <crate> [nextest filters/args…]`: one crate.
  - `scripts/dev/test.sh <lane> rust --crates <a,b,c> [args…]`: several crates, **one after another**, each in its own
    heavy slot hold, stopping at the first failure unless `--keep-going`.
  - `scripts/dev/test.sh <lane> rust --all-crates`: every workspace member, one at a time (same as above with the list
    from `cargo metadata`).
  - `scripts/dev/test.sh <lane> web vitest [files…]` and `… web playwright <spec> --project=mocked` (spec before the
    flag, as the repo's specs need).
- For rust: `test-pg.sh up`; then run `cargo nextest run -p <crate> --test-threads <N> …` through `heavy.sh <lane>` with
  `AURORA_TEST_DATABASE_URL` and `DATABASE_URL` set to the shared URL **on that command** (overriding any `.env`). `N`
  defaults to 4, max 8 (`AURORA_TEST_THREADS`). Use the repo's nextest profile; keep cargo's own build parallelism as
  heavy.sh leaves it.
- **Refuse** (exit 2 with one clear sentence), never "do it anyway":
  - no crate given (`rust` with neither `-p`, `--crates` nor `--all-crates`);
  - `--workspace`, or a bare `cargo test`/`nextest run` style argument list without a crate;
  - any URL in the environment or the args pointing at port 55432;
  - `--test-threads`/`-j` above the cap.
- **Wait, don't pile on**: before starting a crate, if the 1-minute load average is above `2 × nproc` or more than 10
  podman containers are running, print why and wait (poll every 30 s, give up after 30 min with exit 3).
- Web: vitest with `--maxWorkers=4`, Playwright with `--workers=2`, both inside a heavy slot.
- End with one line per crate/suite: what ran, its exit code, its duration; exit non-zero if any failed. Never hide an
  exit code behind a pipe.
