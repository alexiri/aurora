# VEL-004: Incremental compilation for every local build and test loop (lanes, quick gate, owner checkout); CI stays non-incremental

## Goal
Owner priority (2026-11-13): "we spend far too long waiting for local compiles". The single biggest remaining cost is that `profile.dev` / `profile.test` set `incremental = false` (I-24), so a one-line change in `aurora-api` recompiles the whole 75 k-LOC crate twice (lib + lib-test, ~105 s each; 132–250 s per edit→test cycle, `docs/ops/build-performance.md`). I-36 already measured incremental at 7–14 s for the same edit, but only enabled it for the `dev-fast` profile (`just dev`/`build-fast`), never for tests or worker lanes — which is where most of the waiting happens.

## Linked requirements
- Decisions: I-03 (disk), I-24 (incremental off), I-34 (one test binary per crate), I-35 (per-lane target dirs, deleted after the lane), I-36 (`dev-fast`). This task writes **I-37** (refines I-24/I-36).
- Measured baseline: `docs/ops/build-performance.md` (127–243 s non-incremental vs 7–14 s incremental for a one-line api change).

## Context
- `Cargo.toml` `[profile.dev]` (`incremental = false`), `[profile.dev-fast]`.
- `.github/workflows/ci.yml` sets `CARGO_INCREMENTAL: "0"` at workflow level — CI is unaffected by a profile change, and must stay non-incremental (sccache can't cache incremental crates; CI targets are throw-away).
- `.cargo/config.toml`: `rustc-wrapper = scripts/dev/rustc-wrapper.sh` (sccache). sccache skips incremental compilations — only workspace crates are incremental, registry deps stay cached.
- `justfile` (`clean-stale`, `test`, `quick`), `scripts/dev/quick-gate.sh`.
- The owner checkout's `target/` is 57 GB today (54 GB `target/debug`) — without incremental. Disk is ~90 GB free.

## Scope
### In scope
1. **Measure first (on an idle machine — check `uptime`, no other cargo/e2e running; record load):** in your worktree, after one warm `cargo test -p aurora-api --no-run`, `touch services/aurora-api/src/domains/me/mod.rs` (or append+revert a comment) and time `cargo test -p aurora-api --no-run` (a) as today, (b) with `CARGO_INCREMENTAL=1`. Same for `aurora-gateway` and `aurora-db` (a change in `aurora-db` rebuilds its dependents). Record `du -sh target/debug` after each variant.
2. **Turn incremental on for local `dev`/`test`** — `[profile.dev] incremental = true` (the test profile inherits it), keeping `debug = "line-tables-only"` and `[profile.dev.package."*"] debug = false`. CI keeps `CARGO_INCREMENTAL=0` (verify the workflow env still applies to every compiling job, incl. `nightly.yml`; add it where missing). `dev-fast` becomes redundant: keep the profile name as an alias (`inherits = "dev"`) so `just dev`/`build-fast`/`AURORA_DEV_PROFILE` keep working, and say so in the comment.
3. **Bound the disk cost** (the reason for I-24): incremental session dirs accumulate per crate. Make `just clean-stale` also prune `target/*/incremental` entries older than N days (or use `cargo sweep` if installed — don't require it). (The quick gate's disk warning belongs to VEL-005, which owns that script.)
4. **Docs:** decision **I-37** in `docs/90-decisions.md` (refines I-24/I-36: local dev/test incremental on, CI off via env, disk bounded by I-34/I-35 + clean-stale), `docs/ops/build-performance.md` (new measurements table: before/after, per crate, with load context), `docs/18-testing.md` velocity section one paragraph.
