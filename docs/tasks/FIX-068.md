# FIX-068: Guards that pass vacuously and e2e script leaks — SIGPIPE-green edge-route guard, helm-less guards exit 0, dead FIX-057 self-heal, leaked front-door containers block the next run (code review 2026-11-13) — **medium**

## Problem (code review of `09e955c9..bc7857ad`, scripts/)
1. **`scripts/guards/edge-routes.sh` can pass when it should fail.** The "no `/scim` route" and "no relay rendered" checks use `if helm template … 2>/dev/null | grep -q …; then fail`. Under `set -o pipefail`, `grep -q` exits on the first match, `helm` takes SIGPIPE (141), the pipeline is non-zero, the `if` is false → the guard passes exactly when the forbidden resource **did** render (output-size/timing dependent: flaky-green). Audit **every** guard in `scripts/guards/*.sh` for the same `| grep -q` under pipefail pattern.
2. **`scripts/guards/hook-policies.sh` and `scripts/guards/sandbox-network.sh` `exit 0` without helm**, and `run-all.sh` still prints "all guards passed". `hook-policies.sh` never asserts it inspected at least one pre-upgrade Job with a `serviceAccountName` (rename the secrets Job → the guard checks nothing and passes) and only matches `matchLabels` (ignores `matchExpressions`).
3. **FIX-057's stale-lock self-heal is dead code.** `scripts/e2e/gateway.sh`: `lsof -t -- "$LOCK"` runs after `exec 9>"$LOCK"`, so it always lists the script's own pid; `holders` is never empty and the "nobody holds → retry" branch never runs. Also: if only the parent is SIGKILLed, the orphaned `9>&-` subshell keeps running `cargo test` **without** the lock, and a second run can collide on 127.0.0.31–34.
4. **Leaked containers block the next run.** `gateway.sh`'s front-door containers (`aurora-e2e-fd-nginx`, `aurora-e2e-fd-haproxy`) and the `*-gwe2e-dbtarget` Postgres are removed only in the EXIT trap; after a SIGKILL the next run's `podman run --name …` fails "name in use". Check the other e2e scripts (`hosted.sh`, `channels.sh`, `mattermost.sh`, `llm.sh`, `kind.sh`) for fixed-name containers with the same problem.
