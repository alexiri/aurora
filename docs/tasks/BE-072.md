# BE-072: Inbox processing, routing, linking, reach, mirror, commands

## Goal
The core conversation logic of channels: process inbound events (13 §5.1, every step), post answers back through the door (§5.2 mirror), and implement the neutral commands (§5.4). Implement this as handlers on the BE-071 inbox processor.

## Linked requirements
- `docs/13-channels-connectors.md`:
  - §5.1, all 11 steps, in order:
    1. integration active and owned by the connector
    2. echo guard
    3. target agent: dedicated bot / shared DM thread link → DM default → single reachable → `dm_default.choose` picker; shared channel binding, or a "not set up" reply naming owners
    4. speaker: user link / verified-email auto-link / `link_requests` + sign-in-link ephemeral; bot authors only via approved person reach, metered by the app-turn cap
    5. authorization: `can_use` or approved reach, else a polite refusal **before anything reaches the agent**, a pending reach grant, and owner notification (a dashboard notice; the `reach.decide` card DM comes from BE-073, so call its card API if merged, otherwise leave a clearly marked hook)
    6. listen gate
    7. thread mapping (direct → the agent's direct conversation with that person; group → per thread root)
    8. context via correlated `history.read`, as a labelled sanitized untrusted block
    9. files via correlated `file.fetch`, making bound/failed attachments
    10. turn creation (door `thread`, `source_event_id`, crash-idempotent)
    11. receipt (`reaction.add eyes` / `status.set` / placeholder per capabilities)
  - other events: `bot.added` → binding flow (DM `binding.choose` card via BE-073, or a hook), `bot.removed`, `presence.removed`, `message.edited`/`deleted`/`reaction.added` (recorded only)
  - §5.2 mirror:
    - on turn finish with door `thread`, post the durable text once, complete, to the thread link (`dedupe_key answer:<turn_id>`), then files from `send_file`, then remove the receipt
    - doorless turns go to the most recently used thread link
    - web/API turns are not mirrored
    - failed turns post a failure line with a dashboard link
    - shared-bot attribution line
  - §5.4 commands: `help`, `agents`, `use <handle>`, `link`, `unlink`, `bind <handle>`, `unbind`, `approve <code>`, `deny <code>` (`approve`/`deny` resolve the 8-char base32 code and apply the clicker rules of §5.5: `can_use` and the user link)
  - §4.5 capability fallbacks (use `aurora-channels` capability helpers)
  - §6 invariants 1, 2, 4
- `docs/10` §Turns/conversations (`direct`/`group` kinds), app-turn cap (BE-065) for bot speakers.
- Content: `aurora-channels` `Content::platform` (core voice) vs `Content::untrusted`. Model text is never allowed to emit `<@here>`.

## Scope
### In scope
- Inbox handlers for all event kinds above. The mirror runs on the turn-finished lifecycle hook (`domains/hosted/lifecycle.rs`, same pattern as schedules/webhooks/peer tasks). Commands.
- Use the BE-074 repos. Don't create duplicates. If a lookup you need is missing, add it to that repo module.
- Tests `services/aurora-api/tests/channels_inbox.rs`. Drive events through `POST /v1/connector/events` with a registered fake connector and assert on enqueued ops, covering:
  - every step's branches (dedicated DM, shared DM with/without default, picker, channel binding/unbound mention reply)
  - unlinked speaker → link prompt (no turn)
  - verified-email auto-link
  - unauthorized → refusal op and pending reach, no turn
  - listen gate
  - thread mapping reuse
  - context block untrusted
  - file fetch success/failure
  - duplicate event → one turn
  - receipt per capability
  - mirror: answer posted once, doorless to the last link, API turn not mirrored, failure line, attribution
  - each command

### Out of scope
- Cards, action tokens, clicker router (BE-073; you may call its API for `binding.choose`/`dm_default.choose`/`reach.decide` cards if it is merged first, otherwise leave a typed hook), messaging tools (BE-075).

## Constraints / file ownership
- You own `services/aurora-api/src/domains/channels/inbox/**`, `…/mirror.rs`, `…/commands.rs` (new), the lifecycle hook line, and `tests/channels_inbox.rs`. Only append lookups to the BE-074 repos.
- Never let unauthenticated/unauthorized platform input create a turn (invariant 2). Every platform string is untrusted.
