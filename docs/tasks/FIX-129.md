# FIX-129: Agent page uses the available width and its tab strip never scrolls sideways — **small–medium**

## Goal
The agent page is too narrow and, since the Terminal tab was added, the tab strip scrolls horizontally.
- Every tab except Chat is capped at `max-w-4xl` (`web/src/components/agents/agent-page.tsx:126`), so on a
  normal desktop the content sits in a thin column (and the terminal, the file browser and tables suffer
  most).
- The strip has up to 13 tabs (Chat, Instructions, Memory, Skills, Schedules, Webhooks, Peers, Channels,
  Previews, Terminal, Access, Computer/Connect) in an `underline` `Tabs` with `overflow-x-auto`, which
  scrolls sideways well above phone width.
The owner wants no sideways scrolling.

## Linked requirements
- `14 §Visual design` (tokens, shared primitives and page patterns, both themes, no horizontal scroll at
  390 px), `14` §Tabs row of the primitives table ("the strip scrolls within itself at 390 px" — to be
  amended), `14` agent page tab list, FIX-098 (terminal tab), FIX-099 (agent page defects).
- Owner feedback 2026-11-13: "the agent's div is too thin … too many things and we get side scrolling".

## Scope
### In scope
- **Width**: drop the `max-w-4xl` cap for the agent page tabs; use the page pattern's full content width
  (check `14 §Visual design` page patterns; if there is a wide-page pattern, use it, else add a
  `PageWidth`/`wide` variant to the shared pattern rather than a one-off class). Long-form text panels
  (Instructions editor prose, settings forms) may keep a readable max width **inside** the panel.
- **Tab overflow without scrolling**: extend the shared `Tabs` primitive (`web/src/components/ui/tabs.tsx`)
  with an overflow mode: tabs that do not fit collapse into a trailing **More ▾** menu (measured with a
  `ResizeObserver`; the selected tab is always visible — if it lives in the overflow it is shown in place
  of the last visible tab). Keyboard: arrow keys still move across all tabs, the menu is a proper
  menu button (Enter/Space/Escape, `aria-haspopup`, `aria-expanded`). Use it on the agent page; the
  `?tab=` addressing stays unchanged.
- Optionally group rarely used tabs (owner may prefer: Schedules + Webhooks + Peers under "Automation")
  — **don't** do this without the owner; overflow alone solves the scrolling.
- Check the Terminal and Computer panels themselves do not cause page-level horizontal scroll (the
  terminal must fit its container and resize; wide tables scroll inside their own container).
- Amend `14` (Tabs row; agent page) accordingly.
### Out of scope
- Terminal colours/close codes (FIX-098), other agent-page defects (FIX-099).

## Constraints / file ownership
`web/src/components/ui/tabs.tsx`, `web/src/components/agents/agent-page.tsx`, page-pattern component if a
width variant is added, `docs/14`. **Run after FIX-098 and FIX-099** (same agent page / terminal files) or in
the same lane as their last step.

- [ ] At 1280 px the agent page content is wider than 896 px (the old cap).
- [ ] Unit tests for the overflow menu: selected-tab visibility, keyboard, ARIA; axe clean.
