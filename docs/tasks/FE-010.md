# FE-010: Dashboard auth pages and security headers

## Goal
The public/auth pages outside the shell, wired to the real API through the generated client, plus the dashboard's security headers.

## Linked requirements
- M1/14 `§Public / auth (outside the shell)` (`/auth/login`, `/auth/signup`, `/auth/forgot`, `/auth/reset`, `/auth/verify`, `/auth/cli`, `/join`, `/setup-error`), `14 §Architecture rules` (pure API client, generated client, CSP + security headers via middleware, version banner, no `dangerouslySetInnerHTML`, WCAG 2.1 AA); `04 §Email and password`, `§CLI login`, `§Invitations`; contract `docs/API_CONTRACTS.md` M1 (rows `/v1/instance`, `/v1/auth/*`, `/v1/invitations/preview|accept`, `/v1/me`); SEC-22 (same-origin calls; cookies first-party).

## Context
- Existing scaffold (FE-001): Next 16 App Router under `web/src/app`, TanStack Query provider in `src/app/providers.tsx`, `openapi-fetch` client + `ApiError` in `src/lib/api/client.ts`, generated types `src/lib/api/schema.d.ts` (regenerate with `pnpm gen:api` after pulling — do **not** hand-edit), Tailwind 4, shadcn-style `button`. Node 20 locally, pnpm `~/.local/bin/pnpm`.
- The API sets/clears the `aurora_session` cookie itself; the dashboard never reads it (HttpOnly). Unsafe requests are same-origin, so the browser sends `Origin` automatically.
- OIDC buttons: link to `/v1/auth/oidc/{id}/start?return_to=<path>` for each `GET /v1/instance` provider. OIDC callback errors arrive as `/auth/login?error=<code>`.
- Email log-only mode (`instance.email_delivery == "log"`): forgot/verify/signup pages say "Email delivery is not configured; the link was written to the server log."

## Scope
### In scope (`web/src/**`, `web/e2e/**`, `web/tests/**`)
- Pages: login (email+password, OIDC buttons, error code → message map, `?next=` same-origin path redirect after success, default `/`), signup (only when `signup_mode == "open"` or with `?invitation=<token>` from `/join`; otherwise explains invite-only), forgot, reset (`?token=`), verify (`?token=`, auto-submit once), cli (`?code=` prefilled; requires signed-in user — redirect to login with `next`; workspace picker from `/v1/me` memberships; approve → success message), join (`?token=`: preview; signed-in → Accept; not signed-in → "Sign in" / "Create account" (links carry the token); error states: expired, email mismatch, unverified (offer resend)), setup-error (lists `instance.setup_errors`).
- Reuse `src/lib/api/errors.ts` and `src/lib/api/queries.ts` from FE-011 (extend the code→message map with auth codes); field errors (`details.fields`) shown under inputs.
- `src/middleware.ts` (or Next 16 equivalent `proxy.ts` — check the installed version's convention): CSP with per-request nonce exactly as `14` (`default-src 'self'; img-src 'self' data:; script-src 'self' 'nonce-…'; connect-src 'self'; frame-ancestors 'none'`), `X-Content-Type-Options: nosniff`, `Referrer-Policy: same-origin`; host pin only when `AURORA_EXTERNAL_HOST` env is set. Ensure the Next build still works with the nonce (pass it to scripts as Next requires).
- Version banner component: compares `/v1/instance.version` with `process.env.NEXT_PUBLIC_AURORA_VERSION` (if set) — show "new version available" when different.
- Forms: accessible labels, error summaries with `role="alert"`, keyboard operable, loading/disabled states.
- vitest component tests for login (field error rendering, error code mapping) and join (state rendering) using mocked fetch; Playwright specs are written in TEST-011, not here.

### Out of scope
- App shell, org/workspace pages (FE-011+). `/link/channel`, `/oauth/bridge` (M3/M6).

## Acceptance criteria
- [ ] `pnpm lint && pnpm typecheck && pnpm test && pnpm build` pass in `web/`; `pnpm gen:api` produces no diff.
- [ ] Manual smoke against the real API (`. deploy/dev/env.sh`, `cargo run -p aurora-api -- serve`, `pnpm dev`) with `auth.signup_mode = "open"` in a scratch copy of `deploy/dev/aurora.dev.toml`: sign up → lands on `/` signed in; logout; login; forgot shows log-mode notice. Report what was exercised.
- [ ] Response headers on `/auth/login` include the CSP with a nonce and `nosniff` (curl output in report).
