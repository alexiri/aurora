# FIX-008: Podman backend tolerates `stopped` (and unknown) container states

## Goal
The runner's podman backend must work with every podman version we support. CI (`e2e-hosted`, ubuntu-24.04 runner, podman 4.9.x) fails because container inspection deserializes the state through bollard's `ContainerStateStatusEnum`, and podman's Docker-compatible API reports `stopped`:
> `sandbox stop failed … Failed to deserialize JSON: unknown variant `stopped`, expected one of ``, `created`, `running`, `paused`, `restarting`, `exited`, `removing`, `dead`, `stopping``

(run 42375127860, job 128418246953; scenarios s4 idle park, s5 restart and s8 probes fail). This host runs podman 6.1.4, which reports differently, so the bug only shows on podman 4.x. It is a real production bug for any 4.x host.

## Scope
- `services/aurora-runner/src/backends/podman.rs`: make every inspection/listing path that reads a container state robust.
  - Read the state as a string: a raw API call parsed into `serde_json::Value` or a minimal own struct with `status: String`, or bollard options that avoid the strict enum.
  - Map it in one place: `created` → not running; `running` / `paused` / `restarting` → running variants per the existing semantics; `exited` / `stopped` / `dead` / `removing` → stopped; `stopping` → stopping; anything unknown → logged at warn and treated conservatively as "not running, needs reconcile", **never** as running.
  - Check the same for events/list endpoints if they parse state.
- Unit tests over recorded inspect JSON samples for podman 4.9 (`stopped`), podman 5/6 (`exited`) and an unknown value. Put the fixtures in `services/aurora-runner/tests/fixtures/` (minimal JSON is fine).
- If podman 4.9 can be installed locally in a container (e.g. run the e2e against `quay.io/podman/stable:v4.9`), great. Otherwise rely on the fixtures, and the coordinator verifies on GitHub CI.

## Acceptance criteria
- [ ] Fixture tests cover the three versions and pass; `cargo test -p aurora-runner` passes.

- [ ] After the coordinator's push, CI `e2e-hosted` passes 9/9 on ubuntu-24.04.
