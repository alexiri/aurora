## Scope
### In scope
1. **`web/public/aurora-push-sw.js`** exactly per C-835 (plain JS, handlers `install`, `push`,
   `notificationclick`, `pushsubscriptionchange`; texts; URL acceptance; nothing else) and
   `web/public/manifest.webmanifest` linked from the root layout. Response headers for the worker
   (`Cache-Control: no-cache`) via `next.config.ts` `headers()`; CSP gains `worker-src 'self'` and
   `manifest-src 'self'` in `proxy.ts` (nothing else changes).
2. **Push client module** `web/src/lib/web-push.ts`: support detection (Push API, secure context,
   iOS standalone), opt-in marker in `localStorage` (try/catch), Turn-on flow (register worker →
   `Notification.requestPermission()` → `pushManager.subscribe({ userVisibleOnly: true,
   applicationServerKey })` → `POST`), removal (DELETE → `unsubscribe()` → unregister the worker),
   load-time re-sync (key comparison by public key; `rebind: true` when the server does not list
   this browser for the current session; 404 clears the marker), sign-out hook (delete this
   device's row and unsubscribe before the session ends; best effort).
3. **Account › Profile › Notifications**: the Web Push card and device list of `14` (label edit,
   "this device", created, last delivery, state chip, show-names switch with the lock-screen
   warning, Pause, Send test, Remove with `ConfirmDialog`), honest unsupported / insecure /
   denied / iOS states; shown only when `config.available`. Shared primitives only.
4. **Parked approvals UI**: chip, sentences and countdown on the Approvals page, the chat inline
   approval and the workspace overview; post-decision states from `resume_state` ("Approved —
   waiting for the agent to retry (until …)", "Used", "Not used (window ended)", "Revoked", "No
   longer needed"); the approve dialog sentence; the follow-up's "Approval" door chip from
   `door.ref` starting with `approval:`.
5. **Rule editor and grant ask timeout**: bound and hint from `GET /v1/policy/approval-limits`;
   simulate and effective views show "parks" / "clamped to <max>".
6. **Admin › Overview**: the Web Push line of C-836 (from `/v1/instance` `features.push` and the
   admin data the API exposes; if no admin field exists yet, show on/off only and note it).

### Out of scope
Server code; offline caching or any other service-worker feature; push for anything but approvals.

**Adapted from the brief (said so, not silently):**
1. *Door chip.* The transcript's `turn.queued` event carries only the door **name** (`system`), not `door.ref`. The chip "Approval" is read from door `system` +

4. *No `Switch` primitive exists*; the card uses the native checkbox pattern of the neighbouring notification switches (`accent-accent`).
5. *Playwright:* the default headless shell has no Notifications (`Notification.permission` is always `denied`), and no Chromium build here can `pushManager.subscribe()`

6. *Worker robustness found while testing:* a tab opened before the opt-in is not controlled by the worker (it never claims), so `WindowClient.navigate()` rejects;
   the click handler now falls back to `clients.openWindow`, and a refused `focus()` still navigates. Unit-tested.
