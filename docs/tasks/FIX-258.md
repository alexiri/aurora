# FIX-258: the agent's home: a skill path that turns from a file into a folder, and folder modes set without following links (2026-11-27)

## Why

These are the leftovers of FIX-270 (`docs/tasks/FIX-270.md`, Security notes). Both are low.

1. **A skill path that changes between a file and a folder from one version to the next stalls the sync.**
   - FIX-270 made the helpers safe: they are pruned **before** the install, and a helper the home can't hold is
     skipped with a warning.
   - Skills are still pruned **after** the install in `services/aurora-supervisor/src/home.rs`. A skill whose
     `scripts/run` was a file and is now `scripts/run/x.sh` (or the reverse) fails the install's rename. The
     error goes up and fails the whole generation, so no memory, skill or instruction change reaches the sandbox
     until the skill changes again.
   - The template validator refuses the pair **within** one version. Across versions it is reachable, through an
     ordinary edit in a skill library or template.
2. **Folder modes are still set by path.**
   - `set_dirs` changes the mode of every directory under a managed root by path, after `clear_link_chain` and
     `unlink_tree_symlinks` have removed links.
   - A link the agent plants between that sweep and `set_dirs` makes the chmod follow it. In the supported
     deployment (supervisor and agent the same uid) this gains nothing. In the root-supervisor mode the code still
     supports, it is a chmod of any directory.
   - The same applies to parents checked by `clear_link_chain` but not held open: no-follow covers the last
     component only.

## Change

1. Prune skills to the manifest **before** the install, as `prune_to` does for helpers. A skill file the home
   can't hold is skipped with a warning and does not fail the generation. A skill whose files can't all be
   installed is reported to the API on the existing sync-problem path, if there is one. Say in the report what
   the person sees.
2. `set_dirs` walks with directory descriptors:
   - open each directory with `O_DIRECTORY | O_NOFOLLOW` relative to its parent's descriptor (`rustix::fs::openat`);
   - set the mode with `fchmod` on that descriptor;
   - skip anything that is not a real directory.

   Apply the same relative opening where `clear_link_chain`'s callers then create or rename into the tree, if it
   fits without a rewrite. Otherwise say what is left.

## Tests (each must fail before the fix)

- Generation 1 has a skill with the file `scripts/run`, generation 2 has `scripts/run/x.sh`. Generation 2 installs,
  and so do memory and instructions. Also the reverse.
- A link planted inside a skills or helpers tree pointing at a directory outside the home: after `set_dirs`, the
  outside directory's mode is unchanged. Call the step directly if the sync removes the link first.

## Acceptance

Both tests seen failing first. No `std::process::Command`; use the crate's spawn helpers if a process is ever
needed. Clippy for `aurora-supervisor` with `--all-targets` through `heavy.sh`, because CI's clippy caught a
supervisor test on 2026-11-27.

rewrites parts of the supervisor (`supervisor.rs`, `process.rs`, the claude_code adapter): start after it merges.
