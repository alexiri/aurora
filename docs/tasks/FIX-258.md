# FIX-258: the agent's home: a skill path that turns from a file into a folder, and folder modes set without following links (2026-11-27)

## Why

These are the leftovers of FIX-270 (`docs/tasks/FIX-270.md`, Security notes). Both are low.

1. **A skill path that changes between a file and a folder from one version to the next stalls the sync.**
   - FIX-270 made the helpers safe: they are pruned **before** the install, and a helper the home can't hold is
     skipped with a warning.
   - Skills are still pruned **after** the install in `services/aurora-supervisor/src/home.rs`. A skill whose
     `scripts/run` was a file and is now `scripts/run/x.sh` (or the reverse) fails the install's rename. The
     error goes up and fails the whole generation, so no memory, skill or instruction change reaches the sandbox
     until the skill changes again.
   - The template validator refuses the pair **within** one version. Across versions it is reachable, through an
     ordinary edit in a skill library or template.
2. **Folder modes are still set by path.**
   - `set_dirs` changes the mode of every directory under a managed root by path, after `clear_link_chain` and
     `unlink_tree_symlinks` have removed links.
   - A link the agent plants between that sweep and `set_dirs` makes the chmod follow it. In the supported
     deployment (supervisor and agent the same uid) this gains nothing. In the root-supervisor mode the code still
     supports, it is a chmod of any directory.
   - The same applies to parents checked by `clear_link_chain` but not held open: no-follow covers the last
     component only.

3. **FIX-265's leftovers (its second Opus review, 2026-11-27).**
   - **S4-a:** a release that takes longer than its 4 s deadline answers `ok=false`. When it then finishes in the
     background, nothing tells the API. The person sees "stopping did not work" with Stop enabled again, although
     everything ended.
   - **S4-b:** `release_idle_sessions` (`supervisor.rs`) gives all sessions one shared deadline. After one slow
     session, every later one answers `ok=false` at once, although its release is still running.
   - Notes from the same review, to check and either fix or document in `docs/12`:
     - a failed release no longer puts the session entry back, so the next turn starts a fresh child while the old
       processes are still ending;
     - a timed-out blocking scan can still send its group kill later, from a stale "the group is still the child's"
       result, and on the drop path the leader may already be reaped;
     - dropping an unwaited `OwnedChild` releases the ownership mark while tokio may still wait on that pid;
     - `end()` can report `Err` when the tree empties just before the 7 s deadline.

## Change

1. Prune skills to the manifest **before** the install, as `prune_to` does for helpers. A skill file the home
   can't hold is skipped with a warning and does not fail the generation. A skill whose files can't all be
   installed is reported to the API on the existing sync-problem path, if there is one. Say in the report what
   the person sees.
2. `set_dirs` walks with directory descriptors:
   - open each directory with `O_DIRECTORY | O_NOFOLLOW` relative to its parent's descriptor (`rustix::fs::openat`);
   - set the mode with `fchmod` on that descriptor;
   - skip anything that is not a real directory.

   Apply the same relative opening where `clear_link_chain`'s callers then create or rename into the tree, if it
   fits without a rewrite. Otherwise say what is left.

## Tests (each must fail before the fix)

- Generation 1 has a skill with the file `scripts/run`, generation 2 has `scripts/run/x.sh`. Generation 2 installs,
  and so do memory and instructions. Also the reverse.
- A link planted inside a skills or helpers tree pointing at a directory outside the home: after `set_dirs`, the
  outside directory's mode is unchanged. Call the step directly if the sync removes the link first.

### What the person sees (point 1)

There is **no sync-problem path** to the API (the only sync report is `home.synced`), so none was added. When a
skill file cannot be installed, the person sees nothing in the UI: the generation is acked, memory and
instructions arrive, and that skill is missing the file in the sandbox. The only trace is the sandbox log warning.

### The late acknowledgement (S4-a)

A Stop already healed itself: the API re-sends `session.release` every 30 s until `ok: true`. A release nobody
stopped was never re-sent. Now, for a conversation that had a session not released within the deadline, the
supervisor sends `ok: true` once, when:

- every unfinished release of it has ended well (a failed one stays unreleased until a `session.release`; if a
  release task dies, the conversation is never told unasked);
- none of its turns is running;
- its live session, if any, lists no background work and has no child that is still ending
  (`HarnessSession::still_ending`: a replaced or killed claude-code child not seen ended, including the sweep
  after the leader exits by itself).

A normal `ok: true` clears the debt, so there is never a second late one. The API needs no change:
`hosted::only_the_acknowledgement_ends_a_requested_stop` already shows that an unasked `ok: true` ends the
standing entry and a second one is a duplicate, so no new API test was added. The person sees **Background
activity stopped** as soon as it is true.

### Security notes

- **Still by path (point 2).** These keep the earlier discipline (link sweep first, no-follow on the last
  component only): the staging writes under `.aurora/sync`, the instruction files, the `tools.json` and
  `render_inputs.json` renames, the removals in `prune_to`, the apps prune and the `memory/` prune,
  `clear_link_chain` and `unlink_tree_symlinks` themselves, the harvest's restore, and the writers in
  `links.rs`, `servers.rs` and `pg.rs`. A parent swapped at the right moment could redirect one of those writes
  or removals. As before, this gains something only in the root-supervisor mode.
- **`/proc/self/fd` chmod.** Used only after `EACCES` on opening a folder. It changes exactly the inode the
  `O_PATH | O_NOFOLLOW` descriptor holds, and only adds the owner's `rwx`. Root never takes this path.
- **"Stopped" is as true as `release` and the lists are.** The late frame has the limits `docs/12` already
  states for Stop (a process that hides from the sweep), and adapters other than claude-code report no
  background work and keep the `still_ending` default.
- **Group signal.** The check and the signal are two system calls. Between them the member would have to end and
  its group number be taken again.
