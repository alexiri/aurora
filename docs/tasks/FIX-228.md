# FIX-228: Jira Data Center helpers every agent can use — named operations, `jira-find-similar`, `md2jira` — and a `jira-dc-search` skill (owner, 2026-11-22)

## Why

On 2026-11-22 the owner's NightManager agent (an SRE agent on CERN's Jira Data Center, `jira-dc` in
package `atlassian` 1.5.0) drafted tickets after a service review and then, at the owner's request,
wrote down every tooling problem it hit, with helper scripts tested against live Jira. The owner
accepted the generic parts for the Jira DC app, so other agents stop rebuilding them (FIX-227 does the
same for Grafana). What applies to every agent that files Jira issues:

1. **Named calls don't work.** `jira-dc` ships no operations file, so every tool is a `catalogue`
   operation, and `aurora-agent call jira-dc search_issues jql=…` is refused ("a catalogue entry …:
   call it with an explicit --path", `services/aurora-supervisor/src/agent_cli/call.rs`). The agent
   guessed a `--query` option, then used `--path /rest/api/2/search jql=…`. Grafana, GitLab and Indico
   all ship operations files; Jira DC should too.
2. **Hand-written duplicate searches miss things.** The agent's exact-phrase search for its capacity
   ticket missed an open ticket ("Delete the old Cephfs share") that a broad `text ~ "cephfs"` finds.
   Every agent that files issues needs the same "search broadly before you create" step, and
   JQL text-search quoting is easy to get wrong.
3. **Descriptions are wiki markup, not Markdown** (API v2). Agents write reports in Markdown and
   convert by hand: fenced code, tables, nested lists and links come out wrong.
4. The `jira-dc-create-issue` skill uses `curl "$J/…"` while the Grafana skills and the agent use
   `aurora-agent call`; once named operations exist the skill should show them.

The agent's material, read-only, is in `/home/alex/orca/workspaces/aurora/tooling-review-2026-11-22/`:
`README.md` (rows 8–11), `md2jira`, `jira-dupes`, `skills_jira-ticketing_SKILL.md.diff`. Use the
scripts as a starting point, not as files to copy: they force a `nightmanager` label, do not escape

Already done elsewhere, not part of this brief: the `/jira` base path (FIX-224: `aurora-agent` adds it

### 1. Operations file for `jira-dc`

| id | method, path | params / body |
|---|---|---|

| `get_issue` | GET `/rest/api/2/issue/{issueIdOrKey}` | `fields`, `expand` |
| `list_issue_comments` | GET `/rest/api/2/issue/{issueIdOrKey}/comment` | `startAt`, `maxResults`, `orderBy`; `items` `$.comments` |
| `get_issue_comment` | GET `/rest/api/2/issue/{issueIdOrKey}/comment/{id}` | — |

| `edit_issue` | PUT `/rest/api/2/issue/{issueIdOrKey}` | JSON body, `--body @file` |
| `add_issue_comment` | POST `/rest/api/2/issue/{issueIdOrKey}/comment` | body field `body` (string, wiki markup) |
| `transition_issue` | POST `/rest/api/2/issue/{issueIdOrKey}/transitions` | JSON body, `--body @file` |

### 2. Script `jira-find-similar`

In the new skill `skills/jira-dc/jira-dc-search/scripts/jira-find-similar` (Python 3, standard
library, executable). "Search broadly before you create":

```
jira-find-similar --project KEY [--label L] [--include-done] [--max N] [--account A] WORD [WORD ...]
```

- Runs up to two searches through `aurora-agent call jira-dc search_issues jql=… fields=summary,status,updated,labels maxResults=N --out <abs file>`
  (`--account` passed through; temp files under `$TMPDIR/aurora-agent/`, mode 0700, removed after):
  - with `--label`: `project = KEY AND labels = "L" AND statusCategory != Done ORDER BY updated DESC`;
  - with words: `project = KEY AND statusCategory != Done AND (text ~ "w1" OR text ~ "w2" …) ORDER BY updated DESC`.
  `--include-done` drops the `statusCategory` clause. At least one of `--label` or a word is required.
- Per search: `## <title>`, `# jql: <the JQL sent>` (so the report can quote it), `# <total> found
  (showing <n>)`, then one tab-separated line per issue: key, status, updated (date), labels,
  summary — all through a `clean()` like Grafana's script (control characters removed).
- **Validation and escaping** (the JQL is built from arguments, so get this right): project key
  `[A-Z][A-Z0-9_]{0,63}`; label 1..255 characters, no whitespace or `"`; `--max` 1..200 (default 50);
  at most 20 words, each 1..100 characters. A word goes into a JQL string with `\` and `"` escaped
  for JQL, and the text-search reserved characters (`+ - & | ! ( ) { } [ ] ^ ~ * ? \ : /` — confirm
  the list in Atlassian's reference) escaped or replaced by spaces as that reference says; a word
  with spaces becomes a phrase search (`text ~ "\"two words\""`). A word that is empty after this is
  skipped with a stderr note. Usage errors exit 2, a failed call exits 1 with the first lines of its
  output, success 0.
- No default label: the label is whatever the agent uses to mark its own issues, if anything.

### 3. Script `md2jira`

In `skills/jira-dc/jira-dc-create-issue/scripts/md2jira` (Python 3, standard library, executable).
Markdown on stdin to Jira wiki markup on stdout:

```
md2jira < draft.md > draft.txt
md2jira --issue-json --project KEY (--type NAME | --type-id ID) --summary TEXT [--label L ...] [--priority NAME] < draft.md > issue.json
md2jira --comment-json < comment.md > comment.json
```

- Converts: ATX headings `#`..`######` → `h1.`..`h6.`; `**bold**` → `*bold*`; `*italic*` and
  `_italic_` → `_italic_`; `` `code` `` → `{{code}}`; fenced blocks → `{code:<lang>}…{code}` for a
  language Jira knows, `{noformat}…{noformat}` for none, `text`, `console`, `sh`/`bash` output; `-`,
  `*`, `+` and `1.` lists nested by indent → `*`, `**`, `#`, `##` (mixed nesting such as `#*`);
  `[text](url)` → `[text|url]`, bare URLs unchanged; tables with a separator row → a `||h||h||`
  header and `|c|c|` rows; `>` quotes → `bq.` (one line) or `{quote}…{quote}` (several); `---` →
  `----`; blank lines kept.
- **Escaping**: plain text that Jira would read as markup is escaped with `\` (`{`, `}`, `[`, `]`,
  `|` outside tables, and the paired markers `*`, `_`, `-`, `+`, `^`, `~`, `??` when they would
  pair up, e.g. `a -b- c` or `file_name_here`), so the rendered text matches the Markdown. Nothing is
  escaped inside `{code}`/`{noformat}`; inside `{{…}}` only what Jira needs. Do not over-escape
  ordinary punctuation (hyphenated-words, `x - y`, `2*3` must stay readable).
- `--issue-json` prints `{"fields": {"project": {"key"}, "issuetype": {"name"} or {"id"}, "summary",
  "description", "labels"?, "priority"?: {"name"}}}`; summary one line, at most 255 characters (longer:
  usage error, not silent truncation); labels as given (each 1..255, no whitespace), none forced.
  `--comment-json` prints `{"body": "<markup>"}`. Project key as in §2.
- Usage errors exit 2.

### 4. Skills

**New `skills/jira-dc/jira-dc-search/SKILL.md`** (`name: jira-dc-search`, description such as "Search
Jira Data Center issues with JQL, and look for existing issues before filing one"):

- The call: `aurora-agent call jira-dc search_issues 'jql=project = ABC AND statusCategory != Done ORDER BY updated DESC' fields=summary,status,updated maxResults=50 --out /tmp/aurora-agent/s.json`.
  Query parameters are bare `name=value` arguments (there is no `--query`); `aurora-agent describe
  jira-dc search_issues` lists them. `total` vs the issues returned; `startAt` for the next page.
- JQL that agents need: `statusCategory != Done` (not a status name list), `labels = x`, `text ~`
  vs `summary ~`, phrase quoting, reserved characters, `ORDER BY updated DESC`, `updated >= -7d`.
- **Before filing**: run `"$SKILLS_DIR/jira-dc-search/scripts/jira-find-similar" --project ABC <broad
  words>` — the component, the host, the product, the error's key word, not an exact path or message:
  broad words find tickets people wrote in their own words. A match that is the same problem → comment
  on it or tell the person instead of filing; a related one → mention it in the new issue
  (`Related: ABC-123`). Quote the printed JQL when reporting the search.

**`jira-dc-create-issue/SKILL.md`**:

- Step 0: search first (→ `jira-dc-search`, `jira-find-similar`).
- Steps 1–2 with named operations instead of `curl`: `list_projects`, `get_project
  projectIdOrKey=ABC` (issue types), then write the description in Markdown and
  `"$SKILLS_DIR/jira-dc-create-issue/scripts/md2jira" --issue-json --project ABC --type-id 10001 --summary "…" < draft.md > issue.json`,
  `aurora-agent call jira-dc create_issue --body @issue.json --out /tmp/aurora-agent/created.json`.
  Keep one sentence that plain `curl` to `<address>/rest/api/2/…` also works.
- Keep the existing rules (wiki markup not Markdown, optional fields, a `400` names the field,
  confirm with the person, create **once**, after an error or timeout search before retrying — now
  with `jira-find-similar` or a `search_issues` on the summary) and the approval note.
- Comments: `md2jira --comment-json < c.md > c.json` then `add_issue_comment issueIdOrKey=ABC-1 --body @c.json`.
