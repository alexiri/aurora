# FIX-059: The terminal PTY master leaks into every child process, and terminal output beyond the credit is silently dropped (code review 2026-11-13) — **high, security**

## Problem
Code review of `09e955c9..bc7857ad` (P4-TERM, FIX-054), verified by the coordinator:

1. **PTY master fd is inheritable** — `services/aurora-supervisor/src/pty.rs` `PtySession::spawn` opens the master with `rustix::pty::openpt(OpenptFlags::RDWR | OpenptFlags::NOCTTY)` — **no `CLOEXEC`** — and then spawns the bootstrap/shell. std's `Command` does not close inherited descriptors, so:
   - every terminal's shell holds a copy of **its own** master → closing the browser leg never delivers SIGHUP/EOF to the session (the master is never fully closed), shells and their jobs outlive the session;
   - every **later** child the supervisor spawns — the next terminal's shell **and the agent's harness/tool processes** — inherits every open master. An agent process can `read()` the user's keystrokes (passwords typed into `sudo`, `ssh`, `git` prompts) and `write()` commands into the user's terminal. This breaks SEC-87 (the terminal is the user's, the agent never sees its I/O) and `16 §W19` session cleanup.
   - (Likely related) the `pty_env_probe` test flakes that commits ea0f1bc0..6c911809 papered over with an 8-step retry/backoff (`tests/it/pty_env_probe.rs` `open()`), since leaked masters accumulate across sessions in one process.
2. **Over-credit output is discarded** — the shell→runner pump (`pty.rs`, the `read = pty.master.readable(), if credit > 0` arm, ~line 615) reads a full `TERMINAL_CHUNK`, sends `n.min(credit)` bytes and **drops the rest** (the comment claims it "cannot occur"; it can whenever `0 < credit < n`). Terminal output is corrupted under any backpressure (e.g. `cat` of a large file on a slow link). The preview path (`streams.rs`, ~line 505) keeps a pending buffer instead.
3. **Test-only helper in the production library** — `pub fn debug_spawn_session` (`pty.rs` ~557) ships in the release lib and drops a live session without reaping it.

## Linked requirements
- SEC-87 (`docs/17-security.md`), D-161, C-616..C-625, `docs/16-wire-protocols.md §W19`, `docs/12-supervisor-harness.md §Terminal`.

## Scope
### In scope
1. Open the master with `OpenptFlags::CLOEXEC` added. The slave is opened with `std::fs::OpenOptions` (CLOEXEC by default) and handed to the child as stdio (dup'd without CLOEXEC, which is correct). Audit **every other fd the supervisor creates with rustix/nix/raw syscalls** (grep `rustix::`, `openpt`, `pipe`, `socket`, `eventfd`, `memfd` in `services/aurora-supervisor/src/**`) and make each CLOEXEC unless it is deliberately inherited (document any exception in a comment).
2. Read at most the remaining credit: size the `read()` to `min(TERMINAL_CHUNK, credit)` so nothing is read that cannot be sent (simplest; the kernel buffer then provides backpressure and the shell blocks on write — the intended behaviour). Remove the misleading comment and the over-credit `bytes_out` accounting.
3. Gate `debug_spawn_session` behind `#[cfg(any(test, feature = "test-support"))]` (add the feature to the crate if absent and enable it from the dev-dependency in the test's own crate), or move the probe into the test tree; it must not exist in the release binary. Make it reap the child.
4. Re-evaluate the `pty_env_probe` retry loop with the fix in: if the refusals disappear (run the test 20× under load, e.g. alongside `cargo build -p aurora-api`), cut the retry back to at most 2 attempts with a short backoff and say so; if they persist, keep it and report the errno the probes name.

### Out of scope
- Runner-side credit accounting (FIX-060) and API caps (FIX-061).
