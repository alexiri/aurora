# FIX-023: Two timing-sensitive gateway tests

## Problem
- `aurora-gateway` `held_closure::held_request_in_a_tunnel_is_refused_before_the_tunnel_closes` (`services/aurora-gateway/tests/it/hold.rs:507`) failed once on GitHub CI (run 42717292879, nextest shard 2/4, 2026-11-09) and passed on the next run of an unchanged tree.
- `outage::metrics_and_the_state_change_log_line` fails at default test threads under host load (P3-022 report: 3 of 3 under load, passes alone and at 4 threads; captured log empty).

## Goal
Make both deterministic **without weakening what they prove** (SEC-54 for the outage test; the held-request refusal ordering for the hold test). Typical causes: fixed sleeps instead of waiting on a condition, a log capture installed per thread while the code logs from another task, a global metrics recorder shared across tests, wall-clock deadlines too tight under load.

## Scope
1. Reproduce each under load (e.g. `cargo test -p aurora-gateway --test it` with full parallelism while another build runs, and in a loop) and find the cause. Record what you found.
2. Fix the test (condition waits with a generous upper bound, a scoped subscriber/recorder, an injected clock), or the code if the test exposes a real race; say which.
3. Run each fixed test 50 times in a loop at default threads under load, plus the full `aurora-gateway` suite.

## Acceptance
- Both tests pass 50/50 in a loop under load; full `cargo test -p aurora-gateway` green; fmt, clippy `-D warnings`, guards.
- Report: the cause of each flake, the change, and the loop results.

## Constraints
- Never weaken an assertion or widen a timeout so far that the test stops proving its property; if the test is right and the code races, fix the code and say so.
- Owns `services/aurora-gateway/tests/**` (and the gateway source only for a real race). Don't run `scripts/e2e/*` or `scripts/perf/*`.
- Change files only with the Edit/Write tools; never python, sed, awk, perl, `cat >>` or heredocs.
