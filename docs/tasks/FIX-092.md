# FIX-092: Runner stream listener and terminal API bounds — outbound queue, pre-auth connections, idle rule, text frames, the `wait` parameter (REVIEW-5 STRM-5/6/7/8/12, EVID-9, CONV-5) — **high**

Checked against master `c3ec906d`.

## Problem
1. **The runner's per-sandbox outbound queue is unbounded.** `services/aurora-runner/src/channel/mod.rs` ~216 creates `mpsc::unbounded_channel()` per supervisor connection; `push_stream_frame`/`push_stream_data` (~180–201) never check length; the writer (`channel/conn.rs` ~253–263) drains at the supervisor's read speed. A supervisor that stops reading (it lives beside untrusted code) lets producers fill runner memory: every browser `pty.resize` text message becomes a queued frame with no rate limit or coalescing (terminal leg in `stream_listener.rs`), and each live leg can queue a 128 KiB window with no per-sandbox leg cap in the runner. The runner serves every sandbox on its node; its OOM drops all of them.
2. **Unbounded pre-auth connections on the stream listener.** `stream_listener.rs` `serve` spawns a task per connection with no cap (~591–606), and the request head is read with a per-read timeout, not a total deadline (~633–645): one byte every nine seconds holds a socket indefinitely.
3. **Idle rule contradicts the spec.** `docs/16` §W18/§W19: idle "600 s for an upgraded one (a WebSocket's pings count)". The legs ignore `Ping`/`Pong` for idle (`stream_listener.rs`, both legs; the constant's own comment says "(no bytes, no pong)"), and the API drops browser pongs (`services/aurora-api/src/domains/terminal/service.rs` ~522). A user reading terminal output for ten minutes is disconnected with 4504.
4. **Terminal proxy.** Browser `Text` frames are forwarded unbounded (`terminal/service.rs` ~509–517; binary is capped); `b_sink.send` has no timeout (~541, ~580), so a tab that stops reading holds a `TerminalSlot` indefinitely.
5. **`?wait` is parsed and ignored.** `terminal/service.rs` ~175 (`let _ = wait;`); C-616 promises "the server long-polls ≤ `TERMINAL_WAKE_WAIT` 45 s before upgrading". The dashboard compensates by reconnecting every 8 s.
6. **`not_here` is a bare 404.** C-617 names 404 `not_here`; the runner writes a status line with no body (`stream_listener.rs` ~745–751, ~883).
7. **Boot capability `terminal` ignores the runner.** `services/aurora-api/src/domains/runner_plane/boot.rs` `capabilities_for` (~235–240) adds `terminal` from instance config alone; `register` (`service.rs` ~66) gates on the runner's advertisement (C-623).

## Linked requirements
- `docs/16` §W18, §W19; C-616..C-623; `docs/17` SEC-82, SEC-85, SEC-87; `docs/02` §Limits.

## Spec change (apply with the fix)
- `docs/16` §W18/§W19 and `docs/02` §Limits: a total pre-auth deadline (10 s) and a cap on unauthenticated connections per runner replica (256); a per-sandbox live-leg cap in the runner (the supervisor's 64 streams + 2 PTYs); "`pty.resize` is coalesced to the latest size". The idle sentence stays: pongs count — keep-awake stamps stay byte-driven so an idle open tab does not hold a sandbox awake (say so).
- C-617: "404 with the standard error body `not_here`".

## Scope
### In scope
- Bounded per-connection outbound queue; on `Full` close the offending leg (or the connection when control frames cannot be queued); resize coalescing; per-sandbox leg cap.
- Pre-auth semaphore and total head deadline.
- Idle reset on `Pong` in both legs; the API forwards browser pongs (or answers pings itself and reports liveness); keep-awake unchanged.
- Text frames above 256 bytes → close 4502 without forwarding; browser writes under a timeout that ends the leg and frees the slot.
- `?wait=true`: wait for `running` up to `TERMINAL_WAKE_WAIT`, then upgrade; otherwise today's 202.
- `not_here` body; `terminal` capability only when the runner advertised it.

### Out of scope
- Supervisor pumps (FIX-091); dashboard reconnect logic (FIX-098).
