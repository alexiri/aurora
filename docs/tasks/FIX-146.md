# FIX-146: Request tracing end to end — one request id in every log, one trace per chat message — **medium–large, phase 5**

## Goal
The owner (2026-11-14) wants to follow a request across services, the way Sentry shows a
request's path: browser → API → turn → runner → every LLM and tool call through the gateway →
hooks → completion. Today:
- `docs/15 §Observability` already requires `traceparent` to be propagated between API, internal
  gateway, hook host, runner and connector calls, and `02 §Coding rules` requires `request_id` on
  log lines. Neither is done. Only the API public router, the gateway internal router and the hook
  host adopt incoming `traceparent` (`service::trace_context`). Only four outgoing calls inject it
  (`connect/hooks.rs`, `skill_libraries/gateway.rs`, gateway `summarize_client.rs`, `mint.rs`). No
  log line carries a `request_id`.
- Nothing is propagated unless `telemetry.otlp_endpoint` is set, so logs from different services
  cannot be linked to each other without a tracing backend.
- A turn crosses a database queue (API inserts the turn, the runner and the sandbox pick it up), so
  even with propagation each turn's work starts a new trace.
- The request span records only the method. There is no per-request access log line in any Rust
  service.
- The API public router adopts `traceparent` from anyone, browsers included.
- With the chart's default-deny NetworkPolicies, an `otlp_endpoint` set in Kubernetes is silently
  blocked: no egress rule exists for the collector.

**D-232** (decided 2026-11-14) defines the design. **C-732** has the wire detail.

## Design (D-232, summary)
1. **Request id = W3C trace id, always.** Every service installs the W3C propagator and a tracer
   provider at startup. An exporter is added only when `telemetry.otlp_endpoint` is set. Every JSON
   log line emitted inside a span carries `request_id` (32 lowercase hex chars). The sampler is
   `ParentBased(TraceIdRatioBased(telemetry.sample_ratio))`. An unsampled request still has its
   trace id and still propagates it.
2. **Server span + access log** per request on every router except `/healthz`, `/readyz` and
   `/metrics`. Span name `"{METHOD} {route}"`. Attributes: `http.request.method`, `http.route`
   (axum `MatchedPath` template, never the raw path), `http.response.status_code`, and
   `aurora.error_code` (envelope `code`) on ≥ 400. Status is error on 5xx and on panics. One `info`
   log line per request: `message="request"`, `method`, `route`, `status`, `duration_ms`,
   `request_id`. Unmatched routes use `route="unmatched"`.
3. **Trust (SEC-88).** An incoming `traceparent`/`tracestate` is adopted only:
   - on internal listeners (API internal, gateway 4103, hook host, runner ops, relay ops, connector
     host internal), and
   - on the public API routes for machine callers that authenticate with a service token (runner
     plane `/v1/runner/…`, the connector-host and relay routes). This list is a constant in code,
     and a test pins it.

   Everywhere else the headers are ignored and a new trace starts. That covers browsers, SCIM,
   OAuth callbacks, chat-platform webhooks, connector callback ingress and the gateway proxy
   listener (4102, sandbox traffic). Aurora sends `traceparent` only to its own services, never to
   upstream apps, LLM providers, IdPs or chat platforms. The gateway forwards a sandbox's own
   headers unchanged and never adopts them.
4. **Outgoing calls**: one helper, e.g. `aurora_core::telemetry::internal(RequestBuilder,
   peer: &'static str)`. It injects the context and records a client span (`peer`, method, status,
   duration). Every call to another Aurora service uses it. The four ad-hoc
   `.headers(telemetry::headers())` sites switch to it.
5. **Turns cross the queue.** Migration `20261201000150_turn_trace_context.sql`:
   `turns.trace_context text NULL`, with a CHECK on the traceparent format
   `^00-[0-9a-f]{32}-[0-9a-f]{16}-[0-9a-f]{2}$`. `repo/turns.rs` insert writes the current span's
   context (NULL when none is valid). Work on a turn in another process is recorded as children of
   that context, **read from the database or from a trusted Aurora peer, never from the sandbox**:
   - runner work items for a turn carry `trace_context` (C-732 (3)), and the runner's
     dispatch/sandbox-start spans are their children;
   - supervisor reports and channel events the API handles for the turn;
   - every gateway request whose identity carries the turn (the resolver row that already returns
     `turn_id` also returns `trace_context`), approval holds and their resumption, and hook calls
     made for those requests.

   Background jobs that act on many turns start their own root. Child turns (`parent_turn_id`,
   peer tasks) are children of the parent turn's context.
6. **Gateway span** per proxied request, named `"gateway {host}"`. Attributes: `server.address`,
   `http.request.method`, `aurora.app_id`, `aurora.tool`, `aurora.decision`, `aurora.rule_id`,
   `http.response.status_code`, `aurora.connection_id`. For LLM calls also `gen_ai.request.model`
   and `gen_ai.usage.input_tokens`/`output_tokens`, but **only if the gateway already parses
   them**. Do not add body parsing for this.
7. **Attribute allowlist (SEC-88).** Allowed: ids (org, workspace, agent, conversation, turn,
   connection, app, tool, rule), route templates, methods, statuses, hosts, model names, decisions,
   error codes, durations, counts. Never: raw paths, queries, headers, bodies, message text,
   prompts, tool arguments or results, secrets, tokens, emails, display names. Events from
   `sqlx`/`reqwest` that would carry such values must not become span attributes or events at the
   default level.
8. **`x-request-id`** on every public API response, errors and 404s included (C-732 (1)).
9. **Sandboxes and the supervisor export nothing** and get no collector egress.

### Part A — Rust core (`aurora-core`, `aurora-config`, every service's `main.rs`)
- `telemetry.rs`/`service.rs`:
  - provider and propagator always installed, exporter optional, sampler from config;
  - `request_id` added by the JSON formatter (`WithIdentity`) from the current span's OTel
    context;
  - the request middleware replaces `trace_context` and takes a trust argument (`Adopt`,
    `Ignore`, `AdoptOn(&[prefix])`);
  - access log and `x-request-id`;
  - the outgoing helper.

  `tower-http` already has the `trace` and `request-id` features. Use them if they fit; a hand
  layer is fine.
- `aurora-config`: `telemetry.sample_ratio` (raw, validate 0.0..=1.0, default 1.0).
- Apply the middleware to every router in every service and connector with the right trust (Design
  3). Switch every internal Aurora-to-Aurora HTTP call to the helper. Find them all, e.g.
  `rg "reqwest::Client|\.post\(|\.get\(" services connectors`. Classify each call as internal (use
  the helper) or third party (no injection), and list the classification in the completion report.
- Keep the gateway hot path cheap. Spans for proxied requests belong to Part B; Part A only must
  not slow down the proxy listener.

### Part B — Rust: turns and gateway (after A)
- Migration (block `20261201000150..159`) and the `repo/turns.rs` insert.
- Runner protocol `WorkItem.trace_context` (`crates/aurora-protocol/src/runner.rs`) and the
  runner spans.
- API spans for supervisor reports and channel events for a turn
  (`domains/runner_plane/**`, `conversations/service.rs start_turn`).
- Gateway:
  - resolver identity row + `trace_context`;
  - span per proxied request (Design 6);
  - hold/approval spans;
  - hook calls as children.
- Peer/child turns inherit.

### Part C — deploy and dev (after A; parallel with B)
- Helm:
  - `networkPolicy.telemetryTo` (raw NetworkPolicy `to` entries, default `[]`), rendered into the
    egress of every exporting workload (api, gateway, hookhost, runner, relay, connector host,
    connector Deployments);
  - a `NOTES.txt` warning when `config.telemetry.otlp_endpoint` is set and `telemetryTo` is empty;
  - template tests in the style of the existing chart checks.
- kind dev: `deploy/dev/kind-dev.sh up --tracing`:
  - installs Jaeger all-in-one (image pinned by digest, in-memory storage, dev only) from
    `deploy/dev/jaeger/jaeger.yaml`;
  - adds `-f deploy/kind/values-tracing.yaml`, which sets the endpoint to Jaeger's OTLP/HTTP
    port 4318 and `telemetryTo`;
  - prints `kubectl -n aurora port-forward svc/jaeger 16686` for the UI.

  Update the `justfile` comment and `docs/operator` with how to point at Jaeger, Grafana Tempo or
  an OpenTelemetry Collector.

### Part D — Next.js (after A; small)
- `web/src/lib/api/errors.ts` (or wherever API errors are built) keeps `x-request-id`.
- Error toasts and error states show "Reference: <first 8 chars>…" with a copy-full-id button,
  using the existing primitives.
- No browser tracing: CSP `connect-src 'self'`, and the browser is untrusted.

## Acceptance criteria
- [ ] **No collector configured:**
  - `POST` a chat message on kind;
  - `kubectl logs -n aurora -l app.kubernetes.io/name=aurora --all-containers | grep <x-request-id>`
    shows lines from api, runner, gateway (each LLM/tool call of that turn) and hookhost (if a
    hook ran).

  Covered by an integration test where possible (api → hookhost propagation with captured logs,
  turn context → gateway identity) and by an owner check on kind.
- [ ] **With an in-memory exporter (test):**
  - a message POST yields one trace;
  - its server span is the ancestor of the turn's runner, gateway and hook spans;
  - a child turn is in the same trace.
- [ ] **Allowlist test:** a canary secret, a message text and a query value sent through a full
  turn appear in no span attribute, no span event and no access log line.
- [ ] **Trust tests:**
  - a browser route with a client `traceparent` gets a new trace (`x-request-id` ≠ sent id);
  - a pinned machine route adopts it;
  - the gateway proxy listener never adopts;
  - upstream requests leaving the gateway carry no Aurora-injected `traceparent`;
  - the adopt-route constant is pinned by a test.
- [ ] `x-request-id` on public 2xx, 4xx, 5xx and 404 responses. No access line and no span for
      `/healthz`, `/readyz`, `/metrics`.
- [ ] `telemetry.sample_ratio`: out-of-range values refused at startup. At `0.0` no span is
      exported, but logs still carry `request_id`.
- [ ] `turns.trace_context`: format CHECK enforced. A value sent by a sandbox or supervisor never
      reaches it.
- [ ] **Helm:**
  - `telemetryTo` renders into each exporting workload's egress;
  - NOTES warns when it is missing;
  - `kind-dev.sh up --tracing` shows the message trace in Jaeger (owner check, screenshot in the
    completion report).
- [ ] **Web:** the reference is shown and copyable on error states (unit test). Both themes, no
      horizontal scroll at 390 px.
- [ ] **Gates:**
  - `cargo fmt --check`;
  - workspace clippy;
  - targeted tests (aurora-core, aurora-config, api, gateway, runner, hookhost, aurora-db);
  - web typecheck/lint/unit/build;
  - `scripts/guards`;
  - gateway perf budget with tracing on at ratio 1.0, measured when idle.
