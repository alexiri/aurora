# FIX-046: The sidebar's Workspace selector is indented under the Organization one — align the two selectors: same left edge, same width (owner, 2026-11-11)

## Problem

The owner, on FIX-027's two stacked sidebar selectors: "the Workspaces drop-down
doesn't need to be invented under the organization one, the hierarchy is clear enough
as is" — then, on seeing this brief's first draft (which had read that as "remove the
workspace selector"): **"Do NOT delete the workspace selector!! Simply don't indent it
visually in the menu, have it span the same width as the organization selector."**

So the complaint is the *visual nesting*, not the control. FIX-027
(`docs/14-web-dashboard.md:160-172`, merged b028a9b4) renders the Workspace selector
"below it and indented": `ScopeShellSelector`'s `indent` prop puts `pl-8` on the whole
wrapper — caption *and* trigger — so in the sidebar (and the narrow-screen drawer) the
WORKSPACE caption starts ~32 px right of ORGANIZATION and the control is narrower than
the Organization control (owner's screenshot). The nesting is already conveyed by
order and by the captions themselves; the indent invents a hierarchy cue the owner
does not want, and buys a misaligned, harder-to-hit control.

## Goal

Both stacked selectors align: the Workspace caption and control at the same left edge
and the same width as the Organization ones. Nothing else changes — the Workspace
selector keeps its behaviour exactly as FIX-027 built it (pinned "All workspaces…"
entry, rendered only where an organization is active, absent on `/admin/*` and
`/account/*`, menu unchanged).

## Decision (D-163, owner 2026-11-11)

Keep FIX-027's stacked pair; express the organization→workspace nesting by **order and
caption, not indentation**. Drop the indent so the two selectors span the same width.
