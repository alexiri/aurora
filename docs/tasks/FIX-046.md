# FIX-046: Remove the sidebar Workspace drop-down — the org selector plus breadcrumbs carry the hierarchy (owner, 2026-11-11)

## Problem

The owner, on FIX-027's two stacked sidebar selectors: "the Workspaces drop-down
doesn't need to be invented under the organization one, the hierarchy is clear enough
as is."

FIX-027 (`docs/14-web-dashboard.md:160-172`, merged b028a9b4) added two stacked
context selectors to the sidebar: the **Organization** select (with the instance
admins' "All organizations" entry) and, indented below it, a **Workspace** select
("All workspaces…" pinned entry, rendered only where an organization is active).
The workspace drop-down duplicates navigation the shell already provides several ways:

- the **page-header breadcrumb** (`docs/14` §Page header) links org → workspace →
  section on every page;
- the **workspace nav** in the sidebar lists the sections of the workspace the user is
  already in;
- workspace-per-org lists exist as the org root page (`/o/<org>`).

It also costs a second `GET /v1/orgs/{org}/workspaces` fetch per org switch, an
indent-wrapped control in a narrow sidebar, and an "All workspaces…" pseudo-entry that
reads as navigation but is just a link back to the org root.

## Goal

The sidebar keeps **one** context selector — the Organization select, unchanged,
including "All organizations" (instance admins) and the `/account` "Select
organization" placeholder. The Workspace drop-down is removed. Where an organization
is active, the sidebar shows that organization's nav directly; getting from one
workspace to another goes through the org root or the breadcrumb, as it did before
FIX-027.
