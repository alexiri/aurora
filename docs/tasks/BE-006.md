# BE-006: `aurora-protocol` skeleton with JSON Schema generation

## Goal
Home for every wire contract (`16`), with deterministic JSON Schema generation and a drift check, so later milestones only add types.

## Linked requirements
- M0/16 ("`aurora-protocol` skeleton with schema generation"); `02 §Coding rules` (wire types derive Serialize/Deserialize/JsonSchema; `deny_unknown_fields` only for closed vocabularies; open vocabularies as `Known + Other(String)` with bounded length); `16 §Cross-cutting conventions`; `18 §Contract` (JSON Schemas vs checked-in schemas).

## Context
- `16 §Cross-cutting conventions`: machine planes send `X-Aurora-Protocol: <plane>/<n>` (`runner/1`, `supervisor/1`, `connector/1`, `hookhost/1`); API accepts N and N−1; unknown future → 426 with supported range. Open vocabularies: unknown values logged and skipped, never fatal.
- Workspace deps: `serde`, `serde_json`, `schemars` (1.x), `uuid`, `chrono`, `aurora-core`. Do not edit root `Cargo.toml`.

## Scope
### In scope (`crates/aurora-protocol/**`, `schemas/` at repo root)
- Modules (empty placeholders with module docs pointing to the owning doc): `runner` (W5), `supervisor` (W6), `tools` (W7), `connector` (W8), `hookhost` (W9), `gateway_internal` (W4).
- `version`: `Plane` enum (`runner`, `supervisor`, `connector`, `hookhost`), `ProtocolVersion { plane, n }` parse/format of the header value, `CURRENT` per plane = 1, `accepts(n)` (N and N−1), `HEADER = "x-aurora-protocol"`.
- `vocab`: a reusable pattern/macro `open_vocab!` generating `enum X { Known variants…, Other(BoundedString<64>) }` with serde (unknown string → `Other`, over-long → error) and `JsonSchema` (string). Include `BoundedString<const N: usize>`.
- `schema::all() -> Vec<(&'static str, schemars::Schema)>` registry and a binary or test that writes `schemas/<name>.json` (pretty, sorted keys, trailing newline); a test fails if checked-in files differ (`UPDATE_SCHEMAS=1` env regenerates). Register `ProtocolVersion` and one example vocab so the pipeline is exercised.

### Out of scope
- Any concrete W5–W9 message types (later milestones).

## Acceptance criteria
- [ ] Tests: header parse/format round trip, N−1 acceptance, unknown future version rejected; open vocab: known, unknown→Other, over-long rejected; schema drift test passes with checked-in `schemas/`.
- [ ] `cargo test -p aurora-protocol`, clippy `-D warnings`, fmt check pass.
