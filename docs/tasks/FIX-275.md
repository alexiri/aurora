# FIX-275: the template review shows an executable-bit change; Microsoft 365 event cards preview the invitation (2026-11-27)

## Why

Two small leftovers, one from each brief's Completion report:

1. **FIX-271** (`docs/tasks/FIX-271.md`, "Not changed"):
   - A change of **only** a file's executable bit is not a change in `web/src/lib/template-diff.ts`.
   - A skill or helper file whose content is the same but whose mode changed sits in the "Unchanged" fold.
   - The person approves a version without seeing that a file became runnable, which is a meaningful change for a
     helper or a skill script.
2. **FIX-273** (`docs/tasks/FIX-273.md`, "Not changed"):
   - The two Microsoft 365 event approval cards (create and update an event) show subject, start and attendees,
     but no preview of the invitation's body.
   - `docs/09` §approvals asks for one on a request that sends content to people outside.
   - The mail cards already have one.

## Change

1. `template-diff.ts`: a file whose executable bit changed is a change. The review shows it in its section with a
   line in words, "now runnable" or "no longer runnable", next to any content diff. It counts toward the
   section's changed state, so it is never folded as unchanged. Check the server's diff DTO carries the mode for
   both sides. If it doesn't, add it there (`agent_templates` diff) and regenerate OpenAPI and `gen:api`.
2. The Microsoft 365 app (`apps/` or `plugins/` package with the event tools' approval cards): add a `Message`
   field from `/body/content` to both event cards, shown the way the mail cards show theirs. Bump the package's
   version as the other app changes did, and update the package's tests and any card fixture.

## Tests (each must fail before the fix)

- vitest: a version where only `helpers/run.sh`'s executable bit changed shows that file outside the unchanged fold,
  with "now runnable".
- The app's card test (or the gateway/plugin test that renders the card fields): the event create and update
  cards carry the body preview.

## Tests move with the UI

Grep `web/tests` and `web/e2e` (mocked and production) for the review page's section texts and the unchanged fold,
and update every test that sees them in the same commit. Tokens and shared primitives only, both themes, 390 px.

## Placement

One Sonnet lane, size S, web plus the Microsoft 365 package (plus `agent_templates` if the DTO needs the mode).
Independent of the other open briefs. Normal code review by the Orchestrator. Tests only through
`scripts/dev/test.sh`.

### What changed

- `web/src/lib/template-diff.ts`: a skill file or helper that both versions have, with a different executable bit, is
  a change. It carries "This file is now runnable." or "This file is no longer runnable." in `detail`: alone when the
  content is the same, with the content diff when it changed too, and after the "not text" words when there is no line
  comparison. So its skill and the Helper files section are never folded as unchanged.
- `web/src/components/templates/review-version.tsx`: a compared file with a diff shows that sentence above the diff.
  A change of the bit alone already used the words-only layout (the file in full, then the sentence). No new styling.

  product code, route or generated file changed.
- `plugins/builtin/microsoft-365/plugin.yaml`: a `Message` field (`/body/content`) on both event cards, the same
  extraction as the `send_mail` card. Version 1.8.0 to **1.9.0**.

  blocked since FIX-273). Its two event cards are `create_event` and `create_calendar_event`; both got the field.
