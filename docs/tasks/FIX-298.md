# FIX-298: Ruby in the sandbox image, gems installed into the home (2026-11-28; owner)

## Why

An agent working on Puppet code wanted to run `puppet-lint` and couldn't. `puppet-lint` is a Ruby gem, and
the sandbox image has no Ruby, so the agent has no way to install it. It can't use dnf either: the agent runs
as uid 1000 with every capability dropped, on a read-only root filesystem, and the image removes `dnf`, `rpm`,
`sudo` and `su` (`11 §Sandbox image`: "No root, no sudo, no package manager usable by the agent").

Python and Node.js already work this way. They are in the image, and the agent installs packages into its home
(`pip --user`, `uv tool`, `npm` with prefix `~/.local`), which persists across boots. Ruby joins them (D-516):
the language and its build headers are in the image, and `gem install` and `bundle install` write into the
home without root. (`yamllint`, the other tool that agent wanted, already installs today with
`uv tool install yamllint`.)

## Change

1. **Packages (`images/sandbox/Containerfile`, the `base` stage's `dnf install`):** add `ruby`, `ruby-devel`,
   `rubygems`, `rubygem-bundler` and `redhat-rpm-config`.
   - `ruby-devel` and `redhat-rpm-config` are there so gems with C extensions build. On EL, Ruby's `rbconfig`
     names compiler spec files from `/usr/lib/rpm/redhat/`, and without that package every native build fails.
     `gcc` and `make` are already in the image.
   - Check that removing `/usr/bin/rpm*` later in the stage doesn't break native builds. It shouldn't: the spec
     files aren't binaries, and the test below proves it.
   - Add whatever else AlmaLinux 10 splits out that a plain `gem install` needs: `psych` (YAML), `json`,
     `openssl` and `bigdecimal` must load. List what you added in the report.
   - The build fails if Ruby is broken. Following FIX-190's pattern, the `RUN` runs
     `ruby -ropenssl -rpsych -rjson -e 'exit 0' && gem --version && bundle --version`.
2. **Gems go into the home.** Set `GEM_HOME=/workspace/.local/share/gem`.
   - Add `/workspace/.local/share/gem/bin` to the one `PATH`, right after `/workspace/.local/bin`.
   - FIX-138 keeps the `PATH` identical in five places. Change all of them together: the image's `ENV PATH`,
     `images/sandbox/etc/profile.d/aurora.sh`, `images/sandbox/etc/zshenv`, the supervisor's
     `spawn::IMAGE_PATH` (`services/aurora-supervisor/src/spawn.rs`), and each comment that says "keep
     identical".
   - Set `GEM_HOME` as image `ENV`. Confirm that it reaches every process the agent runs: a turn's commands,
     `process_start`, the web terminal, SSH `shell` and exec, and background processes. The terminal drops only
     `AURORA_*`, so it should get `GEM_HOME`. If any spawn path builds its environment from scratch, add
     `GEM_HOME` there next to `PATH`. List each spawn path you checked.
   - Leave `GEM_PATH` unset. With `GEM_HOME` set, RubyGems still finds the system's default gems (bundler,
     json), and the test checks this.
   - `bundle install` without a configured path installs into `GEM_HOME`. It must never try to write `/usr` or
     ask for a password (older Bundler offered `sudo`).
3. **Network:** gems come from `rubygems.org` through the loopback proxy. RubyGems reads `https_proxy` and
   `HTTPS_PROXY`, and Ruby's OpenSSL reads `SSL_CERT_FILE` (`/run/aurora/ca.pem`, the gateway CA). No new
   variables should be needed.
   - Confirm which hosts a `gem install` and a `bundle install` actually contact. Expect `rubygems.org` and
     `index.rubygems.org`.
   - Add those hosts to the example `baseline_allowlist` in `15 §Governance example`, next to
     `pypi.org`/`registry.npmjs.org`.
   - Don't change any default. An instance with `credentialed_only` egress still has to allow them.
4. **Docs:**
   - `11 §Sandbox image`: add Ruby to the base layer list. Add `gem install`/`bundle install` (into
     `~/.local/share/gem`, executables on `PATH`) to the durable user-space installs line.
   - `12 §Terminal` (the `PATH` paragraph): the new `PATH`.
   - `15`: the allowlist example.
   - `90-decisions` D-516 is already written; amend it only if a fact in it turns out wrong.

## Completion report

**A defect found and fixed in the same `RUN`:** it ended in `rm -f … 2>/dev/null; true`, so the whole `&&`

build, and neither could a failed `dnf`, `pip3` or `npm config`. The trailing `; true` and the redirect are
gone. The full image built with all the checks enforced.

base package list (30 new packages, 1 upgraded; measured with dnf in a throwaway base container). The new

"before, compressed" is an estimate: about 1,410 MB. No image-size guard or budget exists for this image.
