# FIX-178: `markdown_safe` is not idempotent for a defanged mention token that a later step escapes

## Goal
Security-relevant (D-271 mention safety; FIX-142's sanitizer). The property test
`aurora-core` `sanitize::safe::tests::any_input_is_safe_idempotent_and_never_panics` failed in CI run
44379069837 (shard rust-test 4; found by the CI Watcher, 2026-11-19). Minimal input:

```
<!-- c --> [ <@here> ![j](data:x)
```

- `markdown_safe` once: `  \<\u{200B}@here\> \!\[j`
- `markdown_safe` again: `  \<@here\> \!\[j` — **not idempotent** (`tests.rs:865`).

Cause: `defang_tokens` (`sanitize/safe.rs` ~1053, "Exception 4") inserts the zero-width space only when
`<` is followed by a typed token such as `@here>`. Pass 1 sees the raw `<@here>`, defangs it, and a later
step escapes `>` to `\>`. On pass 2 the input cleaning strips the ZWSP (by design, see the comment above
`defang_tokens`), but defang now sees `@here\>`, which does not match, so the ZWSP is not re-added. Pass
2's output is probably still inert as markdown (`\<` is text), but a `<@here` without the zero-width break
then reaches connectors after any re-sanitize — exactly what Exception 4 exists to prevent.

Reproduce with the proptest seed
`cc 05890c51e076b9a1c9f218644ffaa4408790b4f782093cce10a860e6be9d6c98` (put it in
`crates/aurora-core/proptest-regressions/sanitize/safe/tests.txt` and commit it **with** the fix, so the
case stays in the suite).

## Change
Make the output a fixed point for every typed neutral token (`@here`, `@channel`, `@all`, user/channel
tokens — every token `defang_tokens` handles), escaped or not. Two candidate fixes; choose with the
security reasoning written in the Completion report:
1. `defang_tokens` also matches the escaped form (`<` followed by the token and `\>`), or
2. order the steps so the escaping of `>` cannot hide a token from defang on a later pass (e.g. defang
   after the escaping, or defang keyed on the token without its closing `>`).
Either one changes what `has_token` sees: check every caller of `has_token` and of the defang (connectors'
mention handling, the pipeline) and keep their decisions unchanged for already-safe input. Never weaken a
check to make the property pass.

## Tests
- The seed above as a committed regression case, seen failing first.
- A unit test per typed token, raw and escaped, that `markdown_safe(markdown_safe(x)) ==
  markdown_safe(x)` and that no output contains `<` immediately followed by the token without the break.
- Gate: the full `aurora-core` sanitize unit and proptest suites (run the proptest with a raised case
  count once, e.g. `PROPTEST_CASES=20000`), the pipeline property tests, the Mattermost connector tests
  and conformance s11/s18 (`--mattermost` if it can run here, else the fake connector conformance; say
  which), workspace clippy, guards.
