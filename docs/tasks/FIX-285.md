# FIX-285: small backend leftovers of FIX-244, FIX-262 and FIX-267 (2026-11-28)

## Why

These are items the 2026-11-28 review found written in the briefs' reports, but owned by no later brief.

1. **FIX-244, "Open (not changed here)":**
   - the lifecycle and default-store notices are sent inside the request. With slow SMTP and many owners, the delete,
     freeze or settings request waits, and a dropped request loses the notices it hadn't sent yet;
   - a change of the default store made by the deployment (Helm mirroring at startup) sends no notice at all.
2. **FIX-262:** the "kind was listed" emergency-read audit row for lists (skills, agents) is deduplicated per kind,
   not per agent. Two agents' lists read within one hour leave only one row.
3. **FIX-267:** a source PATCH reads `ref` and `path` before taking the row lock. Two concurrent address PATCHes can
   overwrite each other's address.

## Change

1. Send the notices after the commit, off the request path, the way emergency access already sends its notices
   (spawned, logged on failure). A dropped request must not lose them: either persist them with the change and let the
   existing sender deliver them, or spawn after commit. Say which, and why. The deployment-side default-store change
   sends the same notice, once per actual change at startup.
2. Add the agent id (or the listed object's id) to the metadata and to the dedup key of the list rows.
3. Read `ref` and `path` from the locked row, as FIX-267 already does for the token. A PATCH that changes only one of
   them keeps the other's current value.

## Tests (each must fail before the fix)

- The changed request answers before a slow mail sender finishes, and the notice is still sent.
- A startup default-store change sends one notice; a restart with no change sends none.
- Two agents' skill lists read by an emergency reader within an hour leave two rows.
- Two concurrent PATCHes, one changing `ref` and one changing `path`, keep both changes. Test it with a barrier, no
  sleeps.

One Sonnet lane, size S–M, Rust (`aurora-api`). Normal code review by the Orchestrator. Not in parallel with FIX-284 if
both touch `emergency_access`; check the files at start. Tests only through `scripts/dev/test.sh`, plus crate clippy.
