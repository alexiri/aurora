# FIX-153: No dead ends between an app and an agent that may use it

## Goal
Owner, 2026-11-15, after adding CERN Phonebook: the agent got `ldap_no_connection`, and the owner could not find where to add the connection: "this whole setup is extremely confusing". Four defects make the path unfindable; this brief removes them. The deeper simplification for apps with nothing to enter is `FIX-154`, which builds on this one.

1. **The gateway's own links lead nowhere.** `decide.rs` builds `connect_url` / `reconnect_url` as `/o/<org>/w/<ws>/apps/<app>` and `create_secret_url` as `/o/<org>/w/<ws>/secrets`. No dashboard page serves either path. Only `apps/<app>/connect` exists, and it is a redirect.
2. **The org dashboard has no way to connect.** The Connect button lives only on a *workspace's* Credentials › Apps tab (`web/src/components/credentials/credentials-view.tsx:45`). The org Credentials › Connections empty state says "Connect it from the Apps tab", but org pages have no such tab. The org **Apps** page (`/o/<org>/apps`) only edits availability: with the open posture it shows one line and no apps at all.
3. **`ldap_no_connection` doesn't say what to do.** One message covers "not connected", "connected but not granted to this agent", "plain HTTP" and "no such app", and it carries no link.
4. **`access_restricted` sends people to the Policy page.** The grant they need is on the agent's Access tab.

## Part A — gateway (Rust, `services/aurora-gateway`)
1. **One link builder** (C-891). Add a small module, e.g. `src/links.rs`, with `connect(app)`, `connect_any()`, `reconnect(conn_id)`, `secrets()` and `access(agent_id)`. Each is built from `external_url` and the `ResolvedHost`'s `org_slug` / `ws_slug`. Replace every hand-built dashboard path in `decide.rs`:
   - the `apps/{…}` uses at ~1174 and ~1858 (`reauth_required`);
   - the `secrets` uses at ~916 and ~1366 (governance);
   - `connect_url` and `create_secret_url` in `hook()` (~1910–1918).
   `manage_url` and the policy/governance URLs keep their paths. App ids are `[a-z0-9-]`; percent-encode anyway.
2. **The `access_restricted` message** (C-893). Add `details.access_url` (the requesting agent: `ctx`/`Ident` `agent_id`) and use it in the message: "…Ask a workspace owner to give this agent access: <access_url>". Keep `manage_url` in the details. The `disabled` variant is unchanged. Add "…then give this agent access" to the `app_not_connected` message.
3. **LDAP refusals** (C-892), in `PolicyHandler::handle` (`decide.rs` ~1437):
   - plain HTTP to an LDAP host → `400 ldap_https_required` with the HTTPS URL;
   - otherwise use the `Fallback` already computed for the request (`Ungranted("connection", app)` → `not_granted`; `NotConnected(app)` → `not_connected`; anything else → `no_app`) for `403 ldap_no_connection` with `details.reason`, `app_id`, `app_name` (from the snapshot app) and the links named in C-892.
   Expose the fallback (or just the reason) on `PreparedRequest` / the hook; don't run a second lookup. The hook's `on_error` still records the row.
4. **Tests.**
   - A fixture `tests/conformance/dashboard-links.json` lists the templates (`{org}`, `{ws}`, `{app}`, `{connection}`, `{agent}` placeholders). A gateway unit test (`include_str!` relative to `CARGO_MANIFEST_DIR`) checks that the builder's output for sample values equals the expanded templates.
   - `tests/it/ldap_lane.rs`:
     - the existing `an_ungranted_agent_cannot_search` now asserts `reason = "not_granted"` and `access_url`;
     - new cases for `not_connected` (no connection row), `no_app` (an LDAP-shaped host with no app) and plain HTTP → `ldap_https_required`;
     - every case still asserts `connections == 0` at the fake directory.
   - Update `tests/it/refresh_proxy.rs` (it reads `reconnect_url`/`connect_url`) and any other test that pins the old paths.

## Part B — dashboard (Next.js, `web/`)
1. **Agent page accepts an id** (C-894). In `src/components/agents/agent-page.tsx`, when the `[handle]` segment matches no handle but equals an agent's `id`, call `router.replace` to the handle URL, keeping the query (`?tab=access`). An unknown value keeps the existing not-found state.
2. **Org Apps page lists apps** (C-894). `src/components/apps/availability-view.tsx` (or a new sibling component rendered by `src/app/o/[org]/apps/page.tsx`) shows the installed apps from `useApps(undefined)` as an `ItemList`: icon (`AppIcon`), name, description, and **Connect…** on each row. This shows under both postures; the posture notice and the restricted allow-list editor stay.
   - **Connect…** opens a `Dialog` listing the caller's workspaces in this org where `my_role === "owner"`. Each row shows whether the app is available there (`useApps(wsId)`), and unavailable rows are disabled with the reason.
   - Choosing a workspace navigates to `connectDeepLink(org, ws, app)` (already in `src/lib/api/apps.ts`).
   - With no owned workspace, the dialog says that a workspace owner connects apps.
   - The page stays owner/admin-gated (`OrgGate`) as today.
3. **Empty states** (C-894). `src/components/apps/connections-tab.tsx` (~216): at org scope the empty state links to `/o/<org>/apps` ("Connect an app from Apps"). At workspace scope, "Apps tab" becomes a link to `?tab=apps`.
4. **Tests** (vitest + Testing Library, existing patterns):
   - an agent page addressed by id redirects to its handle and keeps `tab`;
   - the org Apps page lists apps under the open posture, the Connect dialog lists only owned workspaces, disables unavailable ones and navigates to the deep link;
   - the org Connections empty state links to `/o/<org>/apps`;
   - a test reads `../tests/conformance/dashboard-links.json` and checks that every template maps to an existing `src/app` route and every `tab=` value is one `credentials-view.tsx` / the agent page accepts. If vitest's config can't read outside `web/`, move the fixture into `web/` and point the Rust test at it instead.
   - Add one Playwright journey only if the suite already covers the Apps/Credentials pages: org Apps → Connect… → workspace → the connect dialog opens.

6. The org Connections empty state links to org Apps; no text mentions a tab that the page lacks.
7. New and changed screens pass `14 §Visual design`: light and dark, 390 px without horizontal scroll.
