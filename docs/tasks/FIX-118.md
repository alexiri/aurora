# FIX-118: Built-in packages and the CLI — approval cards show what leaves the account; classifier and claim gaps; the forwarder and login protect credentials (REVIEW-5 PKG-1..PKG-12) — **high (item 1)**

## Problem
Packages
1. **Mail approval cards hide recipients.** The Microsoft 365 `send_mail` summary shows `/message/toRecipients/0/emailAddress/address` and the subject; the Gmail `send_message` summary shows the first `To` header and the subject (`plugins/builtin/{microsoft-365,google-workspace}/plugin.yaml`; `crates/aurora-summary/src/template.rs` ~199–215 returns the first matching header). Further To recipients, Cc, Bcc and the body are never shown. A prompt-injected agent sends to a colleague with an external Bcc; the approver sees "To: colleague, Subject: Status". The approval is the only control on outbound mail.
2. **Other content-bearing writes show a title only**: GitHub issue/PR bodies and file contents; Jira descriptions and all but the first text node of a comment; Confluence and Notion page content; calendar attendees (Google and Microsoft send invitations on create).
3. **The SQL classifier treats implicit user-function calls as read** (`crates/aurora-sqlclass/src/lib.rs` `walk` ~675–741 raises admin only at `FuncCall`): `SELECT 1 OPERATOR(public.!!) 1`, a cast to a non-builtin type, or a view over a volatile function run without approval. `docs/21` §Database lane: "anything unknown → admin".
4. Confluence claims `api.atlassian.com` under `/oauth/token` and injects the bearer there although no tool uses it; GitHub App installation tokens are minted with every permission on every installed repository (`github-app/hooks/src/lib.rs` `mint_request`); the corpus checker counts one negative per tool and has no refusal cases for dangerous untooled endpoints (`scripts/plugins/check_builtin.py`); the Drive agent notes say permanent deletion "is not available" (it is under a full grant) and the README's read-tool rule is stale.

CLI
5. **`aurora run --forward` exposes the agent's credential to every local account**: the forwarder binds `127.0.0.1:0` and adds `Proxy-Authorization` for any client (`services/aurora-cli/src/forward.rs` ~207–281).
6. **Cleartext and cross-server tokens**: `aurora login --url` and `AURORA_URL` accept `http://` (the device-flow response carries the API key), and stored agent tokens of a previous server are kept and sent to the new URL (`services/aurora-cli/src/main.rs` ~129–160; `crates/aurora-client/src/lib.rs` ~53).
7. The CLI prints server-supplied strings without stripping control characters (`approvals.rs` `format_approval`); `aurora logout` deletes the local file without revoking the key.

Owner question outside scope (Q-R5-18): Indico's connect form offers the `full:everything` scope although the app is `custom_only` (D-84 accepted the broad token with mitigations).

## Analysis (worker, lane `plugins`)
- **Summaries use decoders, not hooks (D-188 a).** Every case of items 1–2 (all recipients, Cc/Bcc, body preview, attachment count, attendees, ADF/Notion text) is expressible with five small decoder changes in `crates/aurora-summary/src/template.rs` (`json` wildcard, `json_count`, `json_text`, `mime_attachments`, all-header `mime_header`); no new wasm hook crate. The spec sentence says "a `summarize` hook where a template cannot".
- **The Confluence claim could not be removed or narrowed (D-188 c).** `connect/service.rs:242` (`probe::declared_host`) requires the connect probe URL (`/oauth/token/accessible-resources`) to lie on a declared host entry of the *same app*, so removing the entry breaks Confluence Cloud connects. Narrowing it to the exact path ties with Jira's entry for the same path; `crates/aurora-registry/src/index.rs` breaks ties by the smaller app id (`confluence` < `jira`), which took the path and `list_accessible_sites` away from Jira (seen in `check-builtin.sh`). The acceptance line "a request to `api.atlassian.com/oauth/token/x` is not claimed by Confluence" is therefore **not met**; fixing it needs a gateway/index decision (e.g. a probe-only entry kind) — left open.
- **GitHub App mint narrowing** (optional in the brief) was not done.
- **Logout** cannot revoke the device-flow key: the CLI does not know its id and no endpoint revokes "the current key". It says so (D-188 d).
- Item 3's "views over a volatile function" cannot be detected from the statement; the setup note says the role is the control.
