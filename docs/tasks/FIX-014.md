# FIX-014: A disabled connection must not feed app env or stubs into sandbox boots (AUDIT-002 F-1)

## Problem
A connection with `status = 'disabled'` that an allow rule selects still puts its app into the sandbox boot env and stub files. This is non-secret (env names and values from the manifest, stub files), but it is a behavioural defect carried since FUP-M7, now reproduced by AUDIT-002 (`/tmp/audit-002-logs/11-fupm7.log`: `env=Some("https://a.example/api") files=1`).

The chain:
- `compute_inner` in `services/aurora-api/src/domains/grants/effective.rs` (~line 140) sets `selected` without looking at `c.status`;
- `gateway::app_connections` (`crates/aurora-db/src/repo/gateway.rs:613`) deliberately returns `disabled` rows (the gateway needs them to refuse with the right reason);
- `boot.rs::app_boot_for` trusts `granted_apps`.

## Decision (coordinator)
- A connection that is not `active` contributes **nothing** to the boot document or the home sync: no app env, no stubs, no snippets. It stays visible in the effective listing (marked as not usable, with its status) so the dashboard and agents can explain why.
- Disabling (or re-enabling) a connection that changes a running sandbox's effective env flags `restart_to_update`, exactly as an app becoming unavailable does today (FIX-007, `an_unavailable_app_contributes_no_env_or_stubs_and_flags_restart`).
- The gateway is unchanged. It already refuses a disabled connection and keeps reading `disabled` rows to give the right reason.

## Scope
1. `effective.rs`: exclude non-`active` connections from `granted_apps` (and whatever feeds env/stubs/snippets); keep them in the listing with their status.
2. The restart flag on disable/enable when the effective app set changes, reusing the FIX-007 path.
3. Tests next to `an_unavailable_app_contributes_no_env_or_stubs_and_flags_restart` (api `tests/it`):
   - a disabled selected connection contributes no env, stubs or snippets;
   - disabling flags `restart_to_update`;
   - re-enabling restores the env and flags it again;
   - the effective listing still shows the connection with its status.
4. Docs: one sentence in `docs/11 §The boot document` (or wherever availability is described) and in `docs/09` if it describes `granted_apps`. Decision **D-105** only if a choice beyond this brief is needed.

## Constraints
- **Owns:** `services/aurora-api/src/domains/grants/effective.rs`, the restart-flag path it calls, `services/aurora-api/src/domains/runner_plane/boot.rs` only if needed, api tests, the doc sentences.
- No migration. No gateway change.
