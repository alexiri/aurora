# FIX-019: Hosted model readiness, `no_default_model`, and LiteLLM team verification (owner report, 2026-11-09)

## Problem (production cluster)
- Endpoint config: `{ id: aigw, display_name: AIGW, provider: litellm, base_url: https://aigw.cern.ch, key_origin: { method: endpoint } }`. No `default_model`, `models` or `dialects`.
- A workspace LLM key on `aigw` is active and verified, and is granted to Daneel (Access tab checked, effective view "selected").
- Every chat turn fails with `no_model_key`, and the sandbox never starts.
- `key_origin.method: litellm_team` "couldn't get it to work". The cause is unknown: possibly the spelling `litellm-team` (refused by config validation) or the verification below.

**Cause (from code)**:
- In `services/aurora-api/src/domains/hosted/model.rs`, `select()` → `default_model()` resolves from the endpoint `default_model`, the provider default (LiteLLM: the same field), the allow-list or the static `models`. All are empty here, so it returns `None`.
- The loop then ends in `Selection::NoKey`, and `dispatch::sweep_no_model_key` fails the turn `no_model_key` before any sandbox start.
- The key is fine. No model can be resolved, and the user is told the wrong thing.

`litellm_team` (`crates/aurora-llm/src/litellm.rs` `verify_key_origin`):
- It calls `GET <base>/key/info` with the key as bearer and refuses any key whose `info.team_id` is empty ("key reports no team").
- That was only exercised with the mock's master key.
- The error that reaches the user does not say which step failed.
