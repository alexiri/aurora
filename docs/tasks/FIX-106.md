# FIX-106: Gateway transport hardening — own addresses, tunnel timeouts and caps, translated address ranges, egress-proxy names, database lane errors and role (REVIEW-5 GWT-1/2/3/5/6/7, CRED-2, DB-3) — **medium, security**

## Problem
1. **Tunnels have no inbound bounds.** After `CONNECT` 200 the inner TLS accept has no timeout and the inner HTTP builder has no timer (`services/aurora-gateway/src/proxy/connect.rs` ~116–126, ~165), so hyper's header-read timeout is not enforced there (it needs a timer); keep-alive tunnels have no idle limit; nothing caps live tunnels per credential or in total (`proxy/listener.rs` ~45–58). One authenticated agent can hold tasks and sockets until the gateway — shared by all tenants — runs out.
2. **Open-lane tunnels never idle out** (`connect.rs` ~85 passes `idle = None`; the dial at ~70 has no timeout); `docs/06` §Open-lane: tunnels "end at the idle limit".
3. **The own-listener refusal misses the gateway's routable address.** With the default wildcard bind, `own` holds `0.0.0.0:4102/4103` and `is_own` (`guard.rs` ~134–140) matches a wildcard only against loopback/unspecified. If `allowed_private` covers the pod network (operators add such CIDRs for in-cluster LLMs), an agent can CONNECT to the gateway's pod IP on 4103 (unauthenticated `/metrics`, `/healthz`). `docs/06` §Destination guard: own services are refused "regardless of the allow-list".
4. **Address forms that embed private IPv4 are judged public.** `guard.rs` (~42–47, ~83–102) and the API's probe guard `services/aurora-api/src/domains/connect/env.rs` `is_public` (~24–47) do not refuse NAT64 `64:ff9b::/96`, 6to4 `2002::/16`, IPv4-compatible `::/96`, `fec0::/10`, `198.18.0.0/15`, `192.0.0.0/24`, `240.0.0.0/4`.
5. **With `gateway.egress_proxy`, names are not judged at all** (`upstream.rs` ~54–62; `check_name` judges IP literals only, `guard.rs` ~186): a name resolving to a metadata or private address, or a decimal IP spelling, is handed to the egress proxy. `docs/06` says "the name check runs locally" without defining it.
6. **Database lane.** Login failures relay the upstream server's error text and connection details to the agent (`proxy/database.rs` ~283–296). The gateway database role is granted `SELECT` on `api_keys`, which no gateway query reads (`crates/aurora-db/src/grants.rs` ~79). `docs/01` ~94 says "The gateway uses a least-privilege database role", but the chart uses the owner login unless `database.gatewayRole` and `gatewayExistingSecret` are both set (`values.yaml` ~86–98).

Two decisions for the owner, out of this brief's scope until answered: the database lane's default `sslmode=require` sends the stored database password to a server whose certificate is not verified unless `ca_pem` is stored (Q-R5-7: verify against system roots by default, or keep libpq behaviour and say so); and whether the least-privilege gateway role becomes mandatory or automatic in the chart (Q-R5-11).

## Linked requirements

## Spec change (apply with the fix)
- `docs/06`/`docs/02`: inbound tunnel limits — inner handshake 10 s, header read 30 s, idle limit for every tunnel kind (the WebSocket idle value), a per-credential concurrent-tunnel cap (propose 64) and a global cap; what the "local name check" is in egress-proxy mode (resolve locally and refuse if any address is refused; the rebinding window is accepted and stated).
- `docs/06` §Destination guard: the refused ranges listed in full, including translated forms.
- `docs/01`: "recommended; the default install uses one login" until Q-R5-11 is decided.

## Scope
- Timeouts, timer and caps on tunnels; open-lane idle and dial timeout.
- `own` built from the local interface addresses.
- One shared range table used by `guard.rs` and `connect/env.rs` (a small function in `aurora-core`), embedded IPv4 judged.
- Egress-proxy mode: local resolution and judgement before the CONNECT.
- Database login: fixed messages to the agent, detail in the log.
- `api_keys` removed from the gateway grants (+ `tests/it/gateway_grants.rs`).

## Acceptance criteria
- [ ] Gateway IT: a tunnel that sends no ClientHello closes within the handshake bound; a partial inner header closes at the header bound; an idle open-lane tunnel closes at the (shortened) idle limit; the (cap+1)th concurrent tunnel of one credential is refused.
- [ ] Unit: `Guard` with a wildcard bind and an injected local address refuses `<local-ip>:4103` even with `10.0.0.0/8` allowed; each translated/reserved form is refused by both guards.
- [ ] Gateway IT: with an egress proxy configured, a name resolving to `169.254.169.254` is refused before the proxy is contacted.
- [ ] Gateway IT: a refused database login returns a fixed message without the server's text.
- [ ] `gateway_grants.rs`: `SELECT … FROM api_keys` fails with 42501.
- [ ] `cargo test -p aurora-gateway -p aurora-db`, full `aurora-api` it-suite (connect), `scripts/e2e/gateway.sh`, fmt, clippy, guards.
