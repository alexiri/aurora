## Scope

1. **Capacity:** per runner — backend (podman/kubernetes), live sandboxes / capacity limit (the runner already reports or is configured with a limit — find it; if it isn't reported, add it to the existing registration/heartbeat payload without a protocol break), last seen, version. API route (IA) + `05` + C-number from the reserved block (say which).
2. **Token rotation:** an instance admin rotates a runner's `aur_` token: the API issues a new token (shown once), the old one keeps working for a grace period (configurable, default e.g. 10 min — state it) so the operator can roll the runner, then is refused; audited. Route + `05`; if the chart manages the runner token secret, document the rotation procedure (update the Secret, roll the Deployment) in `docs/operator/runners.md`.
3. **Dashboard:** Runners screen gains the capacity table and a Rotate token action (confirm dialog, one-time display with copy) using the shared primitives; both themes, 390 px.
4. `14` amended: provisioning (adding/removing runners) is Helm/CLI, not the dashboard.
