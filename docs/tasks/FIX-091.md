# FIX-091: Supervisor stream and PTY pumps never wait on a peer; violations are counted in a window; shutdown cannot hang; the stream engine gets tests; terminals open as PID 1 (REVIEW-5 STRM-1/2/3/4/10/11/13; owner report 2026-11-13) — **high**

Checked against master `c3ec906d`: FIX-072/073 did not touch these paths (`pty.rs` line numbers below are post-merge).

## Problem
1. **One stalled preview app stalls every stream of the sandbox.** `services/aurora-supervisor/src/streams.rs`: the single pump task awaits `l.data_tx.send(payload)` in `on_data` (~381) on a 16-slot queue (`DATA_QUEUE`, ~39; the comment says it "never fills in practice"), while the stream task writes with `sock.write_all(&chunk).await` inside its `recv` arm (~514). The window bounds bytes, not frames, and the runner forwards each browser WebSocket message as its own frame. Seventeen small frames to an app that has stopped reading block the pump: no other stream's data, credit or close is processed, `Cmd::Shares` is not applied (a removed share keeps streaming — SEC-82), and the channel `Reset` queues behind it. The runner side was fixed in FIX-060 ("the pump never waits on a leg"); the supervisor was not.
2. **Same defect in the PTY engine.** `pty.rs`: the task loops on `pty.master.writable().await` (~660) and awaits `reap()` (~624/631/650/677) outside its select; the pump awaits `data_tx.send` (~426), `resize_tx.send` (~324) and credit sends. A paste into a program that does not read stdin, then closing the tab, leaves `pty.close` unread; new terminals time out; both PTY slots stay taken.
3. **Shutdown can hang.** `PtyHandle::close_all` (~102–107, added by FIX-073) awaits a oneshot with no timeout and is called before the grace deadline is computed (`supervisor.rs` ~348); a wedged pump makes shutdown wait forever. `Supervisor::shutdown` never closes preview streams although `docs/12` (~505) says "Everything closes on `shutdown`".
4. **The violation counter never decays.** `violations` (`streams.rs` ~216, ~388; `pty.rs` likewise) is incremented for data on an unknown id — which a legal close race produces — and never reset; from the fourth onward every single one aborts the channel with 4400 (`channel.rs` ~531–541), dropping all terminals and streams of the sandbox.
5. **Closing a terminal relies on SIGHUP.** `abort()` drops the master (`pty.rs` ~316, ~430); a shell that ignores HUP survives with its slot.
6. **No tests.** `streams.rs` has one unit test; the runner suites use a fake supervisor; SEC-82's evidence ("supervisor refuses unlisted ports, non-loopback dials and everything with an empty list; … credit accounting") does not exist.
7. **Terminals do not open in production** (owner report 2026-11-13 on `sha-72c88ca`, which includes FIX-054: the tab shows `aurora-supervisor __pty-exec: Operation not permitted (os error 1)`). The message is `pty_exec::run`'s `make_session` branch (not the exec branch, which would print `exec <shell>:`), and `setsid` cannot fail there (the bootstrap is not a group leader), so it is `TIOCSCTTY` → `EPERM`: the slave is already another session's controlling terminal. `PtySession::spawn` (`pty.rs` ~515–527) opens the master with `NOCTTY` but the slave with plain `std::fs::OpenOptions` (no `O_NOCTTY`). In the sandbox the supervisor is PID 1 (`podman.rs`, `init: false`), started by the runtime as a session leader without a controlling terminal, so opening the slave makes it the **supervisor's** controlling terminal, and the bootstrap's `TIOCSCTTY` is refused. FIX-054's IT `pty_env_probe.rs` runs the engine inside the libtest process, which is not a session leader, so it never saw this (the same test-versus-production gap FIX-054 was about). Diagnosed from the code; not yet reproduced in a sandbox.

## Spec change (apply with the fix)
`docs/16` §W18 and §W19: "Data for a stream id this side closed, or was told closed, in the current channel connection is dropped silently and is not a violation. A violation is data beyond the window or for an id never opened. **Four violations within 60 s** on one channel connection close it with 4400; the count resets when the connection changes." `docs/12`: shutdown closes PTYs and preview streams within the shutdown grace. `docs/12` §Terminal, first bullet: "…own session with the pseudo-terminal as its controlling terminal (job control works); the supervisor opens both ends with `O_NOCTTY` and never acquires a terminal itself (it is PID 1 and a session leader in the sandbox)".
