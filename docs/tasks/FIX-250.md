# FIX-250: a GitLab-style diff, shown inside the section it belongs to (owner 2026-11-26)

## Why

Owner request 2026-11-26: "agent template/skills diffs: implement an interface like GitLab's diff, where you collapse
common lines (but allow expanding to see the entire file). Unchanged files are collapsed by default. Show the diffs in
the `About this template`, `Instructions`, etc. sections, not as a separate thing before all those sections."

Today (FIX-247) the review page puts one block "What changed since <version>" above the full content, and every diff
is the shared `Lines` renderer (`web/src/components/ui/lines.tsx`): whole files, every line, no context folding. A long
skill with one changed line is a wall of text, and the administrator has to jump between the diff block and the
section it belongs to.

## Fix

1. **One shared diff component** `DiffView` (replaces `Lines` in `web/src/components/ui`, with the same props plus the
   file name): a unified diff with old and new line numbers, three lines of context around each change, and every
   longer run of unchanged lines folded into one row "N unchanged lines" with **Show 20 more above / below** and
   **Show all** buttons (expand in steps, like GitLab); a **Show the whole file** switch in the file header; a
   changed-line pair highlights the words that differ; a file that was added or removed shows as such; files with no
   change are not shown as diffs at all. Long lines scroll inside the diff box (never the page); keyboard operable (the
   fold rows are buttons with labels naming the line range); both themes, tokens only, 390 px without page
   horizontal scroll, axe clean. A very large file (over 5,000 lines) is folded and says so, with the expand buttons
   still working.
2. **The review page puts each part's diff in that part's section** (web/src/components/templates/review-version.tsx,
   web/src/lib/template-diff.ts from FIX-247): *About this template* (README), *Instructions*, each *Skill* and each of
   its files, *Skills from libraries*, *Helper files*, *Memories*, *Apps*, *Automations*, *Inputs*. A section whose part
   changed shows its changes first (the folded diff) with a **Show the current text** toggle for the full text of the
   new version; a section whose part did NOT change is collapsed to one line "Unchanged" that expands to the text. The
   block at the top stays short: the one-line summary and **Look at these first**, each entry linking to its section;
   the separate big diff block is removed. First version (nothing to compare): sections show the text as today.
3. **The same component everywhere a diff is shown today**: the person's **Review changes** dialog for an agent update
   (`review-changes-dialog.tsx`, per part), and the skill library diff (`web/src/components/skills/library.tsx`); no
   other copy of a line diff remains (`rg -n "<Lines"` finds none).
4. docs/14 (the pattern: folding, expanding, unchanged collapsed) and the C-1114 review paragraph.

## Proof

- vitest for the diff algorithm and the folding model (pure functions, separate from the component): context of three
  lines, two changes closer than six lines merge into one hunk, expanding by steps, show all, added/removed file,
  identical files, CRLF, no trailing newline, very large input, word-level highlight spans.
- vitest for the component (fold rows, expand buttons grant exactly the lines they name, keyboard, labels) and for the
  review page (each diff inside its section, unchanged collapsed, the top block short with links).
- Update every test and spec that asserted the old block or `Lines` (`rg -n "What changed since|Diff of|Lines" web/tests
  web/e2e`).
- One mocked Playwright spec: the review of 1.4.0 against 1.3.0: the diff sits in *Instructions* and in one skill,
  the unchanged sections are collapsed, a fold expands, **Show the whole file** works; 1280 and 390 px, both themes,
  axe clean.

## Hard rules

- Web only: no Postgres container, no Rust. Heavy commands through `heavy.sh <lane> …`. No new dependency (write the
  line diff, or use one already in `web/package.json`). Agent-facing text never cites internal ids. Commit locally.
- Commit slices: brief+tracking; the pure diff and folding model with tests; the component; the review page; the other
  call sites; the Playwright spec; docs.

## Acceptance

- A person reading a review sees the changes in context, folded, inside the section they belong to, and can expand
  to the whole file; unchanged parts are collapsed by default.
- Gate: web lint/typecheck/full test/build, the touched mocked Playwright specs (`--project=mocked`), guards.
