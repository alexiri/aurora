# FIX-132: Self-hosted app registration says who already holds a host and lets the admin fix it; "Instances" renamed — **medium**

## Goal
The owner tried to register the organisation's GitLab server instance-wide (Admin › Instances) and got
"That host is already claimed by another app, an LLM endpoint or another registered instance." with no way
to find out which, or to fix it. Also: "'Instance' is terribly confusing, it's hard to know that they're
related to apps".

## What the code does today
`services/aurora-api/src/domains/app_instances/service.rs::create` refuses with 422
`instance_host_conflict` in three cases, and the API **does** say which in `details.conflict`
(`{kind: static_claim, app_id}`, `{kind: llm_host}`, `{kind: instance, app_id}`), but
`web/src/lib/api/errors.ts:61` maps every case to the same generic sentence.
- `static_conflict`: an active package's static host claim overlaps (wildcards included), or the host is
  an LLM endpoint host, a snapshot reserved host, or one of Aurora's own addresses (`external_url`,
  `hookhost_url`, `advertised_proxy_url` — `plugins/ingest.rs::reserved_names`).
- `repo::app_instances::visible_with_host(org = None, host)`: for an **instance-wide** registration this
  matches a registration of the host by **any org** (`$1 IS NULL` → every row). Admin › Instances lists
  instance-wide registrations only, so an org-level registration of the same host (e.g. made earlier from
  Org › Instances) blocks the admin invisibly. This is the most likely cause of the owner's case; confirm
  it first (query below) and record the finding.

```sql
SELECT i.app_id, i.org_id, o.slug, i.label, i.created_at
FROM app_instances i LEFT JOIN organizations o ON o.id = i.org_id WHERE i.host = '<host>';
```

## Scope
### In scope
1. **Say who holds it.** The 422 carries a precise, permission-aware holder: static claim → app name,
   package and a link to Admin › Plugins/Host claims; LLM endpoint → the endpoint id; Aurora's own
   address → which setting; registration → app, scope (instance-wide or the org's name and a link for an
   instance admin; for an org admin only "another organization — ask an instance administrator", never
   its name). The web maps each `kind` to its own message with the link.
2. **Admin › (renamed) lists every registration**, instance-wide and per-org, with an org column and
   filter, and offers **Make instance-wide** on an org registration: one transaction moves it to
   `org_id = NULL` (connections keep their `instance_id`; the other orgs then see it too), audited
   (`app_instance.promote`, security-critical — it widens who can connect). Registering a host that an org
   already registered offers this action in the error instead of a dead end.
3. **Rename** "Instances" to **"Self-hosted apps"** in the admin and org navigation, page titles, empty
   states and help ("Register your own GitLab, GitHub Enterprise Server, Indico … so people can connect
   to it"); the route path may stay `/instances` (or redirect from it). Use one term everywhere in `14`,
   `09` user-facing wording and operator docs; the API/data names stay.
### Out of scope
- Changing which overlaps are refused.
