Create the database crate (pool, embedded migrator, NOTIFY bus, claim/singleton helpers) and the first half of the schema.

## Linked requirements
- M0/03 (§Conventions, §1 Identity and tenancy, §2 Secrets/connections/OAuth clients, §3 Plugin registry, §4 Policy/grants/approvals, §5 Agents/gateway credentials); `05 §Event bus`; `01 §Design principles` (claims, not locks); `02 §Coding rules` (Database access, Time).

## Context (read only these)
- `docs/03-data-model.md` lines 1–535 (Conventions through §5). `03` is the **owning document** — implement it exactly (columns, types, nullability, defaults, CHECK vocabularies, uniques, partial uniques, FKs with the stated on-delete, ≤N length checks). If you find a contradiction or something unimplementable, record it in your report; do not invent.

- Decisions I-05/I-06 in `docs/90-decisions.md`: sqlx 0.8 macros online against the dev DB (`DATABASE_URL` in repo-root `.env`: `postgres://aurora:aurora@127.0.0.1:55432/aurora`); tests use `#[sqlx::test(migrator = "aurora_db::MIGRATOR")]`. sqlx-cli: `~/.cargo/bin/sqlx` (0.8.6).

## Scope
### In scope (`crates/aurora-db/**` only)
- `MIGRATOR: sqlx::migrate::Migrator = sqlx::migrate!("./migrations")`; `connect(url, max_connections) -> PgPool`; `migrate(&PgPool)`.
- Migrations (forward-only SQL, one file per section, timestamp-prefixed so order is fixed):
  `20261105000000_extensions.sql` (citext, any other needed), `…0001_identity.sql` (§1), `…0002_secrets_connections.sql` (§2), `…0003_registry.sql` (§3), `…0004_policy.sql` (§4), `…0005_agents.sql` (§5). FKs to tables created in a *later* file: add them with `ALTER TABLE … ADD CONSTRAINT` in the later file (state this in a SQL comment). Leave room: BE-005 adds `…0006`–`…0011` for §6–§11.
- `request_log` (§4): range-partitioned by month on `ts`, no FKs; create a default partition plus partitions for the current and next 2 months is the API's job later — for now create a DEFAULT partition only and note it.
- `updated_at` has no trigger (repository layer maintains it; churn columns excluded) — per `03 §Conventions`.
- `bus` module: `notify(executor, channel: Channel, payload: &serde_json::Value)` (`SELECT pg_notify($1,$2)`, refuses payload > 7000 bytes with a typed error); `Channel` enum with the 11 channel names of `05`; `Listener` wrapping `sqlx::postgres::PgListener` that yields `BusEvent::Notification { channel, payload: serde_json::Value }` or `BusEvent::Resync` after (re)connect so consumers re-read state; reconnect with capped backoff; malformed payloads are logged and skipped (never panic).
- `jobs::try_singleton(pool, job_name, f)` — runs `f` only if `pg_try_advisory_lock(hashtext(job_name))` (or a stable 64-bit hash) succeeds on a dedicated connection; releases after.
- `claim` module: document the canonical claim pattern (`UPDATE … WHERE id IN (SELECT … WHERE due AND (lease IS NULL OR lease < now()) ORDER BY … LIMIT $n FOR UPDATE SKIP LOCKED) RETURNING …`) and provide a small tested helper or macro-free example used by tests.
- `DbError` (`thiserror`) mapping unique/FK/check violations (with constraint name) and not-found.

### Out of scope
- Tables of §6–§11 and gateway role grants (BE-005); repositories for domains (later milestones); schema-vs-spec introspection test (TEST-001).

## Acceptance criteria
- [ ] `~/.cargo/bin/sqlx migrate run --source crates/aurora-db/migrations` succeeds on the empty dev DB (`DATABASE_URL` from `.env`) **and** a second run is a no-op.
- [ ] DB tests (`#[sqlx::test]`): migrations apply; partial unique indexes enforce (e.g. one active plugin version per package, one draft/published policy generation per scope, one default agent per workspace); NOTIFY round-trip through `Listener`; oversize payload rejected; `try_singleton` excludes a concurrent second holder; claim helper never hands the same row to two concurrent claimers.
- [ ] `cargo test -p aurora-db`, `cargo clippy -p aurora-db --all-targets -- -D warnings`, `cargo fmt -p aurora-db --check` pass.
- [ ] Report lists every spec ambiguity found in §1–§5.
