# BE-070: Connector registration, admin, ownership and config feed

## Goal
Implement the connector plane's registration/trust/ownership half and the instance-admin connector routes, so a connector (e.g. `connectors/fake` via `aurora-connector-sdk`) can register, get approved and receive its config feed with decrypted platform credentials.

## Linked requirements
- `docs/13-channels-connectors.md` §2 (ownership: `owner_replica_id` + `owner_lease_until`, balancing `ceil(integrations / live replicas)`), §3 (registration, manifest signature, widening → `pending_approval`), §4 table rows `register`, `config`, `credentials`, `retire`; §6 invariant 5 (a connector sees only its own connector id's integrations; no Aurora credentials).
- `docs/05` §Instance administration (`/v1/admin/connectors…`), §Channels `GET /v1/connectors`; contract `docs/API_CONTRACTS.md` §M6 (API-006) C-31, C-32, types `ConnectorAdmin`, `ConnectorInfo`.
- `docs/09 §2` signing (built-in project key or trusted publisher key), reusing `crates/aurora-registry/src/signature.rs` / trust store logic. The connector signature is over sha256 of the canonical JSON of the manifest. Find the canonical-JSON helper used for plugin manifests and reuse it.
- Schema: `connectors`, `connector_replicas`, `channel_integrations` (`credentials_ref` sealed through the secret vault, `credentials_version`) in `crates/aurora-db/migrations/20261105000010_channels.sql`.
- Wire types already exist: `crates/aurora-protocol/src/connector.rs` (`RegisterRequest/Response`, `ConfigResponse`, `Integration`, `Presence`, `Binding`, `CredentialsRequest/Response`, header consts). SDK client: `crates/aurora-connector-sdk` (read it to match exact paths/headers).

## Scope
### In scope
- `services/aurora-api/src/domains/connectors/`:
  - **Admin (IA)**:
    - provision (`aun_` token via `aurora_core::token`, hash stored, shown once)
    - list with replicas, integration count and `widening` reasons
    - approve (C-31 digest match)
    - rotate token
    - delete (409 `connector_in_use`)
  - **Public catalogue** (C-32): `GET /v1/connectors` (active only) and `GET /v1/connectors/{id}/icon` (decode `icon_png_b64`, sanitize per app-asset rules; reuse the plugin icon sanitizer).
  - **Connector plane auth** (`/v1/connector/*`): bearer `aun_…` → connector row. Every call after `register` requires `X-Aurora-Replica` naming a live, non-retired replica of that connector (otherwise 401/409 per the existing plane-error conventions; mirror `runner_plane`). A `disabled` connector → 403.
  - **`POST /register`**:
    - validate the manifest (schema + string sanitization)
    - verify the signature
    - compute the digest
    - set `pending_approval` on first registration or widening (new capability set to true, new setup field, new public callback), otherwise keep `active` or auto-accept narrowing
    - create a replica row
    - return `{ connector_id, replica_id, status, poll }`
  - **`GET /config`**: ETag/`If-None-Match` → 304.
    - Claim ownership within the call: renew this replica's leases; take integrations whose lease lapsed, up to `ceil(active integrations of this connector / live replicas)` where live = `last_seen_at` within 2× config poll.
    - Return only owned integrations of this connector with status `active` (and `validating` for C-33 flows if the validate op needs them; decide and document), their presences and active space bindings.
    - Credentials are decrypted through the vault, never logged.
    - A connector in `pending_approval` gets an empty set.
    - Bump `last_seen_at`.
  - **`POST /credentials`**: CAS on `credentials_version` (409 `stale_version`); re-seal; only for targets owned by the calling replica.
  - **`POST /retire`**: mark the replica retired and release its leases.
- Integration status/ownership helper functions in `aurora-db` (`repo/connectors.rs`, `repo/channel_integrations.rs`) for later tasks.
- OpenAPI registration for management routes (plane routes may be excluded from the public OpenAPI if `runner_plane` is; follow it). Regenerate `web/openapi.json`, `pnpm -C web gen:api`, and add matrix rows (`tests/permission_matrix.rs`) for the new public routes.
- Tests `services/aurora-api/tests/connectors.rs`:
  - provision → register (signed with the test key used by plugin fixtures) → `pending_approval` → config empty → approve → config lists owned integrations with decrypted credentials
  - narrowing re-register stays active; widening goes back to pending
  - two replicas split integrations, and a lapsed lease is taken over
  - another connector's integrations are never returned
  - credentials CAS + stale version
  - retire releases leases
  - bad/absent replica header
  - wrong token → 401
  - IA-only admin routes
