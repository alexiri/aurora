# OPS-017: One containerized dev/test setup: kind + Helm replaces podman compose (phase 1)

## Goal
Decide, with evidence, whether to drop `deploy/compose/` and keep **kind + the Helm chart** as the only containerized setup for local development and integration testing (host-process `just dev` stays for the inner loop). The owner's intent is "maintain just the Kubernetes setup". Implement that unless the evaluation finds a blocker, in which case report it with specifics before removing anything.

## Context
- Compose today: `deploy/compose/` (compose.yaml, aurora.toml, Caddyfile, setup.sh, litellm.yaml, vidaimock/), the `just compose-*` recipes, `docs/operator/install-compose.md`, the `docs/15` §Development section, and `scripts/guards/edge-routes.sh`, which checks the Caddyfile. `scripts/e2e/llm.sh` reads `deploy/compose/vidaimock` and `litellm.yaml` but runs its own containers. The phase-0 exit criterion names the compose stack (OPS-015 fixes it for that exit).
- kind already works on this host (rootless podman provider; `scripts/e2e/kind.sh`, `deploy/kind/`; OPS-011, AUDIT-001 16 min end-to-end).
- The e2e harnesses (`tests/e2e-hosted`, `tests/e2e-gateway`) run services as host processes plus podman sandboxes, not compose. They're unaffected unless you choose to move them.

## Scope
1. **Evaluate** in `docs/ops/dev-environments.md`:
   - cold start time (cluster + install) and warm iteration time (rebuild one service image and roll it) for kind vs compose
   - resource use, and what compose provides that kind doesn't: the edge/Caddy single URL, `llm-mock`, `connector-fake` and `hosted` profiles
   - the developer story for each
   - Propose kind equivalents: Helm values profiles (`deploy/kind/values-dev.yaml`, `values-llm-mock.yaml`, `values-connector-fake.yaml`), ingress for the single URL, and the fake connector and VidaiMock/LiteLLM as optional chart components or a dev-only chart.
2. **Fast image iteration on kind**: a `just kind-dev` flow that builds only changed service images, loads them (`kind load`) and restarts the deployment. Consider building binaries on the host and copying them into a thin runtime image to skip in-container compiles. Coordinate with OPS-018 (live reload), which may use Tilt; if Tilt is adopted there, this recipe may become its fallback.
3. **Migrate**:
   - move VidaiMock/LiteLLM config to `deploy/dev/llm-mock/` (or chart values) and update `llm.sh`
   - update the edge-routes guard to check the Helm ingress/HTTPRoute only
   - delete `deploy/compose/`, the compose recipes and `install-compose.md`
   - write `docs/operator/install-kind-dev.md`
4. **Spec updates**, phase-tagged "(phase 1, OPS-017)":
   - `docs/15` §Development (kind replaces compose)
   - `docs/18` (Playwright against kind, or the host-process stack)
   - `docs/19` (phase-0 exit wording stays historical; note the change from phase 1)
   - a decision entry in `docs/90-decisions.md`
5. **Verify**:
   - `bash scripts/e2e/kind.sh --fresh` still passes
   - the new dev flow brings up a full stack (with llm-mock) where a hosted agent answers a chat
   - `m1.sh` Playwright runs against the chosen target

## Constraints / file ownership
- You own `deploy/**`, `justfile` (dev/compose/kind recipes), `scripts/e2e/{llm,kind}.sh`, `scripts/guards/edge-routes.sh`, `docs/operator/**`, `docs/ops/dev-environments.md`, `docs/15` §Development, the `docs/18` dashboard-testing lines, and `docs/90-decisions.md` (new entry).
- If the evaluation finds a hard blocker for removing compose (e.g. a required workflow kind can't serve), stop and ask through Orca `ask` before deleting anything.
