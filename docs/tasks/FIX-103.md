# FIX-103: Images and developer tooling — truthful sandbox capability label, pinned inputs, a quick gate that runs the affected tests, test-database hygiene (REVIEW-5 OPS-4/5/10/11/15, DEP-6/8) — **medium**

## Problem
1. **The sandbox image advertises `browser` without Chromium.** `images/sandbox/Containerfile` ~58 installs Chromium with `|| echo "chromium unavailable"` and ~75 sets `LABEL org.aurora.capabilities="browser"` unconditionally; the runner reports the label at registration, so the API schedules browser boots on an image that cannot serve them. `scripts/images/sandbox-base-smoke.sh` (~139–153) compares labels only.
2. **Unpinned inputs.** `pip3 install uv` (Containerfile ~61), the Claude Code npm tree installed without a lockfile (~87), `rust:1-bookworm` and `gcr.io/distroless/cc-debian12:nonroot` (`images/services/Containerfile` ~21, ~148), `node:22-slim` and `pnpm@10` (`web.Containerfile`), `postgres:16` in the chart — while the hook image, the sandbox base, sccache and Codex are digest- or checksum-pinned. The rpm package and database remain in the sandbox image after its binaries are deleted (~45, ~63).
3. **The quick gate (the lanes' pre-commit check) can pass without running affected tests.** `scripts/dev/quick-gate.sh`: a migration change tests only `aurora-db` and `aurora-api` (~263, ~305) although gateway and supervisor suites build their databases from the same migrator through `aurora-testkit`; `plugins/`, `scripts/`, `deploy/`, `images/`, `.github/` and `justfile` map to nothing (~294) although `services/aurora-api/tests/it/connect.rs` uses built fixtures and the guards read the chart; the default scope never runs `scripts/guards/run-all.sh`.
4. **Test databases leak.** `aurora_test_<uuid>` databases are removed only in `Drop` (`crates/aurora-testkit/src/lib.rs` ~182–205); killed runs leave full-schema copies forever (`just clean-testkit` removes containers only). The template reaper drops other migration sets by age `WITH FORCE` while another worktree may be cloning from them (`template.rs` ~310–380).
5. `scripts/e2e/llm.sh` (~39, ~96) reuses an existing base sandbox image instead of rebuilding like the other e2e scripts, so it can test an old supervisor.

## Linked requirements

## Scope
- Chromium: install without the fallback in the `sandbox` target, or set the label only when `command -v chromium` succeeds in the same layer; the smoke asserts `chromium --version` when the label is present.
- Pin: digests on every `FROM` and the chart's Postgres image; exact versions (and hashes where the ecosystem supports them) for `uv` and `pnpm`; `npm ci` from a committed lockfile for the harness; a guard that fails on a `FROM` without `@sha256:`. Drop the rpm package from the final image if FIX-031's smoke still works through the bind-mounted os-stage binary.
- Quick gate: migration changes select the reverse-dependency closure of `aurora-testkit`; fixture sources map to `aurora-api`; chart/image/guard/justfile changes run `run-all.sh`; `--dry-run` shows the selection.
- Testkit: reap `aurora_test_%` databases with no connections older than a TTL under the existing advisory lock; clones take the lock shared, reaps exclusive.
- `llm.sh` rebuilds unless `SKIP_IMAGE_BUILD=1`; `docs/18` says it is a manual gate.

## Constraints / file ownership
- Owns: `images/**`, `scripts/images/**`, `scripts/dev/quick-gate.sh`, `scripts/e2e/llm.sh`, `scripts/guards/` (new pin guard + `run-all.sh`), `crates/aurora-testkit/src/{lib,template}.rs` and its tests, `justfile` (`clean-testkit`), `deploy/helm/aurora/values.yaml` (image pins only), `docs/18`, `docs/ops/build-performance.md`.
- Never write to the `aurora` dev database; reaping targets only the test namespaces.
