# BE-075: Messaging tools and the `send_message` action handler

## Goal
The channel messaging platform tools (13 §5.10) and the `send_message` action-approval handler (07 §Action approvals, phase-0 key `send_message`).

## Linked requirements
- `docs/13-channels-connectors.md` §5.10:
  - availability only with an active presence
  - platform resolution order
  - `find_recipient` (correlated `user.lookup`/`spaces.list`; reach-filtered; results pinned as mention anchors)
  - `send_message` (anchor alias or recipient id; reach re-checked at send; the own thread is always allowed; otherwise `proactive_messaging` `off` → refused, `ask` → action approval with a platform-composed summary, `allow` → sent; no broadcast mentions from model text)
  - `read_conversation` (needs `history`; current thread or a bound space; sanitized, labelled untrusted)
  - `list_my_messages`/`edit_my_message`/`delete_my_message` (only own tool-posted messages in the same conversation within 24 h)
- `docs/12` §Phase 0 catalogue (Messaging family).
- `docs/07` §Action approvals:
  - frozen payload
  - platform-composed summary
  - `approved → executed|failed`
  - outcome notice + system follow-up
  - register the `send_message` handler in the BE-065 action-approval handler registry
- Agents' `proactive_messaging` column (`ask` default).

## Scope
### In scope
- `services/aurora-api/src/domains/tools/messaging.rs` (tools) and `domains/channels/messaging.rs` (send logic shared by the tool and the action handler), registering the action handler.
- Tool availability filtering: tools are listed only while the agent has an active presence. Check how the catalogue is filtered per agent and extend it.
- Tests `services/aurora-api/tests/channels_messaging.rs`:
  - tools absent without a presence
  - platform resolution (thread link, then origin, then the only presence, then an error listing platforms)
  - find_recipient filters unreachable people/spaces and pins anchors
  - send to own thread is allowed
  - `off` refused; `ask` creates an action approval and approval posts it; `allow` sends
  - reach revoked between approval and execution → `failed`
  - `<@here>`/broadcast text defused
  - read_conversation requires `history` and labels output untrusted
  - edit/delete only own recent messages

### Out of scope
- Inbox, cards, management.

## Constraints / file ownership
