# BE-066: Apps platform tools `request_app_connection` and `propose_custom_connection`

## Goal
Complete the phase-0 Apps tool family (12 §Phase 0 catalogue): `list_apps` exists; add the other two.

## Linked requirements
- `docs/12-supervisor-harness.md` §Phase 0 catalogue, Apps row.
- `propose_custom_connection {name, host, path?, recipe, reason}`: `docs/08-secrets-credentials.md` §Agent-proposed custom secrets.
  - Create a `secrets` row in the agent's workspace with `status = 'proposed'`, `value_ref = 'pending:'`, `proposed_by_agent_id`, host/path/injection recipe validated exactly like a generic secret create (reuse the secrets service validation: the injection recipe kinds in 08 §5, refusal of governed LLM hosts `llm_host_requires_llm_key`, etc.). Never accept a value.
  - Return `{ "status": "proposed", "secret_id" }` and append a durable `notice` to the conversation telling the person to paste the value in the dashboard (never in chat).
  - The existing routes `POST /v1/secrets/{id}/accept` / `reject` (BE-031) and the FE-020 proposals card complete the flow. Verify that accepting grants the secret to the proposing agent only, and fix it if not.
  - Limit: at most 5 pending proposals per agent (tool error beyond).
- `request_app_connection {app_id, reason}`: decision **I-29** in `docs/90-decisions.md` (authoritative).
- Tool framework: `services/aurora-api/src/domains/tools/{registry,builtin}.rs` (`PlatformTool`, `ToolCallContext`); `list_apps` lives in `builtin.rs`. Follow `domains/tools/memory.rs` for structure and errors.
- Sanitization: `aurora_core::sanitize` (`one_line`, `label`).
