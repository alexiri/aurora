# FIX-096: Skill libraries — bounded frontmatter parsing, full re-validation on approval, refresh races, git-host throttling (REVIEW-5 SKILL-1, SKILL-3..SKILL-10) — **high (item 1)**

## Problem
1. **Repository YAML can exhaust API memory.** `services/aurora-api/src/domains/skill_libraries/content.rs` `parse_skill_md` (~441) deserialises `SKILL.md` frontmatter into `serde_yaml::Value` (serde_yaml 0.9.34, deprecated). The only bound is the 64 KiB file size. serde_yaml limits alias *jumps* to 100 × the event count (`de.rs` ~478), which stops exponential "billion laughs" documents but not products: an anchor of 20,000 scalars, 5,000 aliases to it under a second anchor, and 400 aliases to that stay under the jump limit and expand to about 4 × 10¹⁰ nodes. Browsing a library parses up to 200 `SKILL.md` files (`service.rs` ~546, ~587) and the listing cache is filled only after the parse, so every browse by any org member and every refresh pass repeats it. Anyone who can push to the repository controls the input (SEC-84: repository text is untrusted). The expansion is reasoned from the parser's source, not run: **write the failing test first** (a nested-alias document under a memory/time bound).
2. **Approval does not re-validate what SEC-83 says it does.** `content.rs` `finish` checks hash, name and total size; `approve_update` (`skills/library.rs` ~680) takes file paths from stored JSON (`proposed_parts`, ~456–490) without `validate_path`, the 50-file cap, file sizes or the description rules.
3. **A refresh can undo `forget_head`.** `finish_refresh` writes `last_head_sha = COALESCE($6, last_head_sha)` unconditionally (`crates/aurora-db/src/repo/skill_libraries.rs` ~705–713); an add pinned to an older commit clears the head (`skills/library.rs` ~240) while a pass that read earlier is still running; the pass writes its head back and the added skill gets no update proposal until the repository moves again (C-577, D-154(d)).
4. **The org's 4 MiB open-proposal cap is check-then-act in refresh** (`refresh.rs` ~239, ~327–331; the add path takes `lock_budget`).
5. **Cold browse has no single-flight or deadline**, and `commit_sha` reads bypass the cache (`service.rs` ~520–565, ~647–658): twenty members opening the picker each issue ~200 gateway fetches and retry 40 times on 429 (`content.rs` ~96), draining the org's 5-per-second budget.
6. **A git-host 429 is a refresh failure**: three in a row push the library to the 6-hour backoff and `error` (`content.rs` ~96–99; `refresh.rs` `next_in_secs`); the forwarded `Retry-After` is never read.
7. **`required_access` is parsed and never read** (`crates/aurora-registry/src/manifest/model.rs` ~184–193).
8. `docs/operator/skill-libraries.md` ~28 says browsing costs "up to 200 file reads"; it reads only each skill's `SKILL.md`.

Two related questions go to the owner and are **not** in this brief's scope until answered: whether browse and add may name any commit the connection can fetch rather than only commits the library's ref has pointed at (Q-R5-3; C-571/C-572 currently allow any), and whether pausing a library should also stop approval of proposals already pending from it (Q-R5-6; C-570/C-574 are silent).

## Scope
- Frontmatter: reject anchors and aliases before parsing and deserialise into a typed struct (`name`, `description`); replace the deprecated crate if a maintained parser with limits is already in the dependency tree, otherwise keep it behind the pre-check. Invalid frontmatter yields an invalid listing item, never an error for the whole listing.
- `approve_update` runs the full refresh-time validation; a failing proposal answers 422 `library_skill_invalid`.
- `finish_refresh` is compare-and-set on the head (or an epoch bumped by `forget_head`).
- Refresh takes the org budget lock around sum-and-insert.
- Per-library single-flight and a deadline for the listing; `commit_sha` equal to the cached head is served from the cache.
- 429/503 from the git host: no failure increment; next attempt after the capped `Retry-After`.
- `required_access`: the linter accepts only `read`; `docs/09` says so.
- Operator page corrected.
