## Items
1. **Compose runner reaches the rootless podman socket** (`docs/15` §Development: the `runner` service in profile `hosted` mounts `${XDG_RUNTIME_DIR}/podman/podman.sock` with `label=disable`).
   - Today the distroless `nonroot` runner (uid 65532) maps to a host sub-uid under rootless podman and can't open the socket (`srw-rw---- alex:alex`).
   - Fix it in `deploy/compose/compose.yaml` without weakening the other services. Preferred: `userns_mode: keep-id` with the runner running as the invoking user's uid (e.g. `user: "${AURORA_UID:-1000}:${AURORA_GID:-1000}"`, which `setup.sh` writes into `.env`).
   - Alternative: container-root under rootless podman, which equals the invoking user and is no more privileged than the socket access itself. Document the reasoning in a compose comment and in `docs/15`.
   - The `hosted` profile must also select the podman backend (`AURORA__RUNNER__BACKEND=podman` on the runner service in that profile), the sandbox image (`runner.image`, FIX-003) and the sandbox network.
   - `setup.sh` checks that `podman.socket` is active (`systemctl --user is-active podman.socket`) and prints the fix if not.
   - Prove it by following `docs/operator/install-compose.md` from a clean state with `COMPOSE_PROFILES=hosted,llm-mock` (prefix the project `aurora-o15`): sign up, then create an agent (the fake harness, or claude-code via the mock), then send a chat message. The answer arrives from a real podman sandbox. Record the transcript in the task report and update the docs.
