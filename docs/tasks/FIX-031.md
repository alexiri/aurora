# FIX-031: Nightly `sandbox-base-smoke` is red — the sandbox image has no `rpm` binary, so the base-image override smoke can never compare package lists

## Problem

The nightly job `sandbox-base-smoke` (`.github/workflows/nightly.yml:119-125`, `SMOKE_FULL=1 bash scripts/images/sandbox-base-smoke.sh`) has **never been green**: run 42946111582 (2026-11-11) failed with exit 127, `crun: executable file 'rpm' not found in $PATH: OCI runtime attempted to invoke a command that was not found`.

- `scripts/images/sandbox-base-smoke.sh:61-62` (and the SMOKE_FULL=1 twin for the full target) compares the installed package lists of the two built images with `podman run --rm --entrypoint rpm <image> -qa --qf '…'`. The script exists to prove the P3-019 invariant (a `SANDBOX_BASE_IMAGE` override changes where the base comes from, never what the image contains — docs/18 §Deployment-neutral defaults; AUDIT-003 F-9).
- `images/sandbox/Containerfile` `os` stage (line 43) installs `shadow-utils glibc-common postgresql` with `--setopt=install_weak_deps=False` — the `rpm` binary is not in that list and not guaranteed by any of them on the pinned AlmaLinux 10 base (`ARG SANDBOX_BASE_IMAGE=…almalinux:10@sha256:5a4b41a4…`). The build succeeds; only the later `--entrypoint rpm` invocation fails.
- Effect: a red nightly every run, obscuring real nightly regressions, and the deployment-neutral-defaults invariant (a mirror/override base must produce an identical image) is not actually being verified.

## Goal (priority: **high** — red nightly gate, size: **S**)

The sandbox image ships the `rpm` binary so the smoke script's package-list comparison works; the nightly `sandbox-base-smoke` job goes green.

## Scope

1. `images/sandbox/Containerfile` — add `rpm` to the existing `dnf -y install --setopt=install_weak_deps=False shadow-utils glibc-common postgresql` list in the `os` stage (one word). It must be present in every target built from that stage (`base`, `sandbox`, `sandbox-min`) because the smoke compares both `sandbox-min` (default) and the full `sandbox` target (`SMOKE_FULL=1`).
2. Nothing else changes: `org.aurora.capabilities` labels, users, paths, the supervisor build, the chromium-wrapper — untouched.

## Acceptance
