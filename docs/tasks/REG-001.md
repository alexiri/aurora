# REG-001: `aurora-registry` manifest model, strict parsing, templates, in-manifest validation

## Goal
Typed model of manifest contract v1 (`plugin.yaml`) with strict parsing, the template language, and every validation rule that can be checked from the manifest alone.

## Linked requirements
- M3/09 `§3 Manifest contract v1` (3.1–3.4 incl. `about`, `credentials`/`metadata`, `connect[]` kinds `oauth2`/`fields`/`hook`, `probe`, context variables, `hosts[]`, `token`, `tools`, `approvals`, `agent`, `database`), `§4 Template substitution` (namespaces and where each is allowed), `§5 Mechanisms` (closed list; decoders), `§6 Validation` (the in-manifest subset below); SEC-16/17 (inputs), SEC-18 (human strings sanitized on load).

## Context
- Read `docs/09-app-plugins.md` §3 through §6 (from "## 3. Manifest contract v1" to "## 7. Host claims"). Normative.
- Reuse: `aurora_policy::HostPattern` / `PathPattern` (host patterns with ≤1 `*`, path patterns), `aurora_core::sanitize::{one_line,label,block}`, `aurora_core::limits` (`AGENT_SNIPPET_MAX`, `SUMMARY_LIMITS` consts). Workspace deps: `serde`, `serde_yaml`, `serde_json`, `thiserror`, `regex`, `aurora-policy`, `aurora-core`. Do not edit root Cargo.toml.

## Scope
### In scope (`crates/aurora-registry/src/{lib,manifest/*,template,validate/*}.rs`, `crates/aurora-registry/tests/**`, `crates/aurora-registry/tests/fixtures/manifests/*.yaml`)
- `manifest` module: serde types for the whole contract with `#[serde(deny_unknown_fields)]` (strict at contract 1); `contract` must be 1; ids `[a-z][a-z0-9_-]{1,47}`; semver `version`/`min_core` (`Manifest::parse(yaml, running_version) -> Result<Manifest, Vec<Violation>>`). Human strings (`name`, `description`, labels, tool names, help/notes, approval titles/labels) are sanitized on load with `aurora_core::sanitize`.
- `Mechanism` and `Decoder` as closed enums matching `§5` (unknown → violation), `Inject` step variants (`bearer`, `basic`, `header`, `query`, `remove_header`, `path_template`, `path_regex` (anchored, ≤256 chars, compiles)), `route` (`rewrite_host` + zone), guard (`tenant`), finalize (`aws_sigv4`), transform (`git_commit_trailer`), intercept (`oauth_token_endpoint`), passthrough (`registry_token_challenge`).
- `template`: parse `{namespace.name}` tokens (only those; literal braces otherwise rejected), `Template::references()`, and `check(allowed_namespaces, declared credentials/metadata/fields, permitted context)` per the `§4` table (which namespaces are allowed where).
- `validate::manifest(&Manifest) -> Vec<Violation { code, path (JSON-pointer-like), message }>` implementing these `§6` rules: unknown keys / contract / `min_core` > running; duplicate app ids within the package; duplicate tool ids within an app; host patterns with >1 `*` (via `HostPattern::parse`); every tool host covered by the app's `hosts[].match`; probe URL host and approval `link` host declared (in `hosts` or `about.web_hosts`; link must be https); token endpoint https (or template with a `zone`); tenant/rewrite templates constrained to a declared zone (zone **syntax** only — the public-suffix breadth check is REG-002); template references to undeclared credentials/metadata or unpermitted context variables; `permissions.hooks` equals the set referenced (`connect.kind: hook` ⇒ `connect.authorize`/`connect.exchange` per `§8.2` names used in `§3.2`, `token.kind: hook` ⇒ `token.mint`, `summarize: hook` ⇒ `approval.summarize`); `egress` must not contain `approval.summarize`; `agent.env` names `[A-Z][A-Z0-9_]*` and not reserved (`PATH`, `HOME`, `USER`, `SHELL`, `TZ`, `LANG`, `AURORA_*`, proxy and CA variables `HTTP_PROXY`/`HTTPS_PROXY`/`NO_PROXY`/`ALL_PROXY` (any case), `SSL_CERT_FILE`, `SSL_CERT_DIR`, `REQUESTS_CA_BUNDLE`, `NODE_EXTRA_CA_CERTS`, `CURL_CA_BUNDLE`, LLM client variables `ANTHROPIC_*`, `OPENAI_*`); stub paths relative, normalized, confined to home (no `..`, no absolute); `agent.instructions` ≤ `AGENT_SNIPPET_MAX`; approval summary limits (title ≤120, ≤12 fields); approval header sources not in the forbidden list; `database` (phase 2) accepted only as `{engine: postgres}`.
- Group wildcard superset check: record as a TODO for REG-002 (needs matcher reasoning) — do not implement here.

### Out of scope
- Archive/digest/signature, icon/guide checks, PSL zone breadth, reserved hosts, cross-package duplicates, WIT checks (REG-002/M3 hooks); snapshot compiler.

## Acceptance criteria
- [ ] A complete valid fixture manifest (`tests/fixtures/manifests/valid-full.yaml`) exercising every section parses with zero violations; a minimal `fields` + `bearer` manifest parses.
- [ ] One invalid fixture per rule above (`invalid-<rule>.yaml`) yields exactly the expected violation `code` (table-driven test).
- [ ] Template tests: valid tokens, unknown namespace, disallowed namespace in context (e.g. `fields.*` in `inject`), unbalanced braces.
- [ ] Sanitization on load: a name with bidi controls comes out clean.
- [ ] `cargo test -p aurora-registry`, clippy `--all-targets -D warnings`, fmt.
