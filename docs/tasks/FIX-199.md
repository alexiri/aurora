# FIX-199: SSH keepalives count as activity (D-434)

## Goal
The owner decided this on 2026-11-21 (D-434), after P5-REFINE-20 pass 3.

On the verification cluster, an SSH session running `sleep 600` was closed at exactly 600 s with "aurora: disconnected: no activity". The client was alive and sending OpenSSH keepalives, but the terminator counts only channel bytes as activity (`SSH_IDLE_TIMEOUT`, C-794).

From now on, keepalives count as activity:
- **They reset the idle timeout** (600 s), exactly as channel bytes do.
- **They keep the computer's SSH-held wakefulness going:** `SSH_AWAKE_GRACE` restarts on a keepalive, as on a channel byte.

Nothing else changes:
- No new limit. A keepalive-only session still ends at `SSH_MAX_LIFETIME` (4 h).
- The computer's SSH-held wakefulness still stops at `SSH_AWAKE_CAP` (4 h per boot).
- Both stay configurable lower only.

## Change
1. **`services/aurora-terminator` (russh server).**
   - Count as session activity:
     - an OpenSSH keepalive (`keepalive@openssh.com` global request, and the channel-level `keepalive@openssh.com` request);
     - any other no-op request a client sends to stay alive.
   - Call `Stats::touch()` for them (`state.rs:68`), so `idle_for()` resets.
   - Keep the byte counters for channel data only. The idle loop at `server.rs:752` is unchanged.
2. **The wake path.** Whatever restarts the SSH-held wakefulness on a channel byte must also restart on a keepalive:
   - the stamp the terminator or runner sends (C-1058, `POST /v1/runner/terminal/keep-awake` with `ssh`);
   - or the activity the API reads.
   
   Read P4-SSH-2 and P5-REFINE-4 (`docs/tasks/`), and `services/aurora-runner/src/api.rs` (`KEEP_AWAKE_PATH`, fixed in P5-REFINE-20 batch 5). Find the actual path; don't add a second one.
3. **Rate.** A client may send keepalives every second. Rate-limit what each keepalive triggers (the stamp, a DB write) the way channel bytes are limited today, e.g. at most one stamp per half grace. A keepalive must never cost a DB write or an API call on its own.
4. **Words.** The SSH page (`P5-REFINE-15`'s "SSH you can copy" section) says, in one line: "A session with no output stays open while your SSH client is connected, up to 4 hours." Update `docs/11` §SSH and C-794's idle row (keepalives count) in `docs/API_CONTRACTS.md` first.

- **Wake:** a keepalive-only session restarts the awake grace (unit or IT at the level the existing keep-awake tests use), and each keepalive costs at most one stamp per half grace.
