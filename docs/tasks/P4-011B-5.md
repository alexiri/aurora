# P4-011B-5: Park-and-resume and Web Push end to end, operator docs — **medium, phase 5**

## Goal
Prove the whole journey through real binaries and document it for operators: a long-deadline
approval parks, the agent ends its turn, the sandbox parks, a person approves from a chat card, the
resume turn wakes the agent and the identical request goes through exactly once; a decider without
an open tab gets a push the mock push service can decrypt; a revocation and an expiry end the story
without a turn. Then the operator pages and the manual release check for real push delivery.

## Scope
### In scope
1. **`scripts/e2e/approvals-park.sh`** (new; or an extension of `hosted.sh` if its setup is reused —
   decide and say why): a workspace rule `require_approval` with `approval_timeout_secs = 7200`,
   parking on (threshold 900); the fake harness issues the request → 403 `approval_parked`, the
   turn ends `done`, the transcript has `approval.pending { parked: true }`, the mock upstream saw
   nothing; idle-stop shortened so the sandbox parks; a linked chat user approves from the fake
   connector's card → one system follow-up turn (door ref `approval:…`) wakes the sandbox, the fake
   harness repeats the identical request → forwarded once, request log `approved` + `resumed`; a
   second identical request → a new park (single use). Variants: deny → "denied" follow-up and the
   cooldown answer; deadline expiry (short max for the test) → notice, no turn; approve then freeze
   → grant revoked, the repeat is not matched; switch turned off with a ready grant → still
   consumed once.
2. **Push leg** in the same script: a decider with a registered synthetic subscription (keys
   generated by the test client, endpoint on an allow-listed host overridden to the mock) and no
   open stream receives exactly one push for the parked approval and one reminder at half time
   (short deadline); the mock decrypts and asserts the payload fields and that no canary string
   from the request appears; a decider holding an open `approvals/stream` gets none; sign-out
   deletes the subscription and the next approval sends nothing.
3. **Playwright leg** (`web/e2e`): reuse P4-011B-4's CDP delivery against the e2e stack once
   (opt-in through the UI, deliver, click → Approvals page with the parked chip).
4. **Operator docs**: `docs/operator/limits-and-approvals.md` (parking: when to turn it on, the
   cross-key rule, what agents are told, byte-identical caveat, metrics and the alert on
   `aurora_approvals_parked_pending`), a new `docs/operator/web-push.md` (requirements, Helm values,
   egress, generated vs operator key, rotation, `push status`, the inline-store note, shared-computer
   advice, troubleshooting by `aurora_push_sent_total{result}`), and the **manual release check**
   (Chrome desktop, Firefox desktop, Android Chrome, iOS Home Screen app: opt in, receive, click,
   rotate, sign out) linked from `docs/operator/README.md` and `install-helm.md`.
5. `docs/tests/security-coverage.md`: "Proven by" for SEC-74/75/76/102 with the test names that
   exist on master after P4-011B-1..4 (grep each before citing).

### Out of scope
Feature code (P4-011B-1..4) — a failing journey is reported to the coordinator with the failing
step, not fixed here unless it is in the e2e harness itself.

## Acceptance criteria
1. The e2e script passes locally twice in a row and in CI, with no `SKIPPED:` line; each variant of
   scope 1 and 2 asserts its outcome from the API/request log/mock, not from timing.
2. The script fails if the upstream mock ever sees the parked request before approval (assert the
   count at each step) and if the repeated request is forwarded twice.
3. The Playwright leg passes in the CI Chromium project.
4. Operator pages build (links resolve) and name only metrics the code emits (grep).
5. `security-coverage.md` rows cite real test names; guards exit 0 (`docs-routes.py` keeps the
   invariant table contiguous).
