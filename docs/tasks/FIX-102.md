# FIX-102: Helm chart — the Gateway API preview route, ops ports, probes, half-enabled switches, hook privileges (REVIEW-5 OPS-1/6/7/8/9/12/13/16, DEP-1/2/9/12) — **high (item 1)**

## Problem
1. **With `gatewayApi.enabled` and `relay.enabled` the preview rule shadows the dashboard** (coordinator-verified). `deploy/helm/aurora/templates/routing.yaml` (~80–88) scopes the relay rule with `rules[].hostnames`; `HTTPRouteRule` has no such field (hostnames exist only at `spec`). The API server either rejects the object or prunes the field, leaving a host-less `PathPrefix /` rule to `relay:4112` listed before the web rule (~112), so the dashboard root is served by the relay. `scripts/guards/edge-routes.sh` (~36, ~121) was written with the same assumption and passes. `docs/15` §Networking: the wildcard host is "a second host … Without it nothing about the edge changes."
2. **Ops listeners cannot be scraped.** The runner's ops port 4106 is in no container port list, Service or NetworkPolicy rule; relay 4193 and connector-host 4192 are container ports with no ingress rule (FIX-074 added the relay rule — check and keep it); there is no monitoring-namespace peer and no ServiceMonitor, while `docs/15` §Observability and the alert runbooks assume scraping.
3. **Probes are TCP sockets** (`_helpers.tpl` ~153–157) although `docs/15` says "Kubernetes probes use plain `/readyz`": an API replica without its database, or a gateway reporting `down`, stays in rotation.
4. **Half-enabled features render.** `config.scim.enabled: true` with `scim.enabled: false` serves `/scim/v2` with no edge route (`configmap.yaml` ~66–70; terminal and previews already refuse disagreement); terminal or relay enabled with `runner.enabled: false` renders runner-bound egress and no runner.
5. **Egress wider than needed.** Runner Kubernetes API egress defaults to `0.0.0.0/0` on 443/6443 (`networkpolicy.yaml` ~194–205) although the secrets hook already derives the API server addresses by `lookup` (`hooks.yaml` ~78–91) — and that hook itself falls back to `0.0.0.0/0` when the lookup is empty.
6. **Hook privileges.** One ServiceAccount for both hook Jobs may `get`/`create`/`patch` every Secret in the namespace (`hooks.yaml` ~22–35), including the gateway CA key.
7. **Silent key regeneration.** The secrets hook creates fresh encryption keys when the generated Secret is absent (`hooks.yaml` ~155–166) — after a namespace restore without the Secret, stored credentials become undecryptable with no error. (Trace first whether the API refuses to start in that state; if it does, document that instead.)
8. **PodDisruptionBudgets block drains.** `minAvailable: 1` is rendered for single-replica runner, relay and connector host (`_helpers.tpl` ~242–253).
9. **Guards.** `sandbox-network.sh` checks only the sandboxes namespace; nothing asserts that core ingress from sandboxes opens exactly 4102 and 4105. `hook-policies.sh` exempts `migrate`, whose allow policy is a regular resource — an upgrade from a chart that predates it default-denies the migrate Job.

## Scope

- Hook RBAC: one ServiceAccount per Job; `resourceNames` on `get`/`patch`; `create` only where needed.
- Key regeneration: fail with an actionable message when the Secret is absent and the release is an upgrade.
- PDB only when replicas ≥ 2.
- Guard additions with mutation self-tests; the migrate allow policy rendered as a hook resource.
- Hygiene: the namespace on the `-runner-services` RoleBinding subject.
