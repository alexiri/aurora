# GOV-001: Governance library — org document, validation, effective governance, compliance

## Goal
One implementation of `08 §11` governance semantics (D-40), used by the API (PUT validation, effective view, secret admission) and the gateway (enforcement).

## Linked requirements
- M2/08 `§11.1 Levels` (effective = instance ∩ org; postures = max(instance minimum, org)), `§11.2 Organization governance document` (shape + every validation rule + default for new orgs), `§11.3` compliance of a stored origin, `§11.4` posture semantics, `§11.5` model allow-lists, `§11.6` egress posture + allow-list (org ∪ instance baseline, ≤ `EGRESS_ALLOWLIST_MAX` 500); SEC-35, SEC-36, SEC-38, SEC-39; `18 §Governance` (validation suites: below instance minimum, scope/list subset rules, defaults for new orgs).

## Context
- Read `docs/08-secrets-credentials.md §11` (11.1–11.8). Normative.
- `aurora-config`: instance ceiling = `governance.llm.{allowed_key_scopes, minimum_posture, require_key_origin, known_llm_hosts(_extra)}`, `governance.egress.{minimum_posture, baseline_allowlist}`, `llm.endpoints[]` (allowed_models, key_origin). `aurora-llm` (this crate): `ProviderRegistry`, `Endpoint`, `KeyOriginRule`, `KeyOrigin`, `origin::complies`, `OriginMethod`. `aurora_policy::{HostPattern, PathPattern}` for allow-list entries (aurora-llm may depend on aurora-policy; it must not depend on aurora-db).

## Scope
### In scope (`crates/aurora-llm/src/governance/**` + tests)
- `OrgGovernance` serde model of the `§11.2` JSON (missing sections ⇒ defaults derived from the instance — `{}` means defaults); `GovernanceError { code: "governance_invalid" | "governance_below_instance_minimum", path, message }` list.
- `validate(doc, &Instance) -> Result<OrgGovernance(normalized), Vec<GovernanceError>>` implementing every rule in `§11.2` (endpoints must exist; `key_scopes` ⊆ instance; `allowed_models` subset rule; `origin` subset rule and the `endpoint`-method refusal except `allowed_team_ids` which upgrades to `litellm_team`; postures ≥ instance minimum; allow-list entries parse as policy patterns, ≤500).
- `default_for_new_org(&Instance) -> OrgGovernance` (every instance endpoint allowed, instance scopes, no narrowing, postures = instance minimums, empty allow-list).
- `Instance::from_config(&RawConfig/llm+governance sections, &ProviderRegistry)`.
- `effective(&Instance, &OrgGovernance) -> EffectiveGovernance { llm_posture, egress_posture, endpoints: map id → EffectiveEndpoint { permitted, key_scopes, allowed_models (empty = any), origin_rule: Option<KeyOriginRule> (instance rule narrowed by org; method upgraded to litellm_team when org adds team ids), source markers instance|org per value }, egress_allowlist (org ∪ baseline as parsed patterns), governed_hosts }`; postures `max(instance minimum, org)`.
- Helpers used by enforcement: `EffectiveGovernance::{endpoint_for_host(host) , is_known_llm_host(host), key_permitted(endpoint_id, scope), origin_complies(endpoint_id, stored_origin_json, current_value_version) (per §11.3 incl. value_version match; method endpoint ⇒ true; no rule ⇒ true), model_allowed(endpoint_id, ModelRef) -> Result<(), Vec<String>> (Unknown ⇒ refuse when list non-empty), egress_allowlisted(host, path)}`.
- `StoredOrigin` serde for `secrets.origin` JSON (`status`, `method`, ids, `value_version`, `checked_at`).

### Out of scope
- DB access, API routes, gateway wiring (GW-005, BE-03x).
