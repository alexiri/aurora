# REG-003: `aurora-registry` snapshot compiler, host-claim conflicts, permission diff, snapshot loader

## Goal
Deterministic compilation of active packages into the registry snapshot consumed by gateway, API and hook host; conflict detection for host claims; the permission-widening diff that drives auto-activation; snapshot selection and a typed snapshot + host index for consumers.

## Linked requirements
- M3/09 `§9 Registry snapshot` (canonical JSON: sorted keys, arrays sorted by id; content hash; `format`/`contract`; activation rule: highest supported contract N/N−1, then most recent), `§7 Host claims and conflicts` (claims = (host pattern, path prefix); conflict when some (host, path) matches both; winner decisions by `claim_fingerprint`; loser compiled `claim_status: lost`; overlap with known LLM hosts accepted but never injected), `§10 Package lifecycle` (widening = new hook, new egress host, new context variable, new host claim, new reserved-adjacent zone; narrower/identical ⇒ auto-activate), `06 §MITM lane` step 2 (host index lookup: exact first, then suffix patterns, longest suffix wins; longest path prefix among non-lost claims); SEC-16.

## Context
- Read `docs/09-app-plugins.md` §7, §9, §10 and `docs/03-data-model.md` tables `plugin_packages`, `registry_snapshots`, `host_claim_decisions` (columns only, to align field names like `claim_key`/`claim_fingerprint`).
- REG-001/002: `Manifest`, `Package`, `validate::*`, `HostPattern`/`PathPattern` from aurora-policy; I-14 mechanism shapes.

## Scope (`crates/aurora-registry/src/{snapshot,claims,diff,index}.rs` + tests)
- `claims::claims(&Manifest) -> Vec<Claim { app_id, host_pattern, path_prefix, claim_key, fingerprint }>` (define `claim_key` = canonical `host|path_prefix` string and `fingerprint` = sha256 of the claim's injection-relevant definition; document); `conflicts(&[ (package_id, Claim) ]) -> Vec<Conflict { claim_key_a, claim_key_b, … }>` using pattern-overlap reasoning (two host patterns overlap if some host matches both; path prefixes overlap if one is a prefix of the other); a conservative overlap is acceptable (document).
- `compile(packages: &[ActivePackage{manifest, digest, publisher, hooks_digest}], decisions: &[Decision{claim_key, fingerprint, winner_package_id}], reserved_hosts, contract) -> Result<CompiledSnapshot { json: Vec<u8> (canonical), hash: hex sha256, contract }, CompileError>`; unresolved conflicts ⇒ error listing them (activation waits); losers ⇒ `claim_status: "lost"`.
- `diff::widens(old: &Manifest, new: &Manifest) -> Vec<Widening>` per `§10`.
- `index::Snapshot` (serde of the JSON) + `HostIndex::lookup(host, path) -> Option<&HostEntry>` (exact host first, then suffix patterns longest-suffix-wins; longest path prefix; skip `lost`); `Snapshot::app(app_id)`, tool lookup by (host, path, method).
- `select_active(candidates: &[(contract, activated_at, hash)], supported: u32) -> Option<hash>`.

### Out of scope
- DB ingestion/lifecycle API, gateway mechanism execution, hook host.

## Acceptance
- [ ] Determinism: compiling the same packages in different input orders yields identical bytes and hash (test); JSON keys sorted.
- [ ] Conflicts: two packages claiming `api.x.com` (and `*.x.com` vs `a.x.com`) conflict; disjoint paths don't; decision resolves and loser is `lost`; changed fingerprint invalidates the decision.
- [ ] Widening table tests (each widening kind; narrower ⇒ empty).
- [ ] HostIndex lookup precedence tests; `select_active` N/N−1 rule.
- [ ] `cargo test -p aurora-registry`, clippy, fmt.
