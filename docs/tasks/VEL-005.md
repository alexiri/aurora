# VEL-005: Faster, honest quick gate and test parallelism — reverse-dep scope, nextest, inner-loop clippy flags, more test threads

## Goal
Owner priority (2026-11-13): local compile/test waits. VEL-002 built `scripts/dev/quick-gate.sh`; review found it is both slower and narrower than it should be:
- It maps a change to the touched crate only, so a change in `aurora-core`, `aurora-db` (incl. migrations) or `aurora-protocol` never checks the crates that depend on it — it says "passed" while api/gateway are broken (code review 2026-11-13, finding O9).
- It runs plain `cargo test` (serial binaries) and `clippy --all-targets --all-features` per crate.
- Tests run at 8 threads because every `TestDb` opens a pool of 5 against the shared dev Postgres (`max_connections` 100). Since VEL-003 (template databases) the api it-suite is CPU-bound, so threads are the next lever on a 16-core host.

## Linked requirements
- docs/18-testing.md §"Quick gate (local loops)" (VEL-002) — the gate stays a dev-loop tool, **not** a merge gate.
- `.config/nextest.toml` (OPS-016/OPS-019), `crates/aurora-testkit/src/lib.rs` (`TestDb`, VEL-003 `template.rs`).

## Scope
### In scope
1. **Reverse-dependency scope.** From `cargo metadata --format-version 1` (workspace members only), expand the touched crate set to its workspace dependents for **clippy** (`cargo clippy -p …` covers type errors in dependents cheaply). Tests stay on the directly touched crates plus, when `aurora-db/migrations/**` changed, `aurora-db` and `aurora-api` (migrations change behaviour everywhere). Print the expansion in the plan so the user sees why a crate is included. Cache nothing; `cargo metadata --no-deps` is fast.
2. **nextest when installed**, else `cargo test` as today (detect with `cargo nextest --version`). Doctests: nextest skips them — run `cargo test --doc -p <crate>` only for touched crates that have doctests (or note that they are skipped; your call, documented).
3. **Inner-loop clippy flags**: default mode uses `--all-targets` without `--all-features` unless the touched crate defines features that gate code (detect from metadata: non-empty `features` other than `default`); `--all` keeps `--all-features` (CI parity). Make sure clippy and test use flags that share build artifacts where possible, and say in the doc what CI parity is lost.
4. **Test parallelism**: lower the `TestDb` pool from 5 to 2 connections (check first that no test needs >2 concurrent connections on its pool — grep for `join!`/`try_join!`/spawned tasks using `db.pool` in tests; if some do, make the size an env-overridable default, `AURORA_TEST_POOL_SIZE`), and measure the api it-suite at 8 vs 12 vs 16 nextest threads on an idle machine against aurora-dev-pg. If the dev Postgres needs more than 100 connections for the winning setting, raise it in `deploy/dev` (the aurora-dev-pg container definition — find where it is started) and document it; CI's own Postgres service must get the same setting if CI's thread count changes (it does not have to). Set `test-threads` in `.config/nextest.toml` `[profile.default]` to the measured best (keep `[profile.ci]` unchanged unless you also measured CI).
5. **Template-DB provenance** (finding O8): `crates/aurora-testkit/src/template.rs` stamps provenance in a `public.aurora_template_meta` table that every cloned test database then carries (a schema difference vs. the `AURORA_TEST_TEMPLATE_DB=0` path). Move the stamp to `COMMENT ON DATABASE` (or the template's name) and use a stable hash (sha256 over the migration files) instead of `DefaultHasher`. Keep the advisory-lock/seal/rename protocol as is.
6. **Disk warning**: the gate prints one line when `target/` exceeds 60 GB, naming `just clean-stale` (never deletes anything itself).
7. Docs: docs/18 §Quick gate (scope rules, nextest, flags, what is not CI-parity), `docs/ops/build-performance.md` (thread/pool measurements with load context).

### Out of scope
- Cargo profiles / incremental (VEL-004), wasmtime feature (VEL-006), crate splits (VEL-007).
