# FIX-005: API runtime follow-ups required by the spec (FUP-M2/M4)

## Goal
Close the spec-required follow-ups in the API runtime before the phase-0 exit.

## Items
1. **SSE streams close on session revocation** (FUP-M2; `docs/04` §Sessions: "Revocation is immediate"). Long-lived SSE responses (`/v1/conversations/{id}/stream`, the approvals stream, and any other `text/event-stream` route; grep for them) must end promptly, within ≤ 30 s (the allowed cache window), when the authenticating session is revoked, signed out or expired, or when the API key is revoked or the user suspended.
   - Re-validate on the existing NOTIFY used for sign-out cache flushes, plus a periodic re-check.
   - Test: open a stream, revoke the session, and the stream ends; same for key revocation.
2. **Durable answer text** (FUP-M4.1; `docs/05` §Turn and transcript persistence, `docs/10` §Transcript events).
   - The final answer `text` of a turn must not depend on an in-memory API buffer: a restart of the API replica mid-turn must not lose answer text, and a channel mirror (BE-072) must post the complete answer.
   - Find the buffer (BE-052, `domains/hosted/lifecycle.rs` / reports `turn.events`) and persist the durable `text` events as they arrive per the answer rule in 10, or persist the buffer.
   - Test: simulate the API dropping in-memory state between `turn.events` and `turn.result` (a fresh `AppState`); the final durable text is complete.
3. **Render inputs** (FUP-M4.5; `docs/10` §Agent instructions; `docs/12` §Home projection, the `render_inputs` part). `services/aurora-api/src/domains/hosted/home.rs` currently sends `"apps": [], "channels": [], "peers": []`. Fill them:
   - apps with an effective grant: name, accounts (connection labels + ids for `x-aurora-connection-id`), docs/spec links, the plugin `agent.instructions` snippet (≤ `AGENT_SNIPPET_MAX`), with the snippet marked third-party
   - channels (the agent's active presences: platform, tenant label, mode, handle)
   - peers (agent links with policies)
   - schedules summary
   - Check that the supervisor renderer (`services/aurora-supervisor/src/instructions.rs`) consumes these fields with the shapes it expects, and fix whichever side diverges, matching the S-09-era wire. Bump the home-sync generation on changes to grants/connected apps, presences and peers (12 lists them; verify each bump exists, and add any missing).
   - Tests: API side, the render inputs contain the app snippet, channels and peers; supervisor side, the rendered instructions contain the labelled third-party plugin block, the channels and peers sections.
4. **Model-list cache** (FUP-M4.4): if `docs/08` §Model selection specifies a 10-minute cache for `/v1/agents/{agent}/models` upstream lookups, implement it (per-endpoint, invalidated on key changes); otherwise record that the spec doesn't require it and close the item.
