# FIX-116: Configuration and limits — ignored keys, unguarded development switches, secrets in config, invitation links in logs, the setup gate (REVIEW-5 LIM-1..LIM-10, PLAT-4/6/7/8/9/10, CONN-9) — **medium, security**

## Problem
The recurring pattern across both review waves: a limit or key is specified, parsed and validated, and then nothing reads it.

1. **Ignored keys.** `terminal.awake_cap_secs` and `terminal.wake_window_secs` are range-checked and never read; the terminal keep-awake uses `previews.awake_cap_secs` (`services/aurora-api/src/domains/runner_plane/work.rs` ~144, ~181; `crates/aurora-db/src/repo/sandboxes.rs` ~166–175). `previews.session_ttl_secs` and `previews.session_idle_secs` are parsed, unvalidated and unused (`crates/aurora-config/src/raw.rs` ~575; `docs/15` ~96 documents them as operator keys). `previews.bytes_per_share_day` is used since FIX-072 but unvalidated (zero puts every share over quota).
2. **Development switches accepted in production.** Only the dev IdP and `runner.dev_supervisor_binary` are refused outside a loopback install. Unguarded: `runner.dev_allow_external_network` (removes the sandbox network isolation of SEC-02 with one warning line), `plugins.allow_unsigned` (unsigned packages and connector manifests load; `docs/15` ~171 "dev only"; D-142's wording about the self-hosted path is also wrong — `connectors/plane.rs` never accepts an empty signature), `hosted.allow_fake_harness`, `connector_host.test_types`. `ratelimit.api.enabled = false` removes every `/v1` limit including the anonymous and rejected-bearer buckets (`http/apilimit.rs` ~605) with no guard.
3. **Secrets in the ConfigMap.** The only way to give the mailer a password is userinfo in `email.smtp_url`, which validation accepts (`validate.rs` ~1966; `urlcheck.rs` reports userinfo and nobody refuses it) and the chart renders into `aurora.toml` in a ConfigMap; `docs/15` ~71 says the SMTP password is "referenced from config" by an environment secret that does not exist. Same for `gateway.egress_proxy`.
4. **Invitation links in the log.** With SMTP unset — the default — `LogMailer` writes the full `/join?token=…` link at info level (`services/aurora-api/src/domains/auth/mail.rs` ~47–51) (coordinator-verified). Acceptance still needs the invited e-mail, which bounds the exposure.
5. **The fresh-instance gate closes on the admin's own sign-in.** Unsaved placement refuses ordinary users only while no organization exists (`placement/service.rs` ~66–72); the first admin's sign-in creates one, after which every newcomer gets their own org until the wizard is saved. `docs/04` ~125 specifies exactly that condition — the spec is the defect.
6. **Missing bounds and mismatched defaults.** `relay.request_body_max_bytes`: Rust default 100 MiB, chart and `docs/23` 32 MiB, `docs/15` 100 MiB "lower only", no range check; `relay.max_streams*` unchecked; `runner.orphan_grace_secs`/`capacity_wait_secs` accept zero; `approvals.timeout_secs` has no floor (rules have 60 s); `hosted.background_cap_secs` has no ceiling; SCIM token lifetime ceiling is 730 days in `docs/02`/`docs/03`/`limits.rs` and 1,825 in the validator and `docs/15`.
7. **Constants nobody reads** (beyond FIX-072/074's): `LIBRARY_REFRESH_INTERVAL`, `SCIM_RATE`, `SCIM_TOKEN_MAX_DAYS`, `TERMINAL_AUTH_CACHE`, `TERMINAL_AWAKE_CAP`, `PREVIEW_AWAKE_GRACE`, `PREVIEW_AUTH_CACHE_NEG`, `PREVIEW_REQUEST_BODY_MAX`, `PREVIEW_AWAKE_CAP`, `TURN_PROGRESS_INTERVAL` (the supervisor ticks every 10 s), `ACCESS_NOTIFY_BULK` (not implemented: one notification per user).
8. Name sanitising keeps bidi and zero-width characters (`placement/template.rs` ~175; `oidc/service.rs` ~428; `tenancy/service.rs` ~42); two phase-4 migrations take `ACCESS EXCLUSIVE` for constraint validation and a non-concurrent index on large tables (`20261130000001_groups.sql`, `20261127000001_skill_libraries.sql`) — upgrade-note material.

## Spec change (apply with the fix)
- `docs/04` ~125: "Until a placement is first saved on an instance installed with this release or later, users who are not instance admins are refused with `instance_setup_pending`; an administrator's own sign-in does not end that state."
- `docs/15`: `AURORA_SMTP_PASSWORD` (and `_FILE`) with `email.smtp_username`; "development-only keys are refused unless `server.external_url` is loopback" with the list; `email.log_links` (default false).
- `docs/02`: each limit row's override column matches a key that is read; the unread constants are wired or removed with their rows; one ceiling for SCIM tokens.

## Scope
- Wire or delete each ignored key and constant (prefer wiring where a topic doc specifies behaviour; for `ACCESS_NOTIFY_BULK` mark "not implemented" with this task id if wiring is not small).
- Validation: loopback predicate for the development keys and `ratelimit.api.enabled = false`; userinfo refused in `email.smtp_url` and `gateway.egress_proxy`; the bounds in item 6; chart `fail` for the same keys; one default for the relay body size.
- SMTP credentials from the environment; `LogMailer` logs recipient and subject only unless `email.log_links` is set (dev values set it).
- Setup gate from a persisted marker (set by migration for existing instances, cleared by the first saved placement).
- Sanitiser drops format characters; upgrade notes for the two migrations.
- A guard that every `limits.rs` constant has a reader outside the file and a row in `docs/02` (and the reverse).
