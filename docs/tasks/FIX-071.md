# FIX-071: Runner preview `closed` report scoped to the reporting runner; hello-overdue readiness fence checked (follow-ups from FIX-061 / FIX-058) — **low, hardening**

## Goal
Close two follow-ups the REVIEW-4 lanes recorded:
1. `POST /v1/runner/preview-streams/closed` (`services/aurora-api/src/domains/runner_plane/preview_streams.rs` `closed`) accepts **any** authenticated runner for **any** share: it ignores its `_runner` argument and refreshes `preview_shares.last_accessed_at` and the agent's preview keep-awake stamp (`relay_repo::keep_preview_awake`) for whatever `share_id` it is given. A compromised or misconfigured runner can keep arbitrary agents of other runners awake (resource cost, defeats idle parking) and skew share access stamps. The `open` handler beside it fences on the runner's channel; `closed` must too.
2. FIX-058 fenced `fail_attempt` on "still not ready"; its lane noted that the **hello-overdue** selection (`crates/aurora-db/src/repo/sandboxes.rs` `hello_overdue`, used by `services/aurora-api/src/domains/hosted/readiness.rs` ~207) only uses the generic ready predicate. Verify whether the hello-overdue give-up can still fail a sandbox whose supervisor connected between selection and update (it goes through `fail_attempt`, which is now fenced — if so, document that and add the deterministic test; if not, fence it the same way).

## Linked requirements
- SEC-81/SEC-85 (preview streams), D-146/D-147, C-550..C-559 (runner stream API); D-158, C-580..C-589 (readiness).

## Scope
### In scope
- `closed`: act only when the share's agent's current sandbox is held by the reporting runner (the same predicate `open` uses — reuse it); otherwise return `Ok(())` without writing (it is advisory and must never fail a stream), with a `debug` log naming the runner id and share id (no other data).
- hello-overdue: the verification above + a deterministic test (a sandbox selected as hello-overdue that becomes ready before `fail_attempt` is not failed).

### Out of scope
- Anything else in the relay/preview plane.

## Analysis
- `closed` (preview_streams.rs): `open` has no runner predicate to reuse (`let _ = runner`; it fences on `channel_replica_id IS NOT NULL`), so `closed` now requires a `running` sandbox of the share's agent with `runner_id` = the reporting runner. Otherwise `Ok(())`, nothing written, `debug` log (runner id, share id).
- hello-overdue: `hello_overdue` selects on `bootstrap_used_at IS NULL`; its give-up goes through `fail_attempt`, whose FIX-058 fence skips a fully ready sandbox (supervisor bootstrapped, channel held, harness profile, home synced). So a sandbox that became **ready** between selection and update is not failed (test `hello_overdue_selection_that_became_ready_is_not_failed`). Residual, not fenced (needs `readiness.rs`/`fail_attempt`, outside Owns): a supervisor that connected (`bootstrap_used_at` set) but is not yet fully ready at update time is still given up as `supervisor_unreachable`; a recheck of `bootstrap_used_at IS NULL` inside that sweep's `fail_attempt` call would close it.
