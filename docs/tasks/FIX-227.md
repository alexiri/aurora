# FIX-227: Grafana query helpers every agent can use — `os`, `compare`, `sweep`, `--wide`, display names — and a `grafana-prometheus` skill (owner, 2026-11-22)

## Why

On 2026-11-22 the owner's NightManager agent (an SRE agent on CERN's Monit Grafana, package
`grafana` 1.2.0) ran a 12-hour review of a web service and then, at the owner's request, wrote down
every tooling problem it hit, with patches and new helper scripts tested against live Monit data. The
owner accepted the generic parts for the Grafana app, so other agents stop rebuilding them. The
NightManager-specific parts (its operator prompt, its own skills, a per-service config) stay with
the operator.

What the run showed, by cost:

1. **No standard health sweep.** The most valuable finding (a CephFS mount 98 % full, about 8 days
   to full at the 7-day rate) was found only because the agent happened to look at filesystems. An
   anomaly hunt over the requested window does not show a slow trend.
2. **OpenSearch bodies written by hand**: a Lucene query in quotes, inside JSON, inside a shell
   argument. Several queries failed and were retried.
3. **The script drops `config.displayNameFromDS`.** With several metrics under `terms` (and
   `date_histogram`), OpenSearch frames all print as `Value{host.keyword=…}`: Count, Sum and
   percentile frames of one term can't be told apart without counting positions.
4. **`percentiles` under `terms` alone returns nulls** (plugin 2.x); with an innermost
   `date_histogram` it works.
5. **One frame per series**: 8 hosts × N metrics gives long output that is hard to compare and fills
   the context.
6. **Output cut at 200 rows.** Counts read from cut output are wrong, and a `terms` answer that comes
   back with exactly its `size` buckets is only a lower bound.
7. **`--instant` still requires `--from`.**
8. **Misleading peaks**: a range query samples at its step and misses short peaks;
   `max_over_time(m[30m])` at t covers t−30m..t; one sample at a cap is not lasting saturation;
   high load with idle CPU is tasks blocked on I/O, often a network filesystem.
9. **Relative times** (`now-12h`) make evidence impossible to re-run, and the person's time zone
   differs from the sandbox's UTC.
10. **Access-log byte counts are not network bytes** (485 GB logged against 65 GB of NIC egress:
    aborted transfers), and response-time fields can be in µs.

## Work (all in `plugins/builtin/grafana/**` unless named)

### 1. `grafana-query/scripts/grafana-query`

**1.1 Column names from the display name.** A field's printed name is
`config.displayNameFromDS` when the data source gives one (OpenSearch: `<term> Count`,
`<term> Sum <field>`, `<term> p95.0 <field>`): when the field's `name` is `Value` or empty, the
display name alone; otherwise `name{labels} [display name]`. Time fields keep their name. One helper
used by `print_frame`, `--wide`, `--columns` matching (which still matches on `name`, not the display
name) and the new subcommands. The frame header line (`## frame …`) is unchanged.

**1.2 `--wide`** (every subcommand that prints frames: `promql`, `logql`, `run`, `frames`, `os`).
Per refId, frames that are exactly one time field plus one value field are merged into one table:
`## wide <n> series`, header `Time` + one column per series (named by §1.1), one row per distinct
time (sorted), empty cells as `-` (or whatever `fmt_value` prints for `None` today). Other frames of
that refId print as before after the table. Rows are cut by `--max-rows` like any frame.

**1.3 `--max-rows N`** on the same subcommands: rows printed per frame (and per wide table), default
200 as today, **1 to 5000** (outside: usage error). The cut line stays
`... N more rows not shown (M in all)`.

**1.4 Instant queries need only `--to`.** `promql --instant` and `logql --instant` accept a missing
`--from`; the script then sends `from` = `to` − 5 minutes (Grafana wants a `from` before `to`). A
`--from` equal to or after `--to` with `--instant` is also accepted and replaced the same way. A range
query without `--from` stays a usage error.

**1.5 `os` subcommand** — an OpenSearch/Elasticsearch Lucene query built from flags, so the Lucene
string is one shell argument and never JSON-escaped by hand:

```
grafana-query os --ds UID --from T --to T [--ds-type grafana-opensearch-datasource|elasticsearch]
                 [--query LUCENE] [--metric SPEC ...] [--terms FIELD[:SIZE[:ORDER]] ...]
                 [--hist INTERVAL] [--time-field F] [--raw N [--columns a,b]] [--print-body]
                 [--wide] [--max-rows N] [--account A]
```

- `--query` default `*`. `--ds-type` default `grafana-opensearch-datasource`; only those two values.
- `--metric` (repeatable, at most 6; default one `count`): `count`, `sum:F`, `avg:F`, `max:F`,
  `min:F`, `cardinality:F`, `percentiles:F[:P,P,…]` (default `50,95,99`; each P a number in
  (0, 100], at most 10). Ids `1`, `2`, … in order.
- `--terms` (repeatable, at most 3, nested in the order given): `FIELD[:SIZE[:ORDER]]`, SIZE 1..10000
  (default 10), ORDER `_count` (default), `_key` (ascending) or one of the given metrics written as on
  the command line (`sum:bytes`) → that metric's id. An ORDER naming no given metric is a usage error.
- `--hist INTERVAL` adds the innermost `date_histogram` (`30m`, `1h`, `1d`; validated with
  `parse_step`) and sets `intervalMs`. Its `field` is `--time-field` when given; when not given,
  check the plugin source: if an empty field makes the plugin use the data source's configured time
  field (the skill says it does for the default histogram), leave it empty; otherwise make
  `--time-field` required with `--hist`. Do **not** default to `@timestamp` (Monit's indexes use
  `metadata.timestamp`). Say in the completion report which it is, with the source line.
- Field names (`F`, `FIELD`, `--time-field`): `[A-Za-z0-9_.@-]{1,200}`, else usage error.
- No `--hist` and no `--terms` with a non-raw metric: usage error naming `--raw`, `--terms`, `--hist`.
- `percentiles` with `--terms` and no `--hist`: one stderr note that the plugin returns nulls in a
  terms-only table and `--hist <window length>` gives them as time series. The query still runs.
- `--raw N` (1..200): a `raw_data` metric with `size` N, `order: desc`, no `bucketAggs`; refuses
  `--metric`, `--terms`, `--hist`. `--columns` applies to it as on `run`.
- `--print-body` prints `# body: <compact JSON>` before the results (for the report's evidence).
- The body is `{"from","to","queries":[{refId "A", datasource {uid,type}, queryType "lucene", query,
  metrics, bucketAggs, intervalMs, maxDataPoints}]}`, sent through `run_body` (so the per-refId retry,
  `--columns`, `--wide` and `--max-rows` apply).

**1.6 `compare` subcommand** — "is this normal?" for one PromQL expression:

```
grafana-query compare --ds UID --from T --to T [--offsets 1d,7d] [--step 5m] [--account A] EXPR
```

- The main window and one window per offset (the main window shifted back; default `1d,7d`: the same
  time yesterday and a week ago; at most 5 offsets, each a `parse_step` duration). One
  `query_datasources` call per window, range query at `--step` (default: `fit_step` of the window).
- Per series (labels as `k=v,…`, or `(value)`): one row per window with `min p50 p95 max mean points`,
  then `p95 now / median p95 before  <ratio>x` when both exist. `(no data)` for a window without that
  series. Header lines name the expression, the step and each window's exact RFC 3339 range, so the
  report can disclose them.
- A failed window prints its error and the others still print; exit 1 if any failed.

**1.7 `sweep` subcommand** — a standard host health sweep over a window, one batched request:

```
grafana-query sweep --ds UID --selector 'job="node",instance=~"web.*"' (--from T --to T | --last 12h)
                    [--host-label instance] [--checks FILE] [--trend 7d] [--show-queries] [--json]
                    [--account A]
```

- **Default checks** (node-exporter metrics), each the worst value per host over the window, at
  `--to`, as instant queries: `up min` (`<1`), `load1 max / cpu` (`>2`), `memory used max` (fraction,
  `>0.9`), `iowait max` (`>0.2`), `reboots` (`changes(node_boot_time_seconds)`, `>0`), `network
  errors` (transmit + receive errs increase, `>0`). Take the agent's expressions in `sweep` as the
  starting point and check each one is valid PromQL.
- **Filesystems**: one row per filesystem (`node_filesystem_*`, excluding
  `tmpfs|overlay|squashfs|devtmpfs|autofs`): size, free now, free %, lowest free in the window, used
  per day over `--trend` (default `7d`, from `avail` now vs `offset <trend>`), and a linear days-to-full.
  Network filesystems (`ceph`, `fuse.ceph-fuse`, `nfs`, `nfs4`, `cifs`, `glusterfs`,
  `fuse.glusterfs`, `lustre`) mounted on several hosts appear **once** (keyed by mountpoint, type and
  size). Flag `!` below 10 % free or under 30 days to full.
- **`--checks FILE`**: JSON
  `{"checks": [{"name", "expr", "flag"?}], "replace_default_checks"?: bool, "disable_default_checks"?: [names]}`.
  At most 30 checks; `name` 1..60 characters, printable; `flag` `(>=|<=|>|<)<number>`; unknown keys,
  an unknown default name in `disable_default_checks` or a bad value: usage error naming it. The
  agent keeps this file in its own workspace (the skill shows an example; the agent's
  `linuxsoft.json` is a good one, with made-up names).
- **Placeholders** in every expression (default and file): `${SELECTOR}` (the `--selector` text, which
  must be non-empty), `${WINDOW}` (the window as a PromQL duration such as `43200s`), `${HOST}` (the
  host label, default `instance`). Any other `${…}` is a usage error. Plain text substitution of
  exactly these tokens — not the agent's `HOST` / `{SEL,` / `[W]` replacement, which rewrote any
  `HOST` substring.
- Output: a host × check table (hosts as columns, short host names), `!` before a value that crosses
  its flag; then the filesystem table; then `# ERROR <check>: <message>` per failed refId (others still
  print; exit 1). `--show-queries` prints the window and every expression sent first. `--json` prints
  `{"window", "checks", "filesystems", "errors"}` instead.
- Only `prometheus`-type data sources (Prometheus, Mimir): the request names type `prometheus`.

- **Peaks, steps and windows** — from the agent's prometheus-analysis text: a range query at step S
  shows samples at step boundaries and misses short peaks (use `max_over_time(m[S])` at step S, or an
  instant `max_over_time(m[W])` over the whole window); a point of `max_over_time(m[30m])` at t covers

  expected to fill within 14 days; shared mounts (`ceph`, `nfs`) report the same value on every host,
  report them once with their size.

  capacity trend shows only here), the options, a `--checks` file example with two service checks
  (made-up names), how to read `!`, and that `--show-queries` output is the evidence.
