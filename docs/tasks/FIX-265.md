# FIX-265: background activity: masking that covers the common forms, a list that shrinks, a Stop that reaches orphans (AUDIT-2026-11-27, security)

**Security review by the Orchestrator before merge (SEC-165).**

## Why

The audit's peer-tasks area (`docs/audit/AUDIT-2026-11-27.md`) read FIX-253 lane 1's background-work reports and the
Stop path (D-490(c)) as merged to master.

1. **The masking still shows common credential forms (medium).** `crates/aurora-core/src/sanitize.rs` (~:110-225)
   masks a value only after the exact words in `SECRET_FLAGS` (~:125), after `-p` behind
   `mysql`/`mariadb`/`mysqldump`/`mongo`/`mongosh`, after `-u` behind `curl`, and for `KEY=` names that equal or end
   in `_<secret>`/`-<secret>`. These are shown to the workspace's people in "Background activity":
   - `mysql -pSECRET` (the real mysql form; `-p secret` prompts and reads `secret` as the database);
   - `curl --user bob:pw`, `curl -ubob:pw`;
   - `PGPASSWORD=x`, `MYSQL_PWD=x` (no `_`/`-` before the secret word);
   - `-H 'Authorization:Bearer x'` (the `:` pair masks `Bearer`, but nothing masks the next word);
   - `sshpass -p pw`, `redis-cli -a pw`.
2. **The background-work list never shrinks (medium).** `services/aurora-supervisor/src/adapters/claude_code/stream.rs`
   ~:285-303 adds a `run_in_background` command to the `BackgroundSink`. Nothing removes it: `mod.rs` ~:535-552
   `background_work` returns every entry until the session dies. On the API side (`hosted/reports.rs`, the
   background-activity notice), the "live" check returns early while any `background_activity` notice has no later
   `background_stopped`. So a command that finished an hour ago still reads "still running", and newer background
   work is never shown until someone presses Stop, which kills the whole child. The idle reader on `alexiri/fix-253b`
   stops when the list is empty, so it never stops before the release.
3. **Stop misses a detached process whose parent has exited (medium).** `adapters/claude_code/launcher.rs` ~:137-197
   walks the parent-pid chain down from the harness child. The supervisor is PID 1 in the sandbox (docs/12 §Process
   model), so a process that called `setsid` and lost its parent is re-parented to the supervisor. That covers
   `setsid -f cmd`, a double fork, and `nohup setsid cmd &` from a Bash call whose shell exits. It is outside the
   child's group and outside the walk, and survives Stop. The fixes2 D test keeps the parent alive
   (`exec sleep 600`), so it doesn't cover this.
   - `.take(WALK_MAX_COUNT)` (~:150) sits on the `/proc` listing, so it truncates the snapshot, not the walk.
4. **"Background activity stopped" is recorded before anything stopped (low).** `adapters/claude_code/mod.rs`
   ~:518-528 `release()` sends the kill signal and returns `Ok`. The group kill runs about 2 s later in a spawned task
   (`launcher.rs` ~:58 `kill_group`), and the API records the stopped notice at once.
   - Commit 32a5a0a4 says a failed release is reinserted so a later Stop can retry. Only the still-shared case is
     reinserted. An errored release has already consumed the session, so the next Stop finds no entry and reports
     success.
5. **The non-Linux branch looks unbuildable (cleanup).** `launcher.rs` ~:227-228 and ~:305: the non-Linux
   `descendants` returns `Vec<Pid>` while the kill helpers take `&[Swept]`. Check whether any target builds it; if
   none does, gate the module to Linux (`compile_error!` elsewhere) instead of keeping dead branches.

## Change

1. **Masking** (one function, `aurora_core::sanitize`, used by every caller):
   - the attached short forms `-p<value>` behind the password families, `-u<value>` behind `curl`, `-a <value>`
     behind `redis-cli`, `-p <value>` behind `sshpass`;
   - `--user` (and `--user=`) / `-u` for `curl`; `--password=`/`--token=` with `=` (check they are covered);
   - suffix matching for env names: `…PASSWORD`, `…PASSWD`, `…PWD`, `…TOKEN`, `…SECRET`, `…KEY` (case-insensitive,
     no separator needed), keeping the existing exact names;
   - after a masked `Authorization:` / `Proxy-Authorization:` scheme word (`Bearer`, `Basic`, `Token`), mask the
     next word too.
   - Masking stays conservative: it may over-mask, never under-mask.
2. **The list shrinks.** The claude-code mapper removes an entry when that background command's tool result or
   completion event arrives. Match on the tool-use id, recorded with the entry, not on the command text. The API
   lets a newer `background_activity` report replace the notice, and records `background_stopped` when the list
   becomes empty. If claude-code emits no completion for a background Bash, say so in the report and fall back to
   pruning entries whose process (by pid/starttime, if recorded) is gone.
3. **Stop reaches orphans.** Set `PR_SET_CHILD_SUBREAPER` on the supervisor if it is not PID 1, and tag each harness
   child's processes by session: either a cgroup per harness child (v2, kill the cgroup) or an environment marker
   read from `/proc/<pid>/environ` and checked with starttime as today. Choose the cgroup if the sandbox has
   cgroup v2 delegated; otherwise the marker. Then kill every process tagged with that child, whatever its parent.
   The count cap moves onto the walk's result.
4. **Stopped means stopped.** The release is acknowledged (and the API told) only after the kill task finished and
   re-checked that no tagged process is left. An errored release is reinserted so the next Stop retries, and reports
   failure in words until it succeeds.
5. The non-Linux cleanup of Why 5.

claude-code does emit an end for a background Bash, so the pid-pruning fallback is **not** built. The event shapes
were read from the code strings of the CLI installed here, **2.1.330**. They were **not** seen in a live run, and
not against the pinned 2.1.319. The test lines are hand-written, like the other fixtures. If the pinned CLI sent
no such event, the list would not shrink while the child lives (the old behaviour), and Stop would still work.

### Security notes (SEC-165)

- **Stop's limit.** A process escapes only if it left the child's group **and** the parent tree **and** hides the
  tag: `env -i` or an overwritten environment, or a non-dumpable process (`ssh-agent` is one and daemonizes).
  Hostile code can do this on purpose. A delegated cgroup would close it; the sandbox has none.
- **Wider kill.** `setsid` daemons now also die on every other end of the child, not only on Stop: an abort, a
  release for a changed tool list, a new session epoch, shutdown. Processes started with the platform's process
  tool are the supervisor's own and carry no tag.
- **Who can be signalled.** Only processes of the same uid. A process can copy another child's tag, which only
  gets itself killed by that child's Stop. PID 1 and the supervisor are excluded.
- **Waiting.** A release is awaited in the supervisor's main loop. An idle child ends as soon as the HUP lands.
  A process that ignores HUP costs the 2 s grace, and one that cannot be killed about 7 s per attempt.
  Idle-session releases run one after another; shutdown releases run together.
- **Masking is still pattern matching.** Not covered: `echo pw | … --password-stdin`, positional passwords
  (`htpasswd -b`), flags of other tools, a secret header with an unknown name, and the later words of an unknown
  `Authorization:` scheme (for example the AWS SigV4 form; this predates the brief). It over-masks on purpose,
  for example any `…key=` or `…pwd=` name. Also unchanged: the input is cut at 2 × the cap before masking.
- Only claude-code reports background work or gets the sweep; the other adapters' kills are unchanged.
