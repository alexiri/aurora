# FIX-204: Every dialog field uses `Field`; Rename's "Name" label sits like every other label (owner 2026-11-21)

## Why

The owner, on an account's **Rename CERN Rota** dialog: "the Name label in Rename is badly laid out". The dialog builds its
own field (`components/accounts/account-menu.tsx:158–161`): a `<label className="block space-y-1 text-sm font-medium
text-ink">` wrapping the text and a hand-styled `<input className="block h-10 w-full rounded-control border border-line
bg-surface px-3 …">`, with Cancel / Save in a `flex justify-end` row inside the body. Everything else uses the shared
`Field` + `inputClass` (`components/ui/field.tsx`: label, 6 px gap, `border-line-strong`, hint and error linked by
`aria-describedby`) and puts the buttons in the dialog's `footer` row (`components/ui/dialog.tsx:126`). The SSH key's
Rename (`components/account/ssh-keys-view.tsx:101`, `RenameDialog`) is the model to copy.

`docs/14` §Visual design already requires it ("Field: label, hint and error text linked by `aria-describedby`"; "No one-off
styling where a primitive or pattern exists"). No decision, contract or API change.

## Change (web only)

1. **Account Rename** (`account-menu.tsx` :145–170): `Field id="account-rename" label="Name"` with `inputClass`, the
   server's error under the field (`errorMessage` of the rename mutation, as SSH's dialog does), autofocus with the text
   selected, Enter saves. Cancel and Save move to the `DialogContent` `footer` (as `AddKeyDialog` in
   `accounts/accounts-list.tsx` and the SSH dialog do). Save stays disabled while empty and while saving.
2. **The same fix wherever a form field is hand-rolled** (`rg -n '<label className="block' web/src/components`, 12 hits
   on 55b1bdb8): `admin/plugins-view.tsx:103`, `internet/internet-level.tsx:204,227`, `skills/library.tsx:394,414`,
   `governance/controls.tsx:48`, `settings/access-tab.tsx:460`, `org/manage-frame.tsx:88`, `accounts/accounts-bulk.tsx:123`,
   `org/members-view.tsx:338`, plus any `<input`/`<select`/`<textarea` with hand-written border classes instead of
   `inputClass`/`Select`. Each becomes `Field` (+ `inputClass`, `Select`, `Combobox`). A wrapped checkbox or radio label
   is not a field: leave it. A label that is visually hidden on purpose (`md:hidden` in `manage-frame.tsx`) keeps that
   behaviour through `Field`'s props or an `sr-only` label; say which in the report.
3. Dialogs among them whose buttons sit in the body move them to the `footer` row.
4. **Guard:** add to `web/tests/arbitrary-values.test.ts` (or a sibling `web/tests/no-hand-rolled-fields.test.ts`) a scan
   of `web/src/components` and `web/src/app` that fails on a `<label className="block` that wraps an `input` (not a
   checkbox/radio), and on an `<input` whose `className` contains `border-line` without `inputClass`. Its allow-list
   starts empty.

## Tests move with the UI

In **every commit**: search `web/tests/**`, `web/e2e/**` (mocked **and** `production`), `scripts/e2e/*.sh` and fixtures for
the dialogs and fields you touch (labels, roles, button placement; `rg -n "Rename|getByLabel\(\"Name\"\)" web/tests web/e2e`),
update them in the same commit, never loosen, skip or delete a test to get green. Labels keep their words, so most
`getByLabel` queries keep working; tests that find Save inside the body by DOM position must find it by role. Run every
vitest file that renders a touched component and the mocked Playwright specs that open these dialogs, through `heavy.sh`;
