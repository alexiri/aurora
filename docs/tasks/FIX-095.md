# FIX-095: Harness adapters — the Codex configuration cannot be altered by the agent, session refs are validated, stream lines are bounded, the test binary override leaves the release build (REVIEW-5 LIFE-5/8/9, EVID-5, SUP-10) — **medium, security**

## Problem
1. **The agent can rewrite the Codex configuration between turns.** `services/aurora-supervisor/src/adapters/codex/mod.rs` writes `config.toml` once per session start (`write_home`, ~136–140) into `/workspace/.codex` (~74–78), inside the agent-writable workspace, and every `run_turn` spawns `codex exec` with `CODEX_HOME` pointing there (~300–327) without rewriting. Between turns the agent can change `[model_providers.aurora].base_url` (the next turn's prompt goes where it names, within egress policy) or `[mcp_servers.aurora].command` (the MCP bridge becomes any binary). SEC-66: "nothing in the sandbox can switch it"; the file header (`config.rs` ~1–5) says "Aurora owns the file". No real credential is in the file. The Claude Code adapter passes its MCP configuration inline on argv (`--strict-mcp-config`) and is not affected.
2. **Session references from the stream are stored unvalidated** (`codex/mod.rs` ~279–283; `safe_ref` runs only at start and purge, ~81–85), and purge removes rollouts by suffix `-{ref}.jsonl` (~189–203) while `is_safe_session_ref` accepts a one-character token (`harness.rs` ~238–243): a short ref deletes unrelated rollouts; an unsafe ref makes every later turn fail.
3. **The stdout reader has no line bound** (`codex/launcher.rs` ~80–84; `stream.rs` ~77 parses the whole line): one huge JSONL line can exhaust the sandbox's memory and kill the supervisor mid-turn.
4. **A test override is compiled into the release supervisor.** `codex/launcher.rs` ~17–19 reads `AURORA_CODEX_BIN` ("for tests") to choose the executable that receives the session environment.
5. **Claude Code result mapping ignores `subtype`** (`adapters/claude_code/stream.rs` ~273–291): a `result` without `is_error` is success. If the CLI reports `error_max_turns` or `error_during_execution` with `is_error: false`, a failed turn is reported done. Unverified against the pinned CLI — settle with the live conformance fixture first.

## Spec change (apply with the fix)
`docs/12` §Adapter codex: "the adapter's `CODEX_HOME` is a supervisor-owned directory outside the agent's workspace that is rewritten before every `codex exec`; session rollouts the agent may read stay under the agent's home." If Codex requires rollouts and config under one home, the rule is instead: "the file is re-rendered and its digest verified immediately before every spawn".

## Scope
- Render the Codex config before each spawn; move it out of `/workspace` where Codex allows, else re-render plus verify.
- Validate `SessionRef` when received (UUID shape or a minimum length); purge matches the exact rollout name.
- Bounded line reads (discard and mark an over-long line; never a success).
- Remove the environment read; the conformance test passes `ProcessLauncher { program }`.
- Claude Code: capture a live `result` for an error subtype (`AURORA_TEST_HARNESS_*` conformance) and map any non-success subtype to `harness_failed`; if the CLI never emits that shape, record it in the brief's Analysis.
