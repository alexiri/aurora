# FIX-219: the agent sees who and which channel a Mattermost message mentions, and can mention them back (owner 2026-11-22)

## Why

The owner: "In mattermost, I can write a message tagging a user, like `@jlunadur says that ...` but when that gets to the
agent it's something like `<@user:qb7c1wwoypdfpxr9wp9n84beeo> says that ...`. The agent loses all useful information of
who is being talked about. The mattermost bridge should fill in this information so the agent knows what it needs to, and
it should work both ways: when an agent references a username, it should become a mattermost tag at the other end. This
sort of thing should work as well when sending channel links."

Cause (read from the code, 2026-11-22):
- **Inbound, people.** The connector rewrites every `@name` that is a known user into a neutral token
  (`connectors/mattermost/src/events.rs` `convert_mentions`, `<@user:ID>` / `<@bot:ID>`) and lists it in
  `message.posted.mentions` as `{ kind, ref }` only (`crates/aurora-protocol/src/connector.rs` `Mention`). The core never
  reads the tokens: it puts `m.text` into the turn as it is
  (`services/aurora-api/src/domains/channels/inbox/message.rs` `turn_text`). So the agent gets an opaque id, and no name.
- **Inbound, channels.** A `~channel-name` reference is not converted today; it reaches the agent as typed. That is
  usable when the channel name is a readable slug, but Mattermost gives a channel whose display name has no Latin letters
  a random 26-character name (`~qb7c1wwoyp…`), and in every case the agent does not learn the channel's display name or
  whether the channel exists.
- **History is already readable.** `history.read` (`connectors/mattermost/src/ops.rs` `history_read`) returns the raw
  `@name` text, so the mid-thread context block shows `@jlunadur` while the message that triggered the turn shows a token.
- **Outbound already works for handles.** An agent's message body keeps a platform `@username` as text (`13 §4.3`,
  D-226(b)), the connector leaves a known user's `@username` live (`docs/20 §Rendering`, `mentions::resolve`), and
  Mattermost turns it into a mention. `~town-square` is likewise kept and Mattermost renders a channel link. The agent
  only lacks the handles, which is the inbound gap above. This fix proves the outbound half with tests and tells the agent
  how to write a mention.

## Decision, contract

- **D-460** (owner 2026-11-22; coordinator for the details):
  - (a) The agent sees each mention **as the platform writes it** (`@jlunadur`, `~town-square`), followed by a short
    line naming who or what each one is. It never sees a neutral token.
  - (b) The connector supplies both strings, because only it knows the platform's syntax and names. The core renders
    them; the neutral text contract (`13 §4.3`) is unchanged, and so are the tokens on the wire.
  - (c) Mattermost resolves `~channel-name` too, within the integration's team. Open channels resolve. A private
    channel resolves only when the message's author is a member of it. Anything else stays as typed text, so nobody
    learns the display name of a private channel they cannot see.
  - (d) Outbound needs no new mechanism: the agent writes `@handle` and `~channel` as shown, and the existing rendering
    keeps them live. The `send_message` tool description says so.
- **C-1146** (in `docs/API_CONTRACTS.md`; `13 §4.1`): `Mention` gains two optional fields.
  - `handle?: string`: the mention as the platform writes it, sigil included. It must match
    `^[@~#][A-Za-z0-9][A-Za-z0-9._-]{0,63}$`; the core ignores a handle that does not.
  - `label?: string`: the display name of the person, bot or space. The core passes it through
    `sanitize::label` and ignores it when that leaves it empty.
  - Both are serde `default` and `skip_serializing_if = "Option::is_none"`. An older connector, or one that sends
    neither, keeps working; its tokens reach the agent unchanged, as today.
  - `kind: "space"` mentions now appear from Mattermost (the kind exists already).
- **No SEC number.** The labels are platform data like the message body, already untrusted, sanitized, and not posted
  anywhere by this change. The channel rule in D-460(c) is the one privacy decision. It is tested.

## Change

### 1. Protocol (`crates/aurora-protocol/src/connector.rs`)

- Add `handle` and `label` to `Mention` as in C-1146.
- Regenerate the schemas with `UPDATE_SCHEMAS=1` (`schemas/connector_event_message_posted.json` and any other file that
  embeds `Mention`).
- Fix every struct literal of `Mention`: the fake connector (`connectors/fake/src/control.rs`) and the tests.
  The fake connector fills `handle` as `@<ref>` / `~<ref>` so the conformance suite exercises the path.

### 2. Mattermost connector, inbound (`connectors/mattermost/src/events.rs`, `integ.rs`)

- **People and bots.** In `convert_mentions`, set `handle: Some(format!("@{}", u.username))` and
  `label: Some(display_name(u))`, using the existing `display_name`, which applies the same rule as the author block.
  Set both only when the username matches the grammar of C-1146; otherwise leave both `None`.
- **Channels.**
  - Collect `~name` at a word start: the preceding character is not alphanumeric and not one of `_ . - ~`, and the
    next character after `~` is not `~` (strikethrough).
  - The name grammar is `[a-z0-9][a-z0-9_-]*`, at most 64 characters, lowercased. Trim trailing `-` and `_` the way
    `@name` trims trailing `.` and `-`.
  - Resolve at most 10 distinct names per message, through a new `Integ::channel_by_name(name)`:
    `GET /api/v4/teams/{team_id}/channels/name/{name}` with the bot token, cached one minute like `users_by_names`,
    negative answers included.
  - Keep a channel when `delete_at == 0`, its `team_id` is the integration's team, and either its type is `O`, or its
    type is `P` and the author is a member. Check membership with `GET /api/v4/channels/{id}/members/{author_id}`
    (200 means member, 404 means not); cache the answer for one minute per (channel, author).
  - Never resolve `D` or `G` channels. A failed call leaves the text as typed; it never fails the event.
  - A kept channel becomes `<#space:ID>` in the text, plus a `Mention { kind: Space, ref: ID, handle: "~name",
    label: display_name }`.
  - Do this in the same pass as the `@` conversion, or in a second pass over its output; either is fine as long as the
    two never touch each other's ranges.
- The inbound text stays what it is today in every other respect: `neutralize_tokens` first, the length clamp, `bot_mentioned`
  and `addressed_bot_ref` unchanged.
- `history.read` is unchanged (it already returns `@name` / `~name` as typed).

### 3. Core, the turn text (`services/aurora-api/src/domains/channels/inbox/message.rs`)

- Before `turn_text`, add `agent_text(text, mentions) -> String`:
  - Replace each `<@user:REF>`, `<@bot:REF>` and `<#space:REF>` token whose `REF` has a mention with a valid `handle`
    by that handle.
  - Tokens without a usable mention are left as they are, so an older connector behaves exactly as today.
  - Parse tokens the way the connector's `render::parse_token` does: the same grammar, refs of at most 128 characters
    with no `<`, `>`, space or newline. Put the shared parser in `aurora-channels` (next to `user_mention` /
    `space_mention`), not in a third copy.
- Then append one line after the message, before the failed-attachment lines, when at least one token was replaced:

  ```
  [Mentioned: @jlunadur (José Luna Durán), @aurora (bot), ~town-square (channel "Town Square")]
  ```

  - A person reads `@handle (label)`. Drop the parenthesis when there is no label or the label equals the handle without
    its sigil (case-insensitive).
  - A bot reads `@handle (bot)` when there is no label or the label equals the handle, else `@handle (bot "label")`.
  - A space always reads `~handle (channel "label")`, or `~handle (channel)` with no label.
  - Each handle appears once, in order of first appearance, with at most 20 entries, then `, …`.
  - The labels come from `sanitize::label`. Strip `"` from them, so a label cannot close its quotes.
- The stored turn text, which the dashboard shows, is this rendered text. Nothing else in the core reads the tokens.

### 4. Tool description (`services/aurora-api/src/domains/tools/messaging.rs`)

- `send_message`'s `text` description gains: "To mention someone or link a channel, write it exactly as messages show
  it (for example `@jdoe` or `~town-square` on Mattermost)."
- Keep the `to` description as it is: it already accepts an exact `@handle` or channel name.

### 5. Docs, in the same commits as the code

- `13 §4.1`: the `mentions` shape gains `handle?` and `label?`.
- `13 §5.1`: a new step, before the turn: the turn text shows mentions as their handles and adds the Mentioned line.
- `20`: the event mapping's `message.posted` row covers `~channel` resolution and the private-channel rule; the
  Rendering section notes that `@username` and `~channel` from the agent stay live.
- `API_CONTRACTS` C-1146 (written with this brief; correct it if the build differs).

## Tests

- **Protocol:** a `Mention` without the new fields deserializes and serializes without them. The schema files match.
- **Connector unit** (`events.rs` tests):
  - `@jlunadur` gives a user mention with `handle` `@jlunadur` and the user's display name;
  - `~town-square` (open) becomes `<#space:C1>` with handle and label;
  - `~secret` (private, author not a member) stays text with no mention;
  - `~secret` (private, author a member) resolves;
  - a deleted channel, another team's channel, a `D` channel, `~~strike~~`, `a~b` and an unknown name all stay text;
  - 11 distinct names resolve only the first 10.

  Mock the API as `integ.rs`'s rig does.
- **Core unit** (`agent_text`):
  - every token kind;
  - a token without a mention stays;
  - an invalid handle (`@a b`, `@<x>`, 65 characters, no sigil) is ignored;
  - a label with `"`, newlines or bidi characters is sanitized;
  - duplicates are listed once;
  - the 20-entry cap;
  - nothing is replaced means no Mentioned line;
  - a typed, neutralized token (`<\u{200b}@user:x>`) is never replaced.
- **API IT** (`services/aurora-api/tests/it/`, next to the existing `message.posted` tests): a posted message with a
  user, a bot and a space mention creates a turn whose text is `@jlunadur says ~town-square …` plus the Mentioned
  line. The same message without `handle` gives today's token text.
- **Mattermost e2e** (`connectors/mattermost/tests/mentions_e2e.rs`, run by `scripts/conformance.sh --mattermost`):
  - inbound, a post `@<user> see ~<channel>` reaches the core with both mentions resolved;
  - outbound, an agent body `ping @<user> in ~<channel>` is stored with `@<user>` and `~<channel>` unchanged, and the
    user's `mention_count` rises.

  If it is not run locally, list it as left to CI.
- **Conformance** (`tests/conformance/connector`): s03's mention assertion also checks `handle` when the connector sent
  one. Do not make `handle` mandatory for every connector.

## Tests move with the UI

There is no UI change, but the turn text a person sees in the dashboard changes for Mattermost-originated turns. In
**every commit**, search the Rust tests and fixtures (`services/aurora-api/tests/it/`, `connectors/mattermost/tests/`,
`tests/conformance/`, `tests/e2e-hosted/tests/mattermost.rs`), and `web/e2e/**` (mocked **and** `production`) for:
- inbound turn text containing `<@user:`, `<@bot:` or `<#space:`;
- `Mention` literals.

Update them in the same commit. Never loosen, skip or delete a test to get green. Run only fast targeted tests, through
`heavy.sh`. GitHub CI is the full gate.

## Acceptance

- A Mattermost message `@jlunadur says that ~town-square is down` reaches the agent as that text, plus
  `[Mentioned: @jlunadur (José Luna Durán), ~town-square (channel "Town Square")]`.
- A private channel the author is not in stays `~name`, with no label.
- An agent answer or `send_message` containing `@jlunadur` notifies that user in Mattermost, and `~town-square` renders
  as a channel link.
- A connector that sends no `handle` behaves exactly as before.
- `13`, `20` and C-1146 match the code.

## Not in this fix

- Channel and post URLs (`https://<server>/<team>/channels/<name>`, `/pl/<post id>`) stay as typed. A channel URL
  already carries the name; reading a linked post would need a `history.read` by id. Ask the owner if this is wanted.
- The speaker's own handle in the turn context. A linked person already gets "Mattermost @handle" in Working for; an
  unlinked speaker would need a new column on the turn.
- Display-name mentions written by the agent (`@José Luna`).
- Group mentions (`@devs`) inbound: they stay as typed, and outbound they stay defused (D-271).
