# FIX-214: The conversations list's **New chat** button stays inside its pane (owner 2026-11-21)

## Why

The owner, on an agent's chat: "the 'new chat' button overflows its area." The screenshot shows **+ New chat** sticking
out past the conversations pane's right border into the thread header.

Cause: from 1024 px the list pane is 232 px wide (`web/src/components/chat/chat-panel.tsx:67`, `lg:w-58`; 320 px only
while message search results show). Its header (`components/chat/conversation-list.tsx:~379–386`) is one
`flex items-center justify-between` row with `p-3`, so 208 px hold the `h2` "Conversations" (display font, ~118 px) and a
`shrink-0` primary button with icon and label (~112 px) plus the gap: about 240 px. Nothing may wrap or shrink, so the
button spills out.

No decision, contract or API change.

## Change (web only)

1. **The header fits at every pane width.** Make the list pane a container (`@container` on the pane's root in
   `chat-panel.tsx` or on the `nav` in `conversation-list.tsx`) and size the button by the pane, not the window:
   - when the pane is narrower than the heading plus the labelled button (the 232 px pane), **New chat** is a
     square icon button (the same `PlusIcon`, 36 px on desktop, 44 px on touch as the current `min-h-11`) with
     `aria-label="New chat"` and the shared `Tooltip` "New chat" (`components/ui/`, P5-CHAT-2);
   - when the pane is wide enough (the 320 px search pane, and the full-width list below 1024 px), it keeps the icon and
     the label as today.
   Use Tailwind's container-query variants (`@container`, `@xs:`/`@sm:` or a named size), no arbitrary values
   (`web/tests/arbitrary-values.test.ts`). The `h2` gets `min-w-0 truncate` as a last guard, but at 232 px it must show
   in full.
2. **Same rule for anything else in that header row** (none today; if the empty-list "Start a new chat…" state or the
   busy state changes the button's width — "Starting…" — the icon form keeps its size and shows the busy state as a
   spinner or `aria-busy`, never a wider label).
3. Check the other side-by-side panes with a header button (the status rail header, the agent Settings sub-nav) for the
   same overflow at 1024–1440 px; fix any you find the same way and list them.

## Tests move with the UI

In **every commit**: search `web/tests/**`, `web/e2e/**` (mocked **and** `production`), `scripts/e2e/*.sh` and fixtures for
what you change (`getByRole("button", { name: "New chat" })` keeps working through `aria-label`; text queries on "New
chat" inside the list pane at desktop widths must use the role name; `agent-header-widths.spec.ts`, chat specs,
`refine-19` palette `n` shortcut), update them in the same commit; never loosen, skip or delete a test to get green. Run
the vitest files that render `ConversationList`/`ChatPanel` and the mocked chat Playwright specs through `heavy.sh`. List
production specs you could only update by reading. A merge that turns master red because a test still expects the old
UI is a send-back to this lane.

## Acceptance

- At 1024, 1100, 1280, 1440 and 1920 px (rail closed and open) the New chat button's box lies inside the list pane's box
  (a Playwright check on bounding boxes, added to `agent-header-widths.spec.ts` or a sibling), both themes.
- In the 232 px pane the button is the icon with a "New chat" tooltip on hover and focus; in the 320 px search pane and
  below 1024 px it shows the label.
- Clicking it, the `n` shortcut and the palette's "New chat with <Agent>" still start a new chat.
