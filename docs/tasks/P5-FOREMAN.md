# P5-FOREMAN: built-in `foreman` package — hosts, Puppet reports and facts on a Foreman server (phase 5, D-432, SEC-145)

Read `docs/tasks/P5-CATALOG.md` first (common rules, acceptance, order). This brief owns
`plugins/builtin/foreman/**`, its `REFUSED` entry and its `ICONS.md` row.

## Goal

"Which of my machines failed their last Puppet run?", "what hostgroup and environment is lxplus900 in?",
"show the facts of host X", "when did host Y last report, and what changed?", "run the 'restart service'
job on these three hosts". An agent reads the inventory, Puppet configuration and reports of a Foreman
server (Foreman and Red Hat Satellite; CERN runs one), and, with approval, starts a remote execution job.

## Hosting and connect (D-432)

- **Instance-bound, no default host** (`instances`, label "Foreman server"); base paths allowed. Probe:
  `GET /api/status` expecting `[200, 401]` (check which status an anonymous call gets on a current release).
- **One connect method, `kind: fields`**: `username` (metadata, also shown), `access_token` (secret; a
  **personal access token**, Foreman › My account › Personal Access Tokens, with an expiry), `name`
  (`store: label`). Injected as `basic: { user: "{metadata.username}", password: "{credentials.access_token}" }`
  on `{instance}` under `/api`, and under `/foreman_puppet/api` and `/api/v2` if the docs show plugin APIs
  there (see below).
  - `access_levels`: `read` "Viewer" (`permission_hints`: "Role · Viewer"), `write` "Viewer + Remote
    Execution User" (the role names as Foreman shows them; check). `connect_note`: the token acts with the
    user's roles; a Viewer user cannot change anything.
  - A password instead of a token is not offered.
  - Probe: `GET /api/current_user` names the account (`login`).
- Foreman's own API docs are generated by apipie (`/apidoc` on every server, `docs.theforeman.org` for each
  release). There is no maintained OpenAPI 3 document; write `operations.json` by hand.

## Tool catalogue (verify against the API docs of a current Foreman release and of `foreman_puppet` and `foreman_remote_execution`)

Since Foreman 3.0 the Puppet resources (environments, classes, class parameters) live in the
`foreman_puppet` plugin under its own API path; take the exact prefix from its docs and add the matching
`hosts[]` entry.

**Read (GET):**
- Status and identity: `/api/status`, `/api/current_user`, `/api/dashboard`.
- Hosts: `/api/hosts` (with `search`, Foreman's scoped search), `/api/hosts/*`, `/api/hosts/*/status`,
  `/api/hosts/*/facts`, `/api/hosts/*/parameters`, `/api/hosts/*/config_reports`, `/api/hosts/*/enc`
  (the Puppet external node classifier output: classes and parameters the host gets),
  `/api/hosts/*/interfaces`.
- Hostgroups: `/api/hostgroups`, `/api/hostgroups/*`, `/api/hostgroups/*/parameters`.
- Puppet (`foreman_puppet`): environments, `puppetclasses` (list and one), `smart_class_parameters` (list and
  one, with their overrides).
- Reports: `/api/config_reports`, `/api/config_reports/*` (logs with resource changes and failures),
  `/api/config_reports/last` if the release has it.
- Facts across hosts: `/api/fact_values` (with `search`).
- Infrastructure lookups: `/api/domains`, `/api/subnets`, `/api/operatingsystems`, `/api/architectures`,
  `/api/locations`, `/api/organizations`, `/api/smart_proxies`.
- Audits: `/api/audits` (who changed what).
- Remote execution, read: `/api/job_templates`, `/api/job_templates/*`, `/api/job_invocations`,
  `/api/job_invocations/*`, `/api/job_invocations/*/hosts/*` (a host's output).

**Write (each with an approval template):**
- `run_job` (`POST /api/job_invocations`): title "run a remote execution job"; fields: job template id
  (`job_invocation.job_template_id`), the target (`job_invocation.search_query` or `targeting_type` +
  host ids), the template inputs (`job_invocation.inputs`, clamped), `concurrency_control`, `scheduling`.
  The summary must show **which hosts** are targeted exactly as sent: an agent may not soften a search
  query in the summary. Precedent for clamping: `sentry` / `indico` approvals.
- `cancel_job` (`POST /api/job_invocations/*/cancel`): title "cancel a running job".
- `set_host_parameter` (`POST /api/hosts/*/parameters`, `PUT /api/hosts/*/parameters/*`): title "set a host
  parameter"; fields: host (path), name, value, type.

**Refused** (`REFUSED["foreman"]`, each a `refused …` case): host deletion (`DELETE /api/hosts/*`), power
and boot actions (`PUT /api/hosts/*/power`, `PUT /api/hosts/*/boot`), rebuild (`PUT /api/hosts/*/rebuild_config`,
`build` via `PUT /api/hosts/*`), host and hostgroup edits (`PUT /api/hosts/*`, `PUT /api/hostgroups/*`),
**personal access token creation** (`POST /api/users/*/personal_access_tokens`, SEC-145), user and role
edits (`/api/users`, `/api/roles`, `/api/filters`), and Katello content-view publish/promote
(`/katello/api/content_views/*/publish`, `…/promote`) if a Katello server is the target.

## Agent text

- `agent.summary`: "Foreman hosts, hostgroups, Puppet classes, facts and reports: find failing Puppet runs, read a host's config, run an approved job."
- `agent.instructions`: base `https://<server>/api`; Aurora adds the credentials; use Foreman's `search`
  syntax (`search=hostgroup ~ "lxplus" and last_report < "2 hours ago"`), `per_page` (≤ 100) and `page`;
  JSON bodies with `Content-Type: application/json`; a job runs commands on real machines, so propose the
  exact target and inputs before asking.
- Guide: `api-notes.md` (scoped search syntax and the most useful search keys, the ENC output, report
  statuses, pagination, the Puppet plugin paths); recipes `failed-puppet-runs.md` ("Which hosts failed their
  last Puppet run?": `/api/hosts?search=last_report > "1 day ago" and status.failed > 0`, then each host's
  last report, grouped by error) and `host-overview.md` ("Tell me about a host": status, hostgroup,
  environment, ENC classes, key facts, last report).

## Fixtures

Every host entry (core API and the Puppet plugin prefix), tool, approval and refused item; basic auth
injected only on the registered instance; a `GET /api/hosts?search=…` is the hosts list tool;
`PUT /api/hosts/*/power` selects no tool.

## Owner checks (not blocking)

CERN's Foreman ("Judy", `judy.cern.ch`) may put single sign-on or Kerberos in front of the API. If personal
access tokens with basic auth are refused there, this package still serves other Foreman/Satellite servers,
and CERN needs either an exception for API clients or a CERN-specific connect method in
`aurora-addons-cern`. The package does not depend on the answer.
