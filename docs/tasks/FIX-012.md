# FIX-012: Harvested memory titles and descriptions keep their escape characters (data integrity, phase 2)

## Problem (found by P2-TEST-1, item 4)
The API renders a memory file's front matter with `yaml_str()` (`services/aurora-api/src/domains/hosted/home.rs`). That is `serde_json::to_string`, so `Cafe "menu"` is written as `title: "Cafe \"menu\""`.

The supervisor's harvest (`services/aurora-supervisor/src/harvest.rs`, `unquote()`) strips the outer quotes but **doesn't unescape**, so a harvested edit stores `Cafe \"menu\"`. Every round trip adds another layer of backslashes.

It affects any title or description that contains `"`, `\`, a control character or a non-ASCII escape that JSON writes as `\uXXXX`. That is silent corruption of user data.

## Scope
1. Make the harvest read exactly what the render writes, and the YAML an agent may reasonably write by hand:
   - A **double-quoted** scalar is parsed as a JSON string (`serde_json::from_str::<String>`), which matches the renderer, and YAML double-quoted escapes are a superset for these cases. If that parse fails, fall back to today's behaviour (strip the quotes, keep the inner text) so an agent's slightly malformed edit is never lost.
   - A **single-quoted** scalar unescapes `''` to `'` (YAML rule).
   - An unquoted scalar is trimmed, as today.
2. Leave the renderer alone unless the fix needs it. If you change it, both sides must change together and the checksum trailer must still verify.
3. Tests:
   - **Cross-crate round-trip** in `services/aurora-api/tests/it/home_checksum.rs` (P2-TEST-1's test: real API render plus real supervisor harvest). Today it uses a quote-free title (`Some("Cafe menu")` in the with-front-matter `insert_memory` call) with a comment pointing at this bug. Switch it to a quoted title and restore the `writes[0].title` assertion in "Tampering 2". Cover titles and descriptions with `"`, `\`, a newline, a tab, a non-ASCII character, a `'`, and an empty string. Each must be unchanged after render → harvest. Two consecutive round trips must also be stable (no growth).
   - **Unit tests** for `unquote()`: double-quoted with escapes, single-quoted with `''`, unquoted, and malformed double-quoted (the fallback).
4. Existing memories already corrupted by earlier harvests aren't repaired automatically: there's no reliable way to tell a user's literal backslash from an escape. Say so in the report. A one-off repair would need the owner's decision.

## Constraints
- **Owns:** `services/aurora-supervisor/src/harvest.rs`, `yaml_str` in the API's `domains/hosted/home.rs` (only if needed), and the tests named above.
- No migrations; no change to the wire or the file format beyond correct escaping.
- Decision: **D-101**, only if a choice beyond this brief is needed.
