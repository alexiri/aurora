# FIX-183: Connectors say whether they have an icon (no icon request that 404s)

## Goal
Owner, 2026-11-19 (D-398). Admin › Chat platforms requests `GET /v1/connectors/{id}/icon` for every connector and
logs a 404 for one without an icon (the dev `fake` connector, any self-hosted connector that registered none):
`web/src/components/connectors/shared.tsx` `ConnectorIcon` defaults `hasIcon` to true because `ConnectorAdmin`
has no icon flag. Found by P5-POLISH-11 pass 2 (P5-POLISH-10 #5); pre-existing since P4-MCON-3.

## Change
1. **API (C-1044):** `ConnectorAdmin` (and the other connector views the dashboard renders an icon from, if any)
   gain `has_icon: bool`, true when the connector's registration or managed package carries an icon the icon route
   serves. Derive it from the same source the icon route reads, so the two can never disagree. Additive; the icon
   route is unchanged (still 404 without an icon).
2. **Web:** every `ConnectorIcon` caller passes `hasIcon={c.has_icon}`; with false the monogram tile shows and no
   request is made. Regenerate the API types.
3. Docs: `05` (the connector view), `API_CONTRACTS` C-1044, `13` where the icon is described.

## Tests
API IT: a connector with an icon → `has_icon: true` and the route serves it; one without → `false` and the route
404s. Vitest: `ConnectorIcon` with `hasIcon={false}` renders the monogram and requests nothing. Targeted only (owner
2026-11-19, CI is the gate); `extract-schema --check`, web typecheck.

## Ownership
