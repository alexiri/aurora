# FIX-021: Dashboard — error deep links, model readiness, "Give agents access" (owner report and request, 2026-11-09)

## Problems and request
1. The chat error "This agent has no usable LLM key. **Open LLM keys**" opens the Secrets tab.
   - `web/src/lib/chat/transcript.ts` maps `no_model_key` to path `credentials`.
   - The tab in `web/src/components/credentials/credentials-view.tsx` is local `useState`, so no URL can select it.
2. Owners cannot see *why* a granted key is not usable. FIX-019 adds `GET /v1/agents/{a}/model-readiness` and the turn error `no_default_model`.
3. The LLM key row shows "Verified account: verified". `origin-view.tsx` prints the status where the account (method and ids) belongs.
4. The effective-access view labels an LLM key "(secret, workspace)".
5. **Request:** after creating an LLM key, a secret or an app connection, let the user give one or more agents access right away. Each credential row also gets an Access action.

## Scope
1. **Credentials tabs** read `?tab=` on load and update it on change with `router.replace`. An unknown value falls back to Secrets. This applies to the org and workspace credentials pages.
2. **Chat error copy** (`transcript.ts`, `status-rows.tsx`):
   - `no_model_key` links to `credentials?tab=llm`, plus "Agent access" (agent page Access tab) for owners. Show the server `message` (reason counts) under the copy.
   - New `no_default_model`: "This agent has an LLM key but no model is chosen." with a "Choose a model" link to the Instructions tab.
   - Agent page tabs: use the existing addressing if there is one, otherwise add `?tab=` the same way as point 1.
3. **Access tab**:
   - Add a Model readiness section for hosted agents, owners only, from C-500.
   - In the effective view, show "LLM key" for LLM secrets.
4. **Origin view**: show the method and the ids, or "Verified (endpoint)". Show `origin.detail` in words (C-502).
5. **"Give agents access" step** after creating an LLM key (`llm-form.tsx`), a generic secret (`generic-form.tsx`) and a connection (`apps/connect-view.tsx` on success):
   - Agent list: for a workspace scope, the workspace's agents. For an org scope, group the agents by the workspaces the caller owns, using existing list routes.
   - Nothing is preselected. Buttons: "Give access" and "Skip".
   - Secrets: `POST /v1/secrets/{id}/grants` (C-503).
   - Connections: `POST /v1/connections/{id}/grants` (C-504) with `full`. For an app with `custom_only`, ask for the allowed tools first (every other tool blocked) and send `custom`.
   - Show agents that already have access as such, and name the failing agent in errors.
6. **Row Access action** on secret, LLM key and connection rows (owners):
   - lists the agents that have the credential (`GET …/grants`);
   - "Remove" uses the agent-side `DELETE`;
   - the same add picker as point 5.
7. Add React Query hooks in `web/src/lib/api/` next to the existing `policy.ts` grant hooks, invalidating `grants`, `effective` and the readiness query.
