# FIX-184: Google Workspace and Microsoft 365 ask before sending mail or invitations (by default, changeable)

## Goal
Owner, 2026-11-19 (D-400), answering P5-TOOLASK's proposal: the `google-workspace` and `microsoft-365` builtin
tools that **send mail or invitations to other people** default to Ask (D-397's `approval: ask`), and it stays
configurable: a workspace or organization can lift the default for a tool.

## Change
1. **Packages:** mark `approval: ask` on exactly the write tools that send something to another person: mail
   send (and reply/forward, and sending a draft, where these are separate tools), and calendar event create/update
   **when the tool sends invitations or updates to attendees**. Read every tool of both packages; list each one you
   marked and each write tool you did not mark with the reason, in the Completion report. Bump each package's
   version; re-sign as the builtin build does (never print or copy `cern-release.key`; the build signs).
   If an event tool sends invitations only with an argument (e.g. `sendUpdates`, `send_invitations`), mark the tool
   and say so; do not split tools.
2. **Configurable (check, add only what is missing):** D-397 already lets a workspace lift the default (the
   actions table's **Allowed**, a custom grant naming the tool) and an organization rule naming the tool lifts it
   too. Check both paths work for these tools from the dashboard: the workspace actions table, and an organization
   owner/admin on the organization's rules page. If an organization admin has no dashboard way to allow one named
   tool, add the smallest control that writes the existing rule shape (no new API); if that needs an API change,
   stop and report instead.
3. Docs: `09` (each package's section: which tools ask first and how to change it), `14` if a control is added.
