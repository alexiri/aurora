**Real defects found and fixed under this id** (each with a test that fails without the fix):
1. The relay did not de-frame `chunked` answers: the app's chunk-size lines went to the browser inside hyper's own chunked framing (SSE and every chunked page corrupted), and the last chunk did not end the stream. New `proxy::ChunkedDecoder` (unit-tested at every split point); `sse_events_arrive_as_sent` fails (stalls) without it (shown).
2. Plain HTTP streams idled on the 600 s upgraded limit; now 120 s plain, 600 s after a `101`.
3. The wake-wait page and the start-command exit page did not exist in the relay (the route data of `resolve` was ignored; a stopped sandbox answered a bare 502): the relay now long-polls `resolve { wait_secs: 45 }` when the stream cannot open, retries once when the port listens, else shows the refreshing 503 page, the exit page (502) or the "started too often" page (429 + `Retry-After`). A port that refuses while the start command runs/has exited shows the same pages (no waiting: the body is already consumed). `PREVIEW_LISTEN_WAIT` (5 s, share without a start command) is still unused (AUDIT-004 F-3, FIX-074's list).
4. The supervisor's `shutdown` frame did not close PTYs (`Supervisor::shutdown` only handled turns/sessions): now `PtyHandle::close_all()` → `pty.close { channel_lost }` for each. The stream engine's equivalent ("closes everything on shutdown", docs/12) was not examined and is not changed.
