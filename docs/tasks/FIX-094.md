# FIX-094: Runner robustness — transient Kubernetes API errors do not fail a start, the bootstrap claim survives a lost response, the sandbox-facing listener is bounded, final reports are delivered, sandbox DNS is verified off (REVIEW-5 LIFE-4/10, RUN-1/2/3/4/6/7/9, SEC-1, CONV-6) — **high**

## Problem
1. **A boot can be lost to one transient API error.** `services/aurora-runner/src/channel/conn.rs` `admit`: the bootstrap claim succeeds (the API stamps `bootstrap_used_at`, `crates/aurora-db/src/repo/sandboxes.rs` ~1107), then `channel_hold` fails with a retryable error and the runner closes 1013 before any welcome (~170–173). The supervisor reconnects with the same bootstrap token (`services/aurora-supervisor/src/channel.rs` ~335–342), the API answers 409 `bootstrap_spent`, the runner maps it to 4409, which the supervisor treats as fatal (~291). The session path has a `hold_pending` fallback; the bootstrap path does not.
2. **The claim is retried although it is not idempotent.** `services/aurora-runner/src/api.rs` `claim` (~231) goes through `call`, which retries transport errors, 5xx, 408 and 429 five times (~154–170); a committed claim whose response was lost comes back 409 → 4409 → dead boot. The comment says "No retry on 409/404".
3. **The sandbox-facing channel listener is unbounded before admission.** `channel/mod.rs` ~470–480 spawns a task per accepted connection; the WebSocket handshake (`conn.rs` ~51) has no timeout and there is no cap, so one sandbox opening idle connections to port 4105 can exhaust the runner's file descriptors — for every sandbox on that runner.
4. **A transient Kubernetes API error fails the start.** `backends/kubernetes/mod.rs` `await_running` breaks on any `get_opt` error (~604–607) and then deletes the pod (`remove_boot`, ~661–664); `start` fails on a list error (~744). One 503 from the apiserver during an image pull deletes a healthy starting pod and counts toward the retry bound.
5. **A `Lost` home claim is not classified** (`mod.rs` ~372–383): the start waits out the deadline with a generic reason.
6. **Final reports are dropped at shutdown.** `reporter.rs` ~114–120 retries only while not shutting down; the final flush (`runner.rs` ~285) drops `stopped`/`failed` batches on the first 503, leaving sandboxes in `stopping` until the lease expires.
7. **The ops listener defaults to the sandbox-facing bind.** `runner.ops_bind` falls back to `server.bind` (`crates/aurora-config/src/validate.rs` ~871–876), documented as `0.0.0.0`; the overlap only warns (`services/aurora-runner/src/main.rs` ~78–82). `docs/operator/runners.md` ~50 says the ops port "Must not be sandbox-reachable (SEC-09)".
8. **Sandbox DNS is not verified.** `backends/podman.rs` `verify_network` (~137–165) checks `internal` only; `docs/11` requires `--internal --disable-dns`, SEC-02 says a sandbox "cannot resolve external DNS names", and `docs/operator/runners.md` ~81 says the runner verifies the flag. A network created `--internal` with DNS enabled passes.
9. **Least privilege.** The runner Role grants `get`/`watch` on Secrets it never uses (`deploy/helm/aurora/templates/sandboxes.yaml` ~23–27); `sandboxes/check` answers for any sandbox id regardless of runner (`repo/sandboxes.rs` ~1201–1208).

## Linked requirements

## Spec change (apply with the fix)
- SEC-25 and `docs/16` §W6: "a bootstrap token admits one supervisor connection. Re-presenting it is accepted only while the boot has never held a channel (the first admission did not complete); once a channel was held it is spent (4409)."
- `docs/11` §Start readiness deadline: "a failed or timed-out Kubernetes API call during a start is retried at the next poll; only the start deadline or a terminal pod/claim state ends the attempt". `Lost` claims map to `home_volume_unbound`.
- `docs/16`/`docs/02`: pre-auth connection cap and handshake deadline on the supervisor port.

## Scope
### In scope
- Bootstrap admission: after a successful claim, a retryable hold failure admits with `hold_pending` and a welcome; the API claim is idempotent as specified (same `(sandbox, boot)` returned); the runner's claim is one attempt per connection.
- Channel listener: semaphore on unadmitted connections, handshake under `hello_timeout`.
- Kubernetes: retry-on-next-poll for transient errors in `await_running`/`start` (no `remove_boot`), `Lost` → `home_volume_unbound`; `k8s_mock.rs` gains fault injection (5xx, timeout).
- Reporter: final flush retries retryable errors until `drain_timeout`.
- `ops_bind` default `127.0.0.1` on the podman backend; overlap with an unspecified sandbox-facing bind is a configuration error.
- `verify_network`: read the network's DNS flag from the libpod network JSON and refuse unless disabled (same `dev_allow_external_network` escape).
- Role without `get`/`watch` on Secrets; `known_ids` scoped to the calling runner's sandboxes.
