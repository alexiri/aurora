# FIX-013: Kubernetes sandboxes can pull from a private registry (`runner.k8s.image_pull_secrets`) (phase 2)

## Problem (FUP-M7, owner decision 2026-11-08)
The Kubernetes runner backend gives sandbox Pods no `imagePullSecrets`, so a sandbox image in a private registry can't start. The service images' pull secrets come from the Helm chart, but the runner creates sandbox Pods itself, and `[runner.k8s]` (`crates/aurora-config/src/raw.rs`, `K8sSection`) has no key for it.

The owner chose to add the option. The two other Kubernetes residuals (no per-Pod PIDs limit, `/run/aurora` can't be `noexec`) are documented by the coordinator as accepted limits, not code.

## Scope
1. **Config:** `runner.k8s.image_pull_secrets` (list of Secret names, default empty), validated as DNS-1123 subdomain names with a clear startup error. `docs/15 §Configuration` gains the row.
2. **Runner:** sandbox Pods get `spec.imagePullSecrets` with those names in the **sandbox namespace**, and nothing else changes in the Pod spec. The runner never reads or creates the Secrets; the operator creates them in the sandbox namespace.
3. **Helm:**
   - A values key (e.g. `runner.sandboxImagePullSecrets: []`) renders into the runner's config.
   - Document in `docs/operator/install-helm.md` and `docs/operator/runners.md` §Kubernetes backend that the Secrets must exist in the sandbox namespace, with a `kubectl create secret docker-registry` example.
   - Check whether the chart's existing `imagePullSecrets` for the services should feed the default. Recommend; implement only if it's simple and doesn't leak a core-namespace Secret into the sandbox namespace (it can't: Secrets are namespaced; the operator must create a copy).
4. **RBAC:** no change expected. The runner doesn't need to read Secrets for this. Verify, and don't widen it.
5. **Tests:**
   - Unit tests in the Kubernetes backend's pod-object tests: empty list gives no field; two names render in order.
   - A config test: valid names accepted, an invalid name refused with the key in the error.
   - `helm template` with the values key renders it.
   - `scripts/e2e/kind.sh --fresh` stays 4/4.

## Constraints
- **Owns:** `crates/aurora-config` (the key and its validation), `services/aurora-runner/src/backends/kubernetes/{mod,objects,tests}.rs`, `deploy/helm/aurora/**` (values and runner config), `docs/15`, `docs/operator/{install-helm,runners}.md`.
- No API, gateway or web changes.
- Decision **D-104** only if needed (D-101 FIX-012, D-102 P2-UI-5, D-103 reserved for P2-UI-4).
