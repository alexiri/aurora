# P4-MCON-2: Managed connectors — connector host, built-in types, Helm, e2e, operator docs

## Goal
Aurora runs managed connectors itself (D-128). Build `aurora-connector-host`, make the built-in connector types runnable inside it, ship it in the chart and images, prove it end to end, and rewrite the operator docs so the dashboard flow is the normal path. Spec: `docs/13-channels-connectors.md` **§3.1** (and §3, §8), C-455..C-459 (host plane, delegated auth), `01` (ports 4110/4192), `15` (config keys, Helm bullet), `18 §Managed connectors` (Host and E2E bullets), SEC-69. P4-MCON-1 (merged) provides the API, the host-plane DTOs in `aurora-protocol`, and `instance_setup` on the manifest.

## Scope
1. **SDK** (`crates/aurora-connector-sdk`): `RuntimeConfig` can authenticate as a managed connector: bearer `auh_…` plus header `Aurora-Connector: <id>` (C-458). Keep the `aun_` path unchanged.
2. **Connector crates** (`connectors/mattermost`, `connectors/fake`): each exposes a library entry point the host can call with its settings (a typed `Settings` built from the assignment's `settings` + `secrets`) and returns its runtime + callback router, so the standalone binaries and the host share one code path. Mattermost declares `instance_setup` exactly as `13 §3.1` (public_url, callback_hmac_key `generated_secret`, catchup_window_secs, token_check_secs); fake declares a small `instance_setup` incl. one `secret` and one `generated_secret` field so e2e exercises both. Standalone binaries keep their CLI/env behaviour (self-hosted path).
3. **`services/aurora-connector-host`** (new workspace member, binary `aurora-connector-host serve`): config `connector_host.*` (`15`), token from `AURORA_CONNECTOR_HOST_TOKEN`; registers its catalogue (compiled types; `fake` only with `test_types = true`, with a startup warning), heartbeats every `poll_interval_secs`, long-polls assignments **with its own `instance_id`** (C-456: the shared token carries no host identity; without it the host would be handed types it did not announce), starts/restarts (on settings or revision change)/stops one instance per managed connector, nests each instance's callback router under `/connectors/<id>/` on 4110 (the instance's `public_url` already includes that prefix), serves `/healthz` `/readyz` `/metrics` on 4192, reports per-connector `status` (sanitized messages, never a secret). Never logs assignment secrets. Graceful shutdown stops every instance. Manifest signatures: read from files embedded at build time when present (release build signs with the project key, as for built-in plugins); otherwise send an empty signature (development relies on `plugins.allow_unsigned`). Say in your report exactly how signing is wired.
4. **Images**: a `connector-host` target in `images/services/Containerfile`; add the image to `.github/workflows/ci.yml`'s publish list the same way as the others, `scripts/e2e/kind.sh` `IMAGES`, `deploy/dev/kind-dev.sh` image loading.
5. **Helm** (`deploy/helm/aurora`): `connectorHost` values (`enabled: true`, `replicas: 1`, `resources`, `testTypes: false`, `nodeSelector`, `tolerations`); Deployment + Service (4110) + PDB; the `secrets` hook generates `AURORA_CONNECTOR_HOST_TOKEN` (`auh_<hex>`, idempotent, like `AURORA_RUNNER_TOKEN`); the api gets `AURORA_BOOTSTRAP_CONNECTOR_HOST_TOKEN`; Ingress and HTTPRoute route `/connectors` → host:4110 (and `scripts/guards/edge-routes.sh` knows the rule); NetworkPolicy per `15` (ingress from the edge namespace + `networkPolicy.cilium.edgeEntities` CNP, egress api:4101, DNS, external, `networkPolicy.connectorHostExtraEgress`); config rendered into the host's config. `deploy/kind/values-e2e.yaml` sets `connectorHost.testTypes: true`.
6. **E2E**: extend `scripts/e2e/kind.sh` (or its Rust test) per `18 §Managed connectors` E2E: add the `fake` type via `POST /v1/admin/connectors` (managed), wait for `active`, create an integration, one message round trip, then disable and see it stop.
7. **Operator docs**: `docs/operator/plugins-and-connectors.md` §Connectors leads with the dashboard flow (Admin → Connectors → Add), then "Self-hosted connectors (advanced)" with today's token text; `docs/operator/install-helm.md` (`connectorHost` values, the `/connectors` edge rule, the external-reverse-proxy section: proxy `/connectors/` too); `docs/operator/install-kind-dev.md` if it mentions connector provisioning; `docs/20-mattermost-connector.md` gets a short "Managed (dashboard)" paragraph pointing to `13 §3.1`.

## Acceptance
- `cargo test -p aurora-connector-host` (start/restart/stop per assignment against a stub API, nested callbacks for two connectors, status sanitization, only compiled types), `cargo test -p aurora-connector-sdk -p aurora-connector-mattermost -p aurora-connector-fake`, `bash scripts/conformance.sh` and `--mattermost` (self-hosted path unchanged), `cargo test -p aurora-api --test it connectors` (no regression).
- `helm lint` and `helm template` with defaults, `connectorHost.enabled=false`, `networkPolicy.cilium.enabled=true`, and `deploy/kind/values-e2e.yaml`; `bash scripts/guards/run-all.sh` (incl. edge-routes).
- `bash scripts/e2e/kind.sh --fresh` green with the managed-connector round trip. **Coordinate first:** AUDIT-003 may be using kind and e2e scripts; before running any `scripts/e2e/*`, ask through Orca `ask` and wait for the go-ahead.

Don't change API routes or DTOs (ask if the contract needs a change).
