# FIX-090: Relay plane limits that work — its own API rate class, the visitor's real address, validated runner endpoints, rotatable relay tokens (REVIEW-5 PRV-3/9/13/15/18, EVID-10) — **high**

Checked against master `c3ec906d`.

## Problem
1. **Every relay → API call is charged as a rejected bearer** (coordinator-verified). The relay authenticates to `/v1/relay/*` with an `aul_` token. The API's rate-limit middleware resolves the caller with the user extractors (`services/aurora-api/src/http/apilimit.rs` `resolve` ~572–605); `authenticate_key` accepts only workspace and org key prefixes (`http/auth.rs` ~467), so an `aul_` bearer becomes `Who::Anonymous { rejected: true }` and is charged to `ip-rejected:<relay pod address>` at `REJECTED_BEARER_PER_MIN` = 30 per minute (~624–631), plus the shared `security` counter. The branch that gives relay traffic its own class (`is_relay`, ~676–690, `PREVIEW_API_RATE` 100/s burst 200) sits in the `Who::Principal` arm and is never reached; `exempt` (~105) covers `/v1/runner/` but not `/v1/relay/`. One preview page with thirty subresources, or an anonymous visitor sending thirty random preview cookies in a minute (each forces a `resolve`), makes the API answer 429 to the relay: every preview on the instance then fails, `validate` stops (revoked streams stay open) and `report` stops. The only test (`apilimit.rs` ~848) checks `is_relay` and constants.
2. **The grant-redemption limit keys on the ingress pod** (coordinator-verified). `services/aurora-relay/src/edge.rs` ~1082 takes the client address from `tcp.peer_addr()`; inbound `X-Forwarded-For` is never read (`docs/15` ~861 says the relay "trusts the edge's overwritten X-Forwarded-For exactly like the API"). Behind any edge proxy all visitors share one 30-per-minute bucket per replica, and the check runs before the state cookie or grant is examined, so thirty anonymous `GET /_aurora/grant?g=x` per minute lock out every real redemption on that replica.
3. **The relay dials whatever endpoint the API names, with a live grant.** `services/aurora-api/src/domains/runner_plane/preview_streams.rs` `runner_endpoint_of` (~41–49) concatenates `runner_replicas.advertised_host` unvalidated; the relay sends `Authorization: Bearer aux_…` to it (`services/aurora-relay/src/stream.rs` ~213–223). A runner credential can therefore redirect preview grants to a host of its choosing.
4. **Relay tokens cannot be rotated.** `bootstrap_relay_token` only upserts (`relay/service.rs` ~157–163; `repo/preview_relay.rs` ~189–215; no `revoked_at`/expiry in `relay_tokens`): after the operator changes the secret, the old `aul_` value still authenticates.
5. **Per-replica caps described as global.** The stream caps live in each relay process and the byte quota's `local` fallback counts per API replica (`relay/quota.rs` ~12–19), while `docs/16` gives the caps without "per replica" and says the quota "never fails open".
6. **Tenant identifier as a metric label.** `services/aurora-api/src/jobs.rs` ~167–175 emits `aurora_preview_shares{org=<slug>}`; `docs/15` documents `{state}`.

## Linked requirements
- `docs/16` §W17 ("relay-plane routes … their own per-replica class `PREVIEW_API_RATE`"), §W18; `docs/15` §Port previews; `docs/17` SEC-82, SEC-85; `docs/02` §Limits; C-550..C-559.

## Spec change (apply with the fix)
- `docs/16` §W17: relay tokens — "the token presented at bootstrap is the only valid anchor: bootstrapping with a new token deletes every other `relay_tokens` row and its replicas"; stream caps and the quota fallback stated as per replica, with the bound an operator should expect (`replicas × cap`).
- `docs/15` §Port previews and `docs/23`: new key `relay.trusted_proxies` (same semantics and default as `server.trusted_proxies`); without it the peer address is the client address.
- `docs/11`/`docs/16`: `advertised_host` is a host name or IP literal with an optional port; anything else is refused at runner registration.

## Scope
### In scope
- API limiter: recognise `is_relay(path)` with an `aul_` bearer before the user extractors; authenticate it with the relay-plane extractor and charge only the preview class keyed by relay replica (unknown or dead token → the ordinary rejected-bearer path). A real API test drives the middleware.
- Relay: handle 429/5xx from the API without turning it into a visitor-facing 502 where a retry is possible (`validate`/`report` retry with backoff; `resolve` → the try-later page); cap negative resolves per client address so random cookies cannot spend the class.
- Client address: `relay.trusted_proxies`; rightmost untrusted `X-Forwarded-For` entry when the peer is trusted; used for the grant limiter and for the outbound `X-Forwarded-For`.
- `advertised_host` validation at runner registration (reject scheme, path, userinfo, `?`, whitespace); the relay refuses an endpoint whose host is not a name or IP literal with an optional port.
- Token rotation as specified.
- `aurora_preview_shares` labelled by `state` only.

### Out of scope
- The pump and header defects (FIX-088); wake flow (FIX-089).

## Acceptance criteria
- [ ] API IT through the middleware: 200 `POST /v1/relay/resolve` calls in a minute with a live `aul_` token → no 429; with a dead token → the rejected-bearer limit applies.
- [ ] Relay IT: 200 requests with random preview cookies from one client, then a legitimate request → served (or the login page), not 502.
- [ ] Relay IT: many clients behind one trusted proxy with different `X-Forwarded-For` → not refused together; an untrusted peer's `X-Forwarded-For` is ignored.
- [ ] Runner-plane IT: registration with `advertised_host` containing `/`, `@`, `?` or a space → refused.
- [ ] API IT: bootstrap with a new relay token → the old token answers 401.
- [ ] Metrics test: no org slug label.
- [ ] Each main test seen failing before the fix. Full `aurora-api` it-suite, `cargo test -p aurora-relay -p aurora-config`, fmt, clippy, guards.
