# BE-002: Implement `aurora-config` (layered TOML + env, typed sections, validation)

## Goal
One configuration loader for every service: TOML file + `AURORA__SECTION__KEY` env overrides + `*_file` secrets, typed per section, validated completely at startup with errors naming the key.

## Linked requirements
- M0/15§config; `15 §Configuration`, `§Required secrets`, `§Configuration reference`; `02 §Coding rules` (Configuration).

## Context (read only these)
- `docs/15-deployment-operations.md` sections "Configuration" (all subsections incl. governance example).
- `docs/02-engineering-conventions.md §Limits registry` (defaults that are config-overridable — config keys in that table).
- Root `Cargo.toml` workspace deps (`toml`, `serde`, `thiserror`, …); add `{ workspace = true }` deps only to `crates/aurora-config/Cargo.toml`. Do not edit root Cargo.toml.
- `aurora-core` may not be ready yet; do not depend on it (use your own `thiserror` error type).

## Scope
### In scope (`crates/aurora-config/**` only)
- `load(path: Option<&Path>, env: impl Iterator<(String,String)>) -> Result<RawConfig>`: read TOML (`AURORA_CONFIG` env or default `/etc/aurora/aurora.toml`; missing file allowed only if env supplies everything required), then overlay `AURORA__<SECTION>__<KEY>` (double underscore separators, uppercase → lowercase keys; nested sections e.g. `AURORA__RUNNER__K8S__NAMESPACE`; values parsed as TOML scalars/arrays when possible, else string).
- Required-secret env vars of `15 §Required secrets` (`AURORA_DATABASE_URL`, `AURORA_ENCRYPTION_KEYS`, `AURORA_ENCRYPTION_ACTIVE_KEY`, `AURORA_SIGNING_KEY`, `AURORA_INTERNAL_SECRET`, `AURORA_RUNNER_SESSION_KEY`, `AURORA_RUNNER_TOKEN`, `AURORA_CONNECTOR_TOKEN`, `AURORA_BOOTSTRAP_*`) with `<NAME>_FILE` variants reading the file (trim trailing newline). Secret-valued fields are held in a redacting wrapper (local `Redacted<String>` type with `Debug` = `[redacted]`; BE-001's `Secret<T>` may replace it later).
- Typed structs with serde defaults exactly per the configuration reference table: `server`, `database`, `auth` (incl. `oidc_providers[]` shape: id, display_name, issuer, client_id, client_secret_env, scopes, …—keep fields documented in `04 §OIDC` if you need them; minimal: id, display_name, issuer_url, client_id, client_secret_env), `email`, `secrets` (default_store, stores[] as opaque tables with `id`,`kind`), `llm` (enabled_providers, provider_preference, endpoints[] with id, provider, base_url, allowed_models, key_origin {method, allowed_organization_ids, allowed_workspace_ids, allowed_team_ids}), `governance.llm`, `governance.egress`, `agents`, `hosted`, `gateway`, `approvals`, `plugins`, `hookhost`, `runner` (+`k8s`), `tls`, `retention`, `telemetry`. Unknown keys → error (deny_unknown_fields) naming the key path.
- Per-service views: `ApiConfig`, `GatewayConfig`, `HookhostConfig`, `RunnerConfig`, `ConnectorConfig` built by `validate_for(Service)` that checks exactly the sections/secrets that service needs (e.g. `server.external_url` required URL for api/gateway; `runner.backend` required for runner and ∈ {podman,kubernetes,fake}; enums validated: `auth.signup_mode`, `auth.org_creation`, postures; `gateway.condition_body_bytes` within 4 KiB–8 MiB; `governance.llm.require_key_origin=true` ⇒ every endpoint has `key_origin`; secret formats: base64 32-byte keys, key ids `[a-z0-9]{1,16}`, active key present in keyring, internal secret ≥32 bytes). Collect **all** errors, each naming the key (e.g. `server.external_url: required`).
- Built-in `known_llm_hosts` default list from `15` (with `known_llm_hosts_extra` appended; endpoint hosts removed).

### Out of scope
- Using config in services (BE-008); secret store/LLM semantics beyond shape validation.

## Acceptance criteria
- [ ] Tests: TOML only; env override of nested key; `_FILE` secret; unknown key error names path; multiple errors collected; defaults equal the table (spot-check ≥10 keys); per-service validation (api missing external_url fails; runner bad backend fails); governance example from `15` parses and validates.
- [ ] Secrets never appear in `Debug` output (test).
- [ ] `cargo test -p aurora-config`, `cargo clippy -p aurora-config --all-targets -- -D warnings`, `cargo fmt -p aurora-config --check` pass.
