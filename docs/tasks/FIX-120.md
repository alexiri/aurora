# FIX-120: One connector-host token per host, bound to the connector types it announced (owner, D-178 / Q-R5-8) — **high, security**

## Problem
Every connector host shares one `auh_` token (C-455/C-456: "the token is shared by every host"), and that token can act as **any** managed connector: it registers types, long-polls assignments for any `instance_id` it names, and receives the decrypted settings/secrets of every managed connector of every org (C-456 itself calls the type filter "not an authorization boundary"). One compromised connector-host pod — or one leaked token — yields every org's connector credentials.

## Decision (owner, 2026-11-13, D-178 / Q-R5-8)
One token per host, bound to the connector types that host announced. A host's token can only register, poll assignments for, and receive credentials of the types it is bound to.

## Linked requirements
- `13 §3.1` (connector host), C-450..C-459 (esp. C-455/C-456), `00` (`auh_`), `01`, `08` (purpose `connector.settings`), `15` (connector host operations), SEC-69/SEC-70, D-128.

## Scope
### In scope
1. **Data model:** a `connector_host_tokens` table (or columns on `connector_hosts`) holding one hashed `auh_` token per host with its bound `type_ids` (set at issue time), created/revoked by an instance admin; the shared bootstrap token keeps working **only** for a host that has not yet been issued its own token (migration path), and is refused once the instance has per-host tokens configured — design the migration so existing installs upgrade without downtime and say how in `15 §Upgrades`.
2. **API:** register refuses types outside the token's bound set (403 naming the type); assignments and credential delivery are filtered by the token's bound types (an assignment for any other type is never sent); `instance_id` is bound to the token (a token cannot poll as another host's id). Admin routes to issue (returns the token once), list (prefix + bound types + last seen) and revoke host tokens (`05`, C-numbers from the reserved block — next free after the ones FIX-072 used; say which), audited.
3. **Helm:** the chart issues per-host tokens for the connector-host Deployment(s) it renders (one token per Deployment, bound to that Deployment's configured types; the hooks job generates and stores them the way it generates `AURORA_CONNECTOR_HOST_TOKEN` today); values and `23` updated; the `helm-values-docs.sh` guard stays green.
4. **Dashboard:** Admin → Connectors shows each host with its bound types and token status; issuing/revoking per the routes (small, reuse primitives; `14` updated).
5. Docs: `13 §3.1`, `15`, `23`, `docs/operator/plugins-and-connectors.md`, SEC-69/SEC-70 rows (new tests cited).

### Out of scope
- Managed-connector settings encryption itself (unchanged).
