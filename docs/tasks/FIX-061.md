# FIX-061: A preview session is never bound to the hostname it is presented on; terminal session caps are not enforced (code review 2026-11-13) — **medium, security**

## Problem
Code review of `09e955c9..bc7857ad`, verified by the coordinator:

1. **Preview session ↔ label binding is a tautology** (`services/aurora-api/src/domains/relay/service.rs`):
   - `resolve_once` (~line 282) calls `share_of(&mut conn, &req.label)` only to 404 an unknown label and **discards** the share; it then loads `(session, share)` via `session_of(hash)` — the share **from the session** — and compares `session.share_id != share.id`, which is always false.
   - The streams path (~line 575) has the same pattern.
   - Effect: a preview session cookie minted for share A is accepted on share B's hostname and the relay serves **A's** app under **B's** origin. Origins are the isolation boundary between previews (D-145 random per-share hostnames); content of one share served on another share's origin breaks that boundary (cookie/storage of B's origin readable by A's app; session fixation via a parent-domain cookie). The spec (`docs/11 §Port previews`, C-546..C-549, SEC-80/SEC-85) binds a preview session to its share's hostname.
2. **Terminal caps (C-617 `4409`) are not enforced** (`services/aurora-api/src/domains/terminal/service.rs` ~139–150):
   - the per-user count is `terminal_stream_grants WHERE consumed_at IS NULL`, but a grant is consumed milliseconds after minting, so live sessions are never counted — `TERMINALS_PER_USER` (2) bounds nothing;
   - `TERMINALS_PER_AGENT` (4) is never checked anywhere (the comment says the runner does it; the runner only enforces `TERMINALS_PER_SANDBOX` on `pty.open`);
   - `services/aurora-api/tests/it/terminal.rs` (~405) only tests never-redeemed grants, so it passes.

## Linked requirements
- D-145, SEC-80, SEC-85, C-546..C-549 (previews); C-617 (`4409` limit: `TERMINALS_PER_AGENT`/`_PER_USER`), D-161, SEC-87 (terminal); `crates/aurora-core/src/limits.rs` (`TERMINALS_PER_{SANDBOX,AGENT,USER}`).

## Scope
### In scope
1. In every relay path that accepts a session (`resolve_once`, the streams open path, and any other `session_of` caller — grep), resolve the share **from the request label** and require `session.share_id == label_share.id`; mismatch → the same uniform answer the path uses for a dead session (`login` in resolve — the flow restarts and mints a session for the right share — and `not_found` on streams). Never serve a share other than the label's.
2. Terminal caps over **live** sessions:
   - per user: count live terminal WebSockets for the user (the API replica terminates the browser leg, so an in-process registry — `DashMap<user_id, count>` or a `Semaphore` per user held for the life of the WS — is enough; the contract already says "per user per replica"). Refuse the upgrade with close `4409` when over the cap.
   - per agent: same registry keyed by agent, `TERMINALS_PER_AGENT`, per replica; document in `docs/15 §Web terminal operations` that with N replicas the effective cap is N× (or implement it in the DB if you find a cheap, leak-free way — a lease row with a heartbeat — and justify it).
   - decrement on every exit path (normal close, error, task panic — use a guard type with `Drop`).
3. While there: the review could not confirm whether an open terminal re-checks access during the session (C-617 `4403` "access lost"). Check; if it does not (e.g. a member removed from the workspace keeps an open shell until idle/lifetime timeout), add the periodic re-check the contract implies, or report precisely what the code does and leave it as a finding in the Analysis section.
4. Also check the runner→API preview `closed`/keep-awake report call the review flagged as possibly unauthenticated (`relay`/`previews` runner-plane routes): confirm it requires the runner credential; if it does not, require it.
