# FIX-272: the new-agent-from-template journey: input defaults that work, one copy state per webhook secret, a Template section that follows the server (AUDIT-2026-11-27)

## Why

The audit's web area (`docs/audit/AUDIT-2026-11-27.md`) read the four-step page (P6-TPL-4 B1, FIX-245), the agent's
Template section (P6-TPL-4 B2) and the one-time secret pattern (FIX-248).

1. **A declared input `default` is never applied (medium, both stacks).** `template.yaml` inputs may declare
   `default` (`docs/25` ~:232, "optional; must satisfy the rules above"; `crates/aurora-template/src/model.rs` ~:117).
   - **Server:** `check_inputs` (`crates/aurora-template/src/render.rs` ~:89-160) never reads `input.default`. A
     required input with no value is `Missing`.
   - **Web:** `new-agent/page-view.tsx` ~:118 accepts a required input whose only value is its default
     (`values[input.id] ?? input.default`), but `values` is sent as given (~:169). The text field shows an empty box
     (`about-step.tsx` ~:66-69: `value={values[input.id] ?? ""}`).
   - **Scenario:** `jira_project` (required, default `OPS`). The person leaves it as offered, Next works, and Create
     answers 422 "this input is required" on a field that showed nothing (text) or showed `OPS` selected (choice).
2. **The copy state of one webhook secret carries over to the next (medium).** `new-agent/page-view.tsx` ~:356-372
   re-renders the same `<WebhookSecretDialog webhook={secrets[secretAt]} …>` without a `key`. So `SecretOnce` /
   `OpenSecret` stay mounted, and `useSecretCopy`'s `used`/`copies`/`state` (`ui/secret-once.tsx` ~:16-40) persist,
   though the comment there (~:181) says the state starts over with every new secret.
   - After Copy and Done on secret 1, secret 2 already shows **Copy again**, and Done closes it **without** the
     "You haven't copied it" confirm.
   - The secret is shown only once, so it is lost. The existing test clicks "Close anyway" on both, so it passes
     either way.
3. **"Stop following this template" leaves "Made from …" on screen (low-medium).**
   - `templates/template-section.tsx` ~:29 `status.data?.template ?? agent.template ?? null`.
   - `useDetachAgentTemplate` (`lib/api/agent-templates.ts` ~:321-326) invalidates only the status query. The
     refetched status has `template: null`, and `??` falls back to the stale `agent.template`, whose query is never
     invalidated.
   - `useApplyAgentTemplate` (~:310-316) updates the status and helpers only, so the instructions, skills and
     schedules an apply changed stay stale until a reload.
4. **A refused address after a successful check shows nothing (low).** `templates/add-source-dialog.tsx` ~:81-84 and
   ~:135-139: when `create` fails with `template_url_invalid` in step 2, `urlProblem` is set, which hides the generic
   failure. But the address field isn't rendered while `found` is set, so nothing is shown and Add repository seems
   to do nothing.
5. **Two "give a key" actions can run at once (low).** `agents/answer-fix.tsx` ~:54-112: `GiveKeyButton` and
   `UseAnotherKey` (FIX-249) each have their own mutation and disable only themselves. Clicking one, then the other,
   grants two keys.
6. **One-off styling (cleanup).** `add-source-dialog.tsx` ~:188 `rounded border border-subtle` where the dialogs use
   `rounded-card`/`rounded-control` with `border-line`. `review-changes-dialog.tsx` ~:80 has a hard-coded
   `fixedHeight="600px"` (docs/14 §Visual design: tokens only).

## Decision

**D-500** (audit, 2026-11-27; amends C-1104/C-1141's input rules in place): an input's `default` is the value used
when the person gives none.
- The **server** applies it: `check_inputs` treats an absent or empty value of an input with a `default` as that
  default, before the rules run. It is the authoritative place, so the CLI, a direct API create and an update offer
  agree.
- The **web** pre-fills the field with the default, so the person sees what will be used, and sends what is in the
  field.
- An optional input without a default stays the empty string.

## Change

1. `check_inputs`: the default rule of D-500. `docs/25`'s `default:` line says so. The update offer's merged inputs
   (`updates.rs` `merged_inputs`) use the same function, so nothing else changes there.
2. The about step initializes `values` from the defaults (text and choice) when the step mounts. The validation stays
   as it is.
3. `key` on `WebhookSecretDialog` (`key={secretAt}`). Also make `SecretOnce` key its inner `OpenSecret` by the
   secret (`key={secret}`), so every caller of the pattern is safe.
4. The Template section decides from `status.data` once it is loaded
   (`status.data ? status.data.template ?? null : agent.template ?? null`). Detach and apply invalidate the agent
   query, and apply also the skills and automations queries (the keys those pages use).
5. In step 2 of Add repository, show `urlProblem` in a `Notice` above **Add repository**, with **Back** to edit the
   address.
6. One shared pending state for the starter-key button and the Use another key menu (lift the mutation, or disable
   both while either runs).
7. The styling of Why 6 with the shared tokens and primitives.

**One thing the brief did not foresee** (Change 1 says the update offer needs nothing else). `check_inputs` applying
defaults was not enough there: `updates.rs` renders from the raw stored or merged values. A new version that added
an input with a default would no longer ask for it (`inputs_needed` is empty), yet would write a literal
`{input.<id>}` into the agent. So `aurora-template` also has `with_defaults` (the same rule, without the checks), and
it is applied to the new version's renders (the offer, the apply and the merge's "theirs", all from the same values,
so the merge hash still matches) and at the end of `merged_inputs`, so the stored provenance holds what was used.
The merge **base** still renders from the stored values only, because it is what the agent started from. An agent
made before this fix with a stored `""` for an input that has a default gets the default in its next offer (D-500).

**Choices**

- The about step fills only a value never set, so a field the person cleared stays cleared (the server then applies
  the default, and a required one still says "This is needed.").
- Create sends only the inputs the current plan declares. Without this, pre-filled values for an input a newer
  version dropped would be refused as unknown after a `template_version_changed`.
- Detach and apply invalidate every workspace's agent list (that list is where the agent page reads the agent), by
  key shape, so the Agents page's **Review updates** walkthrough needs no new prop.
- One mutation key per agent for both give-a-key mutations, so every place that shows them (header, empty chat,
  starter-key card) waits together.
- The review dialog's `fixedHeight="600px"` is removed (it is not a multi-step dialog; the shared maximum height
  applies). The connect journey's documented 600 px sheet is unchanged.
- Step 2 of Add repository says the problem in the footer, above the buttons, so a long list cannot scroll it out of
  view, with "Go back to change the address."
