# FIX-107: Plugin trust — publisher changes, key revocation, token endpoints, downgrades and credential-vocabulary changes all need approval; the hook host does not serialise tenants (REVIEW-5 PLUG-1..PLUG-11) — **high, security**

## Problem
The ingest decision (`services/aurora-api/src/domains/plugins/ingest.rs` `decide`, ~179–194) auto-activates any new version of an installed package id whose permissions do not widen (`crates/aurora-registry/src/diff.rs` `widens`, ~57–117). What "widen" omits:

1. **Publisher.** `previous_approved` matches on `package_id` only (`crates/aurora-db/src/repo/plugins.rs` ~138–150) and `widens` never compares `package.publisher`. Any key the admin trusted for publisher B can ship `id: X, publisher: B` as an upgrade of publisher A's installed package X — including a built-in — and it activates without review; B's hooks then run with X's connections' client secrets and credentials.
2. **Token endpoint.** A static OAuth `token_url` is checked only for https (`crates/aurora-registry/src/validate/mod.rs` `check_oauth_url` ~297–366); `diff::zones` (~31–47) covers templated URLs only. An upgrade that changes only `token_url` is not a widening: the next refresh posts every connection's refresh token and the client secret to the new host (`services/aurora-gateway/src/refresh.rs` ~541–552; API exchange `connect/service.rs` ~1083–1138). SEC-17 constrains templated endpoints only.
3. **Version order.** Nothing compares versions: an older signed version re-ingested (upload, or a file dropped into `plugins.dir`, `plugins/scan.rs`) auto-activates, rolling back a security fix.
4. **Credential vocabulary.** Flips to `reauth_required` are computed only for major upgrades (`plugins/upgrade.rs` ~147; SEC-57 says "major"); a minor upgrade can rename or repurpose a required credential field and activate.
5. **Key revocation misses non-canonical key ids.** A SIGNATURE's `key_id` is parsed leniently (`crates/aurora-crypto/src/ed25519.rs` `b64` accepts standard, URL-safe and unpadded base64) and stored as written (`crates/aurora-registry/src/signature.rs` ~148–170; `ingest.rs` ~217); revocation disables packages `WHERE signer_key_id = <canonical>` (`repo/plugins.rs` ~272–288). A package signed with the URL-safe spelling of a trusted key verifies, and stays active when that key is revoked; `enable` has the same equality check. SEC-15: "revoking a key disables its packages".

Hook host and validation:
6. **One lock across module pull and compile.** `services/aurora-hookhost/src/snapshot.rs` `module_inner` (~182–209) holds the module-map lock through the blob fetch (30 s timeout) and compilation; every hook call (`server.rs` ~171) and the snapshot refresh (~150) wait behind a cold load, so one package's slow load fails other tenants' token mints.
7. `connect.authorize` output URLs are checked for scheme only (`hookhost/src/validate.rs` ~110); `random_bytes` returns zeros if `/dev/urandom` cannot be read (`runtime.rs` ~195–204); no manifest size limit and an undocumented 4 × `PACKAGE_MAX` decompressed cap (`manifest/mod.rs` ~48; `package.rs` ~31–40); `docs/09` ~59 promises a standing dashboard banner for `plugins.allow_unsigned` that does not exist, and §8.3 mentions fuel the runtime does not use.

## Linked requirements
- `docs/17` SEC-15, SEC-17, SEC-57; `docs/09` §2 (signatures), §3.3 (OAuth), §8 (hooks), §10 (upgrades); D-142.

## Spec change (apply with the fix)
- SEC-15 / `docs/09` §10: "A version is a first install — and needs instance-admin approval — when its `package.publisher` differs from the installed package's, when it is lower than the highest approved version of that id, or when the package id belongs to the built-in source and the version does not." "`key_id` is the canonical standard-base64 encoding of the key; any other spelling is `signature_malformed`."
- SEC-17 / `docs/09` §3.3: "Token and authorize endpoints, static or templated, lie on a claimed host or a host listed in `permissions.token_hosts`; a change of token-endpoint host is a widening and is shown at approval."
- SEC-57: "any version", not only major: a change in the required credential names flips affected connections to `reauth_required` in the activation transaction.
- `docs/02` §Limits: `MANIFEST_MAX`, the decompressed cap.

## Scope
- `decide`: `publisher_changed`, `version_downgrade`, built-in id protection → `pending_approval` with the reason shown in the admin UI's approval screen.
- `widens` and the linter: token/authorize hosts; reserved-host overlap check on them.
- Flip check for every activation.
- Canonical key ids at parse, storage and comparison; a data fix for existing `signer_key_id` rows.
- Hook host: per-digest single-flight; the map lock held only to read or insert.
- Items in 7: authorize URL host bound to the package's declared hosts; `random_bytes` fails the call; size limits; the banner (expose the flag in the instance payload) or the sentence removed; "fuel" wording corrected.
- Tests and fixtures for each (see FIX-101 for the fourteen rule codes without fixtures).

## Acceptance criteria
- [ ] API IT: v2 signed by publisher B's trusted key for A's package (identical permissions) → `pending_approval` `publisher_changed`; the same with a built-in id.
- [ ] API IT: v2 changing only a static `token_url` host → `pending_approval`; a `token_url` on a reserved host fails validation.
- [ ] API IT: 1.9.0 after 2.0.0 → `pending_approval` `version_downgrade`.
- [ ] API IT: minor upgrade renaming a required credential → affected connections `reauth_required`.
- [ ] API IT: trust a key whose base64 contains `+`/`/`; a package signed with the URL-safe spelling is refused (`signature_malformed`); with a pre-existing non-canonical row, revocation disables it.
- [ ] Hook host test: a blocked blob fetch for package A does not delay a cached call for package B.
