# FIX-155: The terminal wrappers treat `/run/aurora/harness.env` as untrusted, agent-writable data

## Goal
A person who opens the web terminal and runs `claude` or `codex` must not inherit shell commands or
execution-changing environment variables that **agent code** placed in `/run/aurora/harness.env`.
Today the wrappers `/opt/aurora/bin/{claude,codex}` do `set -a; . "$envfile"; set +a`, and the file is
agent-writable (mode `0644`, owner uid 1000 — the same uid the agent runs as; `harness_env.rs` even
comments it "read-only to the agent", which is false at one uid). So any process the agent runs can
rewrite the file and, the next time a **human** launches a terminal harness, (a) execute arbitrary
shell at source time, and (b) set any variable in the human's harness process — `NODE_OPTIONS`
(`--require` → code in the Node-based Claude Code harness), or a rewritten `SSL_CERT_FILE` /
`NODE_EXTRA_CA_CERTS` / `HTTPS_PROXY` pointing at an in-pod listener (MITM of the human's harness
traffic). This is the one path found that runs attacker-chosen behaviour inside a process a human
started (red-team finding F12, 2026-11-15).

This brief is the **interim, in-pod-only hardening**. The complete fix — making the file unwritable
by agent code — needs a second uid and is **D-314** (proposed); this task closes the arbitrary-code
and interpreter-hijack classes now and documents the residual that only D-314 removes.

## Design (decided; the lane implements it, reports with evidence if a part cannot hold)
1. **Parse, do not source.** The wrappers stop running the file as shell. No `. "$envfile"`, no
   `set -a`, no command substitution. They read it line by line as data.
2. **Fixed grammar, fail closed.** Accept only the exact shape the supervisor's `write()`/`q()`
   emit: blank lines, `# comment` lines, and `NAME='VALUE'` where `NAME` matches
   `^[A-Za-z_][A-Za-z0-9_]*$` and `VALUE` is a single-quoted word using `q()`'s `'\''` escaping and
   nothing after the closing quote. **Any other line → the wrapper refuses to start** (prints a
   tamper message, exits non-zero): a genuine supervisor file never contains anything else, so a
   deviation is tampering, not a format to tolerate.
3. **Name allowlist.** Export only names the supervisor is known to write: `HARNESSES_ENABLED`,
   `HTTP(S)_PROXY`/`http(s)_proxy`/`NO_PROXY`, `SSL_CERT_FILE`, `NODE_EXTRA_CA_CERTS`,
   `CODEX_CA_CERTIFICATE`, `DISABLE_AUTOUPDATER`/`DISABLE_TELEMETRY`/`DISABLE_ERROR_REPORTING`,
   `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`, `OPENAI_API_KEY`, `ANTHROPIC_MODEL`/`_BASE_URL`/
   `_AUTH_TOKEN`/`_API_KEY`, `AURORA_CLAUDE_UNAVAILABLE`, `AURORA_CODEX_MODEL`/`_BASE_URL`,
   `AURORA_CODEX_UNAVAILABLE`. Any name not on the list is ignored, so an injected `NODE_OPTIONS`
   (never on the list) cannot reach the child even as a well-formed line.
4. **Operator `client_env` keys.** `render()` also emits endpoint-configured `client_env` names,
   which are open-ended and so cannot be a static allowlist. To keep them working through the
   terminal, the supervisor additionally writes one line `AURORA_CLIENT_ENV_KEYS='K1 K2 …'` (the
   exact names it wrote this render); the wrapper exports a non-allowlisted name **only** if it
   appears in that list **and** is not on the denylist (5). If the terminal does not need
   `client_env`, drop it from the terminal path instead and skip the manifest — decide in the lane,
   record which. Either way, note the residual: the manifest is in the same agent-writable file, so
   it bounds honest renders, not a tamperer (see Residual).
5. **Interpreter denylist (belt and suspenders).** Never export, regardless of the allowlist:
   `NODE_OPTIONS`, `BASH_ENV`, `ENV`, `SHELLOPTS`, `BASHOPTS`, `LD_PRELOAD`, `LD_LIBRARY_PATH`,
   `LD_AUDIT`, `PYTHONSTARTUP`, `PYTHONPATH`, `PERL5OPT`, `RUBYOPT`. The supervisor writes none of
   them, so refusing them costs nothing and catches any future allowlist slip.
6. **Correct the record.** Fix the `harness_env.rs` doc comment that calls the file "read-only to the
   agent" (it is not at one uid); keep mode `0644` but add a comment pointing at D-314 as the real
   fix. No behaviour change in the writer beyond the optional `AURORA_CLIENT_ENV_KEYS` line (4).

### Residual (only D-314 closes it — state it, do not pretend otherwise)
Because the whole file is agent-writable at one uid, a tamperer can still rewrite the **value** of an
*allowlisted* variable — e.g. point `SSL_CERT_FILE`/`HTTPS_PROXY` at an in-pod MITM, or spoof the
`AURORA_CLIENT_ENV_KEYS` list. Per F13 the real LLM key is injected upstream and is not capturable
in-pod, but a rewritten CA/proxy still lets agent code read and alter a human's harness traffic and
prompts. The wrapper cannot tell a supervisor write from an agent rewrite; only an owner-ratified
second uid (D-314) or an integrity check with a key the agent cannot read (which also needs the
second uid) removes this. The `17` residual bullet must say so.

## Acceptance criteria (failing-first: each new test fails before its code)
1. A normal supervisor-written `harness.env` (golden) → the wrapper exports exactly the allowlisted
   names with the same values sourcing would have produced, and execs the harness. Run the file
   through `sh -n` to prove it still parses, and assert the exported set via a wrapper that prints
   its env instead of exec'ing.
2. `harness.env` with an extra shell line (`touch /run/aurora/pwned` or `X=$(touch …)`) → the
   wrapper refuses to start and the side-effect file is **never** created.
3. `harness.env` adding `NODE_OPTIONS='--require /workspace/x.js'` → `NODE_OPTIONS` absent from the
   child env.
4. `harness.env` adding `LD_PRELOAD`, `BASH_ENV`, `PYTHONSTARTUP` → none exported.
5. A line that breaks the grammar (unquoted value, double quotes, two `=`, trailing bytes after the
   closing quote) → refuse to start (fail closed).
6. The allowlisted proxy/CA/model vars pass through unchanged, so a real terminal turn still reaches
   the gateway (keep an e2e or a wrapper-env assertion).
7. Shellcheck/CI shell lint clean; POSIX `sh` only.
8. `cargo nextest run -p aurora-supervisor` (harness_env tests, incl. the corrected comment and any
   `AURORA_CLIENT_ENV_KEYS` line), clippy `-D warnings`, guards.
