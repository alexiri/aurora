# FIX-155: Terminal hygiene — wrappers parse `harness.env`, and the pane says whose environment it is

## Goal
Two small changes. They come out of the 2026-11-15 red-team finding F12 and the owner's decision to
**accept the web terminal as part of the agent's environment** (D-314 withdrawn; `17` residual
"`/run/aurora` is the agent's").

1. **Wrapper hygiene.** `/opt/aurora/bin/{claude,codex}` stop running `/run/aurora/harness.env` as
   shell (`set -a; . "$envfile"`) and stop resolving their own helpers through `PATH`.
2. **Say it in the UI.** The terminal pane tells the person that it runs inside the agent's sandbox.

**This is not a security boundary, and nothing in it may be described as one.** The terminal shell
runs as the agent uid with `HOME=/workspace` and `/workspace/.local/bin` first on `PATH`. Agent code
can therefore shadow `claude` (or any command), plant `~/.zshrc`/`~/.bash_profile`, attach to the
terminal shell (same uid, `ptrace_scope=0`), or rewrite `harness.env` and `ca.pem`. The wrapper
changes remove one surprising behaviour: a tampered file executing shell the moment someone runs
`claude`. The notice makes the trust model visible. Neither closes F12; the residual in `17` is the
answer.

## Design (decided)
1. **Parse, do not source.** Read the file line by line as data. Accept blank lines, `# …` lines and
   `NAME='VALUE'`, where `NAME` matches `^[A-Za-z_][A-Za-z0-9_]*$` and `VALUE` is one single-quoted
   word using `q()`'s `'\''` escaping, with nothing after the closing quote. Export each accepted
   pair. On **any other line**, refuse to start: print `claude: /run/aurora/harness.env is not in
   the expected format` and exit 1. Never apply part of the file. No allowlist and no denylist: the
   terminal is the agent's environment, so they would add upkeep (operator `client_env` names)
   without creating a boundary.
2. **Absolute paths for the wrappers' own helpers.** Use `/usr/bin/mkdir` (and absolute paths for any
   other external command the wrappers run). Today's unqualified `mkdir` runs whatever `PATH` finds
   first.
3. **Correct the writer's comments.** In `harness_env.rs`, `DEFAULT_PATH`'s doc says "read-only to
   the agent", and the module doc says the wrappers shell-source the file. Change them to say the
   file is agent-writable at one uid, that the wrappers parse it (1), and point at the `17` residual.
   Behaviour is unchanged.
4. **Pane notice.** When a terminal opens, the dashboard's terminal pane shows one fixed, muted line:
   *"This terminal runs inside the agent's sandbox: the agent can change what runs here and can see
   what you type."* It is not a dialog and is not dismissed per session. Use the existing primitives
   and tokens, in both themes, with no horizontal scroll at 390 px (`14 §Visual design`).

dotfile handling, the tools socket (FIX-151).

## Acceptance criteria (failing-first)
1. A golden supervisor-written `harness.env` produces the same exported values as sourcing did.
   Assert this with a wrapper copy whose `bin=` prints its environment.
2. A file containing an extra shell line (`touch /tmp/fix155-marker`, or
   `X=$(touch /tmp/fix155-marker)`) makes the wrapper refuse to start, and the marker is never
   created.
3. A grammar break (unquoted value, double quotes, trailing bytes after the closing quote) also makes
   the wrapper refuse to start.
4. With `PATH` set to a directory holding a hostile `mkdir`, the wrapper still creates its state
   directory and the hostile `mkdir` does not run.
5. Shell lint is clean.
6. `cargo nextest run -p aurora-supervisor` (harness_env), clippy `-D warnings`, guards.
7. Web: the notice renders in the terminal pane in both themes, with no horizontal scroll at 390 px.
   Run the repo's web tests, type check, lint and production build.
