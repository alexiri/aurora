# FIX-115: Conversations and credentials — failed turns keep their answer text, home sync stays within its bound, credential updates are compare-and-set (REVIEW-5 CONV-1/2/4, CRED-1/4/5/10/11) — **medium**

## Problem
Conversations
1. **A failed or stalled turn loses the answer the agent had already written.** Text after a turn's last tool call is staged in `turn_answer_buffers` and becomes durable `text` events only in `result()` (`services/aurora-api/src/domains/hosted/reports.rs` ~474). Every API-side failure path — stall, time limit, never started, agent restarted, the no-key and harness sweeps, frozen-agent sweeps — goes through `hosted/lifecycle.rs` `fail` → `finish` (~42–54) and never drains the buffer: the user sees the error, not the text, and the row stays until the conversation is deleted. `docs/10` §The answer rule makes no exception for failed turns.
2. **The `render_inputs` home part is never size-checked** (`hosted/home.rs` ~356; only app snippets are shed, ~317). Peers, channel presences, app accounts and schedules are unbounded in count; a part over `MAX_HOME_SYNC_PART` (200 KiB, `crates/aurora-protocol/src/runner.rs` ~806) is refused by validation, the sync never converges, and the sandbox never accepts turns. (Confirm first what the runner does with an oversized part.)
3. **The no-key sweep looks at the 16 oldest queued turns only** (`crates/aurora-db/src/repo/hosted.rs` ~660; `runner_plane/work.rs` ~165): when those are turns waiting for capacity, a keyless agent's turn behind them starts a sandbox before failing, against "`no_model_key` fails queued turns before any sandbox start is claimed" (`docs/10`).

Credentials
4. **OAuth client PATCH is a lost update.** `oauth_clients/service.rs` (~225–262) reads the row outside a transaction, merges public and secret fields, seals a new value and updates `WHERE id` only (`crates/aurora-db/src/repo/oauth_clients.rs` ~94–113). Two concurrent PATCHes silently drop one change, and the loser's sealed value is never discarded (with Vault, a client secret left unreferenced). The codebase's own convention is compare-and-set on the old reference (`secrets_migrate.rs`, connect `write()`, `reconnect_cas`).
5. Connect-flow randomness falls back to a time-derived UUID if the OS generator fails (`connect/flow.rs` ~24–31; used for the PKCE verifier); the OAuth popup posts to an empty target origin — and silently drops the result — when `external_url` has no origin (`connect/routes.rs` callback, `unwrap_or_default()`); hook-based connects never record requested scopes, so `missing_scopes` is always empty for them (`connect/service.rs` ~579–590; C-42); `source_connection_id` is never written while deletion handles one level of children (`repo/connections.rs` ~123–130).

## Linked requirements

## Spec change (apply with the fix)
`docs/10` §The answer rule: "when a turn ends without a result (failed, stalled, cancelled), the text buffered since its last tool call is written as durable `text` events before `turn.finished`; nothing is discarded silently." `docs/09`: hook-based connects report the scopes the hook was asked for, or none — say which.

## Scope
- Drain the buffer in every terminal path (take under the conversation lock, append non-empty messages, delete the row).
- `render_inputs` packed under the part bound: counts capped with a truncation notice inside the rendered inputs, final size asserted.
- No-key sweep selects keyless agents in SQL (or the start claim checks readiness) so no start is claimed for them.
- OAuth client update: compare-and-set on `secret_ref` and a version for public fields → 409 `conflict`, new reference discarded on loss.
- Random source failure is an error (connect start answers 500); callback refuses to render the success page without an origin (and config validation requires one); requested scopes for hook flows; `with_children` recursive or the unused column documented as reserved.
