# FIX-033: SCIM group member audit rows carry no `org_id` and are invisible in the org's audit trail (code review pass 2 of 09e955c9..master)

## Problem

Every SCIM group member change made through `PUT`/`PATCH /scim/v2/Groups/{id}` writes
its `group_member.add`/`group_member.remove` audit row **without** the organization:

- `services/aurora-api/src/domains/scim/resource_groups.rs:332-362` — `member_evs`
  builds the events with `.target("group", group)` but never calls `.org(...)`; the
  builder defaults `org_id` to `None` (`services/aurora-api/src/audit.rs:101,112-115`).
- `…/resource_groups.rs:467,485` — those events go through
  `commit_critical_many`, so they are written security-critically **with
  `audit_log.org_id = NULL`** (`audit_log.org_id` is nullable,
  `crates/aurora-db/migrations/20261105000001_identity.sql:153`).

Consequences:

1. The org's audit trail cannot see them. The org-scoped read filters
   `org_id = $1` (`crates/aurora-db/src/repo/audit.rs:96` with `Scope::Org`), so
   every SCIM-driven group membership change made after group creation is missing
   from the dashboard audit views — while the identical rows written by
   `create_group` (`…/resource_groups.rs:215-224`, `.org(org.org_id)`), by the
   dashboard (`services/aurora-api/src/domains/groups/service.rs:381-384,418-423`,
   `.org(g.org_id)`) and by the IdP sign-in sync
   (`services/aurora-api/src/domains/groups/sync.rs:39-44`, `.org(ch.org_id)`) do
   appear. This is the "no audit, no change" ledger (docs/04 §Audit) losing its
   per-org rows for one whole class of SCIM writes.
2. The docs state the rows carry the org: docs/04 §Groups ("one row per added or
   removed member", `docs/04-identity-tenancy.md:693`) and C-478 require the
   ordinary `group_member.add|remove` rows with `metadata.via = "scim"`
   (`docs/API_CONTRACTS.md:1090`); the management `scim.error` writer in the same
   file sets `org_id: Some(org)` (`…/management.rs:445-447`), underlining the
   intent.
3. `scim_groups.rs` tests count rows by `target_id` only
   (`services/aurora-api/tests/it/scim_groups.rs:187-193,213-220`), so the gap was
   never caught.

## Goal (priority: **high**, size: **S**)

Every `group_member.add|remove` row written by the SCIM plane carries the org
(`audit_log.org_id` set) and therefore appears in the org's audit trail like the
dashboard's and the sync's rows do.

## Scope

1. `services/aurora-api/src/domains/scim/resource_groups.rs` — `member_evs` takes
   the org (it already receives `caller`; thread `caller.org.org_id` or pass the
   `Uuid`) and sets `.org(org)` on both event kinds.
2. `services/aurora-api/tests/it/scim_groups.rs` — extend the two audit-count
   assertions (or add one) to filter `org_id = $1` so the regression is pinned.

## Acceptance

- A SCIM group `PUT`/`PATCH` member change writes rows with
  `org_id = <org>` (new test assertion green).
- `cargo test -p aurora-api --test it scim` stays green.

## Constraints

- No contract text change needed (C-478 already specifies the rows); this is a
  code + test fix only.
- Change files only with the Edit/Write tools; never python, sed, awk, perl,
  `cat >>` or heredocs.
