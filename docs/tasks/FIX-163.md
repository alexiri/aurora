# FIX-163: "Turn on" is offered for an account whose self-hosted instance was deleted

## Goal
P5-UX-4 (merged `d26d88b6`) rebuilt the accounts list. A connection whose self-hosted app instance was
deleted is turned off with a reason, and the old list hid **Turn on** for it. The new list still offers
**Turn on** in the row's menu, because the accounts API does not carry the connection's `status_reason`.
Turning it on cannot work (there is no instance to reach) and the row should say why instead.

## Change
1. The accounts API (C-917 rows, `services/aurora-api/src/domains/accounts/`) carries `status_reason` for
   a turned-off connection (additive; OpenAPI + `pnpm -C web gen:api`; one line in C-917).
2. The row (`web/src/components/accounts/`): for `status_reason = instance_deleted` (check the exact
   value the instance deletion writes) **Turn on** is not offered; the health line says the app's
   instance was removed and names who can add it again (`WhoCan`, P5-UX-1). Other reasons keep today's
   behaviour.
3. The API refuses a turn-on of such a connection (it should already: prove it with an IT; add the
   refusal if it does not).

## Tests
An IT for the field and the refusal; vitest for the row; the accounts Playwright spec gains the case
(both themes, 390 px). Small (S); any lane between tasks, ideally the one doing P5-UX work.
