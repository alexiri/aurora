## Scope
### In scope
New directory `docs/operator/` with:
- `README.md` (index)
- `install-compose.md`
- `install-helm.md`: values, secrets, NetworkPolicy requirement, ingress/HTTPRoute
- `llm-endpoints.md`: `[[llm.endpoints]]`, governance ceiling, key scopes
- `runners.md`: add a runner (admin token, podman vs kubernetes backend config incl. `runner.k8s.*`, `core_namespace`, binds)
- `plugins-and-connectors.md`: upload, review, approve, trusted keys, host claims, connector provision/token/approve
- `backups.md`: what state lives where (Postgres, secret keyring, gateway CA, home volumes/PVCs), backup and restore steps, key rotation pointers
- `upgrades.md`: the order, migrations, what happens to running sandboxes, per 15 §Upgrades

Every config key mentioned must exist in `crates/aurora-config/src/raw.rs`. Every CLI flag must exist in the code. Mark anything specified but not implemented as "(not yet implemented)" rather than describing it as working.

### Out of scope
- Changing code, the chart or the spec. If the spec and the code disagree, document the code's behaviour and list the disagreement in the completion report.
