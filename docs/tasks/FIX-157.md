# FIX-157: No operation requires an OIDC re-authentication

## Goal
The owner decided that no operation requires a recent OIDC re-authentication any more (D-317, 2026-11-15).

On the owner's CERN SSO deployment the check could never pass. FIX-152's log line showed `auth_time_missing: true`: Keycloak does not send `auth_time`, even with `max_age=0`. Requesting the `basic` scope, which carries the claim, is refused `invalid_scope`. Every guarded operation was therefore unusable: org and workspace delete, account deletion, SCIM setup, instance settings and secret stores.

Remove the 600 s `reauth_at` check from every operation and drop the dashboard's "Sign in again" steps. Every other guard stays.

## Linked requirements
- D-317 supersedes D-305(a) and the re-authentication parts of RFE-004 (C-152), D-132 (C-471/C-472), D-234 (C-733), SEC-90 (C-773/C-776) and FIX-124 (C-746).
- `04 §OIDC` *Re-authentication*, `04 §Instance administration` table, `17` SEC-72/SEC-90 and residual risks.

## What changes (decided)
1. **API: remove the window check** at every call site of `sessions::reauth_age_secs` / `REAUTH_WINDOW_SECS`:
   - `domains/me/service.rs`: account deletion.
   - `domains/freeze/routes.rs`: `require_recent_reauth`, admin org and workspace delete.
   - `domains/scim/management.rs`: `recent_reauth`, SCIM enable and token create.
   - `domains/settings/service.rs`: `require_reauth`, settings writes and import, also called from `domains/admin/secret_stores.rs`.

   **Keep each site's session-only rule** (the `Principal::Session` checks, the "SO" routes). API keys, agent tokens and non-admins are refused exactly as before, with the same codes. Remove `REAUTH_WINDOW_SECS` and the now-unused `reauth_required()` helpers if nothing else uses them. No route answers 412 `reauth_required` afterwards; remove the 412 entries from those routes' utoipa `responses`.
2. **API: keep the OIDC `reauth=1` flow unchanged.** That covers `start`, the callback branch, `stamp_reauth`, `sessions.reauth_at` and C-890's redirect and audit detail. `reauth_age_secs` may be removed from `aurora-db` if it ends up unused; the `stamp_reauth` path stays. No migration.
3. **Web: remove the re-authentication UI.**

   - `account/delete-view.tsx`, including its reauth branch and the description sentence "You will be asked to sign in again with your provider first."
   - `org/directory-view.tsx` (`ReauthNotice`, `reauthUrl` props).
   - `components/auth/reauth-error-notice.tsx` and its four mounts: nothing starts a re-authentication any more.
   - Doc comments in `lib/api/account.ts` and `lib/api/admin-orgs.ts`.

   Keep `oidcStartUrl`'s `reauth` option and the error texts in `errors.ts`; they are harmless and the API flow still exists. Regenerate `web/openapi.json` and `web/src/lib/api/schema.d.ts`.
4. **Tests.**

## Acceptance criteria (failing-first: each new or changed test fails before the code change)
1. `DELETE /v1/me` with a session that never re-authenticated → 204, where it was 412 before. With an API key it is refused as before.
2. Admin `DELETE /v1/admin/orgs/{org}` and `/workspaces/{ws}` with a correct `confirm` and no re-authentication → 204. A wrong slug still gives 400 `confirmation_mismatch`; an API key still gives 403.
3. SCIM enable (`PUT /v1/orgs/{org}/scim` with `enabled: true`) and `POST …/scim/tokens` without re-authentication → succeed. Non-owner and API-key callers are refused as before.
4. `PUT /v1/admin/settings/{section}`, settings import, and a secret-store write without re-authentication → succeed. The critical audit row is still written; non-session callers are still refused.
5. `grep -rn "reauth_age_secs\|REAUTH_WINDOW_SECS" services crates` returns nothing outside `aurora-db`, or nothing at all.
6. Web: none of the touched screens renders a "Sign in again" link. The admin delete dialog deletes on the first confirm. The account deletion page's text no longer mentions signing in again.
7. Gates (batch gate, since this touches several api domains):
