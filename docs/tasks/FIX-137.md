# FIX-137: Real Markdown in chat — links that work, GFM, still safe — **medium, phase 5**

## Goal
The owner (2026-11-13): "Improve markdown support in the chat view, a lot. links have to work, at the very
least!" The renderer is a hand-written 100-line subset (`web/src/components/apps/markdown.tsx`, used by
`components/chat/message-group.tsx:124,310`, the apps connect view, memory, integration dialog, dynamic
forms): headings, paragraphs, flat lists, fenced code, `**bold**`, `` `code` ``, `[text](url)`. Missing:
bare/autolinked URLs (agents mostly print bare URLs, so "links don't work"), `<https://…>` autolinks,
italics, strikethrough, blockquotes, nested and ordered lists with start numbers, task lists, tables,
horizontal rules, headings inside lists, images (as links, see below), escaped characters, hard breaks,
links containing parentheses or query strings with `)`; the link label is followed by a visible
`(href)` copy, which is noisy in chat.

## Linked requirements
- `14` safety rules (line ~33: untrusted text in safe mode — no raw HTML, links show their target,
  `rel="noopener noreferrer nofollow"`, never `dangerouslySetInnerHTML`), `14` chat bubbles (code styling,
  code blocks scroll inside themselves, person messages keep single newlines), `14 §Visual design`
  (tokens, both themes, 390 px), SEC rows on untrusted model output (`17`).

## Plan
1. **Replace the hand-written parser with a maintained CommonMark + GFM parser that renders to React
   elements** (e.g. `react-markdown` + `remark-gfm`, or `micromark` + `mdast-util-to-hast` + a React
   renderer) — no `rehype-raw`, no HTML passthrough; pin exact versions (lockfile, licence check, bundle
   size in the completion report; load it only in the chat/markdown chunk). If the chosen library cannot
   guarantee "no raw HTML" by construction, do not use it.
2. **Links**: autolink bare `http(s)://` URLs and `www.` (GFM autolink literal); `safeHref` stays the
   gate (http/https only; `mailto:` allowed as a link with its address visible; everything else text);
   open in a new tab with `rel="noopener noreferrer nofollow"`. "Links show their target" (`14`) is met by
   a hover/focus title with the full URL and, **when the label differs from the URL's host**, a small
   muted host suffix (`label · example.org`) instead of the whole URL — so a label cannot disguise the
   destination; update `14` with that rule. Links to this dashboard's own origin open in the same tab.
3. **Images**: never loaded (CSP and privacy): rendered as a link "image: <alt> · host".
4. **Elements**: emphasis, strikethrough, blockquotes, nested ordered/unordered lists, task lists
   (read-only checkboxes), tables (scroll horizontally inside their own container, never the page),
   horizontal rules, headings (sized for a chat bubble, not page headings), fenced code with a language
   label and a **Copy** button (syntax highlighting optional: only if a small, pinned highlighter fits the
   bundle budget — otherwise not), inline code; person messages keep `breaks`.
5. **Streaming**: half-finished markdown while a reply streams must not flicker badly (an unclosed fence
   renders as a code block until closed); memoise per finished block.
6. **One renderer everywhere** it is used today (chat, memory, connect view, setup guides, dynamic-form
   help); setup guides (trusted, package-signed) use the same safe mode.
7. Docs: `14` (renderer rules, link rule), `17` if a SEC row names the renderer.
