# FIX-189: `goose` in the web terminal starts ready to use, never in its provider wizard

## Goal
Owner, 2026-11-20 (D-404). Typing `goose` in an agent's web terminal opens goose's setup wizard ("which provider do
you want to connect…"), with a list of providers that a person in Aurora cannot and should not set up. The terminal's
goose must start a session on the agent's model through the gateway, as `claude` and `codex` do: no wizard, no
provider question, no telemetry question.

## Cause (checked in goose's source, tag v1.59.2, `crates/goose-cli/src/cli.rs` `handle_default_session`)
```rust
if !Config::global().exists() {
    return handle_configure().await;
}
#[cfg(feature = "telemetry")]
if get_telemetry_choice().is_none() { configure_telemetry_consent_dialog()?; }
```
A bare `goose` runs the wizard whenever its config **file** does not exist, even when the environment sets
`GOOSE_PROVIDER`/`GOOSE_MODEL`/`LITELLM_HOST`, which `images/sandbox/bin/goose` exports. The wrapper uses
`GOOSE_PATH_ROOT=/workspace/.aurora/terminal/goose`, so the file is
`$GOOSE_PATH_ROOT/config/config.yaml`, and nothing creates it (the FIX-169 code only reads it for `GOOSE_MODE`).
A second path to the wizard: when the API left goose out of the terminal models (a selection error,
`services/aurora-api/src/domains/terminal/service.rs` `terminal_models`), the wrapper has no model or host and execs
bare goose.

## Change (`images/sandbox/bin/goose`)
1. When the wrapper has a model and host (today's `if [ -n "$model" ] && [ -n "$host" ]` branch) and
   `$GOOSE_PATH_ROOT/config/config.yaml` does not exist, create it (mode 0600, owned by the agent user, which the
   wrapper already runs as) with only non-secret keys: `GOOSE_PROVIDER`, `GOOSE_MODEL`, the host key of that
   provider (`ANTHROPIC_HOST` or `LITELLM_HOST` + `LITELLM_BASE_PATH`) and `GOOSE_TELEMETRY_ENABLED: false`.
   Never the placeholder key, never a real credential. Quote values as YAML strings, safely: a model id is checked
   by SEC-122, but write it so that any character is still data. Keep writing atomic (temp file + `mv`), and use
   absolute paths for helpers, like the rest of the wrapper.
2. An existing file is the person's and is left alone. The environment the wrapper sets already overrides its
   provider and model (goose reads the environment first; confirm this on 1.59.2 and note it in the report). If it
   does not, write the provider keys on every start and keep only the person's other keys.
3. Confirm that the telemetry dialog no longer appears: `GOOSE_TELEMETRY_ENABLED=false` in the environment, the
   file, or both (check what `get_telemetry_choice` reads on 1.59.2).
4. No model for goose (no `AURORA_GOOSE_MODEL`/`AURORA_GOOSE_HOST` and no `AURORA_GOOSE_UNAVAILABLE`) and no
   arguments: print `goose: no model is set up for this agent's terminal; check the agent's model on its Behaviour
   page` and exit 1, instead of the wizard. With arguments (for example `goose configure`, `goose --version`), pass
   them through unchanged, as today.
5. `GOOSE_MODE` behaviour (FIX-169) is unchanged. The file the wrapper writes has no `GOOSE_MODE` key, so the
   default stays `auto` until the person saves one.
6. Docs: `docs/12-supervisor-harness.md` §Terminal, the goose sentence of the P5-HARN paragraph: the wrapper creates
   a minimal `config.yaml` (non-secret keys only) when there is none, because goose opens its wizard without one,
   and with no model it says so instead of opening the wizard (D-404).
