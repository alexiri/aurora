# BE-022: `aurora-llm` — provider registry with LiteLLM and Anthropic, key-origin verification

## Goal
The core LLM provider registry (D-16) with the two phase 0 providers, including model listing, model extraction from requests and key-origin verification (D-39).

## Linked requirements
- M2/08 `§6 LLM providers` (trait, phase 0 providers, endpoint config, LLM hosts, model location), `§11.3 Key origin` (methods, `origin_from_response`, compliance); SEC-35, SEC-36 (inputs), SEC-08 (fail closed: unknown model ⇒ `Unknown`); `18 §Governance` ("mock Anthropic-style provider that returns configurable organization/workspace headers").

## Context
- Read `docs/08-secrets-credentials.md` §6 (from "## 6. LLM providers" to "## 7.") and §11.3. Normative.
- Config types: `aurora-config` `llm` section (`enabled_providers`, `provider_preference`, `endpoints[]` with `id, provider, display_name, base_url, dialects, default_model, models, allowed_models, key_origin{method, allowed_organization_ids, allowed_workspace_ids, allowed_team_ids}`) — read `crates/aurora-config/src/raw.rs` for the exact struct names.
- `aurora-core::secret::Secret`. Workspace deps: `reqwest`, `http`, `serde`, `serde_json`, `async-trait`, `thiserror`, `tokio`, `wiremock` (dev), `aurora-config`, `aurora-core`. Do not edit root `Cargo.toml`.
- Host patterns are returned as **strings** in policy host-pattern syntax (`07 §Matching primitives`: exact host, optional `:port`); callers convert to `aurora_policy::HostPattern` (avoids a dependency on the in-progress policy crate).
- Injection: define `LlmInjection { header: Bearer | XApiKey, strip_request_headers: Vec<&'static str> }` locally (litellm: `Authorization: Bearer`, strip `x-api-key`; anthropic: `x-api-key`, strip `authorization`).

## Scope
### In scope (`crates/aurora-llm/**`)
- `LlmProvider` trait as in `08 §6` (adapt types: `HostPattern`→`String`, `InjectionRecipe`→`LlmInjection`, `Client`→`reqwest::Client`, `HeaderMap`/`Method` from `http`); `Endpoint` resolved from config (base URL, dialects default per provider, default_model, static models, allowed_models, key_origin); `Dialect`, `AuthMode`, `OriginMethod {Endpoint, LitellmTeam, ProviderAccount}`, `KeyOrigin`, `ModelInfo`, `ModelRef {Model(String), NoModel, Unknown}`, `LlmError {Unreachable, InvalidKey, Unverifiable, …}` (never containing the key).
- `ProviderRegistry::from_config(llm_cfg)`: registers enabled providers; implicit `anthropic` endpoint (`id = "anthropic"`, no key-origin) when the provider is enabled and no anthropic endpoint is declared; an endpoint whose provider is unknown or not enabled → error naming the endpoint; `endpoint(id)`, `endpoints()`, `endpoint_hosts()`, `is_endpoint_host(host)`.
- `litellm` provider: hosts from `base_url` (host[:port]); `list_models` = `GET <base>/v1/models` (OpenAI list format) with fallback to static `models` when the call fails with a non-auth error; 401/403 ⇒ `InvalidKey`; `verify_key_origin(Endpoint)` = list models succeeds ⇒ `KeyOrigin` empty (complies by construction); `verify_key_origin(LitellmTeam)` = `GET <base>/key/info` with `Authorization: Bearer <key>` → parse `info.team_id`, `info.user_id` (document the pinned call); `origin_from_response` ⇒ None; `client_env` placeholders for each dialect (e.g. `ANTHROPIC_BASE_URL=<base>`, `ANTHROPIC_API_KEY=aurora-placeholder`, `OPENAI_BASE_URL=<base>/v1`, `OPENAI_API_KEY=aurora-placeholder`) — placeholders only.
- `anthropic` provider: fixed `https://api.anthropic.com` (allow overriding the base URL only for tests via a constructor, not config), `list_models` paged `GET /v1/models` with `x-api-key` + `anthropic-version: 2023-06-01`; `verify_key_origin(ProviderAccount)` = `GET /v1/models?limit=1`, read `anthropic-organization-id` / `anthropic-workspace-id` headers (missing ⇒ `Unverifiable`); `origin_from_response` reads the same headers.
- `model_from_request` shared helper: POST to model-invoking paths (list in §6, also under any route prefix for LiteLLM: match by path suffix) ⇒ parse JSON body `/model`; truncated or unparsable ⇒ `Unknown`; missing model field on a model-invoking path ⇒ `Unknown`; other requests ⇒ `NoModel`.
- `origin::complies(origin: &KeyOrigin, rule: &KeyOriginRule) -> bool` per `§11.3` (lists empty ⇒ unconstrained; method `endpoint` ⇒ true).
- Known LLM hosts are already computed by `aurora-config` (`known_llm_hosts()`); expose `governed_hosts(registry, cfg)` = endpoint hosts ∪ known hosts.

### Out of scope
- Secret storage/admission API, gateway governance step, model selection for agents (later M2/M4 tasks).
