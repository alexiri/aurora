# FIX-141: Indico — "book me a room in 513 or 31 for 5 people at 10am tomorrow" works end to end — **small–medium, phase 5**

## Goal
The owner (2026-11-14): "one of the key room-booking features is being able to say something like
'book me a room in 513 or 31, for 5 people at 10am tomorrow'", and the Indico app does not do it.

Indico can do it, and the package already lists every endpoint needed (`search_rooms` B15,
`get_room_details` B16, `create_booking` B22, `book_room` A12 in
`docs/tasks/P2-CAT-7-indico-api.md`). It fails because:
1. **The agent is not told how.** `agent.instructions` (`plugins/builtin/indico/plugin.yaml`) says
   "Prefer the HTTP API" and describes only the official `/export/…` endpoints, which cannot search
   by capacity, building or free time. The agent takes the path that cannot answer.
2. **The search has traps the instructions do not mention** (Indico source, tag `v3.3.14`,
   `indico/modules/rb/controllers/backend/rooms.py` `RHSearchRooms`, `operations/rooms.py`
   `search_for_rooms`, `controllers/backend/common.py` `search_room_args`):
   - availability is filtered **only when `start_dt`, `end_dt`, `repeat_frequency` and
     `repeat_interval` are all present** (`repeat_interval` defaults to 0, so in practice
     `repeat_frequency` is the one that matters). Without it Indico returns every matching room,
     busy or not, and gives no warning;
   - `building` is an exact, single-value match: "513 or 31" means two calls;
   - `capacity` is a minimum (`Room.capacity >= n`);
   - the response is room **ids only** (`rooms`, `rooms_without_availability_filter`, `total`,
     `availability_days`). Names need `GET /rooms/api/rooms/<id>` per room (`RoomSchema`: `name`,
     `full_name`, `capacity`, `building`, `location_name`, `reservations_need_confirmation`, …).
     `list_all_rooms` returns every room on the server and is not an alternative at CERN's size.
3. **Access.** With the default scopes (`read:user`, `read:legacy_api`) the request cannot be
   answered at all. Room search needs `read:everything`. Booking needs either `full:everything`
   (`create_booking`) or only `write:legacy_api` (`book_room`). Nothing tells the person that
   **`read:everything` + `write:legacy_api`** is enough for this request without the
   everything-you-can-do token (D-196).
4. **`book_room` is described wrongly.** `docs/setup.md` §4 says it books "for today". Indico
   (`indico/modules/rb/api.py` `BookRoomHook`) requires `from` and `to` on the **same day**, not in
   the past: tomorrow works. It looks the room up by `Room.id` alone (`location` is ignored), needs
   `username` = the person's **login** (`Identity.identifier`, not the email) even for oneself,
   and refuses rooms that need confirmation ("only allows pre-bookings"). It returns
   `{"reservationID": <id>}`.

## Plan

### A. Agent instructions (the main fix)
Replace `apps[0].agent.instructions` with the text below (or a tightened version of it). Measure the
block's bytes after YAML parsing: it must stay ≤ 2 000 (the draft is 1 669 bytes plus the
"another host" sentence). Keep every rule the current text has (no `ak`/`apikey`/signature, no other
host, internal endpoints may change, confirm, never retry, events are only prepared).

```text
Indico is connected. Send requests to https://<host> of this connection's Indico server; Aurora
adds the token. Never ask for one, never add ak, apikey, signature, timestamp or cookieauth, and
never send this connection's requests to another host.
Official API: /export/categ/<ids>.json (from, to, type, location, room, detail),
/export/categ/favorites.json, /export/event/<id>.json (detail=contributions|sessions),
/export/event/search/<term>.json, /export/timetable/<id>.json, /export/room/<loc>/<id>.json,
/export/roomName/<loc>/<name>.json, /export/reservation/<loc>.json,
/export/event/<id>/material/<folder>/<file>.bin, /api/user/.
Free rooms: GET /rooms/api/rooms/search?building=<b>&capacity=<n>&start_dt=<YYYY-MM-DDTHH:MM:SS>
&end_dt=<…>&repeat_frequency=NEVER, one call per building. Always send repeat_frequency, or busy
rooms come back too. It returns ids: name them with GET /rooms/api/rooms/<id>. Times are the
Indico server's local time; no end time given means one hour, say so.
Book: POST /rooms/api/booking/create, JSON {room_id, start_dt, end_dt, repeat_frequency:"NEVER",
reason, user:"User:<id>"} (id from /api/user/); or POST /api/roomBooking/bookRoom.json, form:
roomid, from, to (same day, YYYY-MM-DDTHH:MM), tz, reason, username (the person's Indico login;
ask if unknown). bookRoom cannot book a room that needs confirmation.
Never guess availability: if room search is refused, say which scope it needs.
/rooms/api/, /user/api/, /user/search/, /search/api/search and /event/create/prepare are internal
to Indico: on a 404 or an unexpected shape, say so. Confirm room, time and person before booking;
never retry a booking. Indico cannot create events by API: prepare one and give the user the link.
```

Verify against Indico `v3.3.14` source before merging (do not guess; cite file and class in the
commit message):
1. **Time zone** of naive `start_dt`/`end_dt` in `RHSearchRooms` and `RHCreateBooking` (expected:
   server local time, `config.DEFAULT_TIMEZONE`). If it is not, fix the "Times are…" sentence.
2. **`user` format** accepted by `Principal(allow_external_users=True)`
   (`indico/util/marshmallow.py`): expected `User:<id>`. Sending it is deliberate even when booking
   for oneself (Indico defaults to the session user when it is absent) so the approval card's
   "Booked for" is never empty.
3. **What `/api/user/` returns** (`indico/modules/users/controllers.py`, the `/api/user/` handler):
   expected `id`, names, email, no login. If it returns the login, say so in the `username` clause
   instead of "ask if unknown".
4. The legacy hook ignores `location`: the new text drops it. Leave the A12 row in
   `P2-CAT-7-indico-api.md` as is but add "(ignored by the hook: `Room.get(roomid)`)".

**If P5-GUIDE has merged when this lane starts**: keep the snippet short (rules, plus "for room

### B. Scopes: say what this request needs
1. `docs/setup.md` §4: fix the `write:legacy_api` row ("Book a single room slot through the HTTP
   API; start and end on the same day, today or later; no pre-booking, no recurrence") and §6 "Limits"
   (same wording). Add a short "Common tasks" table: *Find and book a free room* →
   `read:everything` + `write:legacy_api` (or `full:everything` for pre-bookings and recurrence);
   *Read events and timetables* → `read:legacy_api`.
2. `connect_note.text` in `plugin.yaml`: one sentence: "To find free rooms and book them, also tick
   'Extended: read everything' and 'Book rooms through the documented HTTP API'; 'Everything' write
   access is only needed for recurring bookings, cancellations and favorites." Keep it within the
   field's limit (linter).
3. Do **not** change `default_scopes` (D-196 keeps them minimal) and do not add a scope preset
   mechanism: that is a new manifest feature, out of scope.
