# P5-UX-12: Access editor defaults from the connection, in plain words (owner app-setup walkthrough, 2026-11-15)

## Goal

In the walkthrough, choosing **Custom** for an AWS connection that was Read only showed eight tools, every
one on **Block**, the read tools included. Each was described by a raw HTTP pattern
(`GET, HEAD s3.*.amazonaws.com/*/*/**`). The write tools were offered although the connection blocks them,
and the read-only note the spec calls for (FIX-133) was missing. The write tool "Call an EC2 action (for
example DescribeInstances)" names a read action.

This task makes the editor start from what the connection already says, and speak in sentences.

## Linked requirements

- D-333; contracts **C-938, C-939**.
- Normative: `14 §App setup` §10, `14` (FIX-133 read-only note, ~1754–1755), `09 §3.4` (tools,
  `description`), `09 §6` (lint warning), C-410 (`custom_only`).

## Placement in the new structure (D-342)

The access editor appears in three places:
- the agent's **Access** tab;
- the give-access panels of **Apps & services**;
- the connect journey.

It reads the same in all three. The "Allow writes on the connection" link goes to the connection's row in
Apps & services › Connections (`routes.ts`).

## Context

- **Defaults.** `web/src/lib/grant-editor.ts`: `initialGrantValue` (~113–119) starts Full, and
  `initialDecisions` (~64–71) sets every tool to `block`.
- **Rows.** `web/src/components/grants/grant-form.tsx` row detail is
  `${methods.join(", ")} ${host}${path}` (~86). `description` exists on tools (`manifest/model.rs` ~843;
  `apps/dto.rs` ~139) and is not rendered.
- **Read-only note.** Only in `web/src/components/agents/grant-editor.tsx` (~155–160).
  `GrantForm` has no `access` prop (~39–67); `GiveAccessPanel` / `GrantSubject` (`give-access.tsx`
  ~37–55, ~204–317) have no `access`.
- **AWS package.** `plugins/builtin/aws-keys/plugin.yaml` ~145–170: `ec2_describe` (read, `params`
  Action prefix `Describe`), `ec2_call` (write, the rest). No tool has a `description`.

## Scope

1. **`access` flows to the form.** Add `access?: "read" | "write"` to `GrantSubject` and to `GrantForm`
   props, and pass it from every caller: the Access tab editor, `GiveAccessPanel` after connect,
   `AccessDialog`, and the journey.
2. **Defaults (C-938).** When a grant is **new** (no saved grant):
   - Custom on `access = read`: read tools `allow`. Write tools are not shown as rows; one line reads
     "Writes are blocked: this connection is Read only", with **Allow writes on the connection** when
     the caller may `PATCH access` (C-740). Write tools are not sent, so they stay blocked.
   - Custom on `access = write`: read tools `allow`, write tools `ask`.
   - `custom_only` apps (C-410) open in Custom with these defaults.

   A saved grant always loads as saved. The read-only note renders in every `GrantForm` with
   `access = read`.
3. **Rows in words.** Each tool row shows `name` and `description` (when present). The method and pattern
   move into a per-group **Technical details** disclosure listing each tool's pattern. Umbrella
   (wildcard) tools keep their badge and text.
4. **Package descriptions (C-939).**
   - Give every tool of every builtin package a one-sentence `description` (≤ 200 characters).
   - In `aws-keys`, rename `ec2_call` to "Any other EC2 action (changes, and reads not covered above)",
     and give `ec2_describe` the description "Read-only EC2 Describe* actions (instances, volumes,
     security groups, …)".
   - Bump each changed package's patch version and run `check-builtin.sh`.
   - Linter: in `crates/aurora-registry`, `tool_description_missing` is a **warning** for any package.
     `check-builtin.sh` treats it as an error for builtin packages.
5. **Tests.**
   - Vitest: defaults for read and write connections, new vs saved grants, `custom_only`; the note in
     each caller; rows render descriptions; Technical details lists the patterns.
   - Registry unit test for the warning.
   - Builtin check run over all packages.
   - Playwright: on the walkthrough's read-only AWS connection, Custom opens with 5 reads Allow, no write
     rows, the note visible, and **Give access** enabled at once.

## Constraints / file ownership

- Owns: `lib/grant-editor.ts`, `components/grants/grant-form.tsx`, the `access` pass-through in
  `give-access.tsx` and `agents/grant-editor.tsx`, `crates/aurora-registry` (one lint), the builtin
  `plugin.yaml` files (descriptions and the aws-keys rename only).
- Not beside P5-UX-4 (`give-access.tsx` preselection) or P5-UX-10 (grant editor unreachable sentence):
  serialize. Not beside P5-UX-2, P5-UX-15 or P5-UX-13, which also edit builtin `plugin.yaml` files.
- Package changes: patch bumps only, with no tool id changes, so saved grants keep matching.

## Acceptance criteria

1. "Read only, ask for nothing" on a read-only connection takes one click (Custom) and one save.
2. On a read-and-write connection, a new Custom grant starts with writes at Ask.
3. No tool row shows an HTTP pattern outside Technical details; every builtin tool has a description.
4. Existing grants are unchanged (an IT loads a pre-change custom grant and saves it unchanged).
5. Web and Rust gates; builtin check; axe and narrow-route suites, both themes.

## Dependencies

None hard. Coordinate the file overlaps listed above.

## Suggested agent/model and reason

Sonnet: one shared form with several callers, plus package text. The description writing could go to a
Haiku sub-step reviewed by the lane.
