# FIX-088: Relay HTTP correctness — the app gets its own cookies, a stalled peer cannot block revocation, the remaining timeouts and body cap are enforced, truncated chunked answers abort (REVIEW-5 PRV-2/5/6/7/11/16, EVID-12) — **high**

Checked against master `c3ec906d` (after FIX-072/073, which fixed chunked de-framing, the 120 s plain-HTTP idle limit and the wake-wait pages).

## Problem
1. **The app never receives its own cookies.** `services/aurora-relay/src/edge.rs` lists `cookie` in `DROP_REQUEST` (~105), so the whole header is removed; the unit test `request_header_hygiene` and `tests/edge.rs` (`cookie_set=false`) assert that. `docs/04` §Port previews rule 3 says the relay "removes it [the preview cookie] from the `Cookie` header". The relay passes the app's `Set-Cookie` out (host-only), so every cookie-based app (any login, any session) loses its state on the next request.
2. **A stalled peer blocks the stream pump.** `services/aurora-relay/src/stream.rs` `run_leg` awaits `sink.send(…)` in the command arm and `from_app_tx.send(…)` in the source arm inside its `select!`; while either waits, the revocation watch, the idle timer and the lifetime timer are not polled. A viewer who stops reading a large response keeps the stream open after the share is revoked (SEC-81 promises ≤ 15 s), and the final `sink.send(Close)` has no bound, so a stalled runner holds the stream slot (now capped per share and per user by FIX-072) indefinitely. The revocation test added by FIX-073 (`tests/behaviour.rs` ~435–461) uses a cooperative reader.
3. **Limits still not enforced.** The 60 s response-head limit: `proxy.rs` `read_head` has no timeout (its comment says it has). The request-body cap: `edge.rs` (~1131) checks `Content-Length` only, so a chunked upload passes `relay.request_body_max_bytes`.
4. **The app is not told to close.** The outbound head for a non-upgraded request carries no `connection: close` (`proxy.rs` `build_request_head`; `edge.rs` drops the browser's), so a keep-alive app holds its loopback socket and the supervisor stream until the relay detaches the leg.
5. **Truncated chunked answers look complete.** On a `ChunkError`, or when the leg ends before the terminal chunk, the body task simply ends (`proxy.rs` ~146–160, ~180–186) and hyper writes a clean terminal chunk: the browser renders or saves a silently truncated document.
6. **Header hygiene is undefined and incomplete.** `DROP_RESPONSE` passes `clear-site-data`, `alt-svc` and `service-worker-allowed`, and drops the app's `content-security-policy` with nothing in its place; `DROP_REQUEST` passes `x-real-ip`, `true-client-ip`, `x-forwarded-port`, `x-forwarded-prefix`, `via`. SEC-85 lists what the relay adds, not what it removes.
7. **The smuggling corpus tests a classifier, not the wire** (`edge.rs` ~1107–1135 builds `Request` values; hyper has already normalised folding, bare LF and duplicate names).

## Linked requirements
- `docs/04` §Port previews (cookie rule 3); `docs/16` §W18 and the limits at ~446–449; `docs/02` §Limits (`PREVIEW_HEADER_TIMEOUT`, request body max); `docs/17` SEC-81, SEC-85.

## Spec change (apply with the fix)
`docs/17` SEC-85 gains the normative header lists: request headers removed before the app sees the request (the Aurora preview and session cookies by name — every other cookie is forwarded —, `Authorization` only when it carries an Aurora token prefix, every client-supplied forwarding header: `x-forwarded-*`, `forwarded`, `x-real-ip`, `true-client-ip`, `via`); response headers removed before the browser sees the answer (`clear-site-data`, `alt-svc`, `service-worker-allowed`, `strict-transport-security`, plus the hop-by-hop set); and what happens to the app's `content-security-policy` (decide: pass it through unchanged — the preview origin is the app's own — and say so).

## Scope
### In scope
- Cookie rewriting: remove only `__Host-aurora_preview`, `__Host-aurora_pstate`, `aurora_session` and any `__Host-aurora_*`/`aurora_*` pair; re-serialise the rest; drop the header only when nothing remains.
- Pump: no arm awaits a peer inside the select — writer and reader run as their own tasks, or every send is raced against the revocation watch and the timers; the closing `Close` send is bounded (2 s) and the slot is released regardless.
- `read_head` under `PREVIEW_HEADER_TIMEOUT` → 504; chunked request bodies counted against the cap → 413 and the leg closed.
- `connection: close` on the outbound head of non-upgraded requests.
- Abort the response (`Err` on the body channel) on malformed framing or a leg that ends before the terminal chunk / before `Content-Length` bytes.
- Header lists as specified.
- Raw-socket smuggling tests: CL+TE, duplicate CL, obsolete folding, bare LF → 400 before anything is forwarded.

### Out of scope
- Wake flow (FIX-089); relay-plane rate limits and client address (FIX-090).

## Acceptance criteria
- [ ] IT: `cookie: app=1; __Host-aurora_preview=auv_x` → the app sees exactly `app=1`; a request with only Aurora cookies reaches the app with no `Cookie` header.
- [ ] IT: client stops reading a large response; revoke → the leg closes with 4403 within 2 s and the slot count returns to zero. A runner that stops reading does not hold a slot past the bounded close.
- [ ] IT: app that never answers → 504 at the (shortened) head limit; chunked upload over the cap → 413.
- [ ] IT: keep-alive app sees `connection: close` and its socket closed after one response.
- [ ] IT: app sends `zz\r\n` as a chunk size, and separately the leg drops mid-chunk → the client sees a transport error, not a complete response.
- [ ] Unit tests for each header on both lists; raw-socket smuggling cases.
- [ ] Each main test seen failing before the fix. `cargo test -p aurora-relay` (suite < 30 s), fmt, clippy, guards.
