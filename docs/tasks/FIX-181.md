# FIX-181: Hardening batch from the P5-DEDUP-1 sweep (F1, F2, F4–F7, F10, F11)

## Goal
P5-DEDUP-1's Part A catalogue (`docs/tasks/P5-DEDUP-1.md`, findings) listed small inconsistencies that
are not duplication. Owner, 2026-11-19 (D-396): fix them as below. Each item is a separate commit
`FIX-181: Fn …` with its test seen failing first where it is a behaviour change.

## Items
1. **F1 — gateway link lane, restarting.** `decide/link.rs` (~310) answers `gateway_restarting` without
   `Retry-After`; use `guidance::restarting()` as `decide.rs` does (`Retry-After: 1`).
2. **F2 — gateway StoreUnavailable.** The link lane (`link.rs` ~322) and the DB lane (`decide.rs` ~2966)
   neither count `health::count_refused("approval_store_unavailable")` nor add
   `details.reason = database_unavailable`, as the request lane (`decide.rs` ~1750) does. Make all three
   the same (one helper).
3. **F4 — a frozen agent is always 423** (owner): `ssh` redemption (`ssh/sessions.rs`) and Files open
   (`files/service.rs`) map every error to 409 `not_current`; propagate `ensure_agent_active`'s **423
   `frozen`** as the terminal does, and check every other path that admits a frozen agent's stream or
   session for the same mapping. C-1041 records "a frozen agent is 423 on every route"; update the
   OpenAPI responses.
4. **F5 — constant-time comparison.** `connectors/mattermost/src/callbacks.rs` (~136) `ct_eq` returns
   early on a length mismatch (leaks the token length); compare in constant time over the longer length
   like `aurora-cli/forward.rs` and `aurora-crypto/ring.rs` (or use the `subtle` crate if it is already in
   the dependency tree — no new dependency).
5. **F6 — no invisible formatting characters in any name** (owner): every user-set name and label
   (groups, agents, secrets, app instances, connections, schedules, webhooks, workspaces, organizations,
   API keys, SSH keys, skill names — find every `clean_name`/`name_ok`/`validate_name`-style check) rejects
   `sanitize::is_stripped` characters, as `tenancy::validate_name` does: one shared validator in
   `aurora-core`, used everywhere. Existing rows are not rewritten; say in the report whether any exist on
   a fresh install (none expected) and that an edit of such a row is refused until renamed.
6. **F7 — authorise before parsing** (owner): `keys/routes.rs` (~46, ~98) and `groups/routes.rs` (~75)
   parse pagination before authorising, so a bad cursor answers 400 to someone who may not list; authorise
   first, as `approvals`, `action_approvals` and `invitations` do. Sweep the other list routes for the
   same order.
7. **F10 — remove the vacuous `can_use()`.** `WorkspaceAuth` is only ever built for an active member with
   an effective workspace role (`authz::workspace_access` over `effective_workspace_access` /
   `effective_org_members`, both `status = 'active'`), so `WorkspaceAuth::can_use()` is `true` by
   construction (since BE-010) and every `if !ws.can_use() { 403 }` is dead. Delete `can_use()` and those
   branches (`skills/routes.rs`, `schedules/routes.rs`, `webhooks/routes.rs`, `peer_tasks/service.rs` and
   the others), and add one IT per affected route family that a non-member and an inactive member are
   refused (so the real check is proven where the dead one stood). The `aurora-db` free function
   `can_use(exec, user, ws)` stays (it queries).
8. **F11.** `summarize_client.rs` (~150) calls `.headers(key_id_headers(..))` twice (remove one); in
   `config/validate.rs`, run `check_dev_switches` for relay, terminator and connector as for
   connector_host, and use `check_url` instead of their `starts_with("http://")` checks.
