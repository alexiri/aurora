# P3-014: Gateway under a Postgres outage (RFE-014, D-61, SEC-54)

## Goal
Implement `06 §Operation during a Postgres outage` (phase 3, RFE-014, D-61) exactly as written: the three gateway states, serving from TTL-bounded caches, fail-closed refusals for anything that needs new state, reconnect-then-flush on recovery, and the outage request-log buffer and metrics. **SEC-54** must be proven. The contracts for the refusal codes, `readyz` states, the status fields and the metrics are in `docs/API_CONTRACTS.md` (API-P3's RFE-014 entries, C-380..C-389 or as API-P3 placed them). Read them first; if they're missing, ask through Orca `ask`.

## Spec (read these)
- `06 §Operation during a Postgres outage` in full, the `/readyz` row in the ports table, and the `GATEWAY_*` limits it names in `02`.
- `05 §Event bus` (LISTEN/NOTIFY), `15 §Observability` (metrics and alerts), `17` SEC-54, `18 §Gateway under a database outage` (the test list, which is your acceptance), `80 §RFE-014`.

## Scope
1. A state machine (`ready` / `degraded` / `down`) driven by the DB probe (`SELECT 1` every 5 s, 2 s timeout, two failures) and by connection-class errors on the hot path. Recovery needs one successful probe **plus** the LISTEN subscription re-established.
2. Serving rules (a) and refusals with the exact codes, `retry-after`, `details.reason` and `x-should-retry`. **Default-deny is never weakened**: anything that needs a lookup is refused.
3. Reconnect-then-flush: on recovery, re-subscribe first, then invalidate caches, so no invalidation is lost. Follow the spec's ordering.
4. The outage request-log buffer (bounded as the spec says), flushed after recovery; drops counted.
5. `/readyz` (three states, `?strict=true`), `/internal/v1/status` fields, the `aurora_gateway_state` gauge and the other named metrics.
6. Tests: every item in `18 §Gateway under a database outage`, as gateway integration tests that stop and start a dedicated Postgres or block its port. Use a throwaway container named with your worktree prefix, never the shared dev Postgres. Plus a `scripts/e2e/gateway.sh` scenario if the `18` list calls for one. Update `docs/tests/security-coverage.md` SEC-54 to proven.

## Constraints
- **Owns:** gateway `invalidation.rs`, `resolver.rs`, `plaintext.rs`, `status.rs`, `reqlog.rs`, the refusal paths in `hold.rs` / `guidance.rs`, the gateway's use of the `aurora-db` listener, gateway tests, `scripts/e2e/gateway.sh` (one scenario), and the SEC-54 coverage row.
- No API or web change. No migration unless the spec names one.
- Decision D-108 only if needed.
