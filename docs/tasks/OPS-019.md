# OPS-019: CI: green, fast, and off Node.js 20 (phase 1, now)

## Goal
Make `.github/workflows/ci.yml` pass reliably and run fast on GitHub-hosted runners, and move every action off the deprecated Node.js 20 runtime.

## Facts (2026-11-08)
- Run https://github.com/alexiri/aurora/actions/runs/42367335980: `rust-test` failed after 13m47s. The linker died with SIGBUS (`collect2: ld terminated with signal 7`) while writing a test binary: the runner disk (~14 GB free) filled up from ~100 large test binaries.
  - Interim fix on master (d52e3162): free runner disk + `CARGO_PROFILE_DEV_DEBUG=0` in `rust-test`. It still needs verifying on GitHub.
- Annotation: "Node.js 20 is deprecated … actions/checkout@v4, actions/setup-node@v4, pnpm/action-setup@v4". Also check `Swatinem/rust-cache`, `dtolnay/rust-toolchain`, `EmbarkStudios/cargo-deny-action` and any other action.
- `ubuntu-latest` moves to Ubuntu 26 from 2026-10-19. Pin `ubuntu-24.04` (or 26.04 if verified) explicitly so the image change is deliberate.
- OPS-016 (in progress or merged) changes the local build: the lld linker, one test binary per crate, cargo-nextest, sccache, and profiles. Reuse its choices in CI; don't invent a parallel set.

## Scope
1. **Node 20**: bump every action to a major version that runs on Node 24 (verify each action's `action.yml` `runs.using`). Pin actions by full commit SHA with the version in a comment (supply-chain hygiene; Dependabot will update them in phase 4, OPS-021).
2. **Speed up `rust-test`** (target: well under 10 min on a cold cache, and a few minutes warm). Candidates; measure them and keep what helps:
   - OPS-016's single test binary per crate and the lld linker (`clang` + lld is available on ubuntu runners, or use `rust-lld`)
   - `cargo nextest` with **sharding** across a matrix (`--partition count:i/N`) using a nextest archive built once (`cargo nextest archive`) and shared via an artifact, so only one job compiles
   - `Swatinem/rust-cache` tuned to save once per workflow from the build job, with cache keys that survive Cargo.lock-only changes where safe
   - share the sqlx-cli install via a cached binary (`taiki-e/install-action`) instead of `cargo install` in three jobs
   - split the gated e2e crates (`aurora-e2e-hosted`, `aurora-e2e-gateway`) out of the main test build if they're compiled but skipped
   - Record before/after timings in `docs/ops/build-performance.md` (shared with OPS-016).
3. **De-duplicate the jobs**: lint, test and guards each install sqlx-cli and migrate. Restructure so the expensive compile happens once where possible: e.g. one `build` job produces the nextest archive, `test` shards consume it, `lint` keeps its own `clippy` (a different profile), and `guards` reuses the cache.
4. **Keep coverage**: no test may be dropped. The test count reported in CI is equal to the local `cargo test --workspace` count (minus the env-gated e2e tests, which are skipped as before).

## Constraints / file ownership
- You own `.github/workflows/**` and `.config/nextest.toml` (coordinate: if OPS-016 merged one, extend it), and the CI section of `docs/ops/build-performance.md` and `docs/18-testing.md` §CI pipeline.
- You can't push. Verification on GitHub is done by the coordinator, who will push your branch with the owner's OK. Make the workflow testable locally where possible (`act` is not installed; at least run `actionlint` if available, or validate YAML), and give the coordinator a precise "what to look for" list.

- [ ] After the coordinator pushes: the full CI run is green, `rust-test` time is recorded, and there are no Node 20 annotations.
