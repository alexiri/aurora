# FIX-042: The `previews` home-sync part goes absent exactly when it must empty the supervisor's share list (org switch off, freeze, or pausing/deleting the last share)

## Problem

The supervisor replaces its in-memory preview share list **as a whole** from
the `previews` home-sync part and never reads anything back
(`services/aurora-supervisor/src/supervisor.rs:479-513`, the
`self.preview_shares = …collect()` at `:483`). The API is therefore the only
thing that can ever shrink that list, and it must send an **empty** `previews`
part to do it. Three paths fail to:

1. **Org switch off or agent frozen** — the part is only packed when the org
   switch is on **and** the agent is not frozen
   (`services/aurora-api/src/domains/hosted/home.rs:313-348`; the entry is
   pushed at `:345` inside `if state.config.previews.enabled { if !frozen {
   if on { … } } }`), and `pack` emits **no part at all** when its entry list
   is empty (`services/aurora-api/src/domains/hosted/home.rs:81-105`, the
   `if !cur.is_empty()` at `:102`). So on switch-off or freeze the sync
   carries no `previews` kind, `home_sync` never reaches the replacement
   branch (`supervisor.rs:482`), and the stale share list — ports and start
   commands — survives in supervisor memory. This violates the lifecycle
   table ("allow-list emptied" for freeze and for org-off,
   `docs/11-runner-sandboxes.md:471,473`) and the code's own comment: "Always
   present when the instance runs previews … so a pause/delete/off switch
   reaches it on the next sync"
   (`services/aurora-api/src/domains/hosted/home.rs:358-360`).
2. **Nothing triggers the next sync.** Share create/update/delete bump
   `agents.home_sync_generation` (`bump_agent`,
   `crates/aurora-db/src/repo/preview_shares.rs:273-284`) but `org.previews.update`
   (`set_org_enabled`, `services/aurora-api/src/domains/previews/service.rs:553-575`)
   and the freeze paths (`services/aurora-api/src/domains/freeze/service.rs`)
   bump nothing, so the next home sync happens only by accident of an
   unrelated skills/memory change — potentially never for a quiet agent.
3. **Last-share pause/delete.** `active_for_agent` filters `state = 'active'`
   (`crates/aurora-db/src/repo/preview_shares.rs:136-146`); pausing or
   deleting the agent's only active share yields an empty `shares` array, so
   `pack` again emits no part (`home.rs:102`) — same stale list.

Severity differs by path. The list itself grants nothing (P4-PRV-2 is not
implemented; no relay exists), so nothing is reachable today; but the start
commands and ports of "removed" shares linger in a long-lived process's
memory contrary to the documented "empty when previews are off, the org has
them off, the share is paused or the agent is frozen"
(`docs/12-supervisor-harness.md:455-457`), and every one of these paths is
exactly the security-relevant transition. When P4-PRV-2 lands, a stale list
is an open allow-list.

## Goal (priority: **high**, size: **S**)

The supervisor's share list is emptied at the next sync after any of: org
switch off, agent (workspace/org) freeze, pause or delete of the last active
share — without changing the wire format or the replacement semantics.

## Scope

1. `services/aurora-api/src/domains/hosted/home.rs` — when
   `previews.enabled` (`:361`), always `pack(HomeSyncKind::Previews,
   preview_entries, …)` even when `preview_entries` is empty (org off, frozen,
   no active shares). One-line change plus moving the guards of `:313-348`
   out of the emission decision and into the entries.
2. `services/aurora-api/src/domains/previews/service.rs` —
   `set_org_enabled(false)` bumps `agents.home_sync_generation` for the org's
   hosted agents (the pattern is `bump_org`,
   `crates/aurora-db/src/repo/skills.rs:340-346`) inside the same
   transaction.
3. `services/aurora-api/src/domains/freeze/service.rs` — freeze bumps the
   frozen agents' generation (same pattern; unfreeze does the same so access
   restoration is not delayed).
4. `services/aurora-api/tests/it/previews.rs` — one case per transition:
   with a running sandbox and a share, flip the org switch off (and freeze)
   and assert the next rendered home-sync parts (`home::render`, the same
   call `tests/it/home_checksum.rs:121` uses) contain a `previews` part with
   an empty `shares` array; the supervisor-side replacement to an empty list
   is already covered by `services/aurora-supervisor/tests/it/previews.rs`.

## Acceptance

- The new tests pass; `cargo test -p aurora-api --test it previews` and
  `cargo test -p aurora-supervisor --test it previews` stay green.
- The supervisor's log line `preview share list applied` shows `shares=0`
  after each transition in the tests' rigs.

## Constraints

- Keep the part absent entirely while `previews.enabled` is false (instance
  off = no part, per `home.rs:358-360`); do not change `PACK_MAX` packing or
  the single-entry `{shares: [...]}` entry shape (docs/16 §W5).
- No wire-format change: an older supervisor that skips unknown kinds keeps
  working (docs/16 line 102).
- Do not make `pack` emit empty parts for the other kinds (skills/memory
  keep today's behavior).
- Change files only with the Edit/Write tools; never python, sed, awk, perl,
  `cat >>` or heredocs.
