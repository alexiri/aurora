# FIX-149: Connect and Reconnect are real modals; every dialog has a close icon (owner, 2026-11-14, phase 5, D-272, C-842) — **high (UX)**

## Problem
The owner reported this on 2026-11-14:

> "When I click on 'Connect' for an app, I get a small window with the connect info, but in reality it's just a page running in a smaller version of the entire page. If I make the browser window bigger, I see the sidebar and everything. This is not at all what modal screens should look like, they should be more like what I get if I click 'Details'. You've made this mistake in multiple parts of the app. Implement all those things as actual modals, not like weird popups of other pages. Also, make sure the modals have a close icon so it's clear how they can be dismissed."

Coordinator findings (master `7dc24225`):

1. `web/src/lib/api/apps.ts` ~325: `openConnectWindow` = `window.open(url, "aurora-connect", "popup=yes,width=560,height=760")`. It opens the full dashboard route `/o/<org>/w/<ws>/apps/<app>/connect` (`web/src/app/o/[org]/w/[ws]/apps/[app]/connect/page.tsx` → `components/apps/connect-view.tsx`), with the app shell, inside a browser popup. It has three entry points:
   - **Connect** on every Apps tab card (`components/apps/apps-tab.tsx` ~149);
   - **Reconnect** on Connections cards (`components/apps/connections-tab.tsx` ~95);
   - the agent's `request_app_connection` notice. That link points at the same route (`services/aurora-api/src/domains/tools/apps.rs` ~250, I-29), so it opens as a full page in a tab.
2. `connect-view.tsx` is written for that window. It uses `window.opener.postMessage` (~142) and `window.close()` (~184, the "Close window" button), and the "Give agents access" step (D-137) lives inside the window. An OAuth method nulls `window.opener` and navigates the popup to the provider (~136–139). The callback page (`services/aurora-api/src/domains/connect/page.rs` `connected`) posts to `window.opener`, which is then null. So for OAuth the dashboard never learns the result, and the Give-agents-access step is lost.
3. **Details** (`apps-tab.tsx` ~153) is a real `Dialog`. That is the model the owner wants. But `components/ui/dialog.tsx` `DialogContent` has **no close icon**, so none of the ~34 dialogs built on it has one: Escape and the scrim are the only ways out. The mobile nav drawer in `app-shell.tsx` already has a "Close menu" button.
4. No other `window.open` exists in `web/src`, and no other route is opened as a popup. Before closing, sweep for any view that behaves like one: a route rendered as a narrow page that should be a dialog. Each one found is listed in the report and converted, or listed with a reason.

## Decided (D-272, C-842; the spec text is already in `14` §Key flows "Connect dialog", `14` §Dialogs, `API_CONTRACTS` C-14/C-842)
- **Connect dialog.** Turn `ConnectView` into a dialog body (`ConnectDialog`, `DialogContent size="lg"`, title "Connect <App>" / "Reconnect <App>", description = the package line, as in Details).
  - **Connect** opens it on the Apps tab. **Reconnect** opens it in place on the Connections tab (`reconnect` = the connection id).
  - It covers the whole flow without leaving the dialog: method chooser, fields, scopes, submit, missing scopes, **Give agents access**, done.
  - "Close window" becomes **Done**, which closes the dialog. No `window.opener` or `window.close` remains in `web/src`.
  - Closing the dialog (×, Escape, scrim, Done) discards the form, so secrets are dropped with the component (keep the existing clear-after-submit too).
- **Deep link.** `/o/<org>/w/<ws>/credentials?tab=apps&connect=<app_id>` opens the Apps tab with the dialog open. Closing it removes `connect` from the URL (`router.replace`), so a reload does not reopen it.
  - An unknown or unavailable app shows a `Notice` on the Apps tab, not an empty dialog.
  - The old route `apps/[app]/connect` becomes a redirect to the deep link. `?reconnect=<id>` maps to `?tab=connections&reconnect=<id>`, which opens the Reconnect dialog.
  - `tools/apps.rs` emits the new link (I-29).
- **OAuth sign-in** (C-842):
  - **Opening the window.** On **Continue to sign in**, open `about:blank` synchronously in the click handler (named `aurora-sign-in`, popup features as before), so popup blockers allow it. Then `POST …/connect`. On `{kind:"redirect"}`, set `w.opener = null` and only then `w.location.replace(url)`. On an error, close `w` and show the error in the dialog.
  - **Blocked window.** If `window.open` returns `null`, the dialog says the browser blocked the sign-in window and offers a retry.
  - **While waiting.** The dialog shows "Waiting for you to sign in to <App>…" with **Open the sign-in window again** (focus or reopen) and **Cancel**. Poll `w.closed` (1 s): closed without a result → back to the form with "Sign-in was cancelled".
  - **Result.** The dialog listens on `BroadcastChannel("aurora-connect")` for its `app_id`. `aurora:connected` → ack, then missing scopes and Give agents access. `aurora:connect-failed` → ack, then the error.
  - **Other tabs.** Any other dashboard tab refreshes `["apps"]`/`["connections"]`; this replaces `useConnectedListener`'s `message` listener.
- **Callback page** (`connect/page.rs`): both the success and failure pages post on the channel (nonce'd script; the failure page gains a nonce and script). They close on the ack. Without an ack within 3 s they stay, saying "Connected" (or the error), with a link to the Connections tab. The missing-scopes warning stays on the page. Do **not** add `app_id` to anything secret; it is already known to the flow (state/cookie). If it is not available to the error path, `app_id` is optional there and the dialog matches on "the one flow I am waiting for".
- **Close icon on every dialog** (`components/ui/dialog.tsx`):
  - `DialogContent`'s title row = title (+ description) on the left and a `DialogPrimitive.Close` icon button on the right: `XIcon`, `aria-label="Close"`, a visible focus ring, at least a 44 × 44 px target on coarse pointers, token colours.
  - The title row is sticky at the top of the dialog's scroll area, so × stays reachable in long dialogs at 390 px.
  - `ConfirmDialog`/`FormDialog` inherit it; no per-dialog opt-out.
  - Check that no existing dialog now shows two close controls in its header (a body "Cancel" button is fine).
- **Guard** (vitest, alongside `tests/design-guards.test.ts`): `window.open` appears in `web/src` only in two places, listed explicitly in the guard. One is the sign-in helper. The other is the terminal's **Open in new window** (FIX-138, owner-requested: a full standalone terminal page in a new tab, `noopener`). It is on `alexiri/p5-agent`, unmerged; if that lane merges first, keep its call site on the list. `window.opener` and `window.close` appear nowhere.
