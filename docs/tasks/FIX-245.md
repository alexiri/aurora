# FIX-245: the template journey in the dashboard — the review link, the attention topics and the way in from Agents (owner 2026-11-26, after walking the deployed UI)

## Why

The owner walked the whole agent-template journey in the deployed UI after P6-TPL-1..6 shipped and found it
half-baked: three defects, one chain, and the lesson that nobody had followed real links end to end.

1. **The 404.** The administration Overview shows "NightManager 1.4.0 is waiting for review" with a Review
   button that links `/admin/agent-templates/nightmanager/versions/1.4.0` — a page that does not exist. The
   real page is `/admin/internet-access/templates/[template_id]/[version]` (`adminRoutes.templateReview`).
   The backend's `template_version_href` builds the old address, and notices already stored with it 404 too.
2. **The Apps badge.** The sidebar shows "2" on **Apps** while the Apps page says nothing waits: `topic_of`
   files every kind that is not chat/people under the `apps` topic, so waiting **template versions** are
   counted on Apps although the page that resolves them is What agents may do › Agent templates.
3. **No way in.** On the Agents page only "New agent" shows; "More templates…" hides inside that dialog and
   appears only when the workspace already has an approved template — with both versions still waiting for
   review a person sees nothing and nothing says why.

## Fix

1. **Backend href**: `template_version_href` emits the real address (`/admin/internet-access/templates/…`).
   Items and notices already stored with the old address keep working: `/admin/agent-templates/[template_id]/versions/[version]`
   is a redirect page (the `legacy-routes` table + `LegacyGate` way). A Rust test pins the exact href the
   attention endpoint returns; a web unit test pins `adminRoutes.templateReview` to the same path shape; a
   Rust test walks every href items and notices can emit against a table of web path prefixes.
2. **Attention topics**: template versions get the topic of the page that resolves them (`internet-access`,
   What agents may do) instead of `apps`; the rail badges already render per topic. Inside the Agent
   templates tab the waiting versions sit at the top as a "Needs you" strip with a Review button each. Every
   attention kind is audited against its resolving page.
3. **Template entry**: a visible, always-present **Start from a template** entry beside **New agent** opens
   the gallery; with no approved template yet the gallery says so in plain words (an administrator is sent to
   the Agent templates tab, everyone else is told their administrators have not approved any yet, no dead
   end). Wording from `docs/14` §Vocabulary; `docs/14` updated.

## Proof

One mocked Playwright journey spec that follows real links: Overview → Review → the review page (not a 404)
→ approve; the badge sits on What agents may do and not on Apps; as a member, Agents → Start from a template
→ gallery → Use this template → the four-step page. Both themes, 390 px without horizontal scroll, axe clean
on the touched pages.
