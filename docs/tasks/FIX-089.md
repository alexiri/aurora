# FIX-089: Preview wake and start — one wake per request, the listen wait, the exit page, truthful deny reasons (REVIEW-5 PRV-4/10/12/14/17, EVID-2, WEBA-10) — **high**

Checked against master `c3ec906d`. FIX-073 added the relay's wake-wait: it long-polls `resolve { wait_secs: 45 }`, serves the request when the port comes up, else a self-refreshing 503 page, and a 429 page for `start: "limited"`.

## Problem
1. **The long-poll spends the whole wake budget** (coordinator-verified). `services/aurora-api/src/domains/relay/service.rs` `resolve` (~260–282) calls `resolve_once` every 500 ms while waiting; `resolve_once` calls `demand_wake` whenever the sandbox is `stopped` (~322), and `demand_wake` records a wake against `PREVIEW_WAKES_PER_SHARE_HOUR` (12; `crates/aurora-db/src/repo/preview_shares.rs` ~345–373). A parked sandbox that has not reached `starting` within about six seconds exhausts the hour's budget; the visitor then sees "started too often" for an hour although one start was requested.
2. **Over the limit, the API still answers `allow`.** `relay/service.rs` ~326–330 sets `route.start = "limited"` and keeps `decision: "allow"`; `docs/16` lists `wake_limited` (429) among the deny reasons for a session holder.
3. **`PREVIEW_LISTEN_WAIT` is unused.** `docs/11` ~459: a running sandbox whose port is not listening waits up to 5 s and then answers 502 "nothing is listening". Today the request goes straight to the dial, the supervisor refuses, and the 502 is immediate (`services/aurora-relay/src/edge.rs` ~610–640; `relay/service.rs` `streams` checks only `sandbox` and `runner_endpoint`).
4. **The "start command exited" page cannot appear.** `route.start` is only ever `starting` or `limited`; `exited` (documented in `relay/dto.rs` ~74, handled in `edge.rs` ~213–222) is never produced, and "started too often" reports the wake budget, not `PREVIEW_START_ATTEMPTS` (3 per 10 min, `docs/11` §Port previews item 3: exit code and output tail shown).
5. **Paused and frozen shares answer the wrong page.** `authorize` (`relay/service.rs` ~414–475) mints a grant without the access checks (`access_of`, freeze); `redeem` then fails and the relay turns every redeem error but 400 into 502 "grant service unavailable" (`edge.rs`, grant branch). For a session holder, `resolve_once` answers `not_found` for paused and frozen (~307–313). `docs/04` step 2: "A frozen agent answers the 423 page"; `docs/16` deny reasons: `paused` 403, `frozen` 423.
6. **A database error revokes everyone.** `validate` (~664–676) pushes a pair to `revoked` on any error from `session_of`/`access_of`, so a short database outage closes every open preview stream with 4403.
7. **Dashboard.** After **Start now**, the share's "Waking" status never refreshes (`web/src/lib/api/previews.ts` ~21–27, ~57–63: no polling while a share is `waking`).

## Linked requirements

## Spec change (apply with the fix)
`docs/16` `POST /resolve`: "the wake demand is recorded at most once per request, however long the long-poll runs"; "over the wake budget the answer is `deny` `wake_limited` with `retry_after_secs`". No other spec text changes: the code moves to the documents.

## Scope
### In scope
- `demand_wake` once per `resolve` call (first iteration), and not at all while a demand of the current window is outstanding.
- `wake_limited` as a deny reason with `retry_after_secs`; the relay keeps its 429 page and stops caching the answer.
- Listen wait: `streams` (or the relay's `not_ready`) waits up to `PREVIEW_LISTEN_WAIT` for the share's port in the current boot's listening set before the dial; then the 502 "nothing is listening" page.
- `route.start = "exited"` with the last exit code and tail when the share's start command ended, and `limited` for the start-attempt budget with its own message; the wake budget keeps `wake_limited`.
- `authorize` runs the same access checks as `resolve` before minting; the relay maps redeem 404 → the uniform not-found page, 423 → the frozen page, 403 → paused; `resolve_once` answers `paused`/`frozen` to a session holder.
- `validate`: a database error is a 5xx for the relay to retry; `revoked` contains only decided denials.
- `usePreviews` polls (5 s) while any share is `waking`.

### Out of scope
- Relay header/pump defects (FIX-088); rate classes (FIX-090).
