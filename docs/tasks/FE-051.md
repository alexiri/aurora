# FE-051: Schedules, Webhooks, Peers tabs; action approvals; chat attachments and app-turn cap

## Goal
Dashboard UI for the M5 backend that is now merged: the agent page tabs **Schedules**, **Webhooks** and **Peers**, action approvals on the Approvals page, attachment upload/download in Chat, and the app-turn-cap "Continue" control.

## Linked requirements
- `docs/14-web-dashboard.md` §Agents (agent page tabs: Chat attachments "upload, thumbnails, failed chips"; Schedules; Webhooks "URL shown once on create/rotate"; Peers "agent links and peer tasks"), §Approvals ("pending gateway holds and action approvals (live via SSE), history").
- Contracts: `docs/API_CONTRACTS.md` §M5 (API-005: `Attachment`, `ActionApproval`, `AgentLink`, `PeerTask`, C-27..C-30). Schedules/webhooks shapes come from the generated client (`web/src/lib/api/schema.d.ts`; operations `listSchedules`, `createSchedule`, `updateSchedule`, `deleteSchedule`, `listScheduleRuns`, `runScheduleNow`, webhooks `…Webhook…`, `rotateWebhook`, deliveries). **No hand-written API types** (D-32): use `components["schemas"][…]` and `openapi-fetch` through the existing `src/lib/api/*.ts` pattern.
- Permissions (I-27): schedules, webhooks, links, peer tasks and action-approval decisions are `can_use`. Show the existing forbidden `ErrorState` on 403/404.

## Context
- Agent page: `web/src/components/agents/agent-page.tsx` (tab list + panels; hosted-only tabs are hidden for BYO agents). Follow `MemoryTab`/`SkillsTab` (`web/src/components/memory`, `web/src/components/skills`) for structure, queries (TanStack Query in `src/lib/api/queries.ts`), forms, and tests.
- Approvals page: `web/src/app/o/[org]/w/[ws]/approvals/page.tsx` and `src/lib/api/approvals.ts` (gateway holds + SSE). Add an "Action approvals" section: pending list (summary is platform text; render it as plain text), approve/deny (C-28; 409 `already_decided` → refresh), and history via `?status=`. If the approvals SSE does not carry action approvals, poll every 10 s while the page is visible.
- Chat: `web/src/components/agents/chat-tab.tsx`, `src/lib/api/conversations.ts`.
  - Composer gets an attach button (multipart `POST /v1/conversations/{id}/attachments`, show size limit errors 413).
  - Pending chips with remove; send passes `attachment_ids` (422 `too_many_attachments` message).
  - Transcript `attachment` events and turn attachments render as download links to `GET /v1/attachments/{id}/content`. Never inline-render HTML/SVG; images may show a thumbnail only via an `<img>` of the download URL when `content_type` starts with `image/` and is not `image/svg+xml`.
  - `notice` events with `code: "app_turn_cap_reached"` show a "Continue" button calling `POST /v1/conversations/{id}/continue` (C-27).
- Webhooks: the token/URL appears only in the create and rotate responses. Show it once in a copy box with "you won't see this again", never store it in query cache beyond that dialog, and never log it.
- Schedules form: name, prompt, cron (5 fields; show server validation errors such as the 5-minute minimum), timezone (default workspace timezone), optional gate command/description, enabled toggle. Runs list with outcome. "Run now" (409 `schedule_busy` message).
- Peers tab: links (peer agent, my side's policy select ask/allow/blocked → `PUT /v1/agent-links/{id}/policy` with `revision`, 409 → refetch), peer tasks list (direction, status, budget used, report).

## Scope
### In scope
The tabs, sections and controls above, plus `src/lib/api/{schedules,webhooks,peers,action-approvals,attachments}.ts` (or extensions of existing modules) and vitest tests per component:
- render list, create/edit, error states (403, 409, 422)
- webhook secret shown once and gone after closing
- attachment upload error, plus the SVG not inlined
- Continue button

### Out of scope
- Channels tab (M6, FE-060), Activity tab changes.
