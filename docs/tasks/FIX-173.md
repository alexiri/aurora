# FIX-173: one secret field, with Show

**Owner, 2026-11-18.** "For the ICS and CalDAV addons, the secret url isn't really so secret that
you can't see it when you copy it. Or at least have a button that reveals the value in the text
field (for all secrets, while we're at it). It's useful to verify that you've actually
pasted/written what you intended to." And: "You probably need a common renderer for secret
fields." Decision: **D-375**. No API contract changes: the page only reveals what the person
typed into the field. A stored secret is still never sent to the page (SEC-12).

## Cause (read from the code)
Secret inputs are written by hand in nine places, and only one of them can be revealed:

| Where | Control today | Show? |
|---|---|---|
| `web/src/components/credentials/value-input.tsx` (`ValueInput`: secrets, AI keys, proposals, the journey's token step, the account menu) | `type={show ? "text" : "password"}` + Show/Hide `Button` | yes |
| `web/src/components/apps/dynamic-form.tsx:57` (`FieldControl`, `type: secret`: **ICS "Secret ICS link"**, **CalDAV app password**, every app/connector/integration secret field) | `type="password"` | no |
| `web/src/components/apps/oauth-clients-panel.tsx:125` (OAuth client secret fields) | `type={f.secret ? "password" : "text"}` | no |
| `web/src/components/admin/settings/settings-section-form.tsx:547` (a `secret` setting in "Replace" mode, e.g. `email.smtp_password`) | `type="password"` | no |
| `web/src/components/admin/settings/sign-in-provider-dialog.tsx:344` (OIDC client secret) | `type="password"` | no |
| `web/src/components/admin/secret-stores-view.tsx:227` (secret store credential) | `type="password"` | no |
| `web/src/components/account/send-as-me.tsx:111` (personal access token) | `type="password"` | no |
| `web/src/components/webhooks/webhooks-tab.tsx:126` (webhook signing secret) | `type="password"` | no |

There is also an accessibility bug. `Field` (`components/ui/field.tsx`) adds `aria-describedby` and
`aria-invalid` only to a child whose `id` equals the field's id. `ValueInput` wraps its `<input>`
in a `<div>`, so its hint and error are not linked to the input, and the error border never shows.

## Fix (D-375)

### 1. The primitive: `web/src/components/ui/secret-input.tsx`
`SecretInput` is a controlled input for a value that is written but never read back.
- **Props.** It takes the usual input props (`id`, `value`, `onChange(value: string)`,
  `autoComplete` defaulting to `"off"`, `placeholder`, `required`, `maxLength`, `className`,
  `aria-label`, `aria-describedby`, `aria-invalid`, `disabled`). It also takes an optional
  `revealLabel` (see Accessibility). It forwards the `aria-*` props it receives to the `<input>`,
  so a `SecretInput` with the field's `id` inside `Field` gets its hint and error linked. `Field`
  clones by the `id` prop, and `SecretInput` passes those props through.
- **Starts hidden** (`type="password"`). It sets `spellCheck={false}`, `autoCapitalize="off"` and
  `autoCorrect="off"` always. With those, a revealed value is not sent to a spell-check service and
  is not "corrected".
- **Show / Hide.** One `Button` (`variant="outline"`, `size="sm"`, `type="button"`) sits after the
  input, in the same row (`flex gap-2`, the input `min-w-0 flex-1`).
  - Its text is "Show" while hidden and "Hide" while shown. It has `aria-pressed`, and
    `aria-controls` set to the input id.
  - Toggling keeps the value, the focus position and the caret.
- **Hides again on its own.** The value goes back to hidden when:
  - the component unmounts (a dialog closes, a step changes);
  - the parent clears the value to `""` (forms reset after a successful save). Remember the last
    value this input emitted. A `""` that this input did not emit came from the parent. A person
    deleting everything to retype keeps the field shown;
  - the field is `disabled`.
  
  There is no timer.
- **Accessibility.** The button's accessible name is "Show <label>" or "Hide <label>". The label
  comes from `revealLabel`, or else from the input's `aria-label`, or else plain "Show" / "Hide".
  A screen reader then hears which field is being revealed, and two secret fields in one form
  have distinct buttons.
- **Layout.** Tokens only, both themes, no horizontal scroll at 390 px. The row never wraps the
  button under the input. The input shrinks instead.
- The font follows the caller: `send-as-me` keeps `font-mono`, passed through `className`.
- **No copy button.** The value is what the person just typed or pasted. Only show it.

### 2. Every secret field uses it
Replace each hand-written password input in the table with `SecretInput`, keeping each one's
current `autoComplete`, placeholder, `maxLength`, label and test ids:
- `ValueInput` becomes `Field` + `SecretInput` with the field id. This fixes the `aria` linking.
  Its own `show` state goes away. Keep the component, since five callers use it.
- `FieldControl` renders `SecretInput` for `f.type === "secret"`. The ICS link and the CalDAV app
  password get Show through this. So do every connector, integration (channels) and app connect
  form, because they all render through `DynamicForm`.
- `oauth-clients-panel`: `SecretInput` when `f.secret`. Keep the "Leave blank to keep the stored
  value" placeholder.
- `settings-section-form`: `SecretInput` in Replace mode. "Set" / "Not set" stay as they are.
  There is still no way to see a stored value.
- `sign-in-provider-dialog`, `secret-stores-view`, `send-as-me`, `webhooks-tab`: `SecretInput`.
- **Not changed:** `generated_secret` (server-made, never shown), and `CopyValue` (values the
  server deliberately shows, such as a new API key once or a redirect URI).

### 3. Guard against new one-offs
Add a vitest test (`web/tests/secret-input-guard.test.ts`) that reads every `.tsx` under
`web/src` and fails when `type="password"`, `type={"password"}` or a `"password"` branch of a
`type=` expression appears anywhere except `components/ui/secret-input.tsx`. The message should
say "use SecretInput". Read the files with `fs` and a glob, which is cheap and has no new
dependency.

### 4. Docs
- `docs/14-web-dashboard.md` §Visual design › **Components**: add a **SecretInput** bullet after
  **Field**: "a value written but never read back: hidden while typing, with Show / Hide (named
  after its field) that reveals only what was typed; hidden again when the dialog closes, the
  value is cleared or the field is disabled; every secret field uses it (D-375)."
- In §App setup step 3, "`secret` as password inputs" becomes "`secret` as `SecretInput`".
- In the settings "**Secrets** are write-only fields" bullet, add: "a value being typed in
  Replace… can be shown with Show; a stored value never can."

## Acceptance criteria
1. With ICS and with CalDAV, in Connect, typing or pasting the link or password, then pressing
   **Show**, displays the typed value in the field. **Hide** masks it again, and the value is
   unchanged when submitted. Unit test the `FieldControl` secret branch and test `SecretInput`
   itself.
2. Every row of the table above renders `SecretInput`. The guard test passes, and it fails on a
   planted `type="password"` (check this once, by hand, then remove the plant).
3. `SecretInput` starts hidden. It hides again on unmount, when the parent clears the value to `""`
   (but not when the person deletes the text) and on `disabled`. The button is `type="button"`: pressing it inside a `<form>` does not submit.
   Its accessible name is "Show <label>" or "Hide <label>", and `aria-pressed` follows the state.
4. `ValueInput`'s hint and error are linked to the input (`aria-describedby`), and the error
   sets `aria-invalid` (a test that failed before this change).
5. No request body or route changes. No stored secret is ever placed in a `SecretInput` value
   (the existing SEC-12 contract tests stay green). The settings Replace input starts empty.
6. Both themes. At 390 px, the ICS connect dialog and Administration › Email (SMTP password in
   Replace mode) have no horizontal scroll and the button stays beside the input. Add a
   Playwright mocked check for the ICS dialog at 390 px with Show pressed.
7. Gates (web only): `pnpm tsc --noEmit`, lint, the vitest suites touched plus the guard, the
   Playwright mocked specs that touch secret fields (connect journey, credentials, connectors
   admin, settings email), and `pnpm build`. Existing tests asserting `type="password"` keep
   passing. They test the hidden state.
