# FIX-108: Sign-in and sessions — JIT does not re-admit removed members, re-authentication requires `auth_time`, revocations reach every replica, the CLI approval shows what is being approved (REVIEW-5 AUTH-1..AUTH-6) — **high, security**

## Problem
1. **JIT re-adds a member an admin removed.** `services/aurora-api/src/domains/oidc/service.rs` calls `apply_jit` on every sign-in (~629); it inserts a membership whenever none exists (~794–828). For an org without SCIM, removal is a hard delete (`crates/aurora-db/src/repo/members.rs` ~173) with nothing to distinguish "removed" from "never joined": the person's next sign-in through a provider with a `jit` block restores the membership and workspace bindings. `docs/04` contradicts itself: ~32 says the `jit` block decides what the user joins "on first sign-in"; ~226 says "if the provider has a `jit` block and the user is not a member of that org, add membership". The existing test covers the first sign-in only.
2. **Re-authentication is accepted without `auth_time`.** The freshness check (~520–524) applies only when the ID token carries `auth_time`; OIDC Core requires the claim when `max_age` was sent (the request sends `max_age=0`), and the openidconnect crate does not enforce it. An IdP that ignores `prompt=login` and omits the claim lets a stolen session stamp `reauth_at`, which gates account deletion and SCIM settings. `docs/04` ~243 words the check as conditional.
3. **Revocation can be cached for 30 s after it happened.** The auth cache `put` follows the database read with no generation check (`http/auth.rs` ~500, ~526), so a revoke that lands between them is cached as live; removing instance-admin through `PATCH /v1/admin/users/{id}` does not notify at all (`admin/service.rs` `patch_user`; only disabling does).
4. **`user.admit_by_claim` is not a critical audit action** (`crates/aurora-core/src/audit.rs`), so the row is hidden by the critical filter although SEC-78/D-143 call the admission critical-audited.
5. **The CLI device approval is blind.** `POST /v1/auth/cli` is unauthenticated and takes a free-text hostname; the approval screen (`web/src/components/auth/cli-view.tsx` ~76–96) shows a code field and a workspace picker, nothing about the requesting machine; approval mints a user key with no expiry (`cli_login/service.rs` ~221). A phished code yields a permanent key acting as the victim.

Owner questions outside this brief: a self-service provider with `trusted_email_domains` can link to — and take over — accounts created through another provider (Q-R5-12, D-118); the owner floor promotes the first signer of a claim-created org to owner even when the mapping grants `member` (Q-R5-13, D-139(d) vs D-165(a)); CLI key lifetime (Q-R5-16).

## Spec change (apply with the fix)
- `docs/04` ~226: "JIT membership and bindings are applied on the sign-in that creates the user, and later only for an org the user has never been a member of; a membership removed by an admin is not restored by JIT." (Mechanism: a removal marker per (org, user) cleared by an invitation or an admin add.)
- `docs/04` ~243: "a re-authentication is accepted only when the ID token carries `auth_time` within 60 s (allowing clock skew); a missing claim is refused `reauth_stale`".
- `docs/04` §CLI login step 2: the approval screen shows the requesting hostname, start time and coarse address, and states that approval creates a key that acts as the approver.

## Scope
- Removal marker (migration; `docs/03`), written by member removal, consulted by `apply_jit`, cleared by invitation acceptance and admin add; role-claim sync is unaffected (FIX-080 gates it for SCIM orgs).
- `auth_time` required for re-auth; future values beyond skew refused.
- Cache generation stamp so an invalidation during a read prevents the `put`; `notify_auth_revoked` whenever `is_instance_admin` changes.
- `user.admit_by_claim` in the critical set and its coverage test.
- `GET /v1/auth/cli/pending?code=` (session only) and the approval screen; default key expiry per Q-R5-16 (propose 90 days, configurable) — if undecided, land the screen and leave expiry unchanged.
