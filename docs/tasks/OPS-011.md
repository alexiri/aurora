# OPS-011: kind e2e (Kubernetes backend, Helm install, NetworkPolicy / SEC-02 probes)

## Goal
Prove M7 on a real local cluster: create a kind cluster (rootless podman provider), build and load the images, install the Helm chart from scratch with the documented steps, and run the hosted e2e scenarios against the `kubernetes` runner backend with NetworkPolicy enforcement, including the SEC-02 probes.

## Linked requirements
- `docs/19` M7 acceptance: "e2e-hosted passes on kind with NetworkPolicy enforcement; SEC-02 probes pass on Kubernetes". Phase-0 exit: "the Helm chart installs from scratch with documented steps".
- `docs/11-runner-sandboxes.md` §Backend kubernetes; `docs/15` §Production: Helm; `docs/17-security.md` SEC-02 (and SEC-09 for internal ports); `docs/operator/install-helm.md` (OPS-012/013). Follow it literally and fix the doc where reality differs.
- Host facts: kind v0.33.0, kubectl 1.37, helm installed; rootless podman with cgroup v2 and delegated `cpu memory pids` controllers. Use `KIND_EXPERIMENTAL_PROVIDER=podman`. No `~/.kube` exists yet.
- NetworkPolicy enforcement: kind's default CNI may not enforce NetworkPolicy for every case the chart relies on (egress to specific pods/ports, deny DNS). Verify enforcement with a probe pod first. If kindnet doesn't enforce, install Calico (pinned manifest) with `disableDefaultCNI: true` in the kind config, and document it.

## Scope
### In scope
- `scripts/e2e/kind.sh`:
  - create the cluster (name `aurora-e2e`; kind config in `deploy/kind/`)
  - build the service images and the sandbox image (reuse `scripts/images/*` / the Containerfiles), then `kind load image-archive` them
  - install the chart with a test values file (`deploy/kind/values-e2e.yaml`: the evaluation Postgres enabled, external URL, runner backend `kubernetes`, fake LLM or the TEST-017 LiteLLM mock if merged, otherwise fake harness)
  - wait for readiness, run the scenarios, collect logs on failure
  - tear down with `--keep` to skip deletion
  - idempotent re-runs
- Hosted e2e on k8s:
  - parametrize the TEST-013 suite (`tests/e2e-hosted`) to target a base URL + kubeconfig instead of local processes, or add a k8s-specific test file that reuses its helpers
  - at minimum: sign-up → agent → chat turn answered by the fake harness in a sandbox Pod; park/wake; restart
- SEC-02 / SEC-09 probes from inside a sandbox Pod:
  - no DNS
  - only gateway:4102 and runner:4105 reachable
  - API, Postgres, gateway 4103, runner 4106, hookhost and the Kubernetes API unreachable
  - no service account token mounted
  - non-root and read-only rootfs
- Fix chart, backend or doc defects found, minimally; list each one in the report.

### Out of scope
- CI wiring (no remote CI exists), multi-node, and the upgrade test (separate task).

## Constraints / file ownership
