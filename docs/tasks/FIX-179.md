# FIX-179: Sandbox processes cannot ptrace each other (closes FIX-151's residual)

## Goal
FIX-151 (SEC-121) ties a platform-tool call to the harness process that made it. Its residual (`17`):
a same-uid process in the sandbox can `ptrace` the harness and make calls as it wherever the host's
`kernel.yama.ptrace_scope` is 0. Nothing in Aurora sets that sysctl (a host setting). Owner, 2026-11-19
(D-394): block `ptrace` in the sandbox profile.

## Change
1. The sandbox's seccomp profile denies `ptrace` (and `process_vm_readv`/`process_vm_writev`, which reach
   the same memory) for every process in the sandbox, on both backends:
   - Kubernetes (`services/aurora-runner/src/backends/kubernetes/objects.rs`, the chart helpers in
     `deploy/helm/aurora/templates/_helpers.tpl`): a `Localhost` seccomp profile that is `RuntimeDefault`
     plus these denials, shipped with the chart (a ConfigMap/DaemonSet that installs it on sandbox nodes,
     or the operator's documented path — choose the simplest one that works on kind and on a real cluster
     and say which); the pod falls back to refusing to start, never to running without it.
   - podman (`services/aurora-runner/src/backends/podman*`): `--security-opt seccomp=<profile>` with the
     same profile.
2. Check every harness still works: none of the five (`claude-code`, `codex`, `pi`, `goose`,
   `opencode`) nor the terminal, SSH, `process_start` or the language servers may need `ptrace` (a
   debugger in the sandbox is the one thing that stops working; say so in `17` and the operator doc).
3. `17`: replace the residual with SEC-137 ("no process in the sandbox can trace another"); `12`/`15`
   and the operator doc describe the profile.

## Tests
- Hosted e2e (podman, full image): a process in the sandbox trying `ptrace(PTRACE_ATTACH)` on the
  harness (or `strace -p`) gets `EPERM`; seen succeeding before on a host with `ptrace_scope` 0, or
  reasoned if this box's host refuses anyway (say which).
- Runner unit tests for both backends' pod/container spec carrying the profile.
- The harness conformance suite and `hosted.sh` (full image) green: nothing else needed `ptrace`.
