# FE-013: Account pages, workspace settings (access, API keys), admin users

## Goal
Dashboard pages for the account area, workspace settings, and instance-admin user management, on the generated client.

## Linked requirements
- M1/14 `§Account (/account/*)` (profile, password, sessions "sign out others", personal API keys, delete account — chat links/DM defaults are M6), `§Workspace` → **Settings** (name, timezone, memory language (owners), access bindings, workspace API keys, danger zone), `§Instance administration` → **Users**; `04 §Permission matrix` (UI hides/disables what the role cannot do; backend stays authoritative); contract `docs/API_CONTRACTS.md` M1 rows `/v1/me*`, `/v1/auth/password/change`, `/v1/auth/sessions/revoke-others`, `/v1/workspaces/{ws}` (PATCH/DELETE), `/v1/workspaces/{ws}/access*`, `/v1/workspaces/{ws}/api-keys`, `/v1/api-keys/{id}`, `/v1/admin/users*`, `/v1/workspaces/{ws}/audit`.

## Context
- Built so far: shell + shared utilities (FE-011: `src/lib/api/{errors,queries,unwrap}.ts`, app shell with workspace sidebar where non-Overview items are disabled), auth pages + CSP proxy (FE-010). Generated client `src/lib/api/schema.d.ts` contains all these routes.
- One-time secrets: API key creation returns `key` once — show it in a dialog with copy button and "you won't see it again"; never store it in query cache or local storage.
- `DELETE /v1/me` takes a JSON body `{ password? }` (send `{}` for password-less users); `DELETE /v1/workspaces/{ws}` takes `{ confirm: <slug> }`.

## Scope
### In scope (`web/src/**`, `web/tests/**`; don't edit generated files)
- `/account` (profile: display name, default org select), `/account/security` (change password, sign out other sessions), `/account/api-keys` (personal keys list + revoke), `/account/delete` (password confirm; `last_owner` error explained).
- Workspace sidebar: enable **Settings** → `/o/[org]/w/[ws]/settings` with tabs: General (name/timezone/memory language; disabled for non-owners with explanation), Access (list incl. implicit owners badge; add binding from org members list `GET /v1/orgs/{org}/members` when caller can list them — handle 403 by hiding the picker; change role; remove), API keys (list, create → one-time reveal dialog, revoke), Audit (paginated list with action filter), Danger zone (delete with slug confirmation).
- `/admin/users` (only when `me.user.is_instance_admin`; else 404-style page): search, toggle instance admin, disable/enable; 422 `cannot_modify_self` explained.
- Header user menu: link to Account; Admin link for instance admins.
- vitest tests: one-time key dialog (key not retained after close), access tab permission rendering (owner vs member), admin users toggle error handling.

### Out of scope
- Org pages (members, invitations, org keys, org audit, org settings — FE-012), channel links/DM defaults (M6).
