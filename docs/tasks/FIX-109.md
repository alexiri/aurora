# FIX-109: Freeze authority, approval deadlines and policy matching (REVIEW-5 POL-1..POL-7) — **high, security**

## Problem
1. **A lower authority can lift a higher authority's freeze** (coordinator-verified). `crates/aurora-db/src/repo/freeze.rs` `freeze` (~122–144) updates only `WHERE frozen_at IS NULL`; freezing an already-frozen scope is a silent no-op (`freeze/service.rs` ~138–196: no effects, no audit, 200 returned). If a workspace owner froze an agent first, an org admin's freeze changes nothing; `frozen_authority` stays `workspace_owner`, and the workspace owner can unfreeze (`service.rs` ~198–251 allows rank ≥ stored rank). D-50: "a higher authority's freeze must not be reversible by a lower one"; SEC-45. The test at `tests/it/freeze.rs` ~144–150 pins the current behaviour.
2. **Approvals can be decided after their deadline.** `decide` and `decide_batch` (`repo/approvals.rs` ~221–306) match `status = 'pending'` with no deadline test; expiry is a sweep with a 30 s grace (`expire_overdue`, `jobs.rs`). A parked or orphaned approval past its deadline can still be approved and is audited as `approved`; if the sweep is down the window never closes. Action approvals refuse this (`action_approvals/service.rs` ~191). `docs/07`: "Expiry still denies".
3. **A literal path rule misses the trailing-slash form.** `crates/aurora-policy/src/path.rs` keeps an empty last segment, so a block on `/v1/users` does not match `/v1/users/` (the unit test asserts it), which most frameworks serve identically; `docs/07` is silent and its own rule is "doubt only tightens".
4. **Non-ASCII host patterns are accepted and never match.** Authoring (`policy/validate.rs` ~119, `host.rs` `parse_inner`) accepts `bücher.example`; clients send punycode; no conversion exists.
5. Rollback replaces the draft with no revision check (`policy/service.rs` ~100–130), discarding a colleague's saved draft; a blocklist that becomes empty leaves its old derived block rule (`connect/service.rs` ~510–527); the stream event for a freeze-abandoned approval is labelled `expired` (`freeze/service.rs` `apply_effects`).

## Linked requirements
- `docs/90` D-50, D-55; `docs/17` SEC-28, SEC-45, SEC-49; `docs/07` §Matching primitives, §Approval deadlines, §Lifecycle, §Authoring; `docs/05` SSE `approval` events.

## Spec change (apply with the fix)
- `docs/04`/`docs/07` §Freeze: "freezing a scope that is already frozen by a lower authority raises the record to the caller's authority (who, reason, authority) and is audited; freezing by an equal or lower authority changes nothing and says so."
- `docs/07` §Matching primitives: "A trailing `/` is not significant: `/a/b` and `/a/b/` match the same literal pattern." "Host patterns are ASCII; an internationalised name is written in its punycode form (authoring refuses other characters with that hint)."
- `docs/07` §Approval deadlines: "a decision after the deadline is refused (409 `already_decided`) and the approval is expired in the same transaction".
- `docs/07` §Authoring: "rollback replaces the current draft and requires the draft revision the caller last read". `docs/05`: the approval stream event `abandoned`.

## Scope
- Escalating re-freeze for agent, workspace and org scopes with an audit row (`escalated: true`); response reports the resulting authority.
- Deadline predicate in both decide statements; expire-on-miss; the sweep grace documented or removed.
- Path matcher drops one empty trailing segment; corpus cases for block and allow.
- Authoring refuses non-ASCII host patterns.
- Rollback takes `expect_revision`; empty blocklist deletes its derived rule and invalidates; `abandoned` event (web client handles it like `expired` with its own copy).
