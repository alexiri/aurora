# FIX-087: Shared counters — the SCIM limiter stops refunding refusals; breaker per class; Redis scripts fail closed on garbage; documented Redis ACL is complete (REVIEW-5 CNT-1/2/4/6/7/9/10) — **high (item 1), medium**

## Problem
1. **The SCIM rate limit is about half enforced** (coordinator-verified). `services/aurora-api/src/domains/scim/rate_limit.rs`: `take` returns `Err` on a local refusal without consuming a token (~55–58), and the middleware's `Err` arm refunds one unconditionally (~133–137 for tokens, ~150–156 for rejected bearers; the comment claims "the shared take may have consumed"). A local refusal therefore adds a token to a bucket that was never charged, so a flooding token alternates refused/allowed forever. On a shared refusal `take_shared` has already refunded (`http/counters.rs` ~149, ~173) and the middleware refunds again. The `/v1` path (`http/apilimit.rs` ~717–720) is correct. `docs/05` §Shared counters: "a refusal there [the local pre-filter] is final"; "A store refusal refunds the local token".
2. **One breaker and one pool serve every class.** `crates/aurora-db/src/counters.rs` `build_store` (~236–293) builds one `Guarded`; `http/counters.rs` `over()` (~50–58) hands it to both `security` and `management`. Anonymous requests are charged to the shared store before any auth decision (`apilimit.rs` ~650–654), each new address gets a fresh local bucket, and any `Unavailable` counts toward the single breaker (`crates/aurora-counters/src/guard.rs` ~105–156). With `management = "closed"`, an unauthenticated flood that saturates the 4-connection counters pool opens the breaker and turns every authenticated `/v1` request into 503.
3. **A cancelled caller decides the probe.** The half-open probe runs inside the caller's future (`guard.rs` ~116–128); dropping it records a failure and re-arms the cooldown (~159–167). FIX-065 made this not wedge; it still lets disconnects hold the breaker open.
4. **Redis scripts read garbage as "under the limit".** `crates/aurora-counters/src/redis_store.rs` ~28, ~46 (`tonumber(…) or 0`), ~75 (`… or now`): a non-numeric stored value counts as zero or a full bucket. SEC-62: a backend answer is never read as under the limit.
5. **The documented Redis ACL cannot run the scripts.** `docs/15` ~628 lists `EVALSHA`/`SCRIPT LOAD`/`GET`/`PING`; the scripts also call `TIME`, `INCRBY`, `PEXPIRE`, `SET`. An operator who follows the doc gets `NOPERM` → permanent `Unavailable` → the class policy forever.
6. **Webhook `Retry-After` is clamped to 10 s** (`http/counters.rs` ~229–234) although the window can block for 60 s.
7. **The gateway opens a counters pool it will not use** (`services/aurora-gateway/src/main.rs` ~246–251: `build_store` before the `gateway_shared` check).

## Scope
### In scope
- SCIM limiter: remove the middleware refunds; `take` reports whether the local bucket was charged so the only refunds are the ones `take_shared` makes on a store refusal or `Closed`. Same check on the rejected-bearer bucket.
- One `Guarded` (breaker + pool or pool share) per class for the API and the gateway; the probe runs in a task the breaker owns.
- Lua: a non-nil, non-numeric value → `redis.error_reply`, mapped to `Unavailable`.
- Optional but cheap: a boot-time write probe that logs the missing command when the ACL is too narrow.
- `Retry-After` for webhooks: `secs_ceil(…).max(1)`.
- Gateway: build the store only when `counters.gateway_shared`; the API likewise when no class is shared.

### Out of scope
- Running the Redis conformance suite in CI (FIX-101). Relay-plane rate class (FIX-090).
