# BE-013: Invitations

## Goal
Org owners/admins invite by email; invitees preview and accept with a verified matching email.

## Linked requirements
- M1/04 `§Invitations`, `§Permission matrix` (members/invitations: owner/admin), `§Email and password` (unverified users cannot accept); SEC-21, SEC-32. Contract: `docs/API_CONTRACTS.md` M1 rows `/v1/orgs/{org}/invitations`, `/v1/invitations/*`; C-01 (tokens never returned by any API).

## Context
- BE-010 fixed design; tenancy repos/services from BE-012 (memberships, workspace_access); mailer from BE-011 (`Mailer` trait in `domains/auth/mail.rs`).
- Table `invitations` (`03 §1`): partial unique pending per (org, email); `expires_at` default 7 days; `workspace_ids` bound as `member` on accept.

## Scope
### In scope (`services/aurora-api/src/domains/invitations/`, `crates/aurora-db/src/repo/invitations.rs`)
- Create (validate role ∈ admin|member — `owner` not invitable; workspace_ids must belong to the org; already active member → 409 `already_member`; re-invite of a pending email rotates the token and resets expiry, same 201 response; seat cap `settings.max_members`: active members + pending ≤ cap → else 422 `member_limit_reached`), email `<external>/join?token=aui_…` via the mailer.
- List (`?status`), cancel (`DELETE /v1/invitations/{id}` → `cancelled`), preview (public; 404 for unknown/non-pending/expired tokens, but return status for accepted/cancelled? — return 404 for anything not pending and unexpired), accept (SO; signed-in user's **verified** email must equal invitation email case-insensitively: 403 `email_unverified` / `email_mismatch`; expired → 410 `invitation_expired`; membership `member`/`admin` + bindings created in one transaction; invitation → `accepted`, `accepted_by`; existing *suspended* member → 409 `already_member` (do not silently reactivate)).
- Expired pending invitations are treated as expired at read time (status reported `expired`; optional lazy update).
- Audit: `invitation.create`, `invitation.cancel`, `invitation.accept`.
- utoipa; regenerate `web/openapi.json` + `pnpm gen:api`.

### Out of scope
- Dashboard pages (FE-012, FE-010 `/join`).

## Acceptance criteria
- [ ] Tests: create/list/cancel permissions (member → 403); re-invite rotates token (old token preview → 404); accept with unverified email → 403 `email_unverified`; mismatched email → 403 `email_mismatch`; API key on accept → 403 `session_required`; accept creates membership + workspace bindings; cap enforced; expired → 410; token never present in any response body (assert on JSON).
- [ ] Standard cargo test/clippy/fmt for `-p aurora-api -p aurora-db`; OpenAPI drift; web gen/typecheck.
