# FIX-216: `aurora plugin test` applies the gateway's path hygiene first

## Goal
Found by the P5-GRAFANA lane on 2026-11-21 (its Completion report, finding F2).

The offline package test runner (`aurora plugin test`, `check_snapshot.rs`) matches a fixture's **raw** request path. The gateway's step-3 path hygiene (`06` step 3: dot segments and `%2F` refused with 400 `ambiguous_path`, the path normalized) never runs there. As a result:
- a fixture cannot assert `ambiguous_path`;
- a dot or `%2F` segment inside a `*` position classifies differently offline than in production.

A package author can believe a boundary case selects a tool, or doesn't, when production does the opposite.

## Change
- Run the same hygiene function the gateway uses (`hygiene::check_request_line`, or wherever step 3 lives) before tool matching in `check_snapshot.rs`, and match on the normalized path, exactly as the gateway does. Use one shared function, not a copy.
- A fixture may expect `refused: ambiguous_path`. Document it in the package-test docs (`09` §tests or the plugin authoring guide).
- Re-run every built-in's fixtures. Any fixture whose verdict changes is reported, and fixed in its package with a patch bump.

## Tests
- Runner tests:
  - a `..` segment, `%2e%2e`, `%2F` and `//`, each giving `ambiguous_path` offline as in production;
  - a normal path unchanged.
- The Grafana package's `tests/proxy-boundaries.yaml` gains `ambiguous_path` expectations where production refuses.
- Gate: `scripts/plugins/check-builtin.sh` for every built-in, the CLI and registry tests you touch, fmt, clippy `-D warnings`, guards (through `heavy.sh`).

## Placement
The Grafana lane (`p5-platform`) after FIX-215. Sonnet would do, but the lane runs Opus for FIX-215 anyway.
