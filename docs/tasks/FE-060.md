# FE-060: Channel dashboard pages

## Goal
The M6 dashboard: org **Channels** page, agent **Channels** tab, admin **Connectors** page, account channel links + DM defaults, and the `/link/channel` confirm page.

## Linked requirements
- `docs/14-web-dashboard.md`:
  - public pages: `/link/channel` ("confirm a chat platform account link")
  - Account: "chat platform links, DM defaults"
  - Org: "**Channels**: integrations per connector (setup form from the connector manifest, status, shared bot identity), user links"
  - Agent page: "**Channels** — presences (attach dedicated/shared per integration capabilities; status; re-attach/detach), space bindings, reach requests"
  - Admin: "**Connectors** (provision, token rotation, manifest approval with capability/setup-field diff)"
- Contract: `docs/API_CONTRACTS.md` §M6 (API-006) **C-31..C-38** and the TS types listed there. Use the generated client only (`web/src/lib/api/schema.d.ts`, `components["schemas"][…]`); no hand-written API types (D-32).
- Permissions (I-27, API-006 table):
  - org owner/admin: integrations, admin user links
  - `can_use`: presences, links listing
  - `can_own`: space bindings, reach decisions
  - instance admin: connectors
  - Show the existing forbidden `ErrorState` on 403/404, and hide controls the caller can't use where the page already knows the role.

## Context and specifics
- Existing patterns:
  - dynamic forms from app connect fields: FE-030 connect window (`web/src/components/apps/*`, the field renderer). Reuse it for `integration_setup.fields` and `presence_setup.dedicated.fields`.
  - safe markdown renderer for `setup_guide_md`: FE-030
  - admin pages: `web/src/app/admin/plugins` (FE-031: upload/review/approve with diff). Mirror it for connector manifest approval: show `widening` reasons and the manifest/capability diff, then approve with `manifest_digest` (409 `stale_manifest` → refetch)
  - one-time secret display: `OneTimeKeyDialog` (FE-051). The connector token from provision/rotate is shown once only, with `gcTime: 0`.
- Integration create (C-33) is synchronous and can take ~10 s: show a pending state and handle 409 `tenant_already_bound`, 422 `credentials_invalid` (with the connector message as plain text) and 503 `connector_unavailable`. Credentials are write-only: never prefill, and show "stored" only.
- Presence attach (C-34): offer modes per connector capabilities (`presence_dedicated`/`presence_shared`) and the integration's `shared_bot`. Handle 422 `no_shared_bot`/`mode_unsupported`/`credentials_invalid`. Show the status chip and re-attach/detach.
- Space bindings: list, edit listen mode / `followups_need_mention`, remove (`can_own`).
- Reach: pending requests with approve/block (C-35, `revision`, 409 → refetch) and history.
- `/link/channel?token=aui_…`: signed-in confirm page (redirect to login with return URL if not signed in). Show the platform user and integration label, then confirm with `POST /v1/channel-links/confirm`. Handle 410 `link_expired` and 409 `already_linked`. Never put the token in logs or analytics, and drop it from the URL after use (`history.replaceState`).
- Account: links list with unlink, and DM defaults per linked integration (select among reachable agents; 422 `agent_not_reachable`).
