# BE-031: Secrets and LLM keys API (incl. governance admission and origin verification)

## Goal
CRUD for generic and LLM secrets through `SecretVault`, with governance admission, key validation and key-origin verification at save.

## Linked requirements
- M2/08 `§5 Secrets` (recipes, generic secrets refused on governed LLM hosts — 422 `llm_host_requires_llm_key`, agent-proposed accept/reject), `§6 LLM secrets` (admission → validation → origin verification; unreachable rules), `§11.2/11.3/11.7` (API enforcement points), `§2` (managed/reference, `check_reference`); `05 §Secrets and LLM`; D-39, D-42; SEC-11, SEC-12, SEC-35, SEC-37; `18 §Governance` key admission suites, `§Secrets` reference-mode via memory store.

## Context
- Libraries: `aurora_secrets::{SecretVault, StoreRegistry, SealContext, Purpose::SecretValue, SecretRef, recipe::InjectionRecipe}`; `aurora_llm::{ProviderRegistry, governance::{Instance, effective, OrgGovernance, StoredOrigin}}` (GOV-001); `aurora_policy::HostPattern`. Build the vault + registries once in `AppState` (memory store only in tests via the `memory-store` feature as a dev-dependency).
- Tables: `secrets` (`03 §2`), `organizations.governance`.

## Scope (`services/aurora-api/src/domains/secrets/**`, `crates/aurora-db/src/repo/secrets.rs`, tests `tests/secrets*.rs`)
- All M2 contract rows for secrets, secret stores, llm providers, models, verify. Permission matrix: workspace secrets `can_own` to write (read: `can_use`), org secrets owner/admin; LLM keys additionally governance-permitted for scope.
- Generic: host pattern validated (≤1 `*`), refused when it can match a governed LLM host (`governed_hosts`), recipe validated. LLM: derive host pattern from endpoint, recipe from provider; run admission → `list_models` → `verify_key_origin` (if rule) → store `origin`; unreachable without rule ⇒ save with `origin.status=pending`.
- Values only via vault (AAD purpose `secret.value`, owner = secret id, org); `PUT value` bumps `value_version` and re-verifies; never return values (assert in tests).
- Proposals accept/reject (accept sets value + creates grant row for `proposed_by_agent_id` — grants table write; derived rule compilation is BE-033: call a `grants::compile_secret_grant` stub function if BE-033 isn't merged, else the real one).
