# BE-071: Inbox ingest, operations engine, correlated ops, connector files

## Goal
The connector plane's data half: durable inbox with dedupe, the outbound operation queue with leases, retries and neutral error handling, correlated operations, connector file upload and download, and `link-start`.

## Linked requirements
- `docs/13-channels-connectors.md` §4:
  - rows `events`, `ops/claim`, `ops/results`, `link-start`, `PUT /files/{op_id}`, `GET /files/{attachment_id}`
  - §4.2 Delivery (`op_marker`, `maybe_sent` on re-claim after a lapsed lease)
  - the neutral error code table (core behaviour per code)
  - Correlated operations (`correlation_id`, wait on `aurora_op_result` 10 s / 30 s for `file.fetch`, `connector_unavailable`; ops without an integration are claimable by any live replica)
- §6 invariants 3 (at-least-once in, at-most-once out) and 5.
- `docs/05` §Event bus (`aurora_inbox`, `aurora_op_result`), §Background jobs (inbox processor `aurora_inbox` + every 5 s).
- Limits: `INBOX_LEASE`, `OP_LEASE`, `OP_MAX_ATTEMPTS`, `CONNECTOR_OPS_WAIT`, `ATTACH_IN_FILE_MAX` (`crates/aurora-core/src/limits.rs`).
- Schema: `channel_inbox`, `channel_ops`, `link_requests`, `attachments` (BE-064 adds the BlobStore and attachments domain: reuse it).
- Wire types: `crates/aurora-protocol/src/connector.rs` (`EventsRequest/Response`, `ClaimRequest/Response`, `Operation`, `ResultsRequest`, `OpResult`, `OpError`, `LinkStartRequest/Response`, `FilePutResponse`).

## Scope
### In scope
- `services/aurora-api/src/domains/connector_plane/` (or inside `domains/connectors/` if BE-070 laid it out that way; follow BE-070's module layout):
  - **`POST /events`** (≤100):
    - validate each event, then check `integration_id` belongs to this connector and is owned by this replica (otherwise reject that event with a code)
    - insert into `channel_inbox` (`ON CONFLICT (connector_id, event_id) DO NOTHING` → duplicates), then NOTIFY `aurora_inbox`
    - answer only after commit
  - **`POST /ops/claim`**:
    - long-poll up to `wait_secs` on a NOTIFY channel for new ops of this connector (pick a name like `aurora_ops` and document it in `docs/90-decisions.md` as I-28 if it isn't in 05)
    - `SKIP LOCKED` claim of `pending` ops with `not_before <= now()` for integrations owned by this replica, or with `integration_id IS NULL`
    - set `lease_until = now() + OP_LEASE` and `claimed_by_replica`, increment `attempts`
    - `maybe_sent = true` when re-claiming a `claimed` op whose lease lapsed
  - **`POST /ops/results`**: only the claiming replica may report; apply the neutral code table:
    - `rate_limited`: `not_before` += retry_after (default 30 s), attempt not consumed
    - `unavailable`: exponential backoff up to `OP_MAX_ATTEMPTS`, then `failed`
    - `credential_dead`: presence/integration → `disabled` with reason, op `failed`. Add a hook point for notices (BE-074 will use it).
    - `forbidden`/`invalid`/`too_large`/`unsupported`: `failed`, error log for the last three
    - `not_found`: `dropped`
    - `ok`: `done` + `result`
    - then NOTIFY `aurora_op_result {op_id}`
  - **Op enqueue API** for other domains: `enqueue(tx, NewOp { kind, integration_id, presence_id, payload, dedupe_key })` (dedupe via unique `dedupe_key`), and `call_correlated(state, NewOp, timeout) -> Result<Value, CorrelatedError>`, which inserts with `correlation_id`, waits on `aurora_op_result`, and maps timeout → `connector_unavailable`.
  - Lease-lapse sweeper: lapsed `claimed` ops return to `pending` (claim handles `maybe_sent`). Put it in the existing jobs runner.
  - **`PUT /files/{op_id}`**: only for a `file.fetch` op claimed by this replica; enforce the op's `max_bytes`; sanitize the filename; store through BlobStore as an inbound `bound`/`pending` attachment per the op payload (conversation/turn context comes from the op payload set by BE-072; for now store what the payload names); respond `{ attachment_id }`.
  - **`GET /files/{attachment_id}`**: only if it is referenced by a `message.post` op claimed by this replica; else 404.
  - **`POST /link-start`**: create a `link_requests` row (`aui_` token hashed, 30 min) for an owned integration and return `{ url: <external>/link/channel?token=…, expires_at }`.
  - **Inbox processor skeleton**: claim `channel_inbox` rows (`INBOX_LEASE`, backoff on error, attempts) on `aurora_inbox` + every 5 s, and dispatch by `kind` to a handler trait that BE-072/073 implement. Default: mark `done` with outcome `unhandled`. Exactly-once handling per row via lease + idempotent handlers.
- Tests `services/aurora-api/tests/connector_ops.rs`:
  - event batch with duplicates/rejects, and the NOTIFY fired
  - claim respects ownership and `SKIP LOCKED` across two replicas
  - long-poll wakes on a new op
  - every error code's behaviour
  - re-claim after a lapsed lease sets `maybe_sent`
  - a correlated call succeeds, times out, and an op without an integration is claimable by any replica
  - file PUT/GET authorization and size cap
  - link-start
  - the inbox processor claims and marks rows done exactly once with two concurrent workers
