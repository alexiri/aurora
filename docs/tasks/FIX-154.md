# FIX-154: Give an agent a credential-free app in one step

## Goal
For an app with nothing to sign in to or enter, such as CERN Phonebook or CERN Maps, a person should never need to know that a "connection" exists (owner, 2026-11-15: "this is ridiculous, especially for an endpoint that doesn't require any authentication"). Their whole job becomes **Give access** on the agent's Access tab.

The gateway's gate stays (D-251(d), SEC-110): an LDAP request is still answered only for a granted connection of the app. The difference is that the connection is created inside the grant, for the person, instead of by them on another page.

Depends on `FIX-153` (merged first): it owns the link builder, `access_url`, the agent-page id route and the LDAP `reason` split this brief extends.

## Linked requirements
- D-306 (c), C-895, C-896, C-897; the `05` rows for `GET /v1/apps`, `GET /v1/apps/{app}` and the new `PUT /v1/agents/{agent}/grants/apps/{app}`; `06 §LDAP lane`.
- Unchanged and relied on: C-842 (the connect dialog and its deep link), C-504 (bulk grant from the credential side), C-410 (`app_restrictions`), I-29 (`request_app_connection`), D-123 (`custom_only`).
- `14 §Visual design` for every changed screen.

## Design (decided; report with evidence if a part cannot hold)
1. **`credential_free`** (C-895). One pure function over the manifest/snapshot app, in `crates/aurora-registry` (next to `manifest/model.rs` / `snapshot.rs` `AppEntry`), used by the API and the gateway. It returns true iff:
   - `credentials` is empty, `token`, `instances`, `database` are absent, and `secret_link` is absent where the model has it;
   - `connect` is non-empty, and every method is `kind: fields` with no fields and no scopes.

   Unit-test it against `plugins/addons/cern-phonebook/plugin.yaml` (true), a builtin OAuth app (false), a fields app with one field (false), an instance-bound app (false) and an app with no connect methods (false).
2. **API DTO.** `AppSummary` and the app detail in `services/aurora-api/src/domains/apps/dto.rs` gain `credential_free: bool`. Regenerate the OpenAPI document and the web client types the way the repo already does.
3. **`PUT /v1/agents/{agent}/grants/apps/{app}`** (C-896) in `services/aurora-api/src/domains/grants/{routes,service}.rs`.
   - **Caller and agent checks.** Exactly those of `PUT …/grants/connections/{conn}` (`visible_agent`, owner rule, BYO/hosted rules as they apply today).
   - **App checks, before any write.** 404 `app_not_found`, 403 `app_unavailable` (the posture for the agent's workspace, the same check the connect service uses), 422 `app_not_credential_free`.
   - **One transaction:**
     1. `pg_advisory_xact_lock` on a stable hash of (workspace id, app id).
     2. Select the oldest connection with `status = 'active'`, workspace scope, this workspace, this app.
     3. If there is none, create it through the connect service's existing creation path (`domains/connect/service.rs`, the `fields` branch of `start`) with the first credential-free method and empty fields. Factor out an `_in_tx` helper if needed. Don't duplicate the insert.
     4. Label it from `about.label_hint`, else the app name. Created by the caller.
     5. Audit `connection.created` with `details.via = "agent_grant"` and `details.agent_id`.
     6. Upsert the grant with `grant_connection_in_tx`: same validation (`full_grant_forbidden` for `custom_only`), same audit, same snapshot/cache invalidation as today.
   - **Answer.** `200 { connection, grant, created }`.
   - **Tests** (API ITs, existing harness): creates once, then reuses on a second call and for a second agent; parallel calls create exactly one connection; refuses each error code; refuses a non-owner; `custom_only` → 422; the audit rows; removing the grant (`DELETE …/grants/connections/{conn}`) leaves the connection.
4. **Agent Access tab** (C-897). In `web/src/components/agents/connection-grants.tsx`, after the connection rows, list each app from `useApps(wsId)` that is `credential_free && available` and has no connection in the agent's scope (workspace or org connections of that `app_id`). Each row has the app icon, name, a `Badge` "No sign-in needed" and **Give access**.
   - **Give access** opens the existing `GrantEditor`/`GrantForm` for the app. Full is preselected unless `custom_only`; the tool list comes from `useApp(app)`. On save it calls C-896. Add a mutation in `web/src/lib/api/credential-grants.ts` that invalidates the grants, connections and apps queries.
   - **Empty state.** "No connections in scope" now shows only when there are also no credential-free rows.
   - **Description.** The section description mentions that apps needing no sign-in can be given directly.
5. **Connect dialog** (C-897). In `web/src/components/apps/connect-dialog.tsx`, when the app is `credential_free`, show the `connect_note` text (and link), the label input (default `label_hint`), and the agent picker (`GiveAccessPanel`) on one screen.
   - **One primary action** connects (`POST /v1/apps/{app}/connect`, the zero-field method) and then bulk-grants the chosen agents (`POST /v1/connections/{id}/grants`).
   - **No agents chosen.** It only connects (today's behaviour).
   - **Grant failure.** If the grant step fails, say so and keep the created connection (it is harmless and listed).
6. **Gateway** (C-897), building on FIX-153's reason split. When the request's app is credential-free (the registry function over the snapshot app), the `ldap_no_connection` `not_connected` message and the `app_not_connected` message lead with `access_url` ("A workspace owner can give this agent access on its Access tab: <access_url>"). `connect_url` stays in details. Extend `tests/it/ldap_lane.rs` (`not_connected` on a credential-free app names `access_url`) and add a unit test for `app_not_connected`.
7. **Agent notice** (C-897). `request_app_connection` (`services/aurora-api/src/domains/tools/apps.rs` ~250) links a credential-free app to the requesting agent's Access tab (`/o/<org>/w/<ws>/agents/<agent id>?tab=access`, FIX-153's id route) instead of the connect deep link. Its notice text says "give this agent access". Test it next to the existing ones.
8. **Package guide.** In `plugins/addons/cern-phonebook/docs/setup.md` and the external `aurora-addons-cern` copy, rewrite step 2 of "Connect it" as: "On the agent's **Access** tab, choose **Give access** next to CERN Phonebook". The external repo's change ships with its next release, and the lane notes it for the owner rather than pushing it.

## Acceptance criteria
1. `GET /v1/apps` reports `credential_free: true` for `cern-phonebook` and false for every builtin app (test over the builtin set).
2. With CERN Phonebook installed, approved and available, and no connection: the agent's Access tab shows CERN Phonebook with **Give access**. One save → a connection "CERN directory" exists, the agent holds the grant, and the agent's `POST https://cern-phonebook.ldap.aurora.internal/search` reaches the (fake) directory.
3. A second agent's **Give access** reuses that connection. Parallel calls never create two.
4. Each refusal of C-896 is returned with its code, before any write.
5. The Connect dialog for CERN Phonebook has no empty form, and connects and grants in one action.
6. Before any grant, the agent's refusal and its `request_app_connection` notice point at the agent's Access tab.
7. D-251(d) holds: an agent without the grant is still refused, and no directory is dialled.
8. Changed screens pass `14 §Visual design`: light and dark, 390 px.
