# FIX-203: Log where Mattermost buttons call back (owner 2026-11-21)

## Why

Owner, 2026-11-21. On the CERN instance (`externalUrl` `https://aurora-ui.cern.ch`, Mattermost
`mattermost.web.cern.ch`), clicking **Allow once** on an approval card fails in Mattermost with
`POST /api/v4/posts/<id>/actions/act1` → 400 `api.post.do_action.action_integration.app_error`
("Action integration error", `detailed_error` empty for a non-admin). Neither the aurora-ui nginx nor
the connector-host logged a request at the click, while a hand-made
`POST https://aurora-ui.cern.ch/connectors/mattermost/mm/actions` reaches the connector and is
refused 403 `bad signature` as it should. The owner does not have the Mattermost server log, and
Mattermost strips `integration` from every post a client or the API reads, so nothing showed which
URL the buttons actually carry.

(Not offering **Always allow** on the Mattermost card is by design: `14 §Approvals` "Always allow is
offered only in the dashboard".)

## What

Debug logging only; no behaviour change.

1. `connectors/mattermost/src/connector.rs` `MattermostConnector::new`: one `info` line
   "interactive callbacks expected at this address" with `actions_url` when a public URL is set
   (managed: once per assignment start; standalone: at start).
2. `connectors/mattermost/src/ops.rs`: after `message.post` (incl. ephemeral) and `message.update`
   of a card with actions, one `debug` line "card actions posted to Mattermost" with `op`,
   `channel_id`, `post_id`, `sent` and `returned`. Each is a list of `{id, type, url, iid,
   token_len, sig_len}` per action: what the connector sent, and what Mattermost's answer to the
   create/patch call contains (null fields there mean Mattermost did not echo them).
   **Never logged:** the action token, its signature, labels, message or card text (`02 §Logging`).

Turn on with `RUST_LOG=info,aurora_connector_mattermost=debug` on the connector-host (or the
standalone connector) and post a new card; existing cards are not re-logged.

## Tests

`ops::tests::action_summary_shows_the_url_and_hides_the_token`: the summary carries the URL, the
action id and the integration id, and not the token, the signature, the label or the text.

## Owns

`connectors/mattermost/src/{connector.rs, ops.rs}`, this brief, the PROGRESS row.
