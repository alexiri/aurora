# FE-011: Dashboard app shell — org/workspace navigation, overview with agents, create org/workspace

## Goal
The signed-in shell: landing redirect, org and workspace routes resolved from slugs, navigation, workspace overview listing agents (Daneel visible), and create-org / create-workspace flows. Also the shared client utilities later pages reuse.

## Linked requirements
- M1/14 `§Information architecture` (Organization `/o/<org>/*` workspaces list; Workspace `/o/<org>/w/<ws>/*` overview with agents), `14 §Architecture rules` (pure API client, TanStack Query, no `dangerouslySetInnerHTML`, accessibility), `04 §Sign-up and organization creation` (create org/workspace), `05 §Request scoping` (`GET /v1/resolve` maps slugs → ids). M1 acceptance flow "create workspace (Daneel present)". Contract: `docs/API_CONTRACTS.md` M1 rows `/v1/orgs*`, `/v1/orgs/{org}/workspaces`, `/v1/workspaces/{ws}`, `/v1/resolve`, `/v1/workspaces/{ws}/agents`.

## Context
- Scaffold (FE-001): `web/src/app`, providers, `src/lib/api/client.ts` (`openapi-fetch` + `ApiError`), generated `src/lib/api/schema.d.ts` (do not hand-edit; another task regenerates it as backend routes land — re-read it, it is additive), Tailwind 4, `components/ui/button.tsx`.
- Routes available now: everything in the contract rows above. **Not yet available**: `/v1/me` (BE-016), `/v1/auth/logout` (BE-011, landing soon). For the user menu, call `POST /v1/auth/logout` (it will exist) and show the user only once `/v1/me` exists (guard with a feature check: if the schema lacks it, omit).
- Auth: any 401 from the API → client-side redirect to `/auth/login?next=<current path>` (the login page is built in FE-010).

## Scope
### In scope (`web/src/**`, `web/tests/**`) — do NOT edit `middleware.ts`/`proxy.ts`, `src/app/auth/**`, or `web/openapi.json`/`schema.d.ts`
- Shared utilities (FE-010 and later pages reuse them): `src/lib/api/errors.ts` (error code → message map for M1 codes; `fieldErrors(err)` from `details.fields`), `src/lib/api/queries.ts` (query keys + hooks: `useOrgs`, `useOrg`, `useWorkspaces`, `useWorkspace`, `useResolve`, `useAgents`), `src/lib/auth/use-unauthorized-redirect.ts`.
- Routes: `/` (client: list orgs → redirect to `/o/<first org slug>/w/<default or first workspace slug>`; no orgs → empty state with "Create organization" (POST `/v1/orgs`; on 403 `org_creation_forbidden` explain an instance admin must create it)); `/o/[org]` (workspaces list + "New workspace" dialog: name, optional slug, timezone select (IANA list via `Intl.supportedValuesOf('timeZone')`), memory language select (`english`, `german`, `french`, `spanish`, `italian`, `simple`, …)); `/o/[org]/w/[ws]` (overview: agents list with name, handle, kind, default badge; first-run checklist placeholder text from `14`: "store an LLM key → grant it to Daneel → say hello" (steps not yet linked)).
- Layout: header with org switcher, workspace switcher, user menu (logout); sidebar for workspace sections (only Overview active; others rendered as disabled items with "coming soon" — no dead links). Loading, error and empty states for every query. Keyboard-accessible dialogs/menus (use Radix primitives already present or add `@radix-ui/react-dialog`/`dropdown-menu` — report additions).
- vitest tests: org redirect logic (pure function), agents list rendering (mock data), create-workspace form validation and error display.

### Out of scope
- Auth pages, security headers (FE-010); members/invitations/keys/settings pages (FE-012/013).
