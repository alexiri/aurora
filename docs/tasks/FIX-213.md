# FIX-213: Pause, export, import and delete get their own Settings page (owner 2026-11-21)

## Why

The owner: "Export and import, pause and delete are at the bottom of EVERY agent settings page. This is ridiculous, move
them to their own page and add a menu item for it."

`web/src/components/agents/settings-shell.tsx` (`SettingsShell`, P5-REFINE-11, D-408) renders, under whichever Settings
page is open (Instructions, Apps & access, Memory, Skills, Tests, Other agents), the `extra` slot (`AgentExportImport`,
P5-REFINE-19, Expert: **Export <Agent>…**, **Import into <Agent>…**) and a `DangerZone id="agent-danger"` "Pause or
delete" (**Pause <Agent>** / **Resume <Agent>**, **Delete <Agent>…**) for workspace owners. So six pages end with the
same block.

## Decision

**D-447** (owner, 2026-11-21; amends D-408's Settings frame): an agent's Settings has a page **Manage** (the last entry of
the Settings sub-nav, lead "Pause, export, import or delete <Agent>"), shown to the people who may use at least one of
its actions (workspace owners today). It holds, in this order: **Pause** (or the paused state with **Resume**), **Export
and import** (Expert, hosted agents only, as today), and **Delete** in the danger style. No other Settings page shows
them. The paused banner under the agent header stays (D-407).

## Change (web only; no API or contract change)

1. **`sections.ts`**: a new `AgentPageId` `"manage"` in the `settings` section's pages after `peers`; `PAGE_LABEL.manage =
   "Manage"`, `SETTINGS_LEAD.manage = "Pause, export, import or delete"` (the shell shows it under the title; add the
   agent's name if the lead is built per agent elsewhere). Availability: owners only (the role is not in
   `PageAvailability` today: add what is needed, or filter the page list where `canOwn` is known in `agent-page.tsx`), for
   hosted **and** BYO agents (BYO: Pause and Delete only, no Export/Import, as today). A non-owner who opens
   `?tab=manage` lands on the default page (`resolvePage`).
2. **`settings-shell.tsx`**: remove the `extra` slot and the danger zone from the frame. Move them into a `ManagePage`
   component (`components/agents/manage-page.tsx`): three sections in the page's card style (`Section`/`DangerZone` from
   `ui/section.tsx`): **Pause** (the existing `AgentFreeze`/`ResumeButton` logic, unchanged, with its sentence),
   **Export and import** (`AgentExportImport`, inside `Altitude id="export.agent"` as today), **Delete** (`DangerZone
   id="agent-danger"` with the existing **Delete <Agent>…** that opens `DeleteAgentDialog`). Keep the `id`s so anchors and
   tests can find them.
3. **`agent-page.tsx`**: render `ManagePage` for `tab === "manage"`; stop passing `extra` and `onDelete` to the shell
   (pass what `ManagePage` needs instead).
4. **Links into the old place**: the command palette (`lib/palette-registry.ts:113–117`: Export, Import, Pause, Resume
   open `{ tab: "instructions" }` / `#agent-danger`) now open `{ tab: "manage" }` (and `#agent-danger` there for Delete if
   anything links to it). Search for other links (`agent-danger`, `tab: "instructions"` used for pause/export, the
   paused banner's Resume, notices) and point them at Manage.
5. **docs/14** §Agent settings pages (P5-REFINE-12): the sub-nav list gains **Manage**; the frame no longer ends with the
   danger zone; §Expert speed's export/import location.

## Acceptance

- Instructions, Apps & access, Memory, Skills, Tests and Other agents end with their own content: no Export, Import, Pause
  or Delete under them.
- An owner sees **Manage** last in the Settings sub-nav (left column from `md`, segmented tabs on a phone); it shows
  Pause/Resume, Export and import (Expert, hosted only) and Delete, each working as before.
- A member or approver sees no Manage entry; `?tab=manage` lands on the default page.
- Palette Export/Import/Pause/Resume open Manage; a paused agent's Resume from Manage works at the right authority.
- Both themes; 390 px without horizontal scroll.
