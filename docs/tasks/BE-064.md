# BE-064: Attachments (API side)

## Goal
Inbound and outbound attachments on the control plane: BlobStore, conversation upload and download routes, binding to turns (already partly done), runner-plane attachment routes, `turn.deliver` attachment lists, transcript `attachment` events, and the pending sweep.

## Linked requirements
- `docs/10-agents-conversations.md` §Attachments (lines ~161–176)
- `docs/05-control-plane-api.md`: `POST /v1/conversations/{id}/attachments` (multipart, returns pending attachment), `GET /v1/attachments/{id}/content` (always `Content-Disposition: attachment`, `X-Content-Type-Options: nosniff`); background job "Attachment pending sweep (`ATTACH_PENDING_TTL`) hourly"
- `docs/16-wire-protocols.md` §W5: `POST /runner/attachments` (headers `X-Aurora-Sandbox`, `X-Aurora-Boot`, `X-Aurora-Conversation`, `X-Aurora-Turn`, `X-Aurora-Filename`, `X-Aurora-Caption?`; body = bytes → `{ attachment_id }`), `GET /runner/attachments/{id}` ("only attachments bound to turns delivered to this runner's sandboxes"); `turn.deliver.attachments: [{ attachment_id, filename, size }]`
- Decision **S-11** (`docs/90-decisions.md`): the runner fetches inbound bytes and pushes them over W6. That is RUN-005, not this task.
- `04 §Permission matrix`: upload and read need `can_use` on the conversation's workspace (and the conversation must be visible to the caller: direct conversations are only visible to their user). Unseen → 404.
- Limits in `crates/aurora-core/src/limits.rs`: `ATTACH_IN_FILE_MAX`, `ATTACH_IN_COUNT`, `ATTACH_OUT_FILE_MAX`, `ATTACH_OUT_COUNT` (per turn), `ATTACH_OUT_DAILY_PER_CONVERSATION`, `ATTACH_CAPTION_MAX`, `ATTACH_PENDING_TTL`.
- Schema: `attachments` and `blobs` tables (`crates/aurora-db/migrations/20261105000006_conversations.sql`). No migration is expected; if one is needed, stop and ask.

## Scope
### In scope
- `BlobStore` trait (`put`, `get`, `delete`) + `postgres` backend over `blobs` (key = random UUID string). Place it in `aurora-db` (repo module) or `aurora-api` following existing layering; `attachments.blob_backend = "postgres"`.
- `POST /v1/conversations/{id}/attachments`:
  - multipart with one `file` part
  - enforce the size limit while streaming (413 `payload_too_large`, no buffering beyond the limit)
  - sanitize the filename to `[A-Za-z0-9._-]`, ≤ 128 chars (empty → `file`)
  - content_type from the part, defaulting to `application/octet-stream`; sha256 hex
  - status `pending`, `direction in`, `created_by_user_id`
  - response: an `Attachment` DTO (id, filename, content_type, size_bytes, status, created_at, caption?)
  - axum's default body limit must be raised only for this route
- `GET /v1/attachments/{id}/content`: `can_use` plus conversation visibility; headers `Content-Disposition: attachment; filename="<sanitized>"`, `X-Content-Type-Options: nosniff`, and `Content-Type: application/octet-stream` (never echo a stored HTML/SVG type inline).
- `GET /runner/attachments/{id}`: only when the attachment is `bound` and its turn was delivered to a sandbox owned by the calling runner. Otherwise 404.
- `POST /runner/attachments` (outbound):
  - validate the sandbox and current boot against the runner, and check the conversation/turn belong to that sandbox's agent
  - enforce `ATTACH_OUT_FILE_MAX`, `ATTACH_OUT_COUNT` per turn and `ATTACH_OUT_DAILY_PER_CONVERSATION` (sum of `size_bytes` of `out` rows in the last 24 h). Use 413/429 error codes consistent with `16 §W5` error conventions, and check what the runner maps
  - store with `direction out`, `status bound`, `turn_id` set
  - append a durable `attachment` transcript event (id, filename, size, caption) to the conversation
  - return `{ attachment_id }`
- `turn.deliver.attachments` filled from the turn's bound inbound attachments.
- Hourly sweep job: delete `pending` rows older than `ATTACH_PENDING_TTL` and their blobs (idempotent; follow the existing jobs pattern in `services/aurora-api/src/jobs*` or wherever background jobs live).
- OpenAPI: register the new routes (utoipa), regenerate `web/openapi.json` (`UPDATE_OPENAPI=1` drift test) and `pnpm -C web gen:api`.
- Add the new routes to `services/aurora-api/tests/permission_matrix.rs` (rows only).
- Tests `services/aurora-api/tests/attachments.rs`:
  - upload, then bind via message, then appear in `turn.deliver`
  - oversize gives 413
  - more than `ATTACH_IN_COUNT` on one message gives 422
  - another user's direct conversation gives 404
  - download headers
  - runner GET by the wrong runner gives 404
  - outbound upload creates the event and enforces the caps
  - sweep removes expired pending rows and blobs
