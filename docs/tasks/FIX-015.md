# FIX-015: RFE-016 config keys and the DeltaBus perf script (phase-1 gap found by P2-DOCS-2)

## Problem
`docs/15 §Configuration` lists two **phase 1, RFE-016** keys:
- `events.delta_bus` (default `notify`; an unknown id fails startup);
- `events.delta_coalesce_ms` (default 100, range 100–500).

`docs/15 §Scaling` names `scripts/perf/delta_bus.sh` as "an acceptance item of the phase-1 task", to re-measure the `notify` DeltaBus throughput on the target Postgres.

P1-001 built the `DeltaBus` seam (`services/aurora-api/src/domains/conversations/bus.rs`, `aurora_db::bus::NotifyDeltaBus`) with the coalescer hard-coded at 100 ms / 2 000 chars. But `crates/aurora-config` has **no `[events]` section**: setting either key fails startup (`deny_unknown_fields`), and the script doesn't exist. Found by P2-DOCS-2 while cross-checking `docs/15` against the code.

## Scope
1. **Config:** `[events]` with `delta_bus` (string, default `notify`; any other value fails startup with the key named, since `notify` is the only implementation) and `delta_coalesce_ms` (u32, default 100, validated 100–500). Scope: api. A config test covers the default, a valid value, both out-of-range ends and an unknown bus id.
2. **Wiring:** the API selects the bus by `events.delta_bus` and passes `delta_coalesce_ms` to the coalescer in place of the constant. The 2 000-char flush threshold stays as it is (`docs/15` doesn't make it configurable). A test proves a non-default window is honoured. Adapt `deltas_flow_through_an_injected_bus_coalesced_and_ordered` or add a sibling test.
3. **Perf script:** `scripts/perf/delta_bus.sh`, modelled on `scripts/perf/gateway.sh`. It measures `notify` delta publish → receive throughput and latency on the dev Postgres, against a throwaway database or schema, never the shared tables. Read the numbers `docs/15` gives and compare with them; the script prints the results and a PASS/WARN against those planning numbers, without hard-failing on a slow machine. Document how to run it in `docs/15` (one line) and `docs/operator/limits-and-approvals.md` or the page P2-DOCS-2 created for scaling, if one fits.
4. Add the keys to the operator docs page that lists event or streaming settings, if P2-DOCS-2 created one; otherwise add a short section to `docs/operator/limits-and-approvals.md`.

## Constraints
- **Owns:** `crates/aurora-config` (the section), `services/aurora-api/src/domains/conversations/bus.rs` and wherever the bus is constructed (`app.rs`), `scripts/perf/delta_bus.sh`, the doc lines named.
- No migration. No change to the delta wire format.
- Decision **D-106** only if needed.
