# FIX-194: A form field can name the connection (`store: label`), and every package whose connections have no name of their own uses it

## Goal
Owner, 2026-11-20 (D-420). The agent tells an app's accounts apart only by the connection's **label**: it is
the name in `guide.md` §Accounts, `tools.md`, `api.json` and the 409 `multiple_connections` choices (`24 §5`,
`06` step 6). A connection gets its label from the connect probe (`probe.label`), else from a hook, else on a
reconnect from the connection it replaces, else it is the **app's name**
(`domains/connect/service.rs` ~585).

So every connection of a `fields` app without a probe label is called the same thing. The owner hit it
with the `cern-rotas` addon: two rotas, both "CERN Rota". The agent had to guess which was which. A person
can rename a connection afterwards, but the connect form never asks.

Three builtin apps avoid this with **hard-coded** rules: the form field called `name` becomes the label.
- ICS calendar and outgoing webhook (secret links): `domains/connect/service/link.rs:145` and `:229`.
- CalDAV: `service/own_server.rs:398`. It falls back to `<username> at <host>`.
- An ordinary `fields` app cannot do the same.

The owner chose to make that rule part of the package format instead of exposing other connection fields to
the agent (D-420): the label already reaches the agent everywhere, and nothing else needs to.

## Change
1. **Package format (`crates/aurora-registry`).** `fields[].store` gains **`label`** (`Store::Label`). The value
   becomes the connection's label. It is not stored in metadata or credentials. Linter rules, each with its own
   code:
   - only in a `kind: fields` method (`label_field_method`; `oauth2` fields stay `metadata | tenant_host`);
   - at most one per method (`label_field_duplicate`);
   - `type: text` only (`label_field_type`).
   - The field's name needs no `metadata` declaration.
   - Additive in contract 1. A core that does not know it rejects the package (unknown variant), as for
     earlier additions.
   - Presentation only: adding, changing or removing a label field **widens nothing** (`widens()` ignores
     it).
   - Registry ITs cover each refusal and a valid manifest.
2. **Connect (`services/aurora-api/src/domains/connect/**`).**
   - **Gathering** (`fields.rs`): a `store: label` value goes into `Parsed`/`Gathered` as the label. It is
     checked with the rename's rule, `aurora_core::names::clean(v, 120)` (`connections/service.rs`
     `LABEL_MAX`, C-1041(b)). A failure is the usual field error on `/fields/<name>` (422), and nothing is
     stored.
   - **New connection:** the label is the label field when it is non-empty, else the probe's label, else
     the hook's, else the app's name.
   - **Reconnect:** a non-empty label field replaces the label. An empty one keeps the connection's current
     label (today's reconnect rule).
   - **Remove the hard-coded `name` rules** in `link.rs` (both places) and `own_server.rs`. ICS, webhook and
     CalDAV get their label from the generic field instead (step 4). CalDAV keeps its fallback
     `<username> at <host>` when no name is given.
   - **Behaviour change for ICS, CalDAV and webhook names:** they used to go through `probe::clean_label`
     only (control characters dropped, cut at 120 characters). Now they get the rename's rule, so an
     invisible formatting character is refused instead of stored. Say so in the Completion report.
   - **`FormField.store`** (`apps/dto.rs`, the connect plan): document `label`; regenerate OpenAPI and
     `web/src/lib/api/schema.d.ts`.
3. **Web.**
   - The connect form shows a label field like any text field. Expect no change; check it.
   - **Reconnect** ("Sign in again", Replace): prefill the label field with the connection's current name.
     A required field then needs no retyping, and the person sees the name they will keep.
   - If the shared form cannot prefill, say so in the Completion report. The API rule "empty keeps the
     name" still holds, but a `required` field would then force retyping.
   - Vitest for the prefill.
4. **Builtin packages.** Bump each version.
   - **Moved onto the rule.** The `name` field becomes `store: label`, and `name` is dropped from
     `metadata` (nothing reads the stored `metadata.name`; existing rows keep it, unused):
     - `ics-calendar` 1.1.0 → 1.2.0;
     - `caldav` 1.2.0 → 1.3.0;
     - `webhook` 1.0.0 → 1.1.0.
   - **New optional `name` field** (`store: label`, `type: text`, label "Name") on every `fields` method:
     - `aws-keys` 2.2.0 → 2.3.0, placeholder e.g. "Production account";
     - `sentry` 2.2.0 → 2.3.0, e.g. "Sentry EU, team X";
     - `postgresql` 1.3.0 → 1.4.0, e.g. "Prod DB (eu)". Its help says the name also names the agent's
       `psql` service (C-231, `pgservice::service_base`: "Prod DB (eu)" → `prod-db-eu`).
     - Leaving the field empty gives today's label.
   - **Not changed:**
     - apps whose probe names the account: github, github-ghes, gitlab, jira-dc, confluence-dc, indico;
     - OAuth methods;
     - credential-free apps with no form.
   - Update each changed package's `docs/setup.md` where it describes the form. Run `aurora plugin test` on
     each changed package.
5. **Docs.**
   - `09 §3.4` `fields`: the `store` list, a paragraph on `label` (rules, precedence, reconnect).
   - `09 §6`: the three linter codes.
   - `14`: the connect form's reconnect prefill.
   - `API_CONTRACTS`: C-1091, already written; amend it if the implementation must differ, and say why.
6. **Follow-up outside this repository (not the lane).** The addon `cern-rotas` (alexiri/aurora-addons-cern)
   0.2.0 adds a required "Rota name" field with `store: label`, and drops the "rename the connection" step
   from its setup guide and `connect_note`.
   - The owner's session releases it once the owner's instance runs a core with this change.
   - The core has no release numbering yet (every package declares `min_core: 0.1.0`), so `min_core` cannot
     express the dependency.
   - The lane only reports the merge commit.
