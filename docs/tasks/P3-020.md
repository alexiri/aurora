# P3-020: Workspace-tier skills (RFE-020, D-64, SEC-56)

## Goal
Implement workspace-tier skills: skills that belong to one workspace and sit between org skills and agent skills. That means the migration, routes, precedence and shadowing, the read-only projection into sandboxes, the tool effective set, and the dashboard. **SEC-56** must be proven.

The routes and shapes are in `docs/API_CONTRACTS.md`, API-P3's RFE-020 entries (C-330..C-339). Read them first. If one is missing, or contradicts the spec below, ask through Orca `ask`; don't invent a route.

## Scope
1. **Migration:** the additive `skills.workspace_id` column (nullable FK, the constraints the spec names). Move the `docs/03` row and keep `extract-schema --check` and `schema_matches_spec` green.
2. **API:**
   - workspace skill CRUD and the effective-set route per the contracts;
   - authorization per the access law (`04`), with permission-matrix rows added;
   - precedence and shadowing (agent > workspace > org, or as the spec says);
   - audit rows. Check whether a skill change is in `SECURITY_CRITICAL_ACTIONS`; if the spec makes it critical, use `audit::commit_critical`.
3. **Home sync / render inputs:** the read-only projection of workspace skills into the sandbox, and the supervisor's `skill_list` / `skill_get` reflecting the effective set.
4. **Dashboard:**
   - the agent Skills tab shows the effective set with its source and shadowing;
   - a workspace skills page;
   - the org note.
   It follows `14 §Visual design` and P2-UI-4's guards.
5. **Tests:**
   - every item of the `18` list; the permission matrix (0 inconclusive);
   - the `hosted.sh` skill scenario if `18` names one (use your own `AURORA_E2EH_*` prefix);
   - vitest for the UI;
   - SEC-56 → proven in `docs/tests/security-coverage.md`.
