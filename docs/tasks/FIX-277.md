# FIX-277: an emergency reader reaches the workspace's agents; the Memory review's three rough edges (P5-MEMORY-5 pass 1, 2026-11-27)

## Why

P5-MEMORY-5 pass 1 (`docs/design/skills-memory/verify/MEMORY-REPORT-pass1.md`) checked the Memory pages on a live stack:
17 rows Match, 3 Minor difference, 1 Needs changes. Its change list is the source of truth for this brief; read C-1..C-4
there with their captures.

1. **C-1, broken (FIX-235/FIX-236, emergency access).**
   - `web/src/app/o/[org]/w/[ws]/layout.tsx` sends a visitor to the workspace's manage page whenever
     `my_role == null && administers === true`.
   - The real API answers an organization owner who holds an **active emergency grant** with
     `my_role: null, administers: true, emergency_reader: true`. So every page under `/o/<org>/w/<ws>` (agents,
     Memory, Instructions, Skills, chats, Activity) lands on the manage page, and the emergency read access is
     unusable in the dashboard.
   - The manage page still offers "In an emergency you can open read access" while the access is open.
   - Tests pass only because `web/e2e/fix-236.spec.ts` mocks the reader with `administers: false`, which the real API
     never sends for that person.
2. **C-2, rough (P5-MEMORY-2).**
   - `web/src/lib/memory-key.ts` `memoryName()` names an untitled memory by its first line, but removes only leading
     `#`.
   - A memory starting with a list item, emphasis or code shows those marks as its name: in the list, the reading
     view, History's subtitle, the leave dialog and the Name sort.
3. **C-3, rough (shared Markdown CSS).** `web/src/app/globals.css` `.md ul.contains-task-list` takes the bullet off every
   item of a list that mixes ordinary and checklist items, so ordinary items read as an indented paragraph.
4. **C-4, rough (P5-MEMORY-3).** With `wrap`, `web/src/components/ui/diff-view.tsx` `LineRow` continues a wrapped line
   under the `+`/`-` mark instead of under its text. A long word with no spaces leaves the mark alone on the first
   line.

## Change

1. **C-1:**
   - The workspace layout never redirects while `emergency_reader === true`. The reader stays on the page they asked
     for, which already renders read-only.
   - The manage page doesn't offer to open emergency access while it is open; it says that it is open and until when,
     in the words the emergency pages already use.
   - Search `web/src` for every other place that picks the manage page, or hides workspace content, from `administers`
     alone, and make each one honour `emergency_reader` the same way.
   - Fix the mock in `fix-236.spec.ts` (and every other mock of an emergency reader) to the real shape
     (`administers: true`).
2. **C-2:** `memoryName()` names an untitled memory by its first line as plain text, as search snippets already do:
   - no list, task-list, quote or heading marks;
   - no emphasis or code marks;
   - a link shown by its text;
   - underscores inside a word stay.

   Example: `- *API latency*: `` `platform/api-overview` `` — p50/p95 by route.` becomes "API latency:
   platform/api-overview — p50/p95 by route."
3. **C-3:** checklist items keep the box and no bullet; ordinary items in the same list keep their bullet and indent.
   It applies wherever `Markdown` renders.
4. **C-4:** with `wrap`, a hanging indent: continuations align with the text after the mark, and a long word starts on
   the mark's line and breaks where it must. Callers without `wrap` are unchanged.

### Security notes (C-1)

- The only widening is that the layout stops redirecting when the server says `emergency_reader: true`. The server
  computes that flag per request, for sessions only, from the active grant and the holder still being an org owner.
- No new request, route, link, button or datum. What the pages show is still decided by the server (`ReadAuth`;
  every write refused) and by the existing `emergency_reader` read-only views.
- The two added waits only narrow: nothing writable is drawn, and no versions are asked for, before the flag is known.
  If the workspace request fails, the agent page renders as before and the server still refuses.
- When a grant ends or expires, the redirect comes back with the next workspace answer; this change adds no polling.

### Left open (not changed)

- The organization's Overview and Agents lists still send the reader to the manage page (they go by `my_role`): the
  list answers don't carry `emergency_reader` (only `GET /v1/workspaces/{ws}` does), and the manage page has no link
  into the workspace. While access is open the reader gets in right after opening, or by the workspace address. A link
  on the manage page would be a small follow-up.
