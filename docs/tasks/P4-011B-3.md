# P4-011B-3: Web Push backend — VAPID, subscriptions, delivery, chart — **large, phase 5**

## Goal
Let an opted-in decider's browser be notified when an approval waits and no Aurora tab is open:
the API keeps an instance VAPID key, stores per-browser subscriptions bound to the registering
session, and sends end-to-end encrypted, fixed-field pushes through the destination guard to
allow-listed push services only. Includes the test kit's mock push service, the CLI, the Helm
values and NetworkPolicy. The service worker and the Account UI are P4-011B-4.

   RFC 8292 vectors.
8. **Helm** (C-837, `23`): `push.enabled` (mirrors `config.push.enabled`, renders the api egress

## Acceptance criteria (each new test seen failing first)
1. Unit: RFC 8291 Appendix A and RFC 8292 vectors; payload builder never emits a field outside
   C-832 and stays ≤ 1 KiB with maximal names; `Topic` differs per subscription for one approval
   and never contains the approval id.
2. `api/it/web_push.rs` (mock push service via `push.dev_endpoint_overrides`): the mock verifies the
   JWT and decrypts; **canary test** over title, summary fields, rule, host, path, query, body —
   absent with and without `show_details`; route validation, limits, ownership 404, session-only,
   `push_unavailable` when off, `push_key_stale`; move between two users; `rebind: true` by the
   owner re-binds (200), by another person 404 and nothing moves.
3. Delivery rules: decider at send time (lost `can_approve`, direct-conversation visibility, group
   access), live watcher suppresses, revoked/expired session stops delivery, sign-out /
   sign-out-others / admin revocation / deactivation delete rows, decided/expired/frozen before the
   delay sends nothing, two replicas claim once, batch folds, hourly cap then digest, e-mail path
   unaffected, parked reminder once.
4. Failures: 404/410 delete; 429/5xx retry bound; five failures disable; `rejected_host` after an
   allow-list change.
5. `api/it/web_push_ssrf.rs`: registration refusals (http, userinfo, IP literal, private, look-alike,
   too long); a send to a host that now resolves privately, a redirect, a slow or oversized answer —
   refused or bounded; startup refuses an empty/invalid allow-list and `dev_endpoint_overrides`
   with a non-loopback target or external URL; `push.enabled = false` → no outbound call.
6. Keys: concurrent first start yields one key; sealed rows name the `inline` store with a Vault
   default store (the Vault mock sees no call); secret scan of responses, logs and audit; rotation
   (old-key subscribers delivered, `push_key_stale`, destruction after `PUSH_VAPID_RETIRE` or when
   unreferenced); operator-key mode (`rotate-vapid` exits 3).
7. Chart: renders with `push.enabled` on and off; empty `egressTo` fails the render; mirroring
   rule; `bash scripts/guards/run-all.sh` exit 0.
8. fmt, clippy, targeted tests, `extract-schema.py --check`, OpenAPI regenerated.
