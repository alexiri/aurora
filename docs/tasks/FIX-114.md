# FIX-114: Supervisor — reap orphans as PID 1, bound what it reads and runs, honest transport and wording (REVIEW-5 SUP-2..SUP-9) — **medium**

## Problem
1. **No child reaping.** The supervisor is PID 1 in the sandbox (`services/aurora-runner/src/backends/podman.rs` ~280, `init: false`); `docs/12` §Process model: "Runs as PID 1 (uid 1000), reaps children, forwards SIGTERM to process groups". There is no SIGCHLD handler or `waitpid` in `services/aurora-supervisor/src/`; tokio reaps only the children it spawned. Orphans reparented to PID 1 — tool subprocesses of an aborted turn (`adapters/claude_code/launcher.rs` kills only the harness), `sh -c 'server &'` from `process_start` — stay zombies and consume the sandbox's 512 pids until spawns fail with EAGAIN and every turn ends `harness_failed`. SIGTERM is not forwarded to process groups at shutdown.
2. **Unbounded reads of agent-writable files.** Every 10 s the harvest reads each `memory/*.md` whole before checking its size (`harvest.rs` ~177, ~203); `tools.json`, `render_inputs.json` and staged manifests are read whole (`tools.rs` ~255; `home.rs` ~243, ~256, ~388): a multi-gigabyte file kills the supervisor on the memory limit.
3. **Unbounded bookkeeping and concurrency.** Exited process records are never removed and the `max_running` check is check-then-act (`process.rs` ~345–369); the tools socket and MCP bridge spawn a task per request line with no cap, and the bridge reads lines of any length (`tools.rs` ~534–562; `mcp_bridge.rs` ~146–162).
4. **`wss://` runner URLs are accepted and cannot be dialled** (`boot.rs` ~141; the workspace builds `tokio-tungstenite` without a TLS feature). The supervisor↔runner channel is cleartext inside the cluster, carrying the bootstrap token and session proof; `docs/17` records plaintext only for preview streams.
5. **Secret filter gaps.** The child-environment filter blocks values with the `aub_`/`aup_` prefixes and names ending `_TOKEN`, `_SECRET`, `_PASSWORD`, `_KEY`, `_CREDENTIALS` (`spawn.rs` ~23–26); `DATABASE_URL`, `*_DSN`, `*_PASS`, `*_PWD`, `*_AUTH`, `*_APIKEY`, `*_CREDENTIAL` and the other platform token prefixes pass. `Credential` and `DbTurns` derive `Debug` over the boot token (`proxy.rs` ~24; `pgrelay.rs` ~40).
6. **Wording.** `docs/12` says the supervisor "scrubs the variable from its environment"; it cannot (it relies on being non-dumpable, `boot.rs` ~3–6). `/run/aurora` is owned by the agent's uid, so the agent can replace `ca.pem` and `tools.sock` (`podman.rs` ~41; the supervisor's own trust stays in memory) — an accepted consequence of the shared uid that no document states.

## Linked requirements
- `docs/12` §Process model, §Platform tools; `docs/11` (pids limit); `docs/16` §W6; `docs/17` SEC-01, SEC-25, SEC-34 and §residual risks.

## Spec change (apply with the fix)
- `docs/12` §Process model item 2: "reads `AURORA_BOOT`, makes the process non-dumpable so `/proc/<pid>/environ` is unreadable to the agent, and never passes the variable to a child".
- `docs/17` residual risks: the W6 hop is cleartext inside the cluster network (bootstrap token single-use, session proof boot-bound); `/run/aurora` is writable by agent code, which can therefore redirect its own processes' trust and tool socket but not the supervisor's.
- `docs/16` §W6: `ws://` only until TLS is implemented.

## Scope
- SIGCHLD loop reaping pids not owned by a tokio `Child`; SIGTERM forwarded to registered process groups on shutdown.
- Bounded reads (`take(limit + 1)`) with a notice for oversized files; bounded `list` responses.
- Process table: slot reserved under the same lock as the check; exited records capped; per-session in-flight cap on tool calls (`tools_unavailable` above it); line-length bound in the bridge.
- `wss://` refused at boot with a clear error (or TLS enabled and verified against the boot CA — only if small).
- Filter extended to every platform token prefix and the listed names; manual `Debug` printing `[redacted]`.
