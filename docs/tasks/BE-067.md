# BE-067: Agent avatars (SEC-30): upload, re-encode, public serving, presence icon sync

## Goal
Implement agent avatars as specified, closing the last open SEC-30 half ("avatars are re-encoded").

## Linked requirements
- `docs/10-agents-conversations.md` agent fields: `avatar` is PNG/JPEG/WebP ≤ `AVATAR_MAX` (512 KiB, `aurora_core::limits`), re-encoded to PNG 256×256 by the API, and served publicly only at `/v1/public/avatars/{avatar_public_key}`, rotated on change, so chat platforms can fetch it.
- `docs/05-control-plane-api.md`:
  - `PUT/GET /v1/agents/{agent}/avatar` (S/K; `can_use` per 04 "Create/edit/delete agents, brief, model, avatar")
  - `GET /v1/public/avatars/{key}` (P: a public capability)
- `docs/03` agents columns `avatar_blob_key`, `avatar_public_key` (exist; no migration).
- `docs/17` SEC-30.
- `docs/13` §5.7: avatar changes enqueue `presence.set_icon` ops for the agent's dedicated presences (BE-074 left it unwired). The connector config feed's `Presence.agent.avatar_url` (`connectors/plane.rs` ~330, currently `None`) must carry the public URL.
- `docs/14` Instructions tab: avatar upload/preview/remove.

## Scope
### In scope
1. **Image handling**:
   - Add the `image` crate with **only** the png, jpeg and webp decoders and the png encoder (`default-features = false`). Record it in `docs/90-decisions.md` (I-31) with the reason, and keep `cargo deny check` green.
   - Decode with explicit limits: `image::Limits` with max width/height, e.g. 4096×4096, and a max allocation, e.g. 64 MiB, so decompression bombs are refused.
   - Resize to cover-crop 256×256, then encode a fresh PNG. All metadata (EXIF, text chunks, ICC) is dropped by construction, so the original bytes are never stored or served.
   - Sniff the type from the bytes, not from the client's Content-Type. Reject anything else with 422 `avatar_invalid`; over `AVATAR_MAX` gives 413.
2. **Routes**:
   - `PUT /v1/agents/{agent}/avatar`: raw body or multipart (pick one and record it as contract C-41 in `docs/API_CONTRACTS.md`). It stores the PNG via the BE-064 BlobStore, rotates `avatar_public_key` (a random URL-safe token, ≥ 128 bits), and deletes the previous blob.
   - `DELETE` to remove the avatar, if you add it (record that in C-41 too).
   - `GET /v1/agents/{agent}/avatar`: authenticated, returns the PNG.
   - `GET /v1/public/avatars/{key}`: unauthenticated. It serves only by a current key (old keys give 404), with `Content-Type: image/png`, `nosniff` and cache headers. An unknown key gives 404 with no oracle.
   - Expose `avatar_url` (the public URL, or null) in the Agent DTO.
   - Regenerate the OpenAPI + web schema, and add matrix rows (the public route goes in EXEMPT with a reason).
3. **Presence sync**: on change, enqueue `presence.set_icon` for active dedicated presences, and fill `avatar_url` in the config feed.
4. **Web**: avatar upload/preview/remove in the agent Instructions tab; show avatars in the agents list. Use the generated client and the existing form patterns.
5. **Tests**:
   - PNG, JPEG and WebP uploads are re-encoded to 256×256 PNG.
   - A polyglot/EXIF-laden upload is served as clean PNG bytes: the output decodes, is a fresh encode and contains none of the input's trailing bytes or metadata markers.
   - Oversize gives 413; a non-image or SVG gives 422.
   - A dimension bomb is refused under the limits.
   - The public key rotates and the old key gives 404.
   - The public GET carries nosniff.
   - The permission matrix passes.
   - `presence.set_icon` is enqueued.
   - Web vitest for the upload UI.
   - Update `docs/tests/security-coverage.md` SEC-30 to "proven".

### Out of scope
- User avatars, and avatar moderation.
