# FIX-207: One place to call a webhook from, with an address that works (owner 2026-11-21)

## Why

The owner, on an agent's Automations with a webhook's **How to call it** open: "why is there a separate 'From your
terminal' box outside of the 'How to call it' part?"

Today the same thing is offered three times, and two of them disagree:

1. **How to call it** on the webhook card (`components/automations/webhook-howto.tsx`, `HowToCall`, from
   `webhook-row.tsx:179` with `url={`${w.url_prefix}…`}`): curl/Python/Node tabs from `lib/webhook-snippets.ts`
   (`webhookSnippet`). Its curl reads `curl -X POST auw_9xLPEkbX… …`: `url_prefix` is the **token's display prefix**
   (`services/aurora-api/src/domains/webhooks/dto.rs:58`), not an address, so the command is not even a URL. The real
   address is `<origin>/v1/hooks/<auw_token>` (`domains/webhooks/receive.rs`), shown once at creation or rotation.
2. **Copy as curl** on the same card (`webhook-row.tsx:151`, P5-REFINE-19, Expert): a second generator,
   `webhookCurl` in `lib/copy-as-curl.ts`, with `prefixOnly`.
3. **From your terminal** below the whole list (`automations-tab.tsx:229–240`, `FromYourTerminal`, `fold.cli`, Expert): a
   generic signed call with `"$WEBHOOK_URL"` and `$SECRET`, not tied to any webhook, whose note says "A card's Copy as curl
   does the same".

## Change (web only; no API, contract or decision change)

1. **One generator.** `lib/webhook-snippets.ts` is the only place a webhook call is written (curl, Python, Node, for
   `none`, `bearer` and `hmac_sha256`, with the webhook's header). `copy-as-curl.ts`'s `webhookCurl` calls it (or goes,
   if nothing else uses it).
2. **A command that runs.** Snippets address the webhook as `"$WEBHOOK_URL"` (Python/Node: the `WEBHOOK_URL` environment
   variable), exactly like the secret is `$SECRET`. Above the command, one comment line names where it comes from:
   `# WEBHOOK_URL is the address shown when you created it: <origin>/v1/hooks/auw_9xLPEkbX…` (the origin from
   `window.location.origin` as the other copy helpers do, the token prefix from `url_prefix`). Right after a reveal
   (creation or rotation, `onReveal` with the full `url`), the reveal dialog's snippet uses the real address instead.
3. **One place on the page.** Remove the list-level **From your terminal** box for webhooks
   (`automations-tab.tsx:229–240`). Its signed variant is what **How to call it** shows for a signed webhook.
4. **Copy as curl** (card, Expert) copies the same curl text **How to call it** shows for that webhook (one call to the
   generator), so the two can never differ again.
5. Python and Node tabs follow the same rule (`WEBHOOK_URL` from the environment, the address comment).
6. `docs/14` §Automations (How to call a webhook) and the `fold.cli` row of §Altitudes / §Expert speed: say webhooks have
   no list-level terminal box; their command is on the card.

## Acceptance

- Automations with webhooks shows no "From your terminal" box; each card's **How to call it** is the one place, and its
  curl for a signed webhook signs the body and posts to `"$WEBHOOK_URL"` with the comment naming
  `<origin>/v1/hooks/auw_…`.
- Pasting the curl into a shell with `WEBHOOK_URL` and `SECRET` set delivers (a unit test runs the generated curl's
  signing line against the receiver's HMAC check vector, or compares with the existing signature test vector).
- **Copy as curl** copies byte-for-byte what How to call it shows in its curl tab.
- After creating or rotating, the reveal dialog's snippet uses the full address.

## Not in this fix

The receiver, tokens and secrets; other pages' **From your terminal** boxes (API keys, Computer).
