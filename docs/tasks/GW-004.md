# GW-004: Gateway approval holds + generic approval summary

## Goal
Replace GW-003's fail-closed `needs_approval` placeholder with real holds stored in Postgres, shared across gateway replicas.

## Linked requirements
- M2/06 `§Approval holds` (steps 1–5), `07 §Approvals (gateway holds)` (lifecycle, first decision wins — the decision itself is written by the API task BE-030), `§Batching` (`x-aurora-batch-*` stored), `05 §Event bus` (`aurora_approval` `{id, workspace_id, event}`), `02 §Limits` (`APPROVAL_TIMEOUT` 300 s config `approvals.timeout_secs`, `APPROVAL_BODY_PEEK` 16 KiB, `SUMMARY_LIMITS`), D-04, D-36; SEC-03 (credential selection/decryption only after approval), SEC-08 (approval-store failure ⇒ 503), SEC-18 (summary text sanitized), SEC-28 (expiry denies); `18 §Policy and gateway` hold tests (approve, deny, expiry, client disconnect, SIGTERM, two replicas with a decision written by "the API").

## Context
- Read `docs/06-gateway.md §Approval holds`, `docs/07-policy-approvals.md §Approvals (gateway holds)`, `docs/03-data-model.md` `approvals` table.
- Code: gateway `decide.rs` (where `needs_approval` currently returns 503 `approval_store_unavailable` with `TODO(GW-004)`), `invalidation.rs` (`Hub` owns the LISTEN connection — extend it to also listen on `aurora_approval` and fan decided/expired events out to waiters), `instance.rs` (gateway instance id), `repo/gateway.rs`.
- `ApprovalSummary` JSON shape (decision I-16, add it to `docs/90-decisions.md` is the orchestrator's job): `{ "title": string, "fields": [{"label": string, "value": string}], "text": string|null, "link": string|null, "group": string|null, "source": "template"|"hook"|"generic" }` — mirrors the WIT `summary` record (`09 §8.1`).

## Scope
### In scope
- `crates/aurora-summary/src/lib.rs`: `ApprovalSummary` (serde + clamp to `SUMMARY_LIMITS`: title 120, ≤12 fields, value 200, text 1 000 chars, all through `aurora_core::sanitize::one_line`/`block`), `generic(method, host, path, query, content_type, body_prefix, truncated) -> ApprovalSummary`: title `"<METHOD> <host><path>"` (path with query values masked like the request-log redactor), fields `Method`, `Host`, `Path`, and for JSON bodies up to 8 top-level keys with **values redacted** to their type/length (e.g. `string(42)`, `number`, `object(3 keys)`) — never raw values; non-JSON: `Body: <n> bytes (<content-type>)`; `truncated` noted. Templates/hooks are M3.
- Gateway `hold.rs`: on `needs_approval`: peek body ≤ `APPROVAL_BODY_PEEK` (already buffered by step 4 when a hold could occur), build generic summary, `INSERT approvals (... status 'pending', deadline = now() + timeout, gateway_instance_id, batch fields from Aurora headers ≤128 chars)` + `NOTIFY aurora_approval {id, workspace_id, event:"created"}`; insert failure ⇒ 503 `approval_store_unavailable`. Wait for `decided`/`expired` via the hub with a 2 s poll fallback reading the row. `approved` ⇒ continue the pipeline (credential selection already ids-only; injection happens after) ; `denied` ⇒ 403 `manual_approval_denied` (`details.approval_id`); deadline ⇒ `UPDATE … SET status='expired' WHERE id=$1 AND status='pending'` + NOTIFY `expired` ⇒ 403 `manual_approval_expired`; client disconnect ⇒ `abandoned`. SIGTERM ⇒ all holds answered 503 `gateway_restarting` (`retry-after: 1`) and marked `abandoned`. Request-log decisions `approved`/`approval_denied`/`approval_expired`.
- Open lane: unchanged (needs-approval refuses the CONNECT with 403).
- `repo::gateway`: `insert_approval`, `get_approval_status`, `expire_approval`, `abandon_approval(s)`.

### Out of scope
- API approvals routes/SSE/decision (BE-030), transcript events, channel cards (M6), summary templates/hooks (M3).

## Acceptance criteria
Tests (DB via testkit; a test helper plays "the API" by `UPDATE approvals SET status='approved'|'denied', decided_at=now() WHERE id=$1 AND status='pending'` + `NOTIFY aurora_approval {"event":"decided",…}`):
- [ ] require-approval rule ⇒ row `pending` with generic summary (no raw body values in `summary`), then approve ⇒ request reaches upstream with the injected credential; deny ⇒ 403 `manual_approval_denied`.
- [ ] Short configured timeout ⇒ `expired` + 403 `manual_approval_expired`.
- [ ] Client disconnect during hold ⇒ row `abandoned`.
- [ ] Decision without NOTIFY is picked up by the 2 s poll.
- [ ] Two gateway instances (two handler stacks in one test process) — decision for a hold on instance A wakes only A's waiter and A's response.
- [ ] Policy before decryption still holds: while pending, the secret store `get` count is 0.
- [ ] `aurora-summary` unit tests (clamping, sanitization, JSON redaction, non-JSON).
- [ ] `cargo test -p aurora-gateway -p aurora-summary -p aurora-db`, clippy, fmt.
