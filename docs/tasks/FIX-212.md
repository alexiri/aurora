# FIX-212: The agent's Settings pages use the width, and short fields share a line (owner 2026-11-21)

## Why

The owner, on an agent's **Settings › Instructions** at ~1630 px: "the Agent settings tab also wastes lots of horizontal
space, make it wider. When you have fields that don't need to be wider (like the model selector), consider consolidating
related things on one line."

The page is a 208 px sub-nav plus a form capped at 720 px (`web/src/components/agents/instructions-tab.tsx:179`, `<form
… className="max-w-180 …">`), so half the screen is empty while a 6-row Instructions box makes the agent's main text
scroll inside itself, and a model `<select>` stretches 680 px for a 20-character value. The same rule as D-439 (P5-LAYOUT-1)
applies: the page does not cap itself; text and short fields keep a sensible width.

No decision, contract or API change (D-439's rule applied to the agent settings frame).

## Change (web only)

1. **Instructions** (`instructions-tab.tsx`): remove `max-w-180`; the card fills the settings column (the space right of
   the sub-nav). Inside it, from `md`:
   - **Row 1, who it is:** the picture (avatar, **Change picture**, its hint) on the left, **Name** beside it filling the
     rest. On a phone they stack as today.
   - **Row 2, Instructions:** full width, taller: about 14 rows (it is the agent's main text), still resizable vertically;
     the hint under it as today.
   - **Row 3, how it runs:** **Model** at a fixed field width (about `w-80`, the longest model id readable; truncate with
     the full id in `title`) and **<Agent> may message you first** beside it, aligned with the select (the switch's label
     and hint to its left, as `SwitchField` draws them). They wrap to two lines below `md`.
   - **Advanced** (Expert): **Agent program** and **Effort** on one line, each at its own field width; any other short
     field in the fold joins that line where it fits. Notices and long fields stay full width.
   - The save bar unchanged.
2. **The other Settings pages** (`access-tab.tsx`, `MemoryTab`, `SkillsTab`, `evals/evals-tab.tsx`, `PeersTab`): check each
   at 1630 px. None may be capped narrower than the settings column; short controls that sit alone on a full-width line
   (a select, a number, a toggle) join a related neighbour on one line where it reads naturally. List what you changed per
   page; leave a page alone if it already uses the width well (lists and tables usually do).
3. **The frame** (`settings-shell.tsx`): the sub-nav keeps its width (`md:w-52`); the content column grows to the page's
   right edge (no max width). Anything below the pages that aligns with the content column keeps aligning (FIX-213 moves
   the danger zone away; whichever lands second rebases).
4. **Field widths** come from the existing width utilities (`w-80`, `max-w-xs`, `max-w-sm`…), never arbitrary values
   (`web/tests/arbitrary-values.test.ts`).
