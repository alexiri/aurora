# BE-003: Implement `aurora-crypto` (inline envelope, keyring, HKDF purposes, ed25519)

## Goal
The single implementation of Aurora's at-rest envelope and derived keys, shared by API and gateway.

## Linked requirements
- M0/08§3-4; SEC-11 (AAD binding); `18 §Secrets` (envelope fixtures, AAD row-swap attack, keyring rotation).

## Context (read only these)
- `docs/08-secrets-credentials.md` §3 (inline store) and §4 (HKDF purposes). Summary: keyring `AURORA_ENCRYPTION_KEYS` = `<key_id>:<base64 32 bytes>,…`, active id `AURORA_ENCRYPTION_ACTIVE_KEY`, ids `[a-z0-9]{1,16}`; format `inline:v1:<key_id>:<b64url(nonce[12] ‖ ciphertext ‖ tag[16])>`, random nonce per seal; AAD `aurora:v1:<purpose>:<org_id>:<owner_id>`; HKDF-SHA256(root=`AURORA_SIGNING_KEY`, info=`aurora:<purpose>:v1`) for purposes `oauth-state`, `oidc-state`, `action-token` (HMAC-SHA256), `avatar-key` (HMAC), `link-state`.
- `aurora-core` provides `Secret<T>` (use it for key material and plaintext). Libraries: `aws-lc-rs` (AES-256-GCM, HKDF, HMAC, SHA-256, rand), `ed25519-dalek`, `base64`.
- Do not edit the root `Cargo.toml`.

## Scope
### In scope (`crates/aurora-crypto/**`)
- `Keyring::parse(keys: &str, active: &str) -> Result<Keyring>`; `seal(&self, aad: &Aad, plaintext: &[u8]) -> String`; `open(&self, aad, s) -> Result<Secret<Vec<u8>>>`; `needs_rekey(s) -> bool` (sealed under non-active key); errors are typed, never reveal key material.
- `Aad { purpose: &str, org_id: Uuid, owner_id: Uuid }` rendering exactly `aurora:v1:<purpose>:<org_id>:<owner_id>` (lowercase hyphenated uuids).
- `DerivedKeys::new(signing_root: Secret<[u8;32]>)` with per-purpose AEAD seal/open (for state blobs; format: b64url(nonce‖ct‖tag), AAD caller-supplied) and HMAC sign/verify (constant-time verify).
- ed25519: `verify(public_key, message, signature)`, key/sig parsing from base64, `SigningKey` generation for tests/CLI.
- **Conformance fixture**: `crates/aurora-crypto/tests/fixtures/inline_v1.json` with a fixed keyring, AAD, plaintext, and a sealed string; test opens it (pins the wire format across versions).

### Out of scope
- `SecretStore` trait / SecretRef parsing (M2 `aurora-secrets`); rekey CLI.

## Acceptance criteria
- [ ] Round-trip seal/open; open with wrong purpose/org/owner fails (AAD row-swap test, SEC-11); tampered ciphertext fails; unknown key id fails; rotation: seal under k1, set active k2, old value opens, `needs_rekey` true.
- [ ] Fixture test passes; HKDF purposes produce distinct keys; HMAC verify rejects modified data.
- [ ] `cargo test -p aurora-crypto`, clippy `-D warnings`, fmt check pass.

## Dependencies
- Blocked by: BE-001. Unblocks: M1 (OIDC state), M2 secrets.
