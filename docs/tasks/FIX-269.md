# FIX-269: the template format crate: one path rule for zips and trees, strict semver, and the reference CI that fails loudly (AUDIT-2026-11-27)

## Why

The audit's template-pipeline area (`docs/audit/AUDIT-2026-11-27.md`) read `crates/aurora-template` (P6-TPL-1,
C-1104, C-1141), the version comparison (`aurora-registry`, commit 0582b553) and the reference repository
`templates/examples/` (P6-TPL-5, C-1144).

1. **A zip refuses paths the tree form accepts (medium).** `archive.rs` ~:140 runs `rel_path_problem(name)` on the
   **full** zip name, root included, while `validate.rs` ~:136 (`read_files`) runs it on the path **below** the root.
   So a zip allows one segment fewer and 255 characters including the root.
   - **Scenario:** `skills/x/a/b/c/f.txt` (a depth-4 skill path, which `path_ok` allows) is 6 segments below the
     root. `read_tree` and `aurora template pack` accept it; `read_archive` refuses it with "more than 6 segments".
     The check marks the version `invalid` with `template_archive`, and `aurora template check pkg.zip` fails on the
     zip `pack` has just written. A long path plus a 64-character id fails the same way on the length.
   - This breaks C-1104's promise that both forms give the same content.
2. **`.github` inside a zip is refused, not skipped (low).** `archive.rs` ~:149-152's skip is unreachable for
   `<id>/.github/…`, because the hidden-segment rule in `rel_path_problem` (~:140) refuses it first. The comments
   (~:137-152) and `docs/25` (~:82: "inside a template directory — Aurora skips it … never an error") say otherwise.
   The git path (`is_content`) and the CLI walk do skip it; only zips made by other tools are refused.
3. **The format accepts versions the comparison cannot order (low).** `meta.rs` ~:140-160 `semver_ok` /
   `core_semver` allow leading zeros (`1.02.0`, `1.0.0-rc.01`), which semver §2/§9 forbid.
   - The registry's `parse_core` refuses `1.02.0`, so `check.rs` ~:598 (`let Some(candidate) =
     parse_semver(&meta.version) else { continue; }`) skips that head silently, forever, while
     `aurora template check` prints `ok`.
   - `rc.01` parses as `Num(1)` and so equals a stored `rc.1` ("equal: ignored").
4. **The anchor/alias pre-check misses continuation lines of a flow collection (low).** `yaml.rs` ~:38 resets
   `flow` on every line, so `a: [x,\n  y, &z w]` and `[x,\n  y, *z]` pass. serde_yaml still caps alias expansion, so
   this bypasses the strictness rule, not a billion-laughs guard. The same logic is copied in
   `crates/aurora-registry/src/skill_format.rs`.
5. **The skill reference `ref` rule is looser than the platform's (low).** `meta.rs` ~:671-680 refuses only empty,
   over 200 characters, a leading `.` and `..`. A leading `-`, spaces, `|`, control and bidi characters pass,
   while a source `ref` goes through `aurora_registry::library::check_ref`. With `|` allowed,
   `skill_ref_key` (`hash.rs` ~:225) is ambiguous: ref `main|x` with no path gives the same key as ref `main` with
   path `x|`.
6. **Tests that can't catch a parse failure (cleanup).** `crates/aurora-registry/tests/it/semver_precedence.rs`
   ~:24-47 compares `Option<SemVer>`, and `None < Some(_)`, so a version that stopped parsing still passes every
   "is lower" assertion.
   - The drift test `the_copied_skill_rules_match_the_platform_validator`
     (`services/aurora-api/tests/it/agent_templates.rs` ~:6407) covers names, paths and constants, but not the other
     copies: `is_text` (`skill_rules.rs` ~:62, also used by `agent_helpers`), `clean_text` (`yaml.rs` ~:11) and the
     anchor heuristic.
7. **The reference CI (`templates/examples/`, copied into people's repositories) (low):**
   - `.github/aurora-publish.sh` ~:21: `aurora template list … | jq … | while …` under POSIX `sh` without pipefail.
     A failing `list` (a bad `template.yaml`, more than 100 templates) publishes nothing and exits 0.
   - `.github/workflows/aurora-templates.yml` downloads the `aurora` binary with `curl` and runs it without checking
     the `.sha256` the CLI release job publishes, in a job with `contents: write`.
   - These files are for template authors outside this repository, but they cite `docs/25 §…` and `C-1144`, which
     those authors can't open. Say the fact or link the published docs instead.

## Change

1. `read_archive`: `root_problem` first, then `rel_path_problem` on the path **below** the root, exactly as
   `read_files`. One helper used by both, so the two forms can't drift again.
2. Choose one rule for `.github` inside a zip: **skip it** after the root and `..`/absolute checks and before the
   hidden-segment rule. This matches the git path, the CLI and `docs/25`. Fix the comments.
3. `semver_ok`: refuse leading zeros in the core and in numeric pre-release identifiers. `check.rs` reports a head
   whose version doesn't parse as a template problem (`template_version`, in words) instead of `continue`.
4. `yaml.rs` (and the registry's copy): carry the flow depth across lines. Better: make one shared function in
   `aurora-core` or the registry that both call, and delete the copy.
5. Skill reference `ref`: call `aurora_registry::library::check_ref` (or the shared grammar it uses). Make
   `skill_ref_key` unambiguous (length-prefixed or with a separator the grammar forbids).
   - **The key is part of the content hash** (`hash.rs`). Changing it changes hashes: pin the new golden values, and
     say in the report whether any stored version's hash changes. If any can, keep the old key for stored contents
     and use the new one for new versions only, or stop and ask.
6. The tests: `parse_semver(x).unwrap()` in the precedence tests; the drift test gains `is_text`, `clean_text` and
   the anchor heuristic (one table each).
7. `templates/examples/`:
   - write the list to a file first, and fail on a non-zero exit;
   - pin the CLI's expected sha256 (a workflow variable) and run `sha256sum -c`;
   - replace internal references with plain sentences or the public docs URL.
   - Extend `services/aurora-cli/tests/publish_script.rs`.

## Tests (each fails without its fix)

- `crates/aurora-template` tests:
  - `pack_roundtrips_and_agrees_with_read_tree` with a depth-4 skill file and a 64-character id with a long path;
  - a zip with `<id>/.github/x.yml` reads like the tree (skipped);
  - `semver_ok("1.02.0")`, `semver_ok("1.0.0-rc.01")` are false;
  - the two YAML strings of Why 4 in `anchor_alias_tag_refusals`;
  - a skill `ref` of `-x`, `a b`, `a|b` is refused.
- Registry: the precedence tests unwrap. Delete one version's parse support temporarily to see a test fail, then
  restore it.
- `publish_script.rs`: an invalid `template.yaml` makes the script exit non-zero.

## Acceptance

- One path rule for zips and trees.
- Strict semver at the format.
- A bad head version is a visible problem.
- The reference CI fails loudly and checks what it runs.
- Clean, whole crates: `aurora-template`, `aurora-registry`, `aurora-cli`, and `aurora-api` (whole `--test it`,
  because the check's problem reporting and the drift test change); fmt `--check` by exit code; the workspace
  clippy; guards.
