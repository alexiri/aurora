# OPS-003: Compose skeleton, Containerfiles, Caddyfile, setup script

## Goal
`deploy/compose/` per `15 §Development` so the stack (postgres, migrate, api, gateway, hookhost, web, edge) starts healthy with podman compose.

## Linked requirements
- M0/15§compose; `15 §Images`, `§Networking: one URL`, `§Development: podman compose`; D-29/D-31; `19 §M0` acceptance ("podman compose up starts all services healthy").

## Context
- Read `docs/15-deployment-operations.md` sections Images, Configuration (Required secrets), Networking, Development.
- Binaries and health endpoints from BE-008 (api 4101 health, gateway 4103 health, hookhost 4104, web 4100). Config: TOML at `AURORA_CONFIG` + `AURORA__*` env; dev example `deploy/dev/aurora.dev.toml` (BE-008).
- sqlx offline: image builds have no DB, so builds use `SQLX_OFFLINE=true` with committed `.sqlx/` (I-05). Generate it with `~/.cargo/bin/cargo-sqlx sqlx prepare --workspace` (run as `cargo sqlx prepare --workspace` with `~/.cargo/bin` on PATH) against the dev DB and commit `.sqlx/` (if no query macros exist yet, the directory may be empty — fine).
- **Disk is tight (~35 GB free)**: Containerfiles use one multi-stage Rust builder that builds all service binaries once (`cargo build --release --locked -p … -p …`) with BuildKit/podman cache mounts for registry and target; service images copy their binary from that builder into `gcr.io/distroless/cc-debian12:nonroot`. Web: Next standalone on `node:22-slim` (or distroless nodejs22), non-root.

## Scope
### In scope
- `images/services/Containerfile` (multi-target: `--target api|gateway|hookhost|runner|connector-fake`), `images/services/web.Containerfile`, `.containerignore`/`.dockerignore` (exclude target, node_modules, .next, .git).
- `deploy/compose/compose.yaml`: services and networks exactly as the `15` table (postgres:16 with volume `aurora-pg` and healthcheck; `migrate` one-shot, `api` depends on its successful completion; gateway on core + external `aurora-sandbox` network `10.89.250.2`, volume `aurora-ca`, publishes 4102; hookhost; web; edge `caddy:2` publishing 4000; profiles `hosted` (runner) and `connector-fake`). Healthchecks for each service (distroless has no curl: add a tiny `healthcheck` subcommand? NO — instead rely on compose `depends_on: condition: service_started` and verify health from the host with curl; document this).
- `deploy/compose/Caddyfile`: `/v1/*` → api:4101 (flush_interval -1 for SSE/long-poll paths listed in `15`, request body ≥32 MiB, overwrite `X-Forwarded-For`/`X-Forwarded-Proto`), everything else → web:4100; never route `/internal/*` or `/metrics` (respond 404).
- `deploy/compose/aurora.toml`, `.env.example`, `setup.sh` (idempotent: generate missing secrets in `.env` with `openssl rand -base64 32`, never overwrite; create `aurora-sandbox` network if missing with the exact command in `15`; print first-admin bootstrap command; gateway CA generation is skipped with a TODO message until `generate-ca` exists in M2).
- `justfile` at repo root with `dev-db` (start/ensure `aurora-dev-pg`), `migrate`, `compose-up`, `compose-down`.

### Out of scope
- Runner/sandbox image, Helm, connector-fake behaviour.

## Acceptance criteria
- [ ] `podman compose -f deploy/compose/compose.yaml config` validates.
- [ ] `bash deploy/compose/setup.sh` is idempotent (run twice; `.env` unchanged second time).
- [ ] Build the images and `podman compose up -d`: `curl localhost:4000/v1/instance` reaches the API (404 envelope is fine in M0), `curl localhost:4000/` reaches web, `curl localhost:4000/metrics` is 404, gateway `:4102` answers 503 envelope. If disk space prevents building, stop, report `df -h` and what was verified.
- [ ] Tear down with `podman compose down` (keep volumes listed in report; do not prune unrelated images/containers).
