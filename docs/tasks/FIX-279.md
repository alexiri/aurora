# FIX-279: the Skills pages' rough edges from P5-SKILLS-5 pass 1 (2026-11-27)

## Why

P5-SKILLS-5 pass 1 (`docs/design/skills-memory/verify/SKILLS-REPORT-pass1.md`) found these on the web side; read each
item there with its captures. FIX-278 is the server part (C-1's judgement, C-6's field, C-7's label, B-1).

- **C-1 (web part):**
  - Add from library opens on the first row, even when that skill can't be added. It must open on the first skill
    that can be added, or on nothing when none can.
  - The file summary "n files · k KB" must show the server's numbers (FIX-278).
- **C-2, words.** The preview's and the fold's reasons are the raw rule text, lower case ("the body and files total
  more than 32000 characters"), and for `docx` a cut-off list of paths. Make them sentences, for example "This skill
  is larger than 32,000 characters, the most a skill may hold." or "Some of its file names use characters Aurora
  can't store." Keep a map from the server's reason codes to words in `lib/labels.ts`, never parsing the text.
- **C-3, rough.** List row descriptions aren't limited. One skill takes 9 lines and is about 157 px tall, where the
  mockup rows are about 67 px. Clamp them to two lines with an ellipsis; the panel keeps the full text
  (`web/src/components/skills/list.tsx`). The same applies to the organization list.
- **C-4, flow.** The update notice's count doesn't match the rows it points at. The agent page says 1 while two rows
  are marked, and the organization page says 2 while one is. Count, on each page, the rows this person can review.
  A row this person can't review gets no "Update available" chip, or a chip whose panel says who can review it.
- **C-5, rough.** At 390 px, **Compare**'s diffs and the library **update review**'s diff scroll sideways and cut the
  "Show n more lines" buttons. Pass `DiffView`'s `wrap`, which has FIX-277's hanging indent.
- **C-6 (web part).** The card reads "Branch <name>" from FIX-278's `default_branch` when no branch is set. Until that
  field exists, code against the contract name and keep "Default branch" as the fallback for `null`.
- **Further ideas from the report**, included because they are small:
  - the template screens still say "Use it when:" before a skill's text (`templates/new-agent/review-step.tsx` and the
    admin template review's diff label), wording the skill pages retired;
  - a library whose branch is a full 40-character commit id shows it shortened, as `shortSha` does elsewhere.

## Tests (each must fail before the fix)

- vitest:
  - the dialog opens on the first addable skill, and on none when none is addable;
  - each reason code has a sentence;
  - the row description is clamped (class or computed style);
  - the notice counts only reviewable rows, and a non-reviewable row has no chip;
  - "Branch main" from `default_branch`;
  - a commit-id branch is shortened.
- Mocked Playwright `skills.spec` / `skill-libraries.spec` at 390 px: Compare and the update review don't scroll sideways.

"Use it when") and update them in the same commit. Never loosen an assertion.
