# FIX-130: Org › Governance holds the app posture (moved from Org › Apps) — **small**

## Goal
The org's **app posture** (`open` / `restricted`, `07 §App availability`) is set on Org › Apps
(`web/src/components/apps/availability-view.tsx`). It is an org-wide rule about *what may be used*, like
the LLM and egress postures and BYO, which all live on Org › Governance
(`web/src/components/governance/governance-view.tsx`). The owner (2026-11-13): "the app posture in Apps
feels like it should be in Governance instead". Move the posture control; keep the per-app availability
list where people pick apps.

## Linked requirements
- `07 §App availability`, `03 organizations.app_posture`, `08 §11.1` (org governance), `14` org Apps and
  Governance sections, `14 §Visual design`.

## Scope
### In scope
- Governance gets an **Apps** section: the posture switch (Open: every active app / Restricted: only the
  apps listed as available), its explanation, and a link "Choose available apps →" to Org › Apps.
- Org › Apps keeps the per-app availability toggles (shown only when the posture is `restricted`; when
  `open`, a one-line notice "Every app is available — change in Governance" with the link).
- No API change (same `PATCH` the view already uses); if Governance saves through a different route,
  keep each control on its own route rather than merging requests.
- `14` amended (Governance and Apps sections).
### Out of scope
- Any change to how availability is enforced.

## Constraints / file ownership
`components/governance/governance-view.tsx` (+ a small `apps-posture-panel.tsx` like `byo-panel.tsx`),
`components/apps/availability-view.tsx`, `docs/14`. Run after FIX-117 if it is still touching these views
(tokens/primitives pass).

## Acceptance criteria
- [ ] Web tests: the posture is changed on Governance; Apps shows the toggles only when `restricted` and the
      notice + link when `open`; permissions as before (owner/admin).
- [ ] Shared primitives, both themes, 390 px; typecheck, lint, unit tests, production build.
