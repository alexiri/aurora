# FIX-160: Move to sqlx 0.9 (audit every dynamic SQL string)

## Goal
Dependabot PR #29 (2026-11-16) bumps `sqlx` 0.8.6 → 0.9.0. It does not build: `aurora-db` alone has **305
errors** `E0277: dynamic SQL strings should be audited for possible injections`. sqlx 0.9 accepts only a
`&'static str` as a query; anything built at run time must be wrapped in `AssertSqlSafe(…)`. The other crates
that run SQL fail the same way once `aurora-db` builds (about 255 files call `sqlx::query*`/`QueryBuilder`).

This is a security-relevant change, not a version bump: every run-time SQL string gets looked at once. The
upgrade is done by hand, and Dependabot ignores sqlx minors until it lands (`.github/dependabot.yml`,
`docs/ops/dependencies.md` §Pinned on purpose).

## When
It touches nearly every file that runs SQL, so it runs at a **quiet point**: no lane is editing SQL in
another worktree (between chains, or with the other lanes on web-only or doc work). The Orchestrator
places it. One lane, one branch, merged as soon as its gate is green.

## What changes
1. `Cargo.toml`: `sqlx = "0.9"` with the same features (check the feature names still exist); `Cargo.lock`
   regenerated; `cargo deny` still clean.
2. **Every error site, one of three fixes, in this order of preference:**
   - The string is a constant (a `const`, a literal behind a variable, `concat!`): make it `&'static str`.
     No wrapper.
   - The string is built from **values**: bind them (`.bind(…)`, or `QueryBuilder::push_bind`). A value never
     goes into SQL text.
   - The string is built from **identifiers or fixed fragments** (column lists, `ORDER BY` from an allowlist,
     generated `IN ($1, $2…)` placeholders, table names from code): wrap in `AssertSqlSafe(…)` with a one-line
     `// SQL-SAFE: <why>` comment naming where every interpolated piece comes from (a closed enum, an
     allowlist, a placeholder counter). If a piece can come from a request, a setting or the database, it is
     not safe: change the code to bind or allowlist it, and say so in the completion report.
3. A guard, `scripts/guards/sql-safe.sh`, wired into `run-all.sh`: every `AssertSqlSafe(` has a
   `// SQL-SAFE:` comment on the same or the preceding line.
4. **Migrations.** sqlx 0.9 changes migration handling ("Ensure deterministic migration order", optional
   checksum normalisation, a configurable `_sqlx_migrations` table). Aurora's existing databases must keep
   working: no migration re-runs, no checksum mismatch, the same table. Prove it with
   `bash scripts/e2e/upgrade.sh` (a database migrated by the old binary is opened by the new one) and the
   `aurora-db` migration tests.
5. Anything else 0.9 renamed or removed (pool options, `Any` types, `PgListener`, error variants): follow the
   compiler; no behaviour change.

## Out of scope
New queries, query rewrites for speed, moving to the `query!` macros.

## Gates
`cargo check --workspace --all-targets --locked`; workspace clippy; every test target of every crate that
uses sqlx (`aurora-db`, `aurora-api` it after `bash scripts/fixtures/build.sh` + lib, `aurora-gateway`,
`aurora-secrets`, `aurora-supervisor`, the others `grep -l sqlx` finds); guards (incl. the new one); schema
check; OpenAPI drift; `bash scripts/e2e/upgrade.sh`; `FRONTDOOR=1 bash scripts/e2e/gateway.sh`;
`AURORA_TEST_PODMAN=1 bash scripts/e2e/hosted.sh`.

## Completion report
The number of sites per fix kind (static / bound / `AssertSqlSafe`), every site that changed from
interpolating a value to binding it (each is a finding: say whether it was reachable from input), and the
upgrade.sh result. Then close Dependabot PR #29 (or let the next sqlx PR through) and remove the ignore entry.
