# GW-001: Gateway transport core (CA, proxy listener, lanes, TLS MITM, hygiene, destination guard, forwarding)

## Goal
A working forward proxy on :4102 that authenticates via a pluggable resolver, terminates TLS with minted leaf certificates, applies the transport-level hygiene steps, and forwards to upstreams — with a pipeline hook where policy/injection plug in later.

## Linked requirements
- M2/06: `§Listeners` (4102 proxy, `generate-ca`), `§Credential authentication` (Proxy-Authorization parsing, 407), `§Lanes` (MITM vs open; open lane never injects), `§MITM lane` (TLS termination, leaf certs: SAN host/IP, 7 days, LRU 10 000, regenerate <1 day left, ALPN h2+http/1.1), `§Per-request pipeline` steps **1, 2, 3, 13**, WebSocket upgrades, plain HTTP absolute-form, `§Guidance responses` (envelope, `x-should-retry: false`), `§Graceful shutdown` (stop accepting, drain ≤25 s); D-06, D-11; SEC-05 (Aurora headers never sent upstream), SEC-06 (destination guard), SEC-07 (method override / ambiguous path refused), SEC-09 (proxy port serves nothing else).

## Design (fixed)
- Module layout under `services/aurora-gateway/src/`: `ca.rs` (generate/load CA, leaf minting + cache), `proxy/{mod,listener,connect,absolute,tunnel}.rs`, `auth.rs` (parse `Proxy-Authorization: Basic base64(user:token)`; lane = `open` iff user == "open"; `trait CredentialResolver { async fn resolve(&self, token: &str) -> Result<Option<RequestIdentity>, ResolveError> }` — `RequestIdentity` fields per `06 §Credential authentication`), `pipeline.rs` (`trait RequestHandler` invoked after hygiene with `{identity, lane, host, port, method, normalized path, headers, aurora_headers, body}` returning either `Respond(Response)` (guidance) or `Forward(prepared request)`; default impl = pass-through), `guard.rs` (destination guard + guarded resolver), `hygiene.rs` (steps 1 and 3), `upstream.rs` (pooled hyper client, TLS roots = native + `tls.extra_ca_bundle`, header timeout → 504 `upstream_timeout`, connect/DNS failure → 502 `bad_gateway`/`resolution_failed`), `guidance.rs` (envelope builder; definite verdicts set `x-should-retry: false`).
- Destination guard: refuse private, loopback, link-local, CGNAT (100.64/10), multicast, unspecified, IPv6 ULA unless `gateway.allowed_private` covers it (CIDR, IP, hostname, `*.suffix`); metadata IPs (169.254.169.254, fd00:ec2::254) only by exact-IP entry; the gateway's own listeners and DB address+port always refused. Resolution happens through the guard at dial time (no TOCTOU: connect to the IP that was checked). When `gateway.egress_proxy` is set: name check locally, resolution at the proxy.
- Open lane: after auth + guard (+ `RequestHandler::open_lane_check` hook returning allow/deny), tunnel bytes; record byte counts (exposed to the later request-log task through a callback/trait).
- Production wiring in this task: `serve` uses a `DenyAllResolver` (every credential → 407) until GW-002 provides the DB resolver; tests inject a static resolver.

## Scope
### In scope
- `aurora-gateway generate-ca --out <dir>` exactly per `06 §Subcommands` (refuses to overwrite; `ca.key` mode 0600); CA load at `serve` from `gateway.ca_dir` (validates CA cert + key type).
- Everything in "Design".
- Graceful shutdown on SIGTERM (stop accepting; drain ≤25 s; close tunnels).

### Out of scope
- DB credential lookup (GW-002), ResolvedHost/policy/injection/holds/governance/request log (GW-003+), metrics beyond existing.

## Acceptance criteria
Integration tests in `services/aurora-gateway/tests/` using a local HTTPS upstream (rcgen test CA trusted via `extra_ca_bundle`; `allowed_private` covering 127.0.0.1) and a client (reqwest with `Proxy::all` + basic auth, trusting the gateway CA):
- [ ] HTTPS via CONNECT reaches upstream; response streams (chunked/SSE) intact; HTTP/2 upstream and client both work.
- [ ] Missing/invalid Proxy-Authorization → 407 + `Proxy-Authenticate: Basic realm="aurora"` + envelope `proxy_auth_required`.
- [ ] Origin-form request on 4102 → 400 `not_a_proxy_request`; absolute-form `http://` works.
- [ ] Aurora headers (`x-aurora-*`) and `Proxy-*`/hop-by-hop never reach upstream (upstream asserts).
- [ ] `X-HTTP-Method-Override` / `_method` → 400 `method_override_refused`; `/a/../b`, `/a/%2Fb`, `%5C`, `%00` → 400 `ambiguous_path`; `//a` collapsed.
- [ ] Destination guard: 127.0.0.1 without allow-list → 403 `destination_refused` (details.host); metadata IP refused even with a CIDR allow-list covering it; hostname resolving to a private IP refused.
- [ ] Open lane tunnels bytes without TLS termination (client sees the upstream's cert).
- [ ] WebSocket upgrade through MITM works (echo).
- [ ] Upstream header timeout → 504 `upstream_timeout` (use a short configured timeout in tests).
- [ ] `generate-ca` writes files with correct modes and refuses overwrite; leaf cache reuses certs.
- [ ] `cargo test -p aurora-gateway`, clippy `-p aurora-gateway --all-targets -- -D warnings`, fmt; `bash scripts/guards/dep-graph.sh` passes.
