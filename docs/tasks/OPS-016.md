# OPS-016: Faster builds and tests; worktrees clean up after themselves (phase 1)

## Goal
Cut wall-clock time and disk use of `cargo build` / `cargo test` for both the developer loop and the parallel worker lanes, and make every lane leave no build artefacts behind when it finishes. Measure before and after; keep what helps.

## Facts (2026-11-08)
- Profiles (`Cargo.toml`): dev `debug = "line-tables-only"`, `incremental = false` (I-24, disk), deps `debug = false`.
- There are **101 integration-test files** (46 in `services/aurora-api/tests/`), each linked as its own binary against the full dependency graph. Linking dominates, and every binary is hundreds of MB.
- A full workspace test takes ~15 min (AUDIT-001: build 7m25s, tests 14m49s).
- `ld.lld` and `clang` are installed but unused. `sccache`, `cargo-nextest` and `mold` are not installed.
- The main tree's `target/` reached 69 GB again; each worktree lane builds its own `target/` (~15–25 GB).

## Scope
1. **Baseline**: record the clean build, no-op rebuild, one-line change rebuild in `aurora-api`, the full `cargo test --workspace` (excluding e2e) and `target/` size, in `docs/ops/build-performance.md`.
2. **Linker**: `.cargo/config.toml` with `linker = "clang"` + `-C link-arg=-fuse-ld=lld` for x86_64-linux (and mold if the owner installs it; document both). Keep CI/container builds working (the Containerfiles build in their own images; make sure they have lld, or scope the config so they're unaffected).
3. **Fewer test binaries**: consolidate integration tests into **one test binary per crate** (`tests/it/main.rs` with `mod` files, the usual pattern). Keep test names stable enough that existing scripts and `docs/tests/*-coverage.md` references still resolve (update those docs if paths change: e.g. `api/channels_cards.rs::x` → `api/it/channels_cards.rs::x`). Gated e2e crates stay separate.
4. **Test runner**: evaluate `cargo-nextest` (process-per-test parallelism; tests already use isolated databases via `aurora-testkit`). If it's a net win, add a `just test` recipe and a `.config/nextest.toml` with sensible retries off and timeouts, and keep `cargo test` working too. Needs the owner to install `cargo-nextest`; give the exact command.
5. **Shared compilation cache across worktrees**: evaluate `sccache` (`RUSTC_WRAPPER`) so lanes don't recompile the same dependencies. Note that sccache disables incremental, which is fine for lanes. Document the install, the cache size cap (e.g. 20 GB) and the location. Make it optional: nothing breaks without it.
6. **Developer profile**: decide whether to re-enable `incremental` for workspace members only in the developer loop (a `dev-fast` profile or env in `just dev`), now that per-worktree targets are cleaned up. Record it as a decision superseding or refining I-24.
7. **Disk hygiene**:
   - the Orca worker spec template (the coordinator owns it; provide the text) gains a final step: after `worker_done`, nothing; instead the **coordinator** removes the worktree on merge (already done) **and** runs `scripts/dev/clean-lane.sh <worktree>`, which kills stray processes whose cwd is in the worktree, removes `target/`, and removes podman containers, networks and volumes with the lane's prefix
   - `scripts/dev/disk-report.sh` prints `target/` sizes, podman images/volumes by prefix, kind clusters and free space
   - a `just clean-stale` recipe uses `cargo sweep` if available, else documents `cargo clean`
   - all three are documented in `docs/ops/build-performance.md`
8. **Results**: re-measure everything from step 1, put the before/after table in the doc, and record the decisions (I-34+) in `docs/90-decisions.md`.

## Constraints / file ownership
- You own `Cargo.toml` (profiles, workspace members if tests move), `.cargo/config.toml`, `.config/nextest.toml`, `justfile` (build/test recipes only), the moved test files, `scripts/dev/**`, `docs/ops/**`, `docs/tests/*-coverage.md` (path updates only), `docs/90-decisions.md` (new I-entries) and `docs/18-testing.md` (how tests are run).
- No test may be dropped or weakened while moving. Compare test counts before and after: equal or higher.
- Don't install system packages yourself. List what the owner should install and make everything work without them.

## Acceptance criteria

- [ ] `cargo test --workspace` (excluding e2e) has the same or higher test count, all passing; fmt, clippy `-D warnings` and guards pass.
- [ ] Clean-up scripts tested on a throwaway worktree.
