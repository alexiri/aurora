# FIX-164: Workspace members can read their workspace's Internet access rules (read-only)

## Goal
P5-IA-2's spec (14 §Information architecture, the Internet access page) says a workspace member sees the
workspace's Internet access read-only: its summary sentences and rules, with no Common changes, Add rule
or Tighten…, and one `WhoCan` sentence for who can change it. I-27 gates reads of workspace policy to the
workspace owner, so the merged page (`d7430c4f`) shows members only the limits from above and the
`WhoCan` sentence. **Owner, 2026-11-17 (D-365): members may read their workspace's published rules,
read-only.**

## Change
1. **D-365 amends I-27** for this one case: a member of a workspace may **read** that workspace's
   **published** Internet access policy (rules and defaults of the active generation). Never drafts,
   generation history, warnings, overrides of other workspaces, or any write. Everything else in I-27
   stays.
2. A route for it (prefer a member-readable `GET` that returns only the published rules and the
   summary inputs, not the owner's full policy document; name it in `05` and as a contract line next to
   C-964, number from PROGRESS's next-free line). Permission-matrix rows: member yes, non-member no,
   service key as today.
3. The workspace Internet access page for a member renders the summary sentences and the rules read-only
   from that route (P5-IA-2's components; no edit controls), plus the existing `WhoCan` sentence.

## Tests
ITs: a member reads the published rules; a draft is never visible; a non-member and another workspace's
member are refused; the response has no draft or history fields. vitest for the read-only page; the
Internet access Playwright spec gains the member case (both themes, 390 px, axe). `docs/tests/security-coverage.md`
row for the I-27 amendment. Small–medium (S–M); any lane, ideally with the next P5-UX web work.

## Completion report (lane p5-apps)

- **Route (for the coordinator's I-27 review).** `GET /v1/workspaces/{ws}/internet-access`, **C-1020**, `services/aurora-api/src/domains/policy/routes.rs` (`get_ws_internet_access`). Authorization is `caller.workspace(...)` (`can_use`), the same check every member-readable workspace route makes; no `require_own`. It returns a new DTO `PublishedInternetAccess` (`dto.rs`): `number`, `default_action`, `uncredentialed_default`, `uncredentialed_allowlist`, `open_lane_posture`, `rules` of the **published** generation, built by `service::published_internet_access` (the published row only; the draft is never read). No `draft_revision`, `published_by`, history or warnings. The rules carry the ids their identities and targets name (agents, users, groups, secrets) as in `GET …/policy`; the dashboard shows a secret target as "a stored token" to a member. `GET …/policy`, `/generations`, `/warnings`, `/simulate` and every write stay `can_own` (proved in the same IT).
- **Docs.** C-1020 beside C-964; `05` route row; `04` permission-matrix row; `docs/tests/security-coverage.md` SEC-21 row (no new SEC number: the access-law row is the one this amends); D-365 already records the decision.
- **Tests.** `policy::a_member_reads_only_the_published_internet_access` (fresh workspace; owner's draft invisible; exact key set; published rule readable; owner-only routes still 403 for the member; PUT/POST/PATCH/DELETE 405; an org member without access 404; a member of another workspace 404 with no rules; no session 401), the `WsUse` row in `permission_matrix.rs` (the coverage test lists every OpenAPI route), vitest (`internet-pages.test.tsx` member page; `welcome.test.tsx` summary for a member), Playwright `internet-access.spec.ts` member case (both themes, 1280 and 390 px, axe, the owner's policy never requested).
- **Web.** The member page of a workspace's Internet access shows the summary, the line about apps, the `WhoCan` sentence, the published rules as text (no Common changes, Add rule, Tighten…, Edit/Delete) and the limits from above. The agent's summary (P5-UX-7) reads the same route for every viewer, so a member's Welcome says what an owner's says.
